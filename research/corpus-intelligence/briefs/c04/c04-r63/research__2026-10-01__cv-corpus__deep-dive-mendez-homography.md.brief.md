# docs/research/2026-10-01/cv-corpus/deep-dive-mendez-homography.md
## What it is (1-2 sentences)
Deep-dive read of Miguel Mendez's 2024-02-07 post "Image Registration in Sports Analytics" (StatsBomb CV practitioner, https://miguel-mendez-ai.com/2024/02/07/nfl-field-mapping), a manual interactive web app (upload image → click ≥4 point pairs → compute homography → warped-template overlay) whose value is not detection but the field-template construction recipe, the H_image→template vs H_template→image direction discipline, and a colinearity guard for DLT homography fitting. Targeted at GSE's gap (c): homography degeneracy on yard-lines-only frames.
## Key metrics/methods (formulas where given, else "not specified")
- Template: canonical hand-drawn field image at 120 × 53.3 px — 1 px = 1 yard. Construction constants from the post's code: field height 53 + 1/3 yards, field width 120 yards, painted line width 2 (template) px; elements drawn in code: sidelines, end lines, end zones, hash marks, yard numbers, goalposts. GSE mapping: template lives in meters, xM = x_yards × 0.9144. Hash marks must sit at true NFL lateral offset: NFL = 18 ft 6 in from each sideline; college = 40 ft apart.
- Homography math: 3×3 projective matrix H with 8 degrees of freedom; p_t = H · p_i (homogeneous coordinates: append 1); p_i = H⁻¹ · p_t (inverse direction, used to warp template onto image). 4 point pairs minimum (8 equations, 8 unknowns); overdetermined systems via library least-squares.
- Direction discipline: OpenCV's findHomography(templatePoints, imagePoints) — source=template, dest=image — yields H_template→image, which warpPerspective needs for the overlay; the measurement direction GSE needs is H_image→template (pixels → field meters). Never flip the correspondence order to "match the tutorial."
- The guard from the post's computeHomography(): (1) refuse unless point sets have equal length ≥ 4; (2) after findHomography, if homography.empty() → refuse with "Be sure they are not colinear" — i.e., degenerate correspondences → named refusal, not an emitted matrix.
- DLT colinearity math (standard derivation in file, not from the post): each correspondence stacks two rows into design matrix A (2n×9): [-x_i -y_i -1 0 0 0 u_i·x_i u_i·y_i u_i] / [0 0 0 -x_i -y_i -1 v_i·x_i v_i·y_i v_i]; solve A·h = 0, ||h||=1 via SVD. Colinear inputs: rows of A span < 8 dimensions, nullspace dim ≥ 2, solution not unique, condition number κ(AᵀA) = λ_max/λ_min → ∞ (or κ(A) = σ_max/σ_min → ∞). Near-colinear (yard lines nearly parallel, intersections with a nearby second line giving tiny orthogonal spread): λ_min small but nonzero, solver returns a matrix, fitting-point reprojection error looks fine while extrapolation meters away explodes — so a post-fit residual check alone is insufficient; the guard must measure geometric spread before solving.
- Implementable guard spec (checkCorrespondenceGeometry): need ≥4 correspondences; 2D spread test on BOTH src (pixels) and dst (meters) point sets — covariance 2×2, eigenvalues l1 ≥ l2 ≥ 0; if l2/(l1+eps) < 1e-3 [DERIVED] → throw DegenerateCorrespondencesError "colinear-src"/"colinear-dst"; absolute-scale backstop: sqrt(l2) < MIN_SPREAD, e.g. 8 px src, 0.5 m dst [DERIVED] → "insufficient-spread"; convex-hull area backstop catching "4 points, 3 nearly identical". Error reasons: "too-few" | "colinear-src" | "colinear-dst" | "insufficient-spread"; cv-pipeline.ts catches → logs reason → falls back to hand-seed or skips frame, never lets a degenerate H into tracklets.
- Test assertions: (1) 4 colinear correspondences (yard-lines-only sim) → throws reason "colinear-src"; (2) orthogonal spread 1.5 px → throws "insufficient-spread"; (3) 6 intersections from two crossing line families (known H_gt) → passes; fitHomographyDLT recovers H with mean reprojection error < 1.0 px on 20 held-out points; (4) direction test: projectPoint maps pixel → template meters, and applying the matrix to a template point does NOT land on the pixel (src/dst flip regression); (5) healthy src but identical dst yard values → throws "colinear-dst".

## Findings (numbers and facts, not vibes)
- GSE application (gap c), in file's priority order: (1) the colinearity guard is the #1 takeaway — slots between Chung's landmarksToCorrespondences() and fitHomographyDLT(), converting silent landmark degradation (hash-mark line missed in a frame) into a named refusal instead of garbage meters downstream (the exact failure the repo docstring already fears: "parallel yard lines give no true 2D correspondences"); (2) template recipe enables the next improvement; (3) warp-overlay validation improvement: invert H_image→template, warp template onto the frame, score overlap between warped white paint and the frame's white mask (Dice/IoU), reject H below threshold photometrically — no extra labels needed, the cheapest end-to-end H check available.
- Improvement path beyond Mendez: RANSAC wrapper (minimal 4-point samples, keep model with most inliers) around fitHomographyDLT + guard — broadcast landmark detection will produce outlier intersections; condition-number reporting per frame (early-warning for drift into near-degeneracy); temporal H filtering within a shot (moving average on the 8 parameters or projected control points); photometric warp check as final gate.
- Confidence in file: High on template recipe, p_t = H·p_i and inverse direction, 4-point/8-DOF, the homography.empty() guard and refuse-don't-emit behavior; High on the DLT colinearity derivation as standard CV theory; Medium on the 1e-3 eigenvalue-ratio threshold and absolute spread floors — [DERIVED] engineering choices to tune on GSE footage.
- Current GSE solver throws on a numerically singular pivot (< 1e-12) — the same instinct as the guard, but it fires deep inside the solver with no diagnostic, and near-colinear inputs sail through producing garbage H; the existing < 1e-12 pivot throw is kept as last-resort backstop.
