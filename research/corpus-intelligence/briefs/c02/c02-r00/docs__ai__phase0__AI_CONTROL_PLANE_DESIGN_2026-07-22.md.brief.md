# docs/ai/phase0/AI_CONTROL_PLANE_DESIGN_2026-07-22.md

## What it is (1-2 sentences)
The 2026-07-22 Phase 2 implementation blueprint for the GSE AI control plane: five independent PRs (A task/policy contracts, B invocation ledger, C atomic budget reservations, D credit funding truth, E provider hardening) that make every LLM call policy-gated, cost-accounted, and fail-closed, superseding draft PRs #148/#151.

## Key metrics/methods (formulas where given, else "not specified")
Cost-mode ordering for escalation control: NO_BILLABLE_EXTERNAL < CONFIRMED_CREDITS_ONLY < BUDGETED_CASH; effective mode = min(envMode, task.permittedModes) — a task may restrict below the environment, never escalate above it. Atomic reservation SQL: `UPDATE "AiBudgetWindow" SET "reservedUsd" = "reservedUsd" + $amount WHERE id = $window AND "reservedUsd" + "settledUsd" + $amount <= "capUsd" RETURNING id;` (zero rows → BudgetBlocked). Worst-case cost estimate = max output tokens × pricing version; missing pricing version fails closed for billable modes. Multi-scope reservations acquire windows in fixed lexicographic order inside one transaction (deadlock-free). Concurrency acceptance test: 100 parallel `executeAiTask` calls against a cap fitting 60 → exactly ≤ cap authorized, rest BudgetBlocked, `reservedUsd + settledUsd ≤ capUsd` holds under audit. Env-class resolution table: LLM_COST_MODE unset → production = ConfigurationError (deploy fails), preview/development/test = NO_BILLABLE_EXTERNAL; AI_ENV_CLASS unset derives from VERCEL_ENV/NODE_ENV and logs `envClassSource: 'explicit' | 'derived'`. EMERGENCY_RELIABILITY requires all three: LLM_COST_MODE=EMERGENCY_RELIABILITY + non-expired EMERGENCY_RELIABILITY_UNTIL ISO timestamp + EMERGENCY_REASON string, else ConfigurationError. Funding labels: pre-call CASH_EXPECTED | CREDIT_ELIGIBLE_UNCONFIRMED | CREDIT_EXPECTED_FROM_ACTIVE_GRANT | LOCAL_RESOURCE | EXTERNAL_FREE_ALLOWANCE_UNCONFIRMED | BLOCKED; post-billing reconciled CREDIT_APPLIED_CONFIRMED | CASH_CHARGED_CONFIRMED | NO_VENDOR_CHARGE_CONFIRMED | UNRECONCILED. Credit admission (CONFIRMED_CREDITS_ONLY): only with a fresh (observedAt within TTL), ACTIVATED/PARTIALLY_CONSUMED snapshot covering provider/account/region/model with remainingUsd ≥ worst-case estimate. Retry rules: AmbiguousCharge and ProviderRejected never auto-retried with same funds; PolicyBlocked/BudgetBlocked never retried.

## Findings (numbers and facts, not vibes)
- 5 PR sequence: A (contracts, zero runtime change) → B (ledger, additive) → C (reservations) → D (credit truth read-side) → E (hardening + call-site migration); each additive-Prisma-only, independently revertible; #148/#151 close with unit-by-unit preservation mapping when B lands. [OTHER]
- Governing invariants: provider ≠ payer; cost mode explicit + fail-safe; no silent model substitution; telemetry failure never converts a successful paid call into a retry; one canonical entry point (`executeAiTask`); evidence before promotion. [TRUST-SIGNAL]
- Ledger models: AiInvocation (statuses RUNNING | SUCCEEDED | FAILED | POLICY_BLOCKED | BUDGET_BLOCKED; telemetryStatus OK | DEGRADED separate), AiAttempt (statuses DISPATCHED | SUCCEEDED | FAILED | TIMEOUT | AMBIGUOUS; token counts incl. cacheRead/cacheWrite; @@unique([invocationId, ordinal])), AiFinancialAttribution (estimatedGrossUsd Decimal(12,6); creditGrantSnapshotId never inferred from model id — only from a grant snapshot). [OTHER]
- The #151 defect fix: `providerUsed` written only after transport dispatch begins; every fallback creates a NEW AiAttempt row; a failed direct call is recorded as providerRequested='anthropic-direct', status='FAILED' — the ledger can never claim the failed provider "served" the request; "cash billed" never written by dispatch. [TRUST-SIGNAL: attribution-honesty rule]
- Telemetry cannot break execution: non-throwing emitter; ledger failure sets telemetryStatus='DEGRADED' and enqueues to durable outbox; provider result returned regardless (test: kill the DB between provider success and ledger write → call still returns success). [OTHER]
- Explicitly NOT in scope without owner decision: enabling BUDGETED_CASH anywhere; setting AI_ENV_CLASS=production values; activating EMERGENCY_RELIABILITY; any credit application or account mutation; deleting #148/#151 branches; forcing call-site migration in one sweep. [OTHER]
- Typed error classes (11): Unauthenticated | Forbidden | InvalidInput | ConfigurationError | PolicyBlocked | BudgetBlocked | ProviderUnavailable | ProviderRejected | AmbiguousCharge | TelemetryDegraded | StoreUnavailable, each with `code` literal and `retriable: boolean`. [OTHER]

## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- "No silent model substitution" / "evidence before promotion" invariants: the same anti-gaming discipline the engine needs for projection sources — a projection source may never be silently swapped; promotion requires test evidence. [TRUST-SIGNAL]
- Attribution-honesty ledger (providerUsed only after dispatch; never claim a failed provider "served" a request): a pattern for engine signal attribution — never claim a signal drove a prediction it didn't touch. [TRUST-SIGNAL]
- Fail-closed on missing pricing version (never guess a cost): parallels the engine's rule of never fabricating a metric when the source is missing. [TRUST-SIGNAL]
- Remaining content is LLM-ops cost/governance machinery, not football intelligence. [OTHER]
