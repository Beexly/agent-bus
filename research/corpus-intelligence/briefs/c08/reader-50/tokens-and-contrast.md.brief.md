# docs/design/redesign-2026-09/tokens-and-contrast.md
## What it is (1-2 sentences)
A measured WCAG contrast audit of the live app's color system plus a proposed single-accent semantic token set (light + dark via :root/[data-theme="dark"]), every ratio machine-generated by a committed Node script (contrast-check.mjs) implementing WCAG relative luminance.
## Key metrics/methods (formulas where given, else "not specified")
WCAG relative-luminance + contrast-ratio formulas (script-implemented, dependency-free). AA floor: 4.5:1 text, 3:1 UI. Headline: 1 of 72 current pairs fails AA; all 54 proposed pairs pass.
## Data sources named
`apps/web/styles/design-tokens.css` (live tokens), `apps/web/tailwind.config.ts`, `apps/web/app/layout.tsx` (fonts), and grepped component call sites (KpiCard, PageHero, MetricExplainer, DataTable, pick-card.tsx variants/badges, lib/intelligence/colors.ts, globals.css, methodology-section.tsx, bestball-board.tsx).
## Findings (numbers and facts, not vibes)
- Current: 72 pairs measured, 71 pass, 1 fails — bare text-ultraviolet (#7B61FF) on surface-card (~eclipse/80%, #151225) = 4.36:1, a real AA failure for body text; on bg-carbon it clears at 4.50:1 by only 0.002 (too thin to trust). Prescribed fix: swap to text-ultraviolet-glow (#9F87FF) at those call sites (already the pattern in pick-card.tsx).
- Proposed set: 54/54 pairs pass; worst case = light accent on surface-sunken at 4.84:1.
- Token drift found: tailwind `obsidian` #080A0F vs CSS `--obsidian` #05070B; `--ion-2` comment says #9AA6B8 but ships #B1BAD5; tailwind `ion.3` (#9AA3C0) differs from CSS `--ion-3` (#8B97AB); DESIGN.md colors stale vs live.
- Typography: current primary body token `--t-body` is 15px, one px under the brief's 16px mobile floor; `--w-prose: 720px` already sits in the 60–75 char range once body moves to 16px. Fonts loaded: Exo 2, Inter, JetBrains Mono, Instrument Serif; recommendation is Inter (body/headings, tabular figures via tnum) + JetBrains Mono (hashes, receipts, lines, odds).
