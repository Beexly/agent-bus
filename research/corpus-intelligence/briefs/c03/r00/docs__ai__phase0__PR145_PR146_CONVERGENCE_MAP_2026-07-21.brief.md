## Findings (numbers and facts, not vibes)
- Canonical owners: AI invocation policy → AI control-plane facade (the ONE gate every model call passes through, including any future NOVA-initiated call); provider/model registry → neither currently, a genuine gap to build as `packages/ai-control-plane/registry/` fed by NOVA change-detection review packets; credit lifecycle → NOVA's evidence-gated monetization/policy model (extended); cost attribution/API spend → Phase 4 atomic reservation ledger (current `budget-store.ts`/`cost-monitor.ts` are monthly aggregates, NOT atomic/concurrency-safe); LLM-call telemetry → `AiInvocation`/`AiAttempt`/`AiFinancialAttribution` tables; scheduler → NOVA; source monitoring → NOVA outright; observability → one cockpit, two panels, not two dashboards (`loadClaudeApiCostsDashboard()` stays the one read-model for LLM spend); Founder OS → NOVA outright.
- The forced architectural decision: `credit-pool.ts` and NOVA's `monetization.ts`/`policy.ts` both answer "is this credit real and usable?" — the former from model-ID string shape at runtime, the latter from an evidence-gated opportunity lifecycle at discovery time. `credit-pool.ts`'s own docstring already overclaims that this proves "the credit pool that paid for it" — a Bedrock model ID proves Bedrock was USED, not that AWS Activate credits PAID. Resolution: rename to `providerClassForModelId()` (provider class, never payer-of-record) and query NOVA's credit-grant state before ever labeling spend as credit-covered; until NOVA's credit persistence exists, treat its pool labels as unverified hints only, never displayed as confirmed savings.
- NOVA's persistence is intentionally unwired per #146's own PR description; single Prisma schema (`packages/db/prisma/schema.prisma`), no separate NOVA-only database.
- `internal-llm.ts` has verified gaps: no AbortController signal passed to fetch, no endpoint allowlist, local/external-free lanes conflated.
