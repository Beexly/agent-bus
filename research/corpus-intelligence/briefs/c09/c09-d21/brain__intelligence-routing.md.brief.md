# brain/intelligence-routing.md
## What it is (1-2 sentences)
The wiring diagram for the Sports OS intelligence network: defines three continuous flow patterns (Signal Intake, Query Response, Settlement Feedback) across 15 documented components, with tier-boundary constraints, contradiction handling, and governance gates at each stage.
## Key metrics/methods (formulas where given, else "not specified")
No statistical formulas. Operational thresholds/criteria specified: SETTLEMENT_PENDING flag if no Tier 1/2 final-score confirmation within 6 hours; Tier-5 alerts marked EXPIRED after 30 minutes without Tier 1 corroboration; source reliability scores bounded at ±5 per event and smoothed over a 30-pick rolling window; metrics reports generated at 30th/50th/100th settled pick; calibration check run at each complete 50-pick window. Claim-governance scan rejects: sharp-money claims without Tier 1/2 data, certainty language, injury claims without Tier 1 backing, fabricated specificity. Evidence staleness: Tier 1/2 items beyond TTL trigger FRESHNESS_WARN. Model output (Claude API) is Tier 6 and never evidence.
## Data sources named
Source Acquisition Mesh (polls registered licensed healthy sources, stamps retrievedAt); Tier 1 official feeds, Tier 2 sources, Tier 4 market data, Tier 5 community channels; Evidence Vault (normalized EvidenceItem schema: sourceId, sourceTier, entityType, entityId, claimType, observedAt, retrievedAt, validUntil from TTL, confidence, publicSafe); Entity Graph; Signal Ledger (append-only; events: SIGNAL_RECEIVED, ANSWER_PUBLISHED, ANSWER_WITHHELD, SETTLEMENT_RECORDED); Market Gravity; Claim Governance; Operator Cockpit; Ask the Brain; Research Lab; calibration-feedback-loop.md, source-acquisition-mesh.md, picks-intelligence.md, claim-governance.md, operator-cockpit-governance.md, product-ecosystem.md (15-component dependency map).
## Findings (numbers and facts, not vibes)
- Flow 1 (Signal Intake): source poll → evidence normalization (contradiction check: new item vs equal/lower-tier item on same claim → POSSIBLE_CONTRADICTION; Tier 1 vs prior Tier 1 conflict → CONFLICTED + operator alert) → entity resolution (new node flagged NEW_ENTITY) → append-only Signal Ledger → Market Gravity on Tier 4 arrival → weak-signal stream kept separate.
- Flow 2 (Query Response): question parse → entity/evidence retrieval filtered by freshness, tier, publicSafe, contradiction status → Market Gravity context injected as MARKET_SIGNAL (not fact) → answer with LOW/MEDIUM/HIGH confidence, stated weaknesses, per-claim sourceId+tier citations, explicit unknowns → Claim Governance scan (WITHHELD on failure) → ledger entry → surface delivery.
- Flow 3 (Settlement Feedback): Tier 1/2 final confirmation → picks settled WIN/LOSS/PUSH/VOID (immutable) → SETTLEMENT_RECORDED ledger events → calibration accuracy + evidence-chain quality + source quality signals → source reliability updates → model accuracy updates at 30/50/100-pick milestones.
- Routing constraints: no backward flow across tier boundaries (Tier 5 never into Tier 1/2 stream; Tier 6 model output never cited as evidence); settlement never rewrites historical evidence (immutable); public surfaces see only publicSafe content, flag set at normalization and not overridable at surface level; dependency ordering enforced (no picks evidence display before Evidence Vault + Signal Ledger; no public Ask-the-Brain before Claim Governance).
- 15 components; status: doctrine only, implementation requires approved change proposal.
