# ops/edge/2026-08-19-calibration-gate-split-map.md
## What it is (1-2 sentences)
A read-only research pass mapping exactly where the calibration-gate floors (Brier ≤ 0.22, ECE ≤ 0.05) and the 3-streak live in code, which public surfaces each gate blocks, and proposing a behavior-preserving CALIBRATION-vs-DISCRIMINATION split so the passing reliability story can surface while the failing Brier floor keeps win-rate claims dark.
## Key metrics/methods (formulas where given, else "not specified")
Floors: `DEFAULT_CALIBRATION_FLOORS = { n: 100, brier: 0.22, ece: 0.05, murphyReliability: 0.05 }` (`apps/web/lib/ops/calibration-eligibility.ts:69-74`); `brier > floors.brier` → fail reason (:118); ECE (:120); Murphy-reliability (:121-127). ## Findings (numbers and facts, not vibes)
- Two distinct gates both call themselves `canExposePerformanceStats`: Gate A (env `PERFORMANCE_STATS_ENABLED`, owner flag, no floors) blocks /api/performance, /performance headline, /api/clv, performance content publishing; Gate B (0.22/0.05 floors + 3-streak) blocks the public calibration report (`loadPublicCalibrationReport` → "collecting" when closed) consumed by homepage, /board, /house, /observatory, /calibration, /api/calibration, and the CalibrationPanel inside /performance — so the currently-passing ECE/reliability story is dark because Brier fails.
- Split design: CALIBRATION gate = {n:100, ece:0.05, murphyReliability:0.05} + own 3-streak (currently passing); DISCRIMINATION gate = {n:100, brier:0.22} + own 3-streak (currently failing); legacy combined ≡ CALIBRATION ∧ DISCRIMINATION. Master switch `CALIBRATION_GATE_SPLIT_ENABLED` (unset/false = bit-for-bit today's behavior); only owner flip routes reliability surfaces to the CALIBRATION gate; win-rate/track-record/PROVEN stays on the combined gate regardless.
- Five split ambiguities documented: (1) streak reset couples gates — failing Brier zeroes the streak passing ECE earned, and per-gate priors are unrecoverable retroactively (conservative seed = both start at 0); (2) publish policy re-derives streakMet independently — must pass per-gate streaks explicitly; (3) two streak writers (cron + ops read-path) must advance both counters in one snap under `metricsGeneratedAt` idempotency; (4) one K vs per-gate K needs a decision; (5) name collision with the 7-day Brier regression alarm must not be conflated.
- Value-pinning tests lock 0.22/0.05/0.05 in 4 test files; sealed/holdout zones (`packages/db/prisma/**`, `.github/**`, guardrails, edge-lab walk-forward seal, ladder rung thresholds) must not be touched; BSS fields can be lifted into the durable payload display-only for a future DISCRIMINATION member.
- Not gated by either: the board/picks surface (`PUBLIC_PICKS_ENABLED` + stale-odds kill switches) and confidence display mode are independent of Brier/ECE.
