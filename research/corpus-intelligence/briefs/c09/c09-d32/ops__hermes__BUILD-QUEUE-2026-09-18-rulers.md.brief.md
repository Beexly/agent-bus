# ops/hermes/BUILD-QUEUE-2026-09-18-rulers.md
## What it is (1-2 sentences)
Hermes builder queue (2026-09-18, sixth queue, outranks five others) prescribing five fixes to the three evaluation "rulers" that grade every other queue's output: as-of/lookahead quarantine, same-book closing-line value, the gate-decision writer, conformal-quantile clamping, and walk-forward fold independence. An outside skeleton analysis independently derived the same defects, which the doc treats as cross-validation of the diagnosis.
## Key metrics/methods (formulas where given, else "not specified")
- CLV defect: current grader reports 23.0% beat-the-close rate vs a 52.4% requirement; the doc argues this number is uninterpretable because mint-side and close-side averages are taken over different book sets (a line moving -3 to -2 is good if you took the underdog, bad if you took the favorite — a signed delta averaged across sides is meaningless; grader already uses per-pick ClvKind of POINTS or PROBABILITY, keep that). Fix: grade only over the intersection of bookmaker keys present at both ends; refuse (never average across the mismatch) when the intersection is empty; store additive columns `clvSameBookValue`, `clvSameBookVerdict`, `clvBookBasis` beside existing `clvValue`/`clvVerdict`; report book composition beside the grade and count refusals by reason.
- Conformal quantile: `apps/web/lib/calibration/cqr.ts:10-16` computes rank = Math.ceil((1-alpha)*(n+1))-1 correctly then clamps into [0, n-1]; at n=5, alpha=0.1 the clamp silently returns the largest observed score so the function claims 90% coverage and delivers 83.33%. Fix: return positive infinity below the sample floor (an infinite interval = refusal to price, the withholding direction), applied per stratum using existing `StratumParts`/`stratumKey()`/`parseStratumKey()` in `packages/prediction-engine/src/certificate/stratum-coverage.ts`.
- Walk-forward: `packages/prediction-engine/src/edge-lab/walk-forward.ts:80-137` implements purge, embargo and a sealed holdout correctly, then cuts folds by row index (`sorted.slice(startIdx, endIdx)`) with no group key; documented NFL fixture triplication (one real fixture = up to three `games` rows) lets rows of one fixture land on both sides of a train/test boundary, inflating measured skill by an unquantified amount. Fix: group key derived from existing `findTwinCandidate` and id-shape enumeration in `packages/ingestion-pipeline/src/game-identity.ts` with `isEspnExternalId` at `fixture-collapse.ts:65`; keep purge/embargo byte-identical; report measured grouped-vs-ungrouped skill gap.
- As-of quarantine: `backfill-independent-trueprob.ts` selects settled WIN/LOSS rows and overwrites `factorBreakdown.independentEdge.trueProb` with probabilities computed partly from post-settlement information (`fetchMlbStandings` takes only a season number, no date; NFL EPA read is a whole-season aggregate) — every row it touched carries information that postdates the outcome it scores (bitemporal violation: writes carry transaction time "now", valid time "kickoff", nothing records the difference). Fix: typed field `independentEdge.trueProbBasis` (`post_settlement_backfill` | `as_of_mint`) and a local `assertObservedAtOrBefore` guard mirroring `asof-store.ts:184-199` around the two offending sources.

## Findings (numbers and facts, not vibes)
- Task 1: two of the blended independents do not honor the `commenceTime` they are handed; backfill runs from a four-hourly cron and again inline inside the six-hourly calibration cron.
- Task 2: current CLV = 23.0% vs 52.4% requirement is "a statement about the model and the book composition together, and the two are not separable in the current number"; `ClosingOddsRow` (`clv-capture.ts:38`) carries no bookmaker field and both callers (`settle-sport.ts:622-633`, `free-path-clv.ts:36-49`) omit bookmaker from their Prisma select; the close side has an unused better source — `markClosingSnapshotsIfEnabled` at `settle-sport.ts:867` tags last pre-existing `OddsLineSnapshot` per market/book/side as CLOSE.
- Task 3: `gate_decisions` holds 1,167 rows spanning 2026-06-10 to 2026-06-11 and nothing since — no code writes the table; three readers (`apps/web/lib/board/passes.ts`, `apps/web/lib/board/state.ts`, `apps/web/lib/bot-outbox/load.ts`) have been on fallback paths for 3+ months; `isBootstrap` defaults `true` (`:675`) and readers filter on it, so a naive writer would produce invisible rows; two latent timezone bugs ride along (`todayBounds()` duplicated byte-for-byte using Node process zone (UTC); `passes.ts:126/277/361/366` stamp UTC dates so from 19:00 Central the panel headlines tomorrow's date — correct zone is Central, not Eastern).
- Task 4: n=5, alpha=0.1 case claims 90% coverage, delivers 83.33%; fix = +infinity (refusal to price).
- Task 5: fold independence decides whether several models are genuinely independent or "one estimate wearing several labels"; measured skill gap between grouped and ungrouped on a duplicate-containing fixture set is ordered reported but no value is given yet.
