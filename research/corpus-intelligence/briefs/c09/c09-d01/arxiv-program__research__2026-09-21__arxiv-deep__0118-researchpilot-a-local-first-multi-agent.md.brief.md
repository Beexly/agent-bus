# arxiv-program/research/2026-09-21/arxiv-deep/0118-researchpilot-a-local-first-multi-agent.md
## What it is (1-2 sentences)
Deep-read ledger of "ResearchPilot: A Local-First Multi-Agent System for Literature Synthesis and Related Work Drafting" (arXiv:2603.14629v1, March 2026) — an open-source, local-first four-stage literature-synthesis pipeline (Search → Extraction → Synthesis → Writer) built with DSPy typed contracts, FastAPI + Next.js + SQLite + Qdrant, BYOK model access. Verdict in file: ADAPT the architecture pattern, REJECT the abstract-only extraction design (the paper itself admits abstracts are insufficient for datasets, settings, and quantitative outcomes).
## Key metrics/methods (formulas where given, else "not specified")
No equations — systems paper; formal artifacts are stage contracts (SearchAgent, ExtractionAgent, SynthesisAgent, WriterAgent) and persistence schema.
- SearchAgent: async Semantic Scholar + arXiv queries; filters abstract-less entries; dedups by DOI/title; truncates to ≤10 papers; tolerates partial source failure (HTTP 429 on one source → other source still yields a usable set).
- ExtractionAgent: per-paper DSPy signature over the abstract → JSON with five arrays: claims, methods, datasets, results, limitations. Runs sequentially (keeps context windows small).
- SynthesisAgent: extraction list → three fields: consensus, contradictions, open_gaps.
- WriterAgent: synthesis + bibliography → markdown related-work draft with inline [R1]/[R2] citation labels; "does not verify that every citation label is perfectly supported."
- Orchestration: DSPy signatures as typed input/output contracts; provider changes via env config or per-run runtime overrides (OpenAI-compatible, Anthropic, Groq, OpenRouter); POST /research streaming API with lifecycle events (queued, agent_started, agent_progress, agent_completed, done, error); incremental fetch() reader (not EventSource) so POST body can carry question + config overrides.
- Persistence: SQLite for reports; Qdrant for vector artifacts + semantic history search; keyword fallback when vector search unavailable. Embedding modes: remote / local / auto (local default: BAAI/bge-small-en-v1.5).
- Evaluation used Groq-hosted llama-3.3-70b-versatile.
## Data sources named
Runtime retrieval from Semantic Scholar + arXiv (no static dataset). Persisted artifacts per report: original question, retrieved papers (identifier, title, abstract, source, URL, year, authors, DOI), structured extractions, synthesis (consensus/contradictions/open gaps), markdown draft with [R1]/[R2] labels, warnings, references, timestamp. ## Findings (numbers and facts, not vibes)
- Automated tests: 11 backend tests + 1 frontend smoke test passing locally (streaming, report lookup, setup-failure propagation, report listing/keyword fallback, no API-key leakage in config exposure, dedup/partial-failure search, embedding-mode selection, frontend shell render). Author is explicit these "do not establish output quality."
- One successful end-to-end run (March 14, 2026) on "recent trends in RAG for QA": 12.47 s end-to-end, 10 papers retrieved, 10 extractions, synthesis with 4 consensus / 2 contradictions / 3 open gaps, 2046-character related-work draft; Semantic Scholar HTTP 429 warning tolerated via arXiv.
- Three-query repeat batch: 0/3 completed — provider-side token rate-limit errors before completion (28.42 s and 29.24 s to failure). Author frames this as "an important operational result: even when the pipeline implementation is stable, end-to-end reliability remains constrained by external model-provider quotas."
- Failure-mode catalog (Table 3): Semantic Scholar rate limiting without API key; malformed model JSON (schema validation + defensive parsing); missing remote embeddings (local fallback + keyword fallback); persistence-layer errors (warning surfacing + SQLite-backed persistence).
- Weaknesses acknowledged: 3 queries, no human quality ratings, no baseline comparison, no stage-level latency breakdown.
- Key assumption flagged as a limitation: abstracts suffice for a useful first pass (explicitly insufficient for precise reporting of datasets, experimental settings, or quantitative outcomes).
