## Key metrics/methods (formulas where given, else "not specified")
- **Murphy decomposition (from arXiv:2607.00164, *Verifiable Rewards for Calibrated Probabilistic Forecasting*):** the module works with the identity `brier - (reliability - resolution + uncertainty)` and the file states it is **not** zero on a sample in general. The exact residual is derived as `SUM_b (n_b/n)·var_p(b)` — the within-bucket variance of the *stated* probabilities — and `binningResidual` recomputes it from the buckets so two independent routes assert agreement to **1e-12**. A single sign error in any of the four terms fails the suite. The residual measures binning coarseness, not estimator failure (docs say so). Landed in `calibration.ts` + new `Scorecard` fields + markdown block. Paper's core point: Brier alone is ambiguous — two forecasters can be equally calibrated and differ in Brier purely through **resolution**.
- **Opponent-adjusted NFL pass blocking/rushing (from arXiv:2604.01491):** 153k interactions from 266 games → uncertainty must come from **end-to-end game resampling**; an interval covering zero is "directional, not decisive." Landed as `clusterBootstrap` + `decide`, and `Scorecard.clusterVerdict`.
- **Relabeling null (from arXiv:2603.03613, *NFL Violations in Permutation-Based Optimization*):** its result "applies to ... procedures based on relabeling, resampling, and permutation tests" — landed as `relabelingNull`, the artifact check for a search-many-keep-the-winners gate.
- **BigInt-exact Wilson (from arXiv:2505.23703, *Let's Reason Formally*):** natural language says WHICH claim matters; the formal layer discharges it — landed as `exact.ts`, which **settles the caveat #914 had to tolerate**.
- **Three defects the pins caught:** (1) BigInt/Number mixing in the exact path — fixed, not pinned around. (2) A runaway guard set below the fractions' real size — the reduced Wilson fractions carry z² (denominator 10^30) through n² and every add/multiply, so 96 bits was far too tight; raised to a **4096-bit runaway guard**, documented as such (BigInt never silently rounds, so it is not a precision guard). (3) The relabeling null's orientation was wrong, and the API changed because of it: a p-value alone lies here — a *uniformly* better candidate wins under **every** relabeling, so its p is ~1 while it is maximally robust, whereas a lucky arrangement has a low p because relabeling does better; the API now reports `survivesRelabeling` as the gate-able verdict and ships the p beside it. Also: a mean difference is **invariant** under permuting one arm, so it cannot be permutation-tested at all — the null uses the row-wise hit rate, which is also the statistic the scorecard already bands.
