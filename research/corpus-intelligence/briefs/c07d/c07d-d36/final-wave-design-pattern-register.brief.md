# design/final-wave-design-pattern-register.md

## What it is (1-2 sentences)
The living doctrine register of canonical UI/UX design patterns across Sports OS — Pick Card, Evidence Drawer, Signal Ticker, Market Gravity Meter, Source Tier Badge, Confidence Score Display, Settlement Badge, Empty State — each with required/forbidden elements, when-to-use/when-not-to-use rules, implementation paths, plus a forbidden-pattern list, a pattern retirement protocol, and Codex audit requirements. Sourced from Prompt 4 — Final Wave, under the Sports OS Intelligence Network Master Plan.

## Key metrics/methods (formulas where given, else "not specified")
- **Confidence tiers:** 85–100 → `--ultraviolet` with glow (high conviction, earned glow); 65–84 → `--silver` (moderate); 0–64 → `--ash` (lower — displayed, not hidden, per transparency). Numeric rendered in JetBrains Mono.
- **Minimum calibration set:** confidence score is NOT displayed until **≥30 settled picks** are in the model version's calibration set (else "Calibrating — insufficient data"); displaying 99 or 100 with <30 settled picks is forbidden; score may not appear in social graphics without the context label; no animated real-time scores.
- **Mandatory context label (verbatim):** "Confidence is calibrated against historical results — not a guarantee of outcome."
- **Signal ticker (doctrine only, not implemented):** scroll speed 40–60px per second ("matches eye tracking comfort for data tickers per the motion design guidelines in `DESIGN.md`"); pause on hover; no animation unless data changed in last 5 minutes; signal summary ≤60 characters; timestamp HH:MM relative to now. Color coding: ODDS → `--orbital-cyan`, INJURY → `--ultraviolet`, PICK → `--plasma`, SETTLEMENT → `--silver`.
- **Source tiers:** T1 `--orbital-cyan` border ("Official / Primary Source"); T2 `--orbital-cyan` at 70% opacity ("Licensed / Structured Data"); T3 `--ash` border ("Trusted Secondary Source"); T4 `--ash` at 70% opacity ("Market Signal (context only)"); T5 `--ash` at 50% opacity ("Community Signal (watchlist only)"); T6 dashed border, `--ash` at 40% ("Synthetic / AI-Generated").
- **Settlement badge:** WIN `--silver` text, muted green border (not full-saturation); LOSS `--silver` text, muted red border; PUSH `--ash`/`--ash`; VOID `--ash` dashed + tooltip. No WIN/LOSS before the game's final result is confirmed from a T1 source. No confetti/celebration sounds; no full-saturation green/red (casino associations).
- **Market Gravity Meter (doctrine only):** opening line, current line, movement delta, direction arrow, always-visible label "Market context — not a sharp money signal", attribution "odds data via The Odds API". Explicitly NOT a "sharp money" indicator.
- **Evidence drawer freshness states:** FRESH / DEGRADED / STALE (plus per-item TTL indicator).
- **Retirement protocol:** (1) mark `Deprecated — replaced by [Pattern N]`; (2) never delete the original entry; (3) add a new entry; (4) update consumers via a MEDIUM-tier codemod per `docs/audit/codemod-safety-policy.md`.
- **Codex audit requirements (6):** (1) Pick Card source-freshness disclosure on all public routes; (2) ConfidenceScore `showDisclaimer` defaults true; (3) SettlementBadge never renders WIN/LOSS before T1 confirmation; (4) no full-saturation casino green (`#00FF00` or similar); (5) empty states contain no placeholder pick data; (6) any lock icon (`🔒` or `lock` in className/aria) in any component reported as P1.
- **Tier gating on Pick Card:** Free = direction visible, confidence hidden (blurred/omitted); Pro = direction + confidence; Elite = Pro + early access indicator. Confidence Display is Pro/Elite only.
- **Forbidden-pattern alternatives:** lock icon on a pick → Settlement Badge (WIN) after settlement only; real-time win counter → static win rate badge with claim governance; "AI predicts..." headline → "Model context:" / "Evidence suggests:"; sportsbook green action button → `--plasma` primary CTA; animated confidence score → static score with governance wrapper; fake "sharp money alert" badge → Market Gravity Meter with context label.

## Data sources named
- Source tier tooltips name the tier taxonomy, not vendors: T1 Official/Primary, T2 Licensed/Structured, T3 Trusted Secondary, T4 Market Signal (context only), T5 Community Signal (watchlist only), T6 Synthetic/AI-Generated.
- The Odds API — attribution string for the Market Gravity Meter: "odds data via The Odds API".
- Settlement confirmation requires a T1 (official/primary) source.

## Findings (numbers and facts, not vibes)
1. **Pattern 1 — Pick Card (implemented, baseline; extend only via documented variant):** required — sport label (e.g. "NFL", `--ash`, uppercase, monospace); game label (team A vs B, game date, `--silver`); pick direction (Over/Under, spread direction, `--plasma` accent, prominent); tier badge (FREE/PRO/ELITE, gated); source freshness timestamp (always visible, never omitted); "Entertainment purposes only" disclosure on public surfaces. Forbidden: lock/padlock imagery; win-rate counter in the card body; animated confidence score; sportsbook green background. Impl: `apps/web/components/public/PickCard.tsx`.
2. **Pattern 2 — Evidence Drawer (implemented, cockpit only — not for public surfaces):** expandable panel revealing the full evidence chain — evidence tier badge per item (T1/T2/T3), evidence text, source attribution (outlet name, not internal source ID), TTL indicator, overall freshness status (FRESH/DEGRADED/STALE). Use: cockpit operator view when reviewing provenance; Pro/Elite public read-only summarized version only if owner-enabled. Forbidden: internal source reliability scores (cockpit-only), API endpoint paths/credentials, source IDs revealing the ingestion architecture. Impl: `apps/web/components/cockpit/EvidenceDrawer.tsx`.
3. **Pattern 3 — Signal Ticker (doctrine only, not implemented):** horizontal scrolling marquee of real-time signal events (line movements, evidence arrivals, pick status updates). Use: homepage hero, cockpit header, live views — never in a pick card; not where motion distracts. Proposed impl `apps/web/components/public/SignalTicker.tsx` requires owner approval before homepage use.
4. **Pattern 4 — Market Gravity Meter (doctrine only, not implemented):** visual line-movement context (opening line, current line, movement delta, direction arrow); use Pro/Elite pick detail and the operator-produced intelligence brief; NOT free tier; never where movement could be read as a recommendation without an evidence chain. Impl proposed: `apps/web/components/public/MarketGravityMeter.tsx`.
5. **Pattern 5 — Source Tier Badge (partially implemented):** six variants per the tier spec above; use in Evidence Drawer, public Trust Layer disclosures, Pick Provenance view — NOT in public-feed pick cards (cognitive load). Impl: `apps/web/components/ui/SourceTierBadge.tsx`.
6. **Pattern 6 — Confidence Score Display (implemented, Pro/Elite only):** 0–100 numeric + mandatory governance wrapper ("Confidence is calibrated against historical results — not a guarantee of outcome"); ≥30 settled picks minimum; color bands 85–100/65–84/0–64 per spec. Impl: `apps/web/components/public/ConfidenceScore.tsx`.
7. **Pattern 7 — Settlement Badge (doctrine; implemented as part of Pick Card):** WIN/LOSS/PUSH/VOID badges per spec; WIN/LOSS only after T1-confirmed final result. Impl: `apps/web/components/ui/SettlementBadge.tsx`.
8. **Pattern 8 — Empty State (implemented; extend via established template):** icon (brand-consistent), short headline, body text, optional CTA. Forbidden: "No picks today — check back!" tout language; fabricated placeholder picks; confidence scores in illustrations. Voice examples verbatim: "No active picks in the current window. Intelligence updates as markets open." / "Calibration in progress. Minimum 30 settled picks required before confidence scores are displayed." / "No evidence items in the vault for this entity. Add a source to begin." Impl: `apps/web/components/ui/EmptyState.tsx`.
9. **Empty-state discipline** forbids fabricated placeholder picks and touts — the UI-side expression of the honest "collecting" state.

## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- **TRUST-SIGNAL:** The tier-badge taxonomy (T1–T6), always-visible source freshness, T1-gated settlement, and the "calibrating" empty-state voice are the trust-signal program's public vocabulary. Mechanism: every signal the engine emits must arrive with tier + freshness metadata so the UI can badge it; the 30-settled-pick floor is a calibration-lane gate expressed in component form — the engine must produce ≥30-pick calibration sets per model version before any public confidence display.
- **OTHER — calibration/sizing lane:** The Market Gravity Meter's required "Market context — not a sharp money signal" label and the ban on win-probability-as-percentage without evidence backing are the display-side rules for the same honesty requirement that calibration floors enforce engine-side: never imply precision the model hasn't earned.
- **UNCERTAIN (tension, not contradiction):** The pattern allows confidence display at ≥30 settled picks, while the convergent calibration evidence (resolution term 0.0054 ≈ 0; ≥80 tail inverted at 40.13% vs 86% claimed) shows the current score has zero resolution. Pattern-compliant display would still be calibration-false; the governance wrapper ("calibrated against historical results") is what bridges the gap. Whether the 30-pick floor is sufficient given resolution ≈0 is UNCERTAIN — the calibration lane's next proposal owns this.
- **QB-BEHAVIOR / COACHING / OL / SCHEME:** no direct coverage (component doctrine).

## Engine-actionable? (yes/no + one-line what)
Yes (pipeline side) — the engine must emit per-signal evidence-tier metadata, freshness status (FRESH/DEGRADED/STALE), and T1-confirmed settlement plus ≥30-pick calibration sets per model version before any public confidence can ship; no direct engine math in the file itself.
