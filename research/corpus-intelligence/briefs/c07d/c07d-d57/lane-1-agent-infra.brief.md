## Findings (numbers and facts, not vibes)
**1. nemo-rl-session-memory (Developer +4, 2K):** Not a server or GPU thing — an agent *workflow playbook*: durable, human-readable session record in a repo-local `session/<timestamp>/` directory with four files — `session_state.md` (goal, subtask, plan, blockers, next actions), `timeline.md` (append-only action log), `files.md` (what was inspected/changed and why), `handoff.md` (resume instructions for the next agent). Checkpoint periodically; resume by reading the latest three files. Installs into the agent's skills directory (`npx -y skills add nvidia/skills --skill nemo-rl-session-memory --agent claude-code`). GPU: none. Cost: $0. Fit — Revenue Engine: DIRECT HIT — kit-dm-watcher cron loses context between runs; adopting this four-file convention (seen leads, drafted replies, follow-up queue, handoff for next run) makes it resumable across cron restarts with zero new infrastructure; same pattern for Hermes build sessions on the agent bus (Motif↔Hermes handoffs become `handoff.md` files instead of chat relays). Fit — GSE: DIRECT HIT — long-running Brev jobs (TimesFM-3 weight pulls, frozen benchmark runs, arXiv deep-read batches) die with disconnects and lose state; a `session/` checkpoint diary per job means a resumed session picks up where the last died; pairs with the `nemo-rl-brev-etiquette` sister skill (large artifacts on intended volume, secrets handling).
**2. aiq-deploy + aiq-research (Developer +4 / +3, 2K each):** Matched pair from the NVIDIA AI-Q Blueprint team. aiq-deploy stands up the AI-Q Blueprint — deep-research agent platform (intent classification → clarification → multi-source retrieval via MCP servers → synthesis with Nemotron reasoning models → cited report). aiq-research is the client-side skill that submits research jobs to a running AI-Q backend and polls/retrieves cited reports. Deploy on Brev: Docker Engine + Compose v2 (default durable: AI-Q backend + PostgreSQL, browser UI on :3000), or `uv`-based Python CLI mode, or Helm/K8s — clone `https://github.com/NVIDIA-AI-Blueprints/aiq`, set `deploy/.env` (git-ignored) with keys, `docker compose up`. No Brev one-click launchable — deploy-the-repo flow automated by the skill. GPU: backend + frontend run CPU-only if the LLM points at hosted NVIDIA endpoints (free tier); self-hosted LLM = 2× H100 NVL or 4× A100 (Llama 3.3 70B) — expensive path, only justified if 40 RPM throttles research throughput (unlikely for batch jobs). Web research needs a search-provider key (Tavily/Serper/Exa — Tavily has a free tier; exact quota UNVERIFIED). Cost: $0 GPU if CPU-only on a small Brev VM + free-tier endpoint + Tavily free tier. Fit — Revenue Engine: STRONG — autonomous deep-research backend for B2B sign-shop prospecting (SignPreview lead-arbitrage per-shop research), local business qualification for Kit outreach, wedding-signage trend research for Vow & Post; deploy once on cheap always-on Brev VM, zero human input. Fit — GSE: STRONG — cited deep-research engine as a second lane beside manual deep reads for the arXiv/NGS mega-research program ("deep research on X with citations" as an API call from `scripts/aiq.py`); competitor-intel dossiers and calibration literature sweeps.
**3. dynamo-router-starter + the Dynamo family (Developer +5, 2K):** Operates NVIDIA Dynamo (launched GTC 2025) — cluster-level LLM inference orchestrator wrapping vLLM/SGLang/TensorRT-LLM with an OpenAI-compatible Rust frontend, router, worker pools. `dynamo-router-starter` configures frontend router mode — `round-robin`, `kv` (KV-cache-aware), `least-loaded`, `device-aware-weighted`, `direct`, `random` — and smoke-tests (`scripts/check_router_health.py` hits `/v1/models` + one chat completion). Family: `dynamo-recipe-runner` (select/validate/patch/deploy K8s recipes + smoke test), `dynamo-troubleshoot` (read-only K8s debug-bundle collection + failure-decision-tree classification), `dynamo-interconnect-check` (validates NIXL/UCX/NCCL transport for disaggregated serving). Official bring-up path (PR #9782). Deploy on Brev: `pip install ai-dynamo[all]` then `dynamo run out=vllm <model>` for single-node, or `python3 -m dynamo.frontend --router-mode kv --http-port 8000` with registered workers, or K8s recipes via recipe-runner; vLLM-hackathon Brev configs show the standard Launchable pattern (paste setup.sh). GPU: runs on a single GPU — community deployments run 8B-class models on 1× L40S (48GB); Qwen3-0.6B with `gpu: "1"` per worker. KV-aware routing is pure software — no extra GPU, approximate mode when workers don't publish KV events. Real disaggregation (prefill/decode split) needs 2+ GPUs; NIXL's fast KV transfer wants NVLink/RDMA but degrades to cuda_ipc/shared memory intra-node. Cost: software free; cost = Brev GPU burn only; cheapest self-hosted inference endpoint in the lane — spin up for batch jobs, shut down after. Fit — Revenue Engine: NO CURRENT FIT — no self-hosted LLM fleet exists; kit-dm-watcher drafts via API keys; only earns its place if Garrett ever wants to self-host a small model for DM drafting. Fit — GSE: LATENT — the task's example ("KV-aware routing for his model-router fleet") presupposes a fleet that doesn't exist (his routing is OmniRoute/OpenRouter, external); honest near-term job is Dynamo as the free self-hosted inference server on the Brev box for batch model work (e.g. serving a small open model for gse-ml-service's LLM-adjacent tasks or offline eval harnesses, replacing paid API calls in batch pipelines); KV-aware routing becomes relevant when repeated-prefix workloads (calibration prompt packs, HR-factors prompt pack at scale) actually run against a local model. Verdict: do not deploy "for later" — deploy when the workload exists.
**4. NemoClaw (NVIDIA blueprint, "Launchable"):** Open-source reference stack for running always-on AI agents more safely (Apache-2.0): guided onboarding, hardened blueprint, **routed inference**, **deny-by-default network policy** (policy.yaml declares every allowed host/port/verb/binary — anything else gets a proxy 403), lifecycle management through a single CLI. Agents run inside **OpenShell sandboxes** (filesystem + network + process isolation, capability drops). Three first-class agents: **OpenClaw** (default), **Hermes**, **LangChain Deep Agents Code**. ⚠️ NAME COLLISION — flagged honestly: NVIDIA's "Hermes" is Hermes Agent (get-hermes.ai), a third-party coding-agent harness — NOT Garrett's Hermes (overnight builder on the Minis phone app). Same name, unrelated software. Deploy on Brev: genuinely one-click — Brev provisions a remote VM, installs Docker + OpenShell, starts the agent sandbox, configures inference routing, opens the dashboard in the browser; default inference = NVIDIA Build endpoint (needs free-tier build.nvidia.com API key). GPU: none required (model lives at the provider; GPU only if pointing at a self-hosted model). Cost: cheapest always-on agent in the lane — one Brev CPU VM ($0.04/hr → ~$29/mo at 24/7, UNVERIFIED, confirm in console) + free-tier NVIDIA inference (~40 RPM, fine for DM-watcher cadence); pause the VM when idle; lifecycle management supports stop/start. Fit — Revenue Engine: STRONGEST FIT IN THE LANE — permanent, policy-gated home for **kit-dm-watcher**: OpenShell's deny-by-default network policy is structural enforcement of "drafts replies, never sends" (no egress to Instagram's send endpoints = can't accidentally post); skills/sessions/memory/bridges/hooks map onto the lead pipeline; zero human input after deploy. Fit — GSE: STRONG — always-on agent for overnight GSE ops needing a human relay: **signal-desk drafting** (reply-opportunity drafts for @GalaxySportsHQ — policy-gated to draft-but-never-post, matching the hard "nothing posts without his approval" rule), calibration-job babysitting on the Brev box, arXiv intake triage. Self-evolving angle (agents that "learn from team workflows, create reusable skills") is real but upside, not the buy reason.
**5. rag-blueprint (Developer +6, 2K):** Operates the NVIDIA RAG Blueprint — production RAG stack: NV-Ingest document ingestion, Elasticsearch (default since 2.6.0; Milvus optional), SeaweedFS object store, NeMo Guardrails, **Agentic RAG** (plan-and-execute pipelines, 2.6.0), UI, MCP server, OpenAI-compatible search endpoint. Skill routes intents to playbooks: deploy (Docker Compose standard / retrieval-only / NVIDIA-hosted, Helm, MIG-slicing, library mode), configure (VLM, guardrails, query rewriting, ingestion, search, models, observability, summarization, MCP, eval), troubleshoot, shutdown. Deploy on Brev: deploy-the-repo flow driven by the skill (`docker compose` on a Brev GPU VM, or Helm on K8s); autonomy principles explicit ("if it can be checked with a command, check it — don't ask the user"). GPU: two tiers — CPU-light (NVIDIA-hosted compose variant points embedding/rerank/LLM at build.nvidia.com endpoints — runs on a modest VM); self-hosted (default LLM `nvidia/nemotron-3-super-120b-a12b` with reasoning on; OKE reference 70B-class at 2×H100/4×A100; NV-Ingest's OCR/page-elements/table-structure NIMs add more; RTX 6000 MIG support in 2.5.0). Embedding-only self-host (`llama-nemotron-embed-1b-v2`) fits a single L40S. Known limitation: B200 unsupported for image captioning/guardrails/VLM inference/Nemotron Parse (use H100/A100). Cost: software free; CPU-light = one small Brev VM + free-tier endpoints ≈ near-zero; self-hosted full stack = multi-GPU burn (expensive end of the lane) — batch the ingestion (index on GPU, then serve retrieval from CPU — vectors are just files) and shut the GPU down. Fit — Revenue Engine: CONCRETE — the Kit AI Receptionist (TASK-012) spec demands "answers only from the per-client knowledge base, never invents prices/hours/policies" — literally a RAG-with-guardrails product; this blueprint ships NeMo Guardrails + citations + per-collection data catalogs; one instance = shared KB backend for all Kit client sites. Fit — GSE: CONCRETE — RAG over the 750-paper arXiv corpus + the Sports repo research corpus (`docs/research/`) with 2.6.0 Agentic RAG plan-and-execute for multi-hop calibration questions ("which papers support this estimator choice?"); blueprint's published RAGAS accuracy benchmarks and rag-eval/rag-perf skills give the measurement-first discipline the engine work demands.
**Lane verdict (ranked by $0-first, autonomous-second):** 1. nemo-rl-session-memory — $0, no infra, adopt today as checkpoint convention for kit-dm-watcher, Hermes handoffs, Brev long jobs. 2. NemoClaw (Brev launchable) — cheapest always-on agent (~one CPU VM + free inference, rate UNVERIFIED); permanent, policy-gated home for kit-dm-watcher (draft-never-send enforced by network policy) and overnight GSE draft ops; name collision with his Hermes flagged. 3. rag-blueprint — Kit AI Receptionist's knowledge-backend (guardrailed, cited) + GSE corpus-QA engine; CPU-light/hosted-endpoint tier first, GPU only for bulk ingestion then off. 4. aiq-deploy/aiq-research — autonomous deep-research backend; deploy CPU-only on Brev against free endpoints for sign-shop prospecting (revenue) and arXiv/NGS literature sweeps (GSE). 5.
