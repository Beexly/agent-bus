# gates/GATE-SPECS.md
## What it is (1-2 sentences)
A documentation-only transcription of the acceptance gates **as written in each module's own JSDoc/`//` header** for 179 research-corpus modules in `packages/prediction-engine/src/<family>/*.ts` (23 families, filenames matching `NNNN-NNNNN[vN]-<slug>.ts`, excluding tests and the engine root). Reading rule: headers only (first ~30-80 lines), no module body read, no code run, no test executed; nothing invented, tightened, or loosened.
## Key metrics/methods (formulas where given, else "not specified")
Verbatim formulas stated by headers:
- `P(next score | lead L) = 1/2 + a - bL` — restoring-force form of the lead-dependent scoring-rate term (`1109-2825v2`; b the restoring coefficient, antipersistence `q` also estimated).
- Stale-edge screen: `E[1/(1+X)] <= 1` (do not re-stake).
- Dominance screen: `E[(1+X_i)/(1+X_j)] <= 1` on mutually exclusive/highly correlated picks.
- Variance-budgeted Kelly fraction: `alpha = sqrt(V_target / V(1))` (against a fixed alpha).
- Exact Kelly objective: maximizes `E[log(1 + stake'X)]` (no Taylor or mu/sigma^2 approximations).
- Sliding-window dominance screen: `R_ij(k)`.
- SEAM asymptotic unit-test checks: `w_1 -> 1 as n_direct -> large`, `w_1 -> 0 as n_direct -> 0`.
- `r_cur^X` — convex current-drawdown risk measure added as a constraint on the Kelly log-growth objective.
- KKT correctness certificate: Theorem 3.1's conditions as a build-failing unit test (`2004-12099`).
- `K_ens=4` leave-one-out ensemble in KellyBoost; soft-max over K picks plus a cash leg, negative log-growth loss.
- k-periodic universal portfolio: k = 7 day-of-week or situational buckets.
- N=N'=32 sampled tau pairs per minibatch, quantile Huber loss (kappa=1), CVaR(0.25) decision rule (`1806-06923v2`).
- STaR-Bets CI simulation: n = 256, Bernoulli(0.3), delta = 0.05, 1,000 reps vs randomized Clopper-Pearson.
- MCMC fit bar: all R-hat < 1.1 and effective sample sizes > 400 for ability parameters (`2103-04647`).
- half-Cauchy(0,2.5) scales in the hierarchical AR(1) shrinkage layer (`1812-05170`).
- 50-value log-spaced lambda grid for LASSO/relaxed-LASSO screening (`1911-08138`).
- NOTEARS bootstrap stability: edges kept at stability >= 0.6 (`1803-01422v2`); PCMCI+: taumax=4, ParCorr first, GPDC confirmation on top-50 stable edges, cross-team-season frequency >= 0.4 (`2003-03685v2`).
- OU sizing parameters: pull speed `b`, line volatility `sigma`; fail if `b_hat` sign flips on >20% of markets (`0903-2910v1`).
- kappa=0.25 fractional Kelly (`2002-03448v1`); Gamble A unit test: sizer must return K ≈ 0.667, never saturated K=1 (`1710-01787`).
- Example drawdown constraint d = 0.2 (`1710-01787`); omega grid in [0,1] with selection at <=5% of trajectories drawing below 90% (`2107-08827v1`).
- Fixed 70%-confidence abstention cutoff replaced by ROC-tuned dual-threshold conformal (`2502-07255v2`).
- Target nominal average loss for e-value screening: -0.02 units/pick (`2603-24704`).
- Final wealth within 10% of $576,464; annualized SD in [0.16, 0.19]; max drawdown in [38%, 46%] — replication of the paper's risk profile (`2109-10814v1`).
- Implied mixture-weight honesty: collapse to p~0 = publish "the market already prices everything the history model knows" (`1802-08848v1`).
- Epochs/time: 25-50 snapshots for disagreement features; T stochastic forward passes for MC-dropout; >=300 settled parlay slips; >=100 bets for the positive-EV sim; >=20 contests Showdown; >=10 slates EMS portfolio; >=300 unsettled? (no); ~380 team-seasons aggregated; 5000 synthesized football-plausible discrete DAGs; B=1,000 correlated performance vectors; N=10 over 100 random instances for the Kelly solver check; 100 simulation runs for covariate recovery; 200-question human pilot for LiveQA-NFL; ~200 labeled NFL plays video pilot; 4 weeks of discovery-loop runs; 30 nights storage test.

## Findings (numbers and facts, not vibes)
- **Corpus tallies.** 179 gates specified: **116 `NOT EVALUATED`**, **63 "gate stated, no status line"**, **0 `NO GATE STATED`**. Every one of the 179 modules states a gate — gap is evaluation, not coverage. `NOT EVALUATED` reason (recorded verbatim): gate "requires historical walk-forward data not available in this environment."
