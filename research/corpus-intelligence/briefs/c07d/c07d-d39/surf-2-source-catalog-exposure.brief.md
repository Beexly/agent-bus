# engine/research/2026-09-28/surf-2-source-catalog-exposure.md
## What it is (1-2 sentences)
A 2026-09-28 forensic write-up of a confirmed privacy/security leak: the anonymous public route `/api/sources/catalog` on the GSE web app published the full `DATA_SOURCE_STACK` (provider names, refused-source statuses, and the `envVar` name behind every provider) — found by walking the import graph rather than reading route files, because the earlier 403-route sweep was structurally blind to `lib/` imports. The route was fenced dark-by-default with 29/29 tests green.

## Key metrics/methods (formulas where given, else "not specified")
- Exposure: `apps/web/app/api/sources/catalog/route.ts` was anonymous (no auth), rate-limited at 60 requests/minute per IP, and returned `DATA_SOURCE_STACK`, per-source `status`, and `providerStatuses()` including the `envVar` name behind every provider.
- Sweep method (corrected): walk the import graph from every public page (403 pages, BFS to depth 4, resolving `@/` aliases), looking for keep-out vocabulary in reachable `lib/` or `components/` modules.
- First naive run: 272 of 403 public pages flagged — almost entirely noise from keep-out list containing bare words `carries` and `opportunities` matching English in comments ("carries a claim", "hidden opportunities"). 272 findings, zero signal.
- After tightening patterns to data-shaped tokens (`target_share`, `rush_yards`, `receiving_yards`, `fumbles_lost`, `opportunities:`): 113 pages, of which 43 were ungated. Most of the remainder are `/admin/**` and `/cockpit/**` (session-gated at layout). `/api/sources/catalog` was the one genuine public exposure.
- Verification: new `apps/web/__tests__/source-catalog-fence.test.ts` (dark by default; asserts serialized 404 body contains no provider name, `envVar`, or refused-source status); non-vacuity proven by removing the guard call and re-running (test goes red, restoring goes green); `npx tsc --noEmit -p tsconfig.json` clean; eslint `--max-warnings=0` over `app lib __tests__` clean; 29/29 across source-catalog-fence, internal-surface-fence, public-surface-sweep, and board-phase2-routes.

## Data sources named

- Referenced docs: `surface-exposure-sweep.md` (earlier sweep that swept 403 routes and reported zero exposures — wrong on this one); `public-surface-sweep.test.ts` (follow-up: transitive walk to become a second pass inside it, unblocked but not yet done).

## Findings (numbers and facts, not vibes)
- The anonymous route returned: (a) `DATA_SOURCE_STACK` — full list of feeds by name (7 listed above); (b) per-source `status` carrying the refused ones: `permission-required`, `founder-gated`, `planned`, `waiting-for-real-observations`; (c) `providerStatuses()` including the `envVar` name behind every provider, mapping the shop's wiring to its configuration.
- Doctrine naming: "Data sources: which sources are used and which were refused (that is competitive intel)" is on the keep-out list; "A rate limit is not a fence" — 60/min throttles a scraper, does not withhold the payload; the route was treating its own rate limiter as if it answered the doctrine.
- Why the earlier sweep missed it: `surface-exposure-sweep.md` swept 403 routes and reported zero exposures but read one file at a time; the route's own text only imports from `@/lib/data-sources/catalog` — the keep-out data lives one import away in a `lib/` module. Limitation was listed in the earlier doc as "does not cover `lib/` components rendered inside cleared pages" and turned out to be the one that mattered; found a live exposure on the first run.
- Fix: `INTERNAL_API_ROUTES["/api/sources/catalog"]` with opt-in flag `SOURCES_CATALOG_PUBLIC` (founder-owned under law 3; the change does not set it, route is dark by default); route refuses before its rate limiter and before any loader runs; uses same `internalSurfaceBlockedResponse` envelope as `/api/calibration` and `/api/gse/v1/truth`, with `Cache-Control: no-store`; two public pages (`/fantasy`, `/fantasy/baseline`) linked a "Data sources" button at it — links removed (a dark link is a broken product surface, not a fence); the cockpit's own sources page still works (session-gated; the correct home).
- Flag note: the doctrine also says "the cleared/forbidden source registry is trust-building copy" — showing the *cleared* sources is a legitimate founder product call; the fence makes it one flag instead of a code change, dark until he decides. No threshold, gate, or flag was moved; `SOURCES_CATALOG_PUBLIC` is new and unset — surface darker than before, never brighter.
- Non-vacuity proof: removing the guard call makes the fence test go red, restoring it goes green — "a green fence test that was never seen to fail proves nothing."
- Loader-set nuance: `internal-surface-fence.test.ts` loader-order check needed `loadSourceLiveEvidence` added to its known-loader set; left as an explicit list rather than loosened to a generic `load*(` regex, because the generic version produced a false "has no loader to guard" failure on `/api/gse/v1/truth` — "weakening an assertion to accommodate a new route would have hidden a real regression in a pre-existing one."
- Limitations explicitly NOT proven: the transitive sweep is static text match over the import graph to depth 4, statically-analyzable `@/` imports only; cannot see leaks built by composing two allowed payloads, dynamically-constructed imports, database-fetched values named like projections, or modules reached through barrel files re-exporting under different names; it is a wider net, not a proof. It is also not a CI guard yet — the finding came from a scratch script, not something that runs on every commit; turning the transitive walk into a second pass inside `public-surface-sweep.test.ts` is the obvious unblocked follow-up.

## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- TRUST-SIGNAL: the leaked `DATA_SOURCE_STACK` (The Odds API, Sleeper public API, Premium charting overlays, Airwave transcript spreadsheet, Beat reporter source mesh, Galaxy Studio asset engine, Scores24 reference feed) plus refused statuses (`permission-required`, `founder-gated`, `planned`, `waiting-for-real-observations`) is competitive intel in the trust-target intake sense: knowing which feeds the shop uses and which it was refused tells a competitor exactly where its signal edge (and its gaps) live. Serves the trust-target intake program as a defensive example — the same catalog logic applies to any data-source disclosure surface.
- OTHER (methodological, sweeps/QC): the core lesson is a general static-analysis limitation — single-file route sweeps are structurally blind to keep-out material living one import away in `lib/`. Any engine sweep that checks one file at a time inherits this blindness; the corrected method (BFS to depth 4 from every public page, resolving aliases, data-shaped keep-out tokens like `target_share`, `rush_yards`, `receiving_yards`, `fumbles_lost`, `opportunities:` rather than bare English words) is a reusable QC pattern for the fence-verification lane.
- OTHER (test rigor): the non-vacuity discipline — removing the guard must turn the test red — and the refusal to weaken an assertion (`load*(` regex would have hidden a real regression on `/api/gse/v1/truth`) are transferable to calibration/sizing test discipline: a calibration gate that has never been seen to fail proves nothing.
- UNCERTAIN: the follow-up (transitive walk as a second pass inside `public-surface-sweep.test.ts`) is described as "unblocked" but not done; treat the 29/29 suite as the current fence state, not a continuously-enforced CI guard.
