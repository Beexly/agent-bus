# research/2026-09-28/orchestration/ngs-feed-creation-plan.md
## What it is (1-2 sentences)
The standing research plan for building GSE's internal NGS tracking feed: ranked source options (asonty TSV bootstrap → nflverse aggregates → scrape probe → broadcast CV → licensed feed), the per-frame target schema at 10 Hz, the validation protocol with hard calibration gates, eight milestones M0–M6, data-QC standing rules, license notes, and the Garrett-blocker list — under the HARD internal-only doctrine that no NGS data or metric names ever appear on any public surface.

## Key metrics/methods (formulas where given, else "not specified")
Formulas verbatim from the file:
- **No-teleport inequality:** `hypot(dx,dy) ≤ 12.0·Δt + 0.5` for every player/horizon (`test_no_teleport`); **speed cap:** predicted speed `≤ 12.0` yd/s.
- **ECE_regression formula:** `ECE_regression = Σ_b (n_b/N)·|RMSE_b − σ̄_b|` over 10 equal-count bins of `σ̄ = sqrt(0.5·(σx²+σy²))`. Gate: **ECE < 0.15 yd**.
- **Coverage gates:** coverage at Mahalanobis ≤ 1 (expect **0.393**) and ≤ 2 (expect **0.865**) for 2D Gaussian; gate within **± 5 pp** of nominal. On synthetic data with known σ = 0.5 yd noise: ECE < 0.10, coverage within ± 3 pp.
- Recalibration paths: isotonic recalibration `σ_cal = f(σ̄)` or temperature-scale `logvar' = logvar + log T` fit to minimize validation NLL; if still failing, module ships point predictions only and failure is logged.
- **RMSE yardstick:** `sqrt(0.5·(MSE_x + MSE_y))` in yards; BDB 2026 leaderboard band **0.518–0.540** (directional only — different data). Target: **beat 0.540** on GSE's own held-out games with Phase 3 ensemble + TTA; expected Phase 3 gain ~**0.005–0.010**; Phase 3 TTA uses `σ²_mix = mean(σ²) + var(means)` over original + horizontal flip.
- Phase 1 gate: single relational model beats Phase 0 baseline RMSE by **≥ 10%** on game-level held-out block (expanding-window splits, train games 1..N−2k, validate N−2k+1..N−k, test most recent k ≥ 10%, min 20 games).
- Loader tests: `test_loader_schema`, `test_causality` (zeroing frames with frame_id > t leaves outputs unchanged < 1e-6), `test_canonicalization` (left-direction play mirrored-identical), `test_flip_involution` (flip twice == original exactly), `test_permutation_invariance` (permute 22 player rows permutes outputs < 1e-5), `test_determinism` (identical seeds → max abs diff < 1e-6), plus `test_finite`, `test_positive_uncertainty`, `test_conf_range` (conf ∈ [0,1]), `test_baseline_beats_naive`, `test_calibration_synthetic`.
- Scrape doctrines (verbatim): raw-first; validity-by-content; **pace-between-attempts** (`NGS_RAW_SLEEP` default **0.25s**, `NGS_RAW_TIMEOUT` default **30s**, `NGS_RAW_RETRIES` default **4**, retry set {408, 429, 500, 502, 503, 504}); empty-envelope sentinel (HTTP 200 + empty body or `stats: []` means "nothing here," never banked); finality-from-schedule (refetch until every game FINAL; future weeks never requested); failed≠absent; atomic writes (tmp + rename); schedule upserted by `game_id`.
- Schema numbers: 22 players + BALL = **23 rows/frame** at **10 Hz**; `time` seconds since snap (snap = 0); x ∈ [0,120], y ∈ [0,53.3] yards; field 120×53.3 yd = 109.7×48.8 m; history window T = 10 frames (1.0 s); `yardline_100` 1–99; play_direction canonicalized to `"right"`.
- CV PoC acceptance: on ≥ 50 plays, per-player CV-derived positions agree with Zebra-chip frames within **mean error < 1.0 yd, 95th percentile < 2.0 yd**.
- Scale cross-check tolerance (from the fourtverts deep-dive dependency): 10% [DERIVED]; referenced implementation spec items in that file.

## Findings (numbers and facts, not vibes)
- **Hard constraint:** train on GSE's own NGS data — BDB 2026 data is never a training input.
- **Verified-but-negative:** (1) nflverse publishes NO per-frame tracking data — its NGS product is player-week aggregates only; (2) public `nextgenstats.nfl.com/api` may be dead (2026-09-04 commit notes NGS moved behind NFL+ Premium paywall at `pro.nfl.com/api/secured/*`); probe-first, do not build before probing; (3) `nfl-ngs-raw` itself only gets tracking for highlight plays (per-game lookups denied from every egress tested) — bootstrap/validation only, not a corpus.
- asonty TSV key finding: TSVs contain the ENTIRE runtime of the play including dead time before line set and post-TD celebration — the loader must trim to the play window (line_set → terminal event). `dir` = 0 faces far sideline, clockwise.
- Legal posture (HARD): DIY extraction on NFL+/broadcast streams is blocked without counsel; `pro.nfl.com/api/secured/*` fallback needs a user-bound token from Garrett's NFL+ Premium via id.nfl.com login (client-credentials tokens 401 on every secured route); scrape lane automated access is "at tolerance" — Garrett's call, never self-cleared.
- **BDB license contradiction flagged as CONTRADICTION:** movement spec (2026-09-26) records BDB 2026 as CC BY-NC 4.0 benchmark-only; older tracking playbook (2026-07-02) records 2026 terms as no-license/confidential with post-contest data-destruction requirement. Resolution required by reading actual license text before ANY BDB data touches the build — default posture: no BDB data at all, even benchmarking.
- NGS internal-only doctrine: all NGS-derived data behind an explicit `INTERNAL` boundary; CI fence (style of existing `apps/web/lib/fences/no-raw-ngs-fence.ts`) scans every public route/API handler/content component for registered NGS field-name/metric identifiers and fails the build on any match; fence list maintained alongside target schema; public surfaces may show only derived judgments. Violations = integrity failures, not style issues.
- Storage discipline: raw frames as per-play Parquet in lake (`lake/tracking/season=YYYY/week=WW/game_id/play_id.parquet`); Postgres gets derived per-play features only — a season is ~50M+ player-frames, DB never sees them.
- Six Garrett blockers listed (do not work around): (1) licensed-feed money (SkillCorner, Genius, even $99.99/mo SIS); (2) NFL+ Premium user-bound token; (3) NFL ToS exposure on scrape/DIY-CV lanes; (4) BDB license verification; (5) movement-spec open questions — which NGS seasons licensed/available for expanding-window depth; whether ball-landing spot available at inference or landing head needs upstream predictor (with logged degradation); GPU budget for 5-seed ensemble cadence (nightly vs weekly); (6) detector procure-vs-train decision.
- Milestones M0–M6 build order: skeleton → bootstrap corpus → physics baseline → scrape probe verdict → spec loader+feature integration → CV PoC (gated on counsel/license) → licensed-feed pipeline (stubbed/disabled until contract).
- 13 standing data-QC rules committed as repo rules (raw-first one-way boundary; validity-by-content; empty-envelope sentinel; pace-between-attempts with env-tuned pacing; finality-from-schedule; atomic writes + upsert by game_id; no raw frames in Postgres; canonicalize at load; game-level chronological expanding-window splits; license posture; uncertainty gates before downstream; every number file-verifiable; NGS internal-only fence).

## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- The 10 Hz 22-player relational movement model with ball-landing conditioning (`ball_landing_x/y`, `frames_to_landing`, `dist_to_ball_landing` anchor) is the tracking-lane foundation for QB-BEHAVIOR: per-frame QB kinematics (speed, acceleration, direction of motion, orientation) conditioned on game context feed the QB behavioral profiles — the mechanism is that QB movement under pressure, pocket-exit acceleration, and throw-timing kinematics become per-play features rather than box-score proxies. (Note: `is_targeted_receiver` per-frame flag also directly feeds TRUST-SIGNAL — receiver trust-target intake.)
- Per-frame validity + empty-envelope-sentinel doctrines (OTHER/data-QC): the mechanism is that missing-data handling is made explicit (`failed` ≠ absent) so the engine never trains on silently-dropped plays — directly relevant to the calibration program, since unrecorded failures bias calibration sets.
- Uncertainty gates ECE < 0.15 yd / coverage ± 5 pp (TRUST-SIGNAL/calibration): the mechanism forces movement-model uncertainty to be calibrated before any downstream consumption — this is the same calibration discipline Garrett demands engine-wide, and the isotonic/temperature-scale recalibration ladder is reusable for any probabilistic engine head.
- The 23-entities/frame schema with identity keys (nflId, gsisId, esbId) (OTHER): gsisId join surface into nflverse rosters via the playbook's GSIS crosswalk — the mechanism is a stable player-identity join across every data lane, which the QB-behavioral program depends on to attach movement features to the right player across seasons.
- CONTRADICTION to flag (OTHER): the BDB 2026 license conflict between the movement spec and the older tracking playbook — unresolved, must not be silently resolved in favor of convenience; any benchmark use of BDB data is blocked pending license read.
- UNCERTAIN (OTHER): whether the public NGS API is live or dead (probe-first verdict pending); whether ball-landing spot is available at inference in production; GPU budget for the 5-seed ensemble cadence. All are Garrett-blocked.
