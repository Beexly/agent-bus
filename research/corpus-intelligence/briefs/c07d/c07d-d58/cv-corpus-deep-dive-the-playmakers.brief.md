## Key metrics/methods (formulas where given, else "not specified")
- Model: YOLOv8 (ultralytics ≥ 8.0.196), single-pass detection, grid-based localization with NMS; primary notebook `WR/notebooks/WRYOLOCUSTOM.ipynb` = "YOLOv8 with Roboflow"; YOLOv5 50-epoch alternative also exists.
- Reported results: **mAP@0.5 = 0.759**, **F1 = 0.62 @ conf 0.229**; best class WR **94.2% precision**, Corner Back **88.5%**, Safety **87.9%**.
- Roboflow hosted-model numbers (for the record, unverified marketing-page metric — do NOT cite as authors' claim): mAP@50 **90.2%**, Precision **87.5%**, Recall **82.7%**; differs from README's 0.759, likely a different version/split.
- Detector-v2 comparison protocol: train two candidates with identical splits — A: YOLOv8n fine-tune (same family as current production file detector); B: Faster-RCNN ResNet50-FPN (two-stage; the AWS-SageMaker-blog hypothesis says it wins on small/occluded objects). **DECISION RULE: promote B only if it beats A by >= 5 points of recall in the worst-3 occlusion cells AND measured FPS stays within the file-detector budget;** otherwise stay one-stage and spend the budget on more labels.
- Test assertions: (1) fixture of 8 boxes / two classes, mock detector returns 6 TP / 1 FP / 2 FN → assert `recall === 0.75`, `precision === 6/7 ≈ 0.8571` (tol 1e-9), mAP@0.5 via standard 11-point interpolation pinned to hand-computed value; (2) license gate test — reads `DATASET_LICENSES.json` sidecar, **fails if any training dataset in the eval config lacks an explicit license entry** (expected fail message matches `/no license recorded/`); (3) stratified report test — per-class AND per-occlusion-cell recall, cells exist for `high-occlusion` with `n >= 0`.
- No formulas beyond the metrics above; no p-values, R², confidence intervals.
