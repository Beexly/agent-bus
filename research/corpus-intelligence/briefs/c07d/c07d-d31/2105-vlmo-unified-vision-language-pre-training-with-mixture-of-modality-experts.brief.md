# arxiv-program/research/2026-09-21/arxiv-deep/2105-vlmo-unified-vision-language-pre-training-with-mixture-of-modality-experts.md
## What it is (1-2 sentences)
A full-paper read (ar5iv HTML, arXiv:2111.02358v2, Bao, Wang, Dong, Wei et al. — Microsoft, 2021) of VLMo: a single Transformer that switches between fast dual-encoder retrieval and deep fusion-encoder reasoning via Mixture-of-Modality-Experts (MoME), pre-trained stagewise (image-only → text-only → joint). The file's verdict is ADAPT: one model for both historical-play retrieval (dual mode) and deep matchup reasoning (fusion mode), with a stagewise pre-training recipe (tracking-only → text-only → joint) that fits NFL data scarcity — but it needs a new tracking-modality expert and NFL corpora. Note in file: an earlier wrong ID (2111.11483, a physics paper) was corrected via the arXiv API to the true VLMo ID 2111.02358, confirmed clean against the dedup list.

## Key metrics/methods (formulas where given, else "not specified")
- MoME block (Eq. 1–2): H'_l = MSA(LN(H_{l−1})) + H_{l−1}; H_l = MoME-FFN(LN(H'_l)) + H'_l.
- Three experts: V-FFN (vision), L-FFN (language), VL-FFN (vision-language fusion). Shared multi-head self-attention across modalities; experts replace the FFN per block.
- Routing is deterministic by input modality and layer index: image/text-only inputs use V/L experts throughout; image-text pairs use V+L experts in bottom layers and the VL expert in top layers (top-2 layers base, top-3 large).
- Stagewise pre-training: (1) train V-FFN + shared self-attention on image-only data via BEiT masked image modeling; (2) freeze those, train L-FFN on text-only data via MLM; (3) full model with three losses — image-text contrastive (ITC), image-text matching (ITM), masked language modeling (MLM).
- Configs: Base = 12 layers, 768 hidden, 12 heads, FFN 3072; Large = 24 layers, 1024 hidden, 16 heads, FFN 4096. 224×224 images, 16×16 patches, RandAugment, BERT-uncased tokenizer, max text length 40, whole-word masking. 200k steps, batch 1024, AdamW (β1=0.9, β2=0.98), LR 2e-4 (base) / 5e-5 (large), 2.5k-step linear warmup + linear decay, weight decay 0.01. Base: ~2 days on 64×V100-32GB; Large: ~3 days on 128×V100-32GB.
- Dual-encoder mode: encode image and text separately, dot-product similarity (linear-time retrieval). Fusion-encoder mode: joint encoding, [T_CLS] → classifier.
- Vision-language data: COCO, Visual Genome, SBU, Conceptual Captions (4M pairs) for base/large; 1.0B noisy web image-text pairs for VLMo-Large++ (200k steps @16k batch + 100k steps @32k batch). Image-only: BEiT-style masked image modeling corpus (ImageNet-scale). Text-only: large text corpus for MLM.
- Eval (all public): VQA 2.0 (3,129-answer classification), NLVR2 (image-pair + text entailment), COCO/Flickr30K retrieval (Karpathy split), ImageNet classification, ADE20K segmentation. Baselines: UNITER, VILLA, UNIMO, ViLT, ALBEF, VinVL, SimVLM, Florence, ALIGN.
- Assumptions: (1) shared self-attention aligns modalities while separate experts preserve modality-specific statistics; (2) fusion needed only in top layers; (3) single-modality pre-training transfers to the joint task (stagewise > joint-only ablation supports this); (4) deterministic expert routing by modality/layer is sufficient (no learned gating).
- GSE implementation spec (effort: 4–6 weeks): single multimodal Transformer with THREE experts — T-FFN (tracking), V-FFN (video), L-FFN (text). Stage 1: pretrain T-FFN + shared attention on tracking-only data (Big Data Bowl 2018–2022, masked-trajectory modeling à la BEiT). Stage 2: freeze, pretrain L-FFN on text-only NFL corpus (nflverse pbp descriptions, injury reports, beat-writer text) via MLM. Stage 3: joint training with tracking↔text contrastive + matching + MLM on paired (play window, pbp text) data; fusion expert on top layers. Serving: dual mode precomputes play embeddings weekly (fast retrieval API); fusion mode on-demand for matchup cards.
- Reproducible test: Big Data Bowl tracking + nflverse pbp text, 2018–2022 train / 2023 val / 2024–2025 test (time-ordered). Metrics: (a) text→play retrieval Recall@10 on 500 labeled concept queries vs. ImageBind-style (2103) joint model and vs. CLIP text-video baseline; (b) fusion-mode play-EPA prediction MAE vs. tracking-only baseline.
- Acceptance gate: ACCEPT if VLMo-style model beats the 2103-style single-space model by ≥3 points Recall@10 on retrieval AND fusion-mode EPA MAE beats tracking-only baseline by ≥2% on held-out seasons. REJECT if no retrieval gain over the simpler joint space (MoME complexity unjustified) or no EPA gain (fusion adds nothing). Pre-registered.
- Improvement experiment: LEARNED expert routing with a tracking gate — replace hand-coded modality/layer routing with per-token gating over {T,V,L,TV,TL,VL,TVL} experts trained with load-balancing loss; adaptive fusion depth per play (formation-decided plays → shallow fusion, personnel/matchup-context plays → deep fusion). Router expert-utilization statistics become an interpretable "which modality mattered" signal for matchup cards.

## Data sources named
- COCO, Visual Genome, SBU, Conceptual Captions (4M pairs); 1.0B noisy web image-text pairs (proprietary) for Large++.
- BEiT-style masked image modeling corpus (ImageNet-scale); large text corpus (MLM).
- NFL corpora (GSE adaptation): Big Data Bowl 2018–2022 tracking; nflverse pbp descriptions; injury reports; beat-writer text.
- Code + pretrained models: https://aka.ms/vlmo (stated in paper). Compared architectures: 2103 (ImageBind-style joint model), CLIP text-video baseline, ALBEF (reranking), ViLT (linear patch projection), BEiT, ViT.

## Findings (numbers and facts, not vibes)
- VQA test-dev / test-std (Table 1): VLMo-Base 76.64 / 76.89 (vs ALBEF-Base 74.54 / 74.70, ViLT-Base 71.26, VILLA-Base 73.59 / 73.67); VLMo-Large 79.94 / 79.98; VLMo-Large++ 82.88 / 82.78 (vs Florence-Huge 80.16 / 80.36, SimVLM-Huge 80.03 / 80.34, SimVLM-Large 79.32 / 79.56).
- NLVR2 dev / test-P: Base 82.77 / 83.34 (vs ALBEF-Base 80.24 / 80.50); Large 85.64 / 86.86; Large++ 88.62 / 89.54 (vs SimVLM-Huge 84.53 / 85.15).
- Retrieval (Table 2): VLMo-Large++ COCO text-retrieval R@1/R@5/R@10 = 83.1 / 96.0 / 98.2, image-retrieval = 65.2 / 86.5 / 92.2; Flickr30K TR = 96.8 / 100.0 / 100.0, IR = 88.1 / 98.4 / 99.3 — beats Florence-Huge (COCO TR 81.8 / 95.2, IR 63.2 / 85.7) with linear-time retrieval.
- Ablations: stagewise image+text init NLVR2 82.09 / 82.49 vs image-only init 80.33 / 81.06 (Table 4); MoME 80.13 / 80.31 vs standard Transformer 78.81 / 79.27 (Table 5 rows [6] vs [4]); all three losses together best (ITC alone 73.91/73.75 → ITC+ITM+MLM 80.13/80.31).
- ImageNet acc@1: VLMo-Base 85.5 (vs BEiT-Base 85.2, ViT-Base 83.6); ADE20K mIoU 53.4 (vs BEiT 52.8).
- Limitations in file: expert routing is hand-designed (top-K layers), not learned — may be suboptimal for a third modality (tracking); dual-encoder retrieval is linear-time but still requires encoding the full corpus per query side; "significant speedup" claim is vs. region-feature fusion models, not vs. CLIP; 2 modalities only (vision+language) — a tracking expert is untested in this framework; NFL text (jargon-heavy) differs from caption text.
- GSE fit: file found no MoME/unified dual+fusion architecture in the existing research map (multimodal fusion exists only as a commissioned ML-brief topic) — NEW capability. The stagewise recipe maps onto NFL data reality: abundant tracking-only data, abundant text-only data, scarce paired data.

## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- OTHER (tracking lane): the T-FFN tracking expert + stagewise recipe is a direct mechanism for the tracking lane — pretrain on abundant tracking-only data (Big Data Bowl 2018–2022, masked-trajectory modeling à la BEiT) before any paired play-text data exists, so the lane's scarce (play window, pbp text) pairs are spent only on joint fine-tuning. Dual mode then gives a fast historical-play retrieval API ("find plays like this 3rd-and-7 look") from weekly precomputed embeddings. Relevant program: tracking lane.
- QB-BEHAVIOR: fusion mode (play window + text → deep cross-modal reasoning feeding the engine) is the mechanism that turns tracking + scouting text into a joint predictive representation — a QB-behavioral profile could fuse route/runner tracking windows with pbp-text context and output play-EPA predictions, with the acceptance gate requiring ≥2% EPA-MAE improvement over the tracking-only baseline to justify the fusion complexity. The learned-routing improvement experiment's expert-utilization statistics ("which modality mattered") give an interpretable attribution channel per play. Relevant program: QB-behavioral profiles + tracking lane.
- SCHEME: text→play retrieval Recall@10 on 500 labeled concept queries vs. a 2103-style single-space model and CLIP baseline is the SCHEME-facing benchmark — if the MoME model beats the single-space model by ≥3 points, concept-level scheme retrieval ("plays where the defense showed X") becomes a queryable store rather than a manual film task. Relevant program: SCHEME (concept-query retrieval over play corpus).
- COACHING: the serving split (dual mode precomputed weekly for retrieval; fusion mode on-demand for matchup cards) gives a mechanism for coaching-tendency inputs — matchup cards can be generated by fusing clip evidence with text scouting, and the router statistics attribute which modality drove each call, making the card auditable for coaching-tendency features. Relevant program: coaching tendencies (matchup-card generation).
- UNCERTAIN: a tracking expert (T-FFN) is untested in the MoME framework and NFL text is jargon-heavy vs. caption text — the paper's ablations support stagewise transfer only for vision+language; whether T/L/VL experts behave the same is unverified. Also CONTRADICTION-risk: the file's retrieval claim (linear-time "significant speedup") is measured against region-feature fusion models, not CLIP — don't read it as beating CLIP's retrieval speed.

## Engine-actionable? (yes/no + one-line what)
Yes — 4–6 week build of a T/V/L-expert multimodal Transformer (Stage 1: masked-trajectory pretraining on Big Data Bowl 2018–2022; Stage 2: MLM on NFL text corpus; Stage 3: joint contrastive+matching+MLM), serving dual-mode play retrieval weekly and on-demand fusion-mode matchup cards, gated on ≥3pt Recall@10 retrieval gain and ≥2% EPA-MAE gain; a learned per-token router is the follow-on improvement.
