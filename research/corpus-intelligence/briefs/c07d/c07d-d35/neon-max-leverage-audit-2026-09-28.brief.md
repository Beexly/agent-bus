# data-sources/research/2026-09-28/neon-max-leverage-audit-2026-09-28.md
## What it is (1-2 sentences)
A deep-research pass (2026-09-28, research only — nothing adopted or changed) over current Neon Postgres docs, documenting the Pro/Launch/Scale billing model with meter-by-meter prices and 15 findings ranked by expected impact for Garrett's workload (signals-writer cron, branch hygiene, autoscale caps, pooled connections, and a set of evaluated-but-queued options like AI Gateway, Data API, Object Storage, Lakebase Search).

## Key metrics/methods (formulas where given, else "not specified")
Verbatim pricing and meter mechanics:
- **Compute:** CU-hours = compute size × hours running; **1 CU ≈ 4 GB RAM + CPU + local SSD**; minimum size **0.25 CU**; all computes in the project count (each branch gets a read-write compute by default; read replicas add read-only computes); suspended computes accrue zero. Launch: **$0.106/CU-hr**. Scale: **$0.222/CU-hr**. Free allowance: **100 CU-hrs/project/mo**.
- Central cost equation: `0.25 CU × ~730 hrs/mo = ~182.5 CU-hours/mo` → Launch **≈ $19.35/mo** for compute alone; Scale **≈ $40.50/mo**; Free: 182.5 > 100 CU-hr allowance → compute **suspends mid-month** until the next billing period (hard outage).
- **Storage:** GB-months, metered hourly, on actual usage. Root branches: logical data size. Child branches: `min(changes since creation, logical size)`. Bills even while compute is suspended. Launch/Scale: **$0.35/GB-mo**. Free allowance: 0.5 GB/project.
- **Public network transfer (egress):** total bytes over public internet per project per month, **shared across Postgres, Object Storage, and Functions**; includes logical-replication traffic. 500 GB/project/mo included, then **$0.10/GB** (Launch); Free: 5 GB/project/mo.
- **Extra branches:** beyond 10/project Launch (25/project Scale), prorated hourly — **$1.50/branch-month (~$0.002/hr)**.
- **Instant restore (PITR):** GB-months of WAL retained, root branches only; configurable window, **defaults 1 day on paid**. **$0.20/GB-mo**; up to 7-day window Launch, 30-day Scale. Free: 6 hrs, ≤1 GB.
- **Snapshots:** GB-months. Manual snapshot limits: 100 (Launch/Scale), 1 (Free). Scheduled backups: first snapshot full, subsequent **incremental**. **$0.09/GB-mo**; billing began May 1, 2026.
- **Object Storage:** GB-months, **no per-operation charge**; egress shares the transfer allowance. **$0.023/GB-mo**; Free: 5 GB/project.
- **Functions:** Capacity-Hours (active vs. waiting) + invocations. Launch: $0.10 active / $0.025 waiting per Cap-Hr, **$0.60/M invocations**. Scale: $0.12 / $0.03, $0.60/M. Free: 10 active / 400 waiting Cap-Hrs, 1M invocations.
- **AI Gateway:** prepaid credits; 1 credit = $1, **$5 minimum**, credits valid **12 months**; provider list prices passed through with **no markup** (Databricks Foundation Model APIs).
- **Private network transfer:** Scale only (AWS PrivateLink): **$0.01/GB**.
- Scale-to-zero: suspends compute after **5 minutes of inactivity** (Launch: fixed 5 min or disabled; Scale: configurable 1 min → always-on). **Any DB traffic resets the idle timer.** Logical replication subscribers pin the compute awake (no scale-to-zero while connected).
- Neon plans are now **Free / Launch / Scale**, all usage-based, **no monthly minimum** on Launch/Scale; legacy plans auto-migrated in **February 2026** (Azure Marketplace excepted).
- Neon Auth included: **60k MAU free, 1M MAU on Launch/Scale**.
- Connection pooling: PgBouncer in transaction mode, **10,000 client connections** on `-pooler` hostname; pooler always free. **max_connections only 104 at 0.25 CU** on direct connections. Pooled string for app routes; **direct** for migrations, `pg_dump`, and anything using `SET`/prepared statements (pooler forbids them).
- Read replicas are their **own compute billed in CU-hours** — offload storage, not compute (Finding 12: NOT a cost saver at this workload's read volume).
- Region: Neon on AWS (e.g., us-east-2 Ohio; hostnames carry region); 500 GB Launch transfer allowance dwarfs the workload, so region alignment (Neon us-east-2 ↔ Vercel `iad1`) is a **latency** lever, not a cost lever.

## Findings (numbers and facts, not vibes)
- **The pasted billing screenshot was Vercel's, not Neon's** — "Billing Items / Personal / Free / Teams / PickPilot's projects / Pro / Active / v0's pricing page" is the Vercel billing dashboard (v0 is Vercel's product). Vercel Personal = Free; team "PickPilot's projects" = **Pro ($20/seat/mo)** — Vercel-leg scope. Garrett's actual Neon plan tier is **unconfirmed** (Finding 0: verify in 5 min at console.neon.tech → Billing → Billing Items).
- Finding 1: the signals-writer cron is the #1 cost suspect. A cron hitting the DB more often than ~every 6 minutes keeps the compute at ~100% duty cycle ≈ **$19/mo on Launch at the 0.25 CU floor**; even a 10-minute cron yields ~60–70% duty. Options: (a) accept ~$19/mo as the price of fresh signals; (b) batch the writer (every 15 min roughly halves duty cycle); (c) move the writer to **Neon Functions** next to the DB (queued for evaluation — $0.10/$0.025 per Capacity-Hour + $0.60/M invocations on Launch).
- Finding 2: every branch bills while awake; the branch-only testing rule multiplies branch count; each forgotten branch with an awake compute is a second ~$19/mo leak; branches beyond 10/project cost **$1.50/branch-month**. Mitigations: `neon.ts` 7-day TTL branch policy already landed in the repo (auto-expire once `neon deploy` runs); delete branches when done; idle branches' computes also scale-to-zero after 5 min idle (~$0 compute) but still count toward the branch allowance and their storage delta.
- Finding 3: cap autoscaling max — a 0.25 CU floor spiking to 4 CU during a backfill/calibration run bills **16×** for those hours. Default posture: min 0.25 CU, max **0.5–1 CU**; raise deliberately for known heavy jobs.
- Finding 4: spending notifications email at **80% and 100%** of a custom monthly threshold (e.g., $30).
- Finding 5: PITR history window — confirm **1 day, not 7**; writer-cron WAL piles up at 7 days and bills at $0.20/GB-mo. Upgrading plans raises the *maximum*, not the configured value — verify after any plan change.
- Finding 6: use pooled connection strings everywhere on Vercel (free) — direct connections risk `max_connections` (104 at 0.25 CU) under serverless concurrency.
- Finding 7: Data API (queued for evaluation) — exposes Postgres over HTTPS with PostgREST syntax, enabled per branch; no separate charge found; read routes for the signals table could be served straight from Neon, deleting Vercel functions (savings land on the **Vercel** bill, not Neon's). Caveats: queries still wake branch compute; auth/rate-limiting posture must be designed.
- Finding 8: AI Gateway (queued for evaluation) — one Neon credential reaches many LLM providers; **list prices passed through with no markup**; OpenRouter takes a markup on routed models; NVIDIA NIM's free tier is flaky. Caveats: frontier models (OpenAI, Gemini) need access requests; per-model pricing in the API catalog currently null (check models.dev / console catalog); credits expire in 12 months — start with $5–20.
- Finding 9: Object Storage for backtest artifacts — **$0.023/GB-mo** (~$0.23/mo per 10 GB), no per-op fees; branches with the database (files and rows stay in sync per branch); versioned backtest/calibration datasets belong here.
- Finding 10: Neon Auth included (60k MAU free, 1M on Launch/Scale) — substitutable if any lane pays for Clerk/Auth0/etc.
- Finding 11: Lakebase Search (queued for evaluation) — vector, keyword, hybrid search directly in Postgres ("agent retrieval and RAG need no separate vector store"); relevant when the bge-m3/Qwen3 embedding lane produces vectors; avoids a Pinecone/weaviate bill.
- Finding 13: region alignment is a latency lever, not a cost lever.
- Finding 14: scheduled backups — automated on paid plans; scheduled snapshots incremental after first full; daily schedule + 1-day PITR is the cheap DR posture; delete stale manual snapshots.
- Waste-pattern checklist (~10 min): (1) Monitoring → compute graph — flat line at 0.25 CU 24/7 = cron pinning; spiky = check autoscale max. (2) Branches list — unrecognized branch with active compute = leak. (3) Billing → Billing Items — expect compute ≫ storage ≫ transfer. (4) Settings → Postgres → history window should read 1 day. (5) Snapshots list — delete stale manual snapshots. (6) Spending notifications — set a threshold. (7) Vercel env: app routes on `-pooler`, migrations on direct.
- Deliberately NOT recommended: read replicas for cost; the Scale plan (**2.1× the compute rate, $0.222 vs $0.106**); disabling scale-to-zero on Launch; overbuying AI Gateway credits.
- Signals table is ~84.5k rows; storage trivial at current volumes (even 1 GB = $0.35/mo) — "compute duty cycle is the entire game."
- Every finding labeled with Difficulty and Reversible; untested items marked **queued for evaluation**, never dismissed.

## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- **OTHER — infra cost bound on the calibration/sizing lane.** The honest budget envelope for the signals table (the engine's trust-intake and prediction read surface): always-on compute at the 0.25 CU floor costs ~$19.35/mo on Launch; a writer cron at ≤6-minute cadence pins it there. Any trust-signal intake design that increases writer cadence or holds replicas always-on has a dollar figure attached — cap autoscale max at 0.5–1 CU so a backfill afternoon can't 16× the bill. This is OTHER but it gates how aggressively the tracking lane can write.
- **OTHER — queued-for-evaluation AI Gateway vs. OpenRouter is the model-routing decision.** If the agent fleet's models are in the gateway catalog at list price with no markup, the gateway is the cheapest compliant router for the overnight reasoning work (the overnight queue spec) — needs a measured 1-week comparison on the fleet's actual models. Directly serves the overnight-reasoning program's token budget.
- **OTHER — Object Storage as the home for backtest/calibration artifacts.** Versioned backtest and calibration datasets (~$0.23/mo per 10 GB) branching with the DB fit the branch-per-experiment workflow (overnight queue's 51 worktrees; throwaway-branch testing rule) — audit receipts (fit logs, calibration tables) stay attached to the branch that produced them.
- **OTHER — Lakebase Search kills a future vector-DB line item for the embedding lane.** The moment bge-m3/Qwen3 embeddings land, vector search lives in Postgres — no Pinecone/weaviate bill — relevant to any retrieval-based trust-signal or coaching-tendency lookup.
- **TRUST-SIGNAL — pooled-connection reliability posture.** `max_connections` of 104 at 0.25 CU means unpooled Vercel fan-out can 500 under concurrency exactly when traffic spikes (game windows) — the trust lane's read surface must use `-pooler` strings or the public reliability story breaks at the worst moment.
- **CONTRADICTION to check:** the memory record (2026-10-01) states a standing HARD rule — "No agent tests DB work on the default Neon branch — writers/migrations/backfills run on throwaway copy-on-write branches, auto-expire 7d" — which Finding 2's branch-count cost warning directly reinforces: each throwaway branch adds compute/storage and counts toward the 10-branch Launch allowance. The rule and the cost finding are consistent (both require TTL hygiene), not contradictory — but the Neon API key for `neon deploy` is the unmet dependency (founder tap owed per 2026-10-01 memory).
