## Key metrics/methods (formulas where given, else "not specified")
- SCORING RUBRIC (100 points total; shard scoring <70 auto-rejected and re-run):
  - EVIDENCE (0–30): one traced row per listed file, each 'safe' claim carrying a verbatim quote. −3 per file skipped or paraphrased. −30 if any file undeclared-partial.
  - ATTACK (0–25): every provided scenario traced with SURVIVES/BREAKS + guard quote, PLUS ≥4 self-invented scenarios strictly nastier than the provided set.
  - INTERROGATORIES (0–20): graded questions answered correctly WITH quotes. Each wrong or unquoted answer −5. (These have known answers; bluffing is detected.)
  - SELF-ADVERSARY (0–15): five least-certain 'safe' verdicts re-attacked; each broken finding or reinforced-with-new-evidence verdict scores; hand-waving scores 0.
  - DELIVERABLES (0–10): ≥3 new full-code tests that fail before / pass after, and ≥1 substantive patch OR a proof-of-absence with verbatim evidence.
- REGISTER (machine-scanned): praise tokens ("textbook", "excellent", "ironclad", "production-grade", "world-class", "robust"(bare), "perfectly", "flawless") VOID the shard.
- Four output passes per shard, STOP-and-wait-for-"continue" between: PASS 1 EVIDENCE (hypothesis + one traced row per file, verbatim quotes, declared partial reads); PASS 2 ATTACK (provided scenarios + ≥4 nastier own, fencepost tables at every boundary, shown arithmetic for every cost/growth claim); PASS 3 SELF-ADVERSARY (break own 5 least-certain 'safe' verdicts); PASS 4 FINDINGS (ranked CRITICAL→SMALL with file:line, interrogatory answers, learning ledger, ≥3 tests + ≥1 patch or proof-of-absence, rubric subscores, staked verdict SOLID/SOLID-WITH-FIXES/NEEDS-WORK with confidence % and one-line pre-mortem).
- Attacker/defender mode (recommended for CRITICAL shards 1, 3, 4, 6): run shard twice — Conversation A = ATTACKER ("rewarded per confirmed BREAK"), Conversation B = DEFENDER (refute each with verbatim evidence or concede); ship only findings surviving B.

- Recommended shard order: 9 (cockpit) → 5 (db) → 3 (engine) → 4 (public-api) → 2 (ingestion) → 10 (frontend) → 7, 8, 6, 11, 12 → 1 (billing) last ("pre-hardened this week; v4 exists to force receipts on its SOLID").
