# ops/archive/root-museum/REPO_INTELLIGENCE_REPORT.md
## What it is (1-2 sentences)
An autonomous operator's deep-read of the Beexly/Sports monorepo (2026-06-01, branch `claude/trusting-ramanujan-mYK6E`) combining source-code reading with a full validation pass (install, Prisma generate, typecheck, test). Its headline verdict is that the platform is genuinely well-built with ahead-of-competitors trust architecture, but the single most important conceptual gap is that `confidence` (a 0–100 heuristic quality score) is fed to the calibration layer as if it were a win probability.

## Key metrics/methods (formulas where given, else "not specified")
- **Scoring formula** (`packages/prediction-engine/src/scoring.ts`): components = consensus (max 30) + market depth (max 20) + edge (max 25) + volatility penalty (−15) + context (line movement, rest, schedule stress, H2H, venue form, cross-market, uncertainty) + flat +10 base, clamped 0–100. Refuses to emit below `MIN_PUBLISH_CONFIDENCE=50` or `MIN_BOOKMAKERS=2`.
- **Model version:** `MODEL_VERSION = "v5.0.0"` stamped on every pick.
- **Calibration** (`apps/web/lib/calibration/compute.ts`): buckets settled picks by confidence; computes observed-vs-expected win rate, delta, **Brier score**; emits review-only proposals at n≥30 and |delta|≥0.12. Never mutates weights. Flaw: sets `expected = confidence/100`.
- **New this session:** market-neutral `discrimination` metric — does observed win rate rise as confidence rises? — exposing `improving | flat | inverted | insufficient-data`, high/low bucket win rates, spread, monotonicity. 6 new tests; full calibration suite 52/52 green.
- **Odds API** (the-odds-api): `https://api.the-odds-api.com/v4`, region `us`, american odds; 7 sports (NFL, NCAAF, NBA, NCAAB, MLB, NHL, MLS) × 3 markets (h2h, spreads, totals); `FRESHNESS_THRESHOLD_MS = 1h`; per-pick `dataFreshnessAt`; `SourceCoverageReport` FRESH/AGING/STALE/MISSING/CONTRADICTORY; 15s timeout; exponential backoff + jitter honoring Retry-After on 429/5xx; reads `x-requests-remaining`/`x-requests-used`; `SourceSnapshot` stores raw payload + hash before normalization.
- **Readiness:** 7-phase bootstrap progression, all flags default safest; `canApplyCalibrationAdjustments` is hardcoded `false` (human-gate doctrine, load-bearing).
- **Cost:** every Claude call through `apps/web/lib/claude-api/messages.ts` hardcodes `claude-sonnet-4-6` (15× occurrences); no Haiku/Opus tiering, no prompt caching; spend measured via `ClaudeApiCallRecord` per-surface ledger + `ClaudeApiBudget` (monthly budget, alert thresholds, override) but not optimized.
- **Validation baseline:** `npm install` exit 0, 593 pkgs (13 vulns: 1 critical, 4 high); Prisma Client v5.22.0; typecheck green 9 workspaces strict zero errors; tests green — apps/web 1,855, engine 197, ingestion 17, types 28. Caveat: apps/web tests run against a stub Prisma client (`DATABASE_URL` unset → "All reads return empty results"); no live DB/migration coverage — the largest coverage blind spot.
- **Surface:** 48 API routes · 60 pages · 103 lib modules · 165 web test files · 25 components · 3 workers (data-refresh, pick-generation, content-publishing) · 6 packages (types, db, data-ingestion, ingestion-pipeline, prediction-engine).
- **Settlement** (`settlement.ts`): pure `calculatePickResult()` for SPREAD/MONEYLINE/TOTAL, correct home-perspective spread convention, soccer-draw handling; 31 unit tests.

## Findings (numbers and facts, not vibes)
- Headline: not vaporware, not slop; trust architecture (bootstrap gating, immutable signal snapshots, human-gated calibration, server-side paywall, compliance gates) genuinely well-built, in places ahead of commercial competitors.
- Core gap: confidence is a 0–100 desirability heuristic, not P(win); calibration treats it as probability. For spread/total (priced ≈50%), observed win rate ≈50% while confidence sits 65–90 → public calibration reports systemic "overcalling"; a naive deflation fix would destroy UX. Partial fix this session: discrimination metric (ranking-signal test).
- Human-gated recommendations (NOT taken at report time): (1) persist modeled win probability distinct from confidence (scoring already computes vig-free fair prob — currently `fairProbability: null`); calibrate that with Brier; keep confidence as display/ranking. (2) market-aware calibration proposals. Both require MODEL_VERSION bump + operator sign-off.
- Pick lifecycle state machine: ingest odds → score → GateDecision (SCORING→PUBLISHED|GATED) → persist Pick (result=PENDING, isBootstrap) → settle (worker) → record PickSignalSnapshot outcome → (if canonical+eligible) feed calibration.
- `isBootstrap` flags fence pre-canonical picks out of all public stats; `LossAutopsy` + `ModelJournalEntry` are public-accountability surfaces.
- R1 settlement single-point-of-failure (settle-picks cron was a no-op; grading lived only in the worker) ADDRESSED 2026-06-01: extracted shared `settleSport()` into `@sports/ingestion-pipeline`; worker and cron both call it. Residual: stale-unsettled-picks alert + live-path integration test; enabling in prod is operator decision.
- Read-only odds connectivity check: blocked/unverified — no live `THE_ODDS_API_KEY` in container; recommended single read-only `getSports()` call in authed environment to confirm quota headers.
- Gaps flagged: single-provider dependency (no failover); `MIN_BOOKMAKERS=2` thin — two agreeing books yield 100% "consensus" with no real price discovery; consider raising floor or down-weighting <4-book markets more aggressively.
- Compliance posture: `Promotion` model hard-gates public render on non-empty disclosureText, termsUrl, responsibleGamingText, status=ACTIVE + complianceStatus=APPROVED, non-expired, geo allow/deny; "Risk free" banned; banned-phrase scan tests — above-average pre-launch responsible-gaming posture. Gap: no documented legal review of the-odds-api data-licensing terms for commercial redistribution; no per-state operations matrix (human/legal task).
- 7 risks registered (R1–R7): settlement SPOF (mitigated), confidence-as-probability (High trust), stub-Prisma test blind spot (Med), 13 npm vulns + EOL deps eslint 8 / glob 7 / rimraf 3 (Med), single odds provider + MIN_BOOKMAKERS=2 (Med), Sonnet-only no caching (Med cost), repo clutter `_overnight_quarantine/` stray lock files (Low).
- Server-side paywall in `app/api/picks/route.ts`: DB-level tier gate, per-field entitlement nulling, bootstrap exclusion, data-quality floor, 503 readiness gate.
- Next actions prioritized: P0 settlement reliability + calibration semantics (human-gated); P1 model routing/caching + integration tests; P2 vuln triage/odds failover/repo hygiene. No hard-stop violations; no destructive DB ops, no Stripe live, no prod deploy.
