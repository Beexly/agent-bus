# arxiv-program/research/2026-09-21/arxiv-deep/0811-causal-feature-selection-contextual-multi-armed.md
## What it is (1-2 sentences)
Paper: Zhenyu Zhao, Yexi Jiang (2024), arXiv:2409.13888 (RecSys 2024 Bari). Introduces two model-free filter scores — Heterogeneous Incremental Effect (HIE) and Heterogeneous Distribution Divergence (HDD) — that rank candidate context features by the heterogeneous treatment effect they induce across bandit arms (i.e., features that change WHICH arm is optimal), rather than by outcome correlation. Verdict: ADAPT — cheap pre-screen for GSE's pick-selection/abstention bandits, but built for binary rewards and randomized arm assignment, so scores must be re-derived for win/loss/ROI rewards before adoption.

## Key metrics/methods (formulas where given, else "not specified")
For each feature x: bin into m_x bins (each of size N_b) to capture nonlinearity and handle continuous/categorical uniformly.
- HIE: FI_HIE(x) = Σ_{b=1}^{m_x} (N_b/N)·(P_{w_b}(Y=1) − P_{w*}(Y=1)), with w_b = argmax_{i∈{1..k}} P_{b_i}(Y=1) (per-bin winning arm), w* the global winning arm. Score = sample-weighted incremental gain of using per-bin winners over the global winner.
- HDD: FI_HDD(x) = Σ_b (N_b/N)·D_b(P_{b_1},…,P_{b_k}) − D(P_1,…,P_k), where D_b = Σ_{i,j} (N_{b_i}N_{b_j}/N_b²)·Σ_{v∈{0,1}} P_{b_i}(Y=v)·log(P_{b_i}(Y=v)/P_{b_j}(Y=v)) (pairwise KL over binary outcomes), and the pooled term drops the bin subscripts. I.e., sample-weighted contextual KL divergence between arm reward distributions within bins, minus the non-contextual (pooled) KL divergence — how much MORE the arm distributions diverge once conditioned on the feature.
- Combined: FI(x) = α1·ĤI_HIE(x) + α2·ĤI_HDD(x), min-max normalized, α's as hyperparameters.
- Downstream evaluation: LinUCB, nonlinear LinUCB (quadratic term), and Cohort-based Thompson Sampling CMAB trained with selected vs unselected features; reward compared.
- Assumptions (stated or implied): binary reward Y (derivation for binary only; extension not shown); arms randomly assigned in the logging data (needed for per-bin arm-conditional probabilities to be causal); binning granularity chosen by the analyst; min-max normalization across features for the combined score.
- UNCERTAIN: HDD's pooled-divergence subtraction can go negative; the paper does not discuss interpreting negative scores. Bin count m_x is a free parameter with no guidance.

## Data sources named
- (a) Synthetic: CausalML heterogeneous-treatment-effect data generator (public CausalML Python package); 10 trials × 50,000 samples, 3 arms, 10 features (5 true HTE-important, 2 correlated with outcome but no HTE, 3 irrelevant). Ground truth known.
- (b) Real: online randomized experiment at Roblox optimizing content cover image — 4 variants (arms), 600,000 samples; reward computed by offline matching (count reward where the model's selected arm equals the observed arm). Feature list not enumerated in text; "most features are categorical"; one synthetic irrelevant random feature added as negative control. Roblox data proprietary.

## Findings (numbers and facts, not vibes)
- Synthetic: HIE, HDD, and combined "effectively select the true important features that produce high CMAB rewards" across LinUCB, nonlinear LinUCB, and Cohort Thompson Sampling (Figure 2, qualitative — no reward numbers in text).
- Real: importance scores "align with the CMAB rewards"; the added irrelevant random feature "ranked the lowest"; HIE "more sensitive — dropping to the lowest for unimportant features" (Figure 3, qualitative).
- Table 1 (exact, seconds per trial, 10 features × 50,000 samples): HIE+HDD 2.7s vs LinUCB 647.3s vs nonlinear LinUCB 665.5s vs CohortMAB 82.5s — the model-free screen is ~240× faster than LinUCB-based selection and ~30× faster than CohortMAB.
- Paper's claim: model-free HIE/HDD match or beat model-embedded selection on downstream CMAB reward with far less compute and no model-misspecification risk. No p-values or confidence intervals stated.
- GSE transfer risks: (1) GSE has no randomized pick-assignment log, so per-bin arm-conditional probabilities would be confounded by the engine's own selection bias (good picks get posted; bad ones don't) — without randomization or IPS weighting, HIE/HDD measure selection artifacts, not HTE. (2) Binary-reward derivation only; GSE rewards are ternary-ish (win/loss/push) plus continuous ROI — KL terms need re-derivation or binarization (which discards stake sizing). (3) Future-work admits the planned online validation (10k contents × CMAB with different feature sets) was not yet run — the "online" claim is pending.
- Referenced related files/ledgers: pairs with ledger 0810 (AMS); existing-research-map line 144; GSE props/DFS lane and learning-to-abstain lane.

## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- Pick-selection / abstention bandit feature screen (OTHER, serves the learning-to-abstain and props/DFS lanes): arms = bet types (spread/ML/total) or engine versions per game; for abstention, arms = {post, skip}. Features that change WHICH pick to make (or whether to post) are exactly HTE features — this is the correct filter, not correlation-with-win.
- Critical transfer fix (OTHER): use inverse-propensity weighting from the engine's own posting policy, or restrict to quasi-randomized subsets (e.g., all-model-output games before the posting filter, which GSE logs in the predictions DB); otherwise HIE/HDD ranks confound selection artifacts with true treatment effects.
- Regime-conditional feature screening (OTHER): compute HIE in rolling 4-week windows and select features whose HTE is stable vs emerging (e.g., weather features gain HTE in December) — a "regime-conditional feature screen" that feeds the changepoint-resetting bandit from ledger 0810's improvement experiment, closing the loop between feature selection and non-stationary model selection.
- Extension worth testing (OTHER): re-derive HDD for continuous graded rewards (ROI per pick) using differential-entropy/KL between per-bin reward densities (KDE or quantile-parameterized), so stake-sizing and push information is not discarded.
- Acceptance gate: ADAPT if on the GSE 2025 holdout replay (a) HIE/HDD rank a known-spurious correlate (e.g., raw team win% — predictive of outcome but not of arm-differentiation) below true HTE features like line-movement buckets, AND (b) the LinUCB selector using HIE/HDD top features beats the correlation-selected selector by ≥ 1.5 ROI points per 100 picks. REJECT if either fails.
