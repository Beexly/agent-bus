# arxiv-program/research/2026-09-21/arxiv-deep/2202-where-is-the-ball-3d-ball-trajectory.md
## What it is (1-2 sentences)
Ponglertnapakorn & Suwajanakorn (2025, arXiv:2506.05763). A three-stage LSTM pipeline that estimates the 3D trajectory of a bouncing ball (including multiple bounces and hits) from 2D monocular tracking, using a novel camera-independent ray parameterization (P = (p_ground, p_vertical) ∈ R⁴) so one network handles arbitrary camera views; trained solely on PhysX/Unity simulation, it outperforms geometric/physics and prior learning baselines and generalizes to real tennis, soccer, and table-tennis video.

## Key metrics/methods (formulas where given, else "not specified")
- Input parameterization (§3.1.1): each 2D track point (u,v) back-projected to 3D viewing ray r(s) = c + ds from camera center c and direction d (from extrinsics E and intrinsics f, px, py — eqs. 1–2): c = ψ(E⁻¹[0,0,0,1]ᵀ), d = ψ(E⁻¹[u−p_x, v−p_y, f, 0]ᵀ), ψ = dehomogenization. Ray reparameterized as two intersection points with two perpendicular planes — ground plane (y=0) and a vertical plane (z=0, e.g., coplanar with a tennis net) — dropping always-zero coordinates → P = (p_ground, p_vertical) ∈ R⁴. Camera-independent (camera location/orientation/focal length drop out).
- Stage 1 — EoT network (LSTM^ε): stack of 3 bidirectional LSTMs with shortcut connections (Yu et al. 2017) + 3 FC layers; input = temporal differences ΔP_t = P_{t+1} − P_t (shift invariance); output ε_t ∈ [0,1], probability the ball ends its current trajectory or stops; auxiliary signal, not hard segmentation.
- Stage 2 — height prediction: forward LSTM^f and backward LSTM^b predict height differences Δh^f_t / Δh^b_t, accumulated from h^f_0 = 0 / h^b_N = 0, combined by ramp sum h_t = (1−w_t)h^f_t + w_t h^b_t with w_t = (t−1)/(N−1) (eq. 3). Height (1 DOF, camera-independent) uniquely determines the 3D point via ray intersection r^y_t(s*_t) = h_t, guaranteeing reprojection consistency (projection of predicted 3D = input pixel). Bidirectional LSTM^height refines absolute heights (fixes drift / below-ground protrusion).
- Stage 3 — refinement network (LSTM^refine): stack of 3 BiLSTMs predicting residual deltas (δx_t, δy_t, δz_t) on reconstructed 3D coordinates (ResNet-style identity-friendly), absorbing 2D tracking noise and enforcing learned 3D smoothness priors.
- Losses: EoT loss (eq. 4) L_ε = −(1/N)Σ_t [γ·ε^gt_t·log ε_t + (1−γ)(1−ε^gt_t)·log(1−ε_t)] (weighted binary cross-entropy); 3D reconstruction loss (eq. 5) L_3D = (1/N)Σ_t ‖(x,y,z)^gt_t − (x,y,z)^final_t‖²₂; below-ground loss (eq. 6) L_B = (1/|Y|)Σ_{y∈Y} y², Y = {y^final_t | y^final_t < 0}; total (eq. 7) L_Total = λ_ε L_ε + λ_3D L_3D + λ_B L_B with (λ_ε, λ_3D, λ_B) = (10, 1, 10).
- Training: all networks jointly, Adam, lr 0.001 constant, batch 256, 1,400 epochs, BPTT; Gaussian noise added to 2D inputs to simulate tracker noise.
- Stated assumptions: (a) first and last frames of the input sequence lie on the ground (y=0) — known initial height for accumulation; (b) camera intrinsics + extrinsics known; (c) camera high enough and facing downward so no viewing ray is parallel to either plane; (d) each "trajectory" begins when a force is applied (kick/hit) and ends before the next force or rest.
- Metrics: NRMSE (Mocanu et al. 2017 convention — RMSE normalized by max ground-truth range in x/y/z); on Real TrackNet (tennis): landing accuracy (T.F1, T.acc) and landing error (LE) per SynthNet's protocol.
- Baselines: SynthNet (Ertner et al. 2024, SOTA tennis), physics-based Shen et al. 2016 (optimizes initial velocity+position with contact-point constraints — reimplemented by authors), learning-based Mocanu et al. 2017 (restricted Boltzmann machines — official code, results verified with original authors). Noise robustness tested at ±5/10/15/20/25 px input noise.

## Data sources named
- Training: synthetic data from the PhysX physics engine in Unity — bouncing ball simulated with sequences of impulse forces; per-timestep 3D positions, 2D projected coordinates, end-of-trajectory flags. Three synthetic datasets (matching Mocap, IPL, TrackNet camera params and trajectory characteristics): 5,000 training sequences + 500 test sequences each; plus a Synthetic Single-Launch dataset (300 train / 100 test sequences).
- Real Mocap: ping-pong ball with IR reflective sticker, 8 synchronized IR cameras at 50 fps in ≈100 m² studio; 344 sequences, 103,872 data points, highly accurate 3D ground truth; 2D tracks from all 8 cameras.
- Real IPL: Fotouhi et al. 2017 — 2-minute capture of a real soccer match from 6 synchronized cameras on both touchlines at 25 fps with 2D tracking annotations; 3D ground truth via triangulation + Rematas et al. 2018 camera pipeline; 9 sequences successfully calibrated (lengths 18–147 frames, avg 68; ball travels 30.60×47.07 m², max height 1.66 m). Missing 2D points filled with an autoregressive LSTM (App. D.1).
- Real TrackNet: Huang — 81 video clips from 10 tennis matches, broadcast camera, 2D ball-tracking annotations; camera calibrated via PnP from court detection; 118 trajectories from 13 clips of one match evaluated qualitatively (avg 3 strokes, up to 9 bounces). No 3D ground truth — landing-position evaluation only.
- Project page: https://where-is-the-ball.github.io/; Unity-Projects GitHub link (sinoriani/Unity-Projects) in appendix for simulation reference. No explicit statement of model-code release in the paper text read.

## Findings (numbers and facts, not vibes)
- Tennis landing (Real TrackNet, vs SynthNet): landing accuracy 87.21%, F1 0.807, landing error 0.63 m vs SynthNet's 3.58 m (Table 4, §4.2.1; SynthNet numbers quoted from its paper) — a ~5.7× reduction in landing error.
- Single-launch trajectories (distance NRMSE ± std err, Table 3/§4.2.2): Ours 0.03±0.002 (≈0.6 cm RMSE on that dataset) vs Shen et al. 2016 0.11±0.01 vs Mocanu et al. 2017 1.02±0.03.
- Noise robustness: with ±25 px input noise (1664×1088 resolution), Ours degrades to ≈0.05/0.07/0.09/0.11 at 5/10/15/20/25 px (partial table) vs Shen 0.64 at ±25 px and Mocanu 1.20±0.42 — paper's claim: degrades minimally.
- Parameterization ablation (Table 1, distance NRMSE, Synthetic→Real Mocap/IPL): proposed p_ground+p_vertical input + height output: 0.05/0.09/0.01 (synth) and 0.68/0.74 (real). Naïve pixel-input + xyz-output: 14.13/0.31/0.70 synth, 11.68/2.45 real — the representation is the decisive ingredient; naïve 3D regression overfits badly (large synth→real gap).
- Component ablation (Table 2): removing LSTM^height explodes error (e.g., synth Mocap 0.05→6.26); removing LSTM^refine raises errors across all datasets (synth Mocap 0.05→0.10, real IPL 0.74→1.84); EoT flags matter most on Tennis/IPL where player-induced direction changes are less predictable.
- Sim→real caveats: simulation ignores spin, aerodynamics (Magnus), and court/turf-type friction; unusual trajectories degrade (App. G).
- GSE acceptance gate (pre-registered in the deep read): ADOPT the architecture if, on held-out real NFL kick/punt sequences with 2D tracks from broadcast video: (a) landing-spot error ≤ 1.5 yards MAE, AND (b) beats a fitted-physics baseline by ≥25% on landing error, AND (c) sim-trained weights transfer (≤2× error inflation synthetic→real). Reject if any condition fails or per-sequence camera calibration cannot be automated to <5% frame failure rate.

## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- New capability, no GSE duplicate: no learned 3D ball-trajectory-from-broadcast model in the GSE corpus (NGS does not publish 3D ball coordinates for kicks) — learned physics prior converting abundant 2D broadcast tracks into 3D trajectories — OTHER.
- Kick/punt trajectory engine: outputs feed hang-time / landing-spot / distance models and the kicking-evaluation desk; proposed NFL sim replaces PhysX spheres with a rigid-body prolate-spheroid flight model (drag, Magnus lift, gravity; impulses for kick launches) — kicking-game evaluation lane — OTHER.
- 6-DoF improvement direction in the read: angular velocity state (spiral rate, wobble) + Magnus coefficients fit from NGS kick data, spin as a latent variable the EoT network detects from 2D wobble signatures; hypothesis: beats sphere-assumption sim-to-real transfer on tumbling punts while matching on stable-spiral kickoffs — kicking-game physics — OTHER.
- Complements wave-5a trajectory-prediction papers (player movement forecasting) by solving the ball side of the simulation state — OTHER.
- Bidirectional (non-causal) architecture — offline/post-play inference only, not real-time in-play — TRUST-SIGNAL (honest scope labeling for engine consumers).
- INFERENCE: requires calibrated cameras per sequence (broadcast NFL cameras move/zoom → per-segment PnP calibration from yard-line intersections is a prerequisite); ground-start/end assumption (y=0 at both ends) requires manual trimming — operational friction for automated pipelines.
