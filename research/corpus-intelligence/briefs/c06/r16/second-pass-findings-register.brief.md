## Findings (numbers and facts, not vibes)
- F1 [CRITICAL]: schema is still a betting-pick system, not model-owned fantasy — Pick supports only SPREAD/TOTAL/MONEYLINE with one active pick per game/pickType; no Contest/ContestSlate/PlayerProjection/ProjectionDistribution/PlayerEligibility/Lineup/LineupSlot/SalarySnapshot/OwnershipProjection/OptimizationRun entities.
- F2 [HIGH]: NFL-specific identity fragmentation — Player requires unique gsisId, PlayerGameStat uses NFL season/week fields, SnapCount/Injury/DepthChartEntry retain nullable player IDs and free-text names; generic Entity/EntityEdge graph exists but operational fantasy tables bypass it.
- F3 [HIGH]: no model registry — modelVersion is free-text on Pick/ShadowSignal/PerformanceSummary/CalibrationProposal/LadderEvent; no immutable ModelArtifact hash/commit/feature-schema hashes/training window/approval/promotion lineage.
- F5 [HIGH]: source registry has a real guard (license, commercial-use, attribution, robots, rate limit, verdict, assertIngestible) but lets use-with-caution sources into the ingestible verdict set while its own comment says that class has no written commercial grant.
- F7 [HIGH]: data-refresh worker fail-open path when paid-odds governor can't be constructed → paid requests possible without a functioning credit governor; fail closed instead.
- F8 [MEDIUM]: hard-coded owner allowlist in apps/web/lib/auth.ts creates deployment-coupled admin authority.
- F13 [HIGH]: ranking-basis census only measures which fallback key (incl. confidence/100) drives sorting — not ownership probabilities or contest utility.
- F14 [HIGH]: drift monitoring missing (Evidently taxonomy: feature/data, concept, prediction drift, training-serving skew, data quality).
- F15 [HIGH]: no causal injury/news uncertainty model — injury status should be an event-time availability distribution with late-scratch scenario simulation.
- F16–F30: tracking/event/video/travel/weather/facilities providers cataloged with rights boundaries (e.g., NBA tracking "not available for every game" — missingness must be flagged, never imputed as zero).
- F31–F38: no SLOs/error budgets/RTO-RPO/DR drill; no secret-rotation schedule or KMS; Prisma stores OAuth access/refresh/id tokens as text; no privacy notice/DSAR/erasure workflow; gambling compliance gaps (age/geo, self-exclusion, ≥5-year regulatory retention); no per-pick versioned explanation artifact; CI lacks DAST/API-authz/SBOM; no measurement plan; current-mode posture (internal calibration only, no auto-publish) is a safety control but not a signed release gate.
- Expanded conclusion: the bottleneck is converting breadth into a trustworthy temporal data contract, durable fantasy schema, model registry, distributional/ownership model, and sealed evaluation loop.
