# product/live-war-room-spec.md
## What it is (1-2 sentences)
Phase 5 build spec (Radical #10, DEC-009 YouTube Live primary): the owner streams live (headline = Sunday NFL afternoons) with a real-time overlay showing the model's per-pick confidence updating as `PickSignalSnapshot` factor scores shift in-game — "watch the model think," research broadcast, never a tout show. Code at `apps/web/app/warroom/`, `apps/web/lib/warroom/`; Codex owns the WebSocket gateway + overlay, Claude owns overlay UX + show structure.
## Key metrics/methods (formulas where given, else "not specified")
No statistical formulas. Concrete operational numbers:
- **Calibration moment rule: a pick's score updating by >0.2 mid-game is surfaced on-stream** (narrated shift when material).
- Show structure timings: pre-game/pre-slate phase **60–90 minutes** (slate state → each pick's factor breakdown + pre-mortem → one or two notable gates → chat Q&A); in-game variable phase; settlement wrap; next-slate tease.
- Overlay layout: 1920×1080 horizontal stream; example rows "BOS @ NYY -3.5 [confidence: 73 → 71]", "CLE @ MIA -7 [confidence: 68 → 72]", "NYJ @ BUF o42.5 [confidence: 65 → 65]"; changed numbers flash briefly, arrow shows delta from publish time; footer "Last update: 8:42 PM ET · Model v6.0.5".
- Data pipeline: engine emits `PickSignalSnapshot` updates to a Redis pub/sub channel; WebSocket gateway at `wss://galaxysportsedge.com/api/warroom/stream`; overlay client = OBS browser source; polling fallback every **15 seconds** via `/api/warroom/state`. This is the ONE approved WebSocket use — explicit exception to master plan Part 4 rule 9 ("No websockets unless already in the dependency tree"), Codex adds it with a decision-log entry.
- Access tiers: FREE = public YouTube stream + public chat read, no expanded overlay factor breakdown; PRO = overlay variant 2 with factor breakdown text inline; ELITE = early-access private RTMP feed with full overlay incl. pre-mortem text + convergence flags, plus Discord channel access. Overlay is a parameterized HTML page: `?overlay_variant=elite`; owner sets multiple OBS scenes per tier.
- Chat: Option A Discord embed (primary for Elite; Elite post, Pro+ read, FREE read on delay); Option B YouTube native chat (public mirror, owner moderates); Phase 5 ships A primary / B mirror, Phase 6+ may unify.
- Cadence: Sundays during NFL season headline; mid-week (NBA playoffs, big NCAA games) case-by-case. Slate with zero published picks (all gated) → shorter episode **15–20 min** focused on the gates — "why the model passed."
- Schedule/reminders: `/warroom/schedule`, calendar (.ics) subscription, email reminders **1 hour before** each stream (transactional via Resend), Discord announcement, Twitter bot auto-posts "going live in 30 min."
- VOD: every episode archived to YouTube, replays at `/warroom/replays` (Phase 5 = simple embedded playlist; Phase 6+ may add time-coded jump points, Whisper auto-transcript, searchable topic archive).
- Compliance: pre-stream scan of show description/title/notes; post-stream scan of auto-generated YouTube description + Twitter posts; NO real-time in-stream scanner (live audio ungateable) — reliance on owner's voice training instead. Hype drift gets clipped + flagged.
- Voice rules: pass examples include "The model is showing 73% on BOS -3.5. The heaviest factor is rest advantage at 0.81. Let's look at the pre-mortem." and "Model's confidence just dropped from 73 to 71. The rest-advantage read just flipped." Fail examples: "This is a slam dunk! Hammer it!", "I'm 100% on this one.", "You CANNOT lose tonight.", "Everyone, get your bets in NOW."
- 10 acceptance criteria for v0: WebSocket gateway emitting PickSignalSnapshot updates; overlay renders in OBS browser source; 3 overlay variants parameterized; schedule + .ics works; email reminders fire; Discord announcement via Discord bot; Twitter teaser auto-post via Twitter bot; YouTube Live embed at `/warroom/[episodeId]`; Elite-scoped Discord channel; VOD archived to YouTube playlist.
- 4 open items: OPEN-WR-1 no custom event themes in v0; OPEN-WR-2 Twitch fork only if a community develops organically (Phase 5 = YouTube Live only); OPEN-WR-3 gated-slate short-episode rule (see timings); OPEN-WR-4 no real-time overlay reactions (👍/👎) in v0 — "distraction from the data."
- Brand: ultraviolet `#7B61FF`, deep slate background, mono font for numbers, subtle animations only — "no Twitch-style explosions or hype effects."
## Data sources named
Live `PickSignalSnapshot` / `GameSignal` snapshot updates flowing in-game; published-pick factor breakdowns and pre-mortem text; model version string; per-pick confidence scores with publish-time baseline for the arrow delta; Elite variant adds convergence flags. External services named: OBS Studio (overlay rendering), YouTube Live (primary), Discord (chat), Twitter bot (teasers), Resend (transactional email), Whisper (Phase 6+ transcripts). No external sports-data vendors named in this spec.
## Findings (numbers and facts, not vibes)
- This is a build spec, not a research report: no empirical results, no measured calibration performance, no historical viewership/engagement numbers in the file.
- Settlement phase includes an explicit accountability step: "Note which pre-mortem bullets 'called' each loss" — a public, per-episode loss-attribution loop.
- The >0.2 mid-game confidence-shift rule is the spec's single concrete materiality threshold for surfacing model updates live.
- Tier-gated information ladder is three deep: free (numbers only) → Pro (factor breakdown inline) → Elite (pre-mortem text + convergence flags on a private RTMP feed).
- Everything the spec ships in v0 for replay is a plain YouTube playlist embed; time-coded, transcribed, searchable archive is explicitly Phase 6+.
## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- Live model-confidence overlay with publish-time baseline arrows + >0.2 shift narration — TRUST-SIGNAL: real-time public calibration; the model's uncertainty moves visibly, which is the strongest anti-tout credibility signal in the file set.
- Per-episode loss attribution ("which pre-mortem bullets 'called' each loss") — TRUST-SIGNAL: public failure accounting; losses are traced to stated-before-the-fact reads rather than buried.
- Anti-hype voice rules with fail examples (slam dunk / 100% / cannot lose / get your bets in NOW) + clip-and-flag enforcement for drift — TRUST-SIGNAL: the same credibility-guardrail family as the B2B compliance scanner, applied to live audio.
- Gated-slate episodes (15–20 min on why the model passed when it publishes nothing) — TRUST-SIGNAL: restraint as content; the passes are as informative as the picks.
- Redis pub/sub → WebSocket gateway → OBS browser-source overlay with 15s polling fallback; parameterized overlay variants per tier; .ics + Resend + Twitter bot reminder stack — OTHER (live-ops infrastructure).
- Ultraviolet `#7B61FF` / deep-slate / mono-numbers overlay style — OTHER (brand presentation).
## Engine-actionable? (yes/no + one-line what)
Yes — adopt the >0.2 mid-game confidence-shift "calibration moment" threshold as a concrete real-time trigger rule for flagging material in-game model moves, and the pre-mortem-bullet-called-loss accounting as a public lessons-learned loop mechanic.
