# product/cross-sport-correlation-engine-spec.md
## What it is (1-2 sentences)
Phase 5 build spec (Radical #7): Pro+ users run their own hypotheses against Galaxy's historical data via a three-part query model (trigger event in sport A → observation window → outcome measured in sport B), getting aggregate stats with confidence intervals and qualitative significance markers — the product is the inquiry, never a recommendation. Code at `apps/web/app/correlate/`, `apps/web/lib/correlation-engine/`; Codex builds the engine, Claude owns query UX + voice.
## Key metrics/methods (formulas where given, else "not specified")
Delta explicitly defined: **delta = trigger-conditioned outcome rate − unconditional outcome rate** (the headline number). No p-values or closed-form significance formulas given; significance is a qualitative `SignificanceMarker` enum by design:
- `type SignificanceMarker = "INSUFFICIENT_SAMPLE" | "WEAK" | "MODERATE" | "STRONG" | "VERY_STRONG"` — explicitly NOT a p-value ("the engine is not a stats package"; "no p-value theater").
- Result shape: `{ query, sampleSize, triggerEventCount, observationCount, outcome: { measure, overallRate, triggerRate, delta, confidenceInterval: [number, number] | null, significance }, warning, computedAt, modelVersion }`.
- Confidence interval always shown as a range around the delta, never a single percentage alone.
- Observation window options: same_night | next day | within 7 days.
- Query structure: trigger (Boolean DSL over sport + market/signal conditions) / observe (window) / outcome (sport + measure). Example: `sport == "MLB" and market.sharp_money_signal == true and game.day_of_series == 3 and game.series_length == 4`, observe `same_night`, outcome `sport == "NHL" and measure pick.over_under_outcome`.
- Worked voice example: "When MLB sharp money fired on day 3 of a 4-game series (N=42 events), NHL overs the same night hit 56% (CI: 41% – 71%, MODERATE)." / "Sample is too small (N=8) to draw conclusions. Try widening the date range." (N=8 = INSUFFICIENT_SAMPLE per the rule that warning fires on too-small samples.)
- Rate limits: PRO = 10 queries/day via visual builder; ELITE = 100 queries/day via DSL mode (Phase 5 DSL spec adds `correlate`, `trigger`, `observe`, `outcome`, `measure` keywords); FREE = read-only on public community queries.
- Performance budget: typical query runs under **10 seconds** against the full historical set (default per OPEN-CORR-4: full historical data set; result caching per (query hash, data snapshot timestamp) defaulted on, OPEN-CORR-1).
- Data is a frozen snapshot: queries run against settled `Pick` rows (`settledAt IS NOT NULL` AND `eligibleForLearning = true`) + `GameSignal` + `SourceSnapshot` rows, with `IngestionRun` for freshness/timestamp anchoring; re-running later can differ as new history settles.
## Data sources named
No external sources — pure internal historical: `Pick` rows (settled, eligible-for-learning only), `GameSignal` rows, `SourceSnapshot` rows, `IngestionRun`. No live signals. Community library at `/correlate/community` surfaces most-starred saved queries (Pro+ can star; saved queries re-run against latest data on open, with last-computed timestamp). Phase 2 Loss Room data, Phase 3 Twitter bot data, Phase 4 calibration data all queryable (acceptance item 10).
## Findings (numbers and facts, not vibes)
- This is a spec, not a research report: no empirical correlation results are published in the file — no cross-sport correlation claims, no measured deltas, no validated patterns. The file explicitly says the engine does not promise correlations exist; "some hypotheses will hold; most won't."
- The engine never recommends bets: result page carries a mandatory non-removable disclaimer — "This is historical correlation, not future prediction. Past patterns may not hold. Sample sizes shown." Voice rules fail examples include "You'll never guess what we found!", "GUARANTEED", "Bet NHL overs every MLB sharp-money night and profit."
- Anti-patterns named and refused: no "secret pattern" framing (findings are public), no certainty language, no "follow this pattern" recommendation, no p-value theater.
- 10 acceptance criteria for v0: visual builder functional; DSL parse + execution; typical query under 10s; result includes sample size + CI + significance marker; save/share/star; community page; tier rate limits; brand-safety scan on result rendering = zero hits; non-removable disclaimer; performance on the full Phase 2/3/4 data sets.
- 4 open items: OPEN-CORR-1 result caching defaulted yes (TTL tied to snapshot timestamp); OPEN-CORR-2 cross-user friend query libraries defaulted NO in v0 (privacy-preserving: public queries public, private queries private); OPEN-CORR-3 no custom viz beyond result chart in v0; OPEN-CORR-4 performance ceiling = full historical data set.
- Concrete example triggers named in the file: "When NFL openings are bullish on home dogs, do NCAA home dogs perform better the next day?" / "Does sharp money in MLB on the East Coast correlate with anything in NBA on the West Coast that night?" — illustrative queries, not findings.
## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- Mandatory CI + sample size + INSUFFICIENT_SAMPLE warning on every result — TRUST-SIGNAL: honest calibration-state presentation; no single-percentage claims without the range.
- Qualitative significance markers instead of p-values; anti-hype voice rules; mandatory non-removable disclaimer; zero-tolerance brand-safety scan on rendering — TRUST-SIGNAL: the entire output contract is engineered to prevent tout-style certainty claims.
- Trigger/observation-window/outcome query model over settled Picks + GameSignals — OTHER: a reusable hypothesis-testing scaffold the engine could use internally to test its own cross-sport suspicions before promoting them to features.
- Saved-query community library with starring and re-run-on-open — OTHER: crowd-sourced hypothesis pipeline, not an intelligence signal per se.
- Visual builder vs DSL tiers with 10 vs 100 queries/day — OTHER (product packaging).
## Engine-actionable? (yes/no + one-line what)
Yes — the trigger/observe/outcome query template with delta = conditioned-rate minus base-rate, mandatory CI, and INSUFFICIENT_SAMPLE guards is a ready-made internal hypothesis-testing protocol for validating cross-sport suspicions on settled history before they touch any model.
