# arxiv-program/research/2026-09-21/arxiv-deep/0268-efficient-feature-interactions-with-transformers-improving.md
## What it is (1-2 sentences)
Prakash & Kothari (2024) propose a "Proximity-Aware Contextual Transformer" (FT-Transformer + explicitly structured feature relationships) for tabular spending-propensity prediction on Dream11 (200M+ user fantasy gaming platform), benchmarked against GBDTs and tabular transformers. Verdict in file: ADAPT — the architecture and especially the neighboring-round contextual-feature pattern port to GSE's tabular models; the Dream11 spending numbers themselves do not transfer.
## Key metrics/methods (formulas where given, else "not specified")
Objective: L̂ = min_f Σ_i L(P_i, P̂_i); P = f(U, R, C); feature groups U (user: demographics/winnings/wallet), R (round: game type/expected users), C (proximity-aware: rounds t−5..t+5 around current round). Tokenizer: T_j^(num) = b_j^(num) + x_j^(num)·W_j^(num); T_j^(cat) = b_j^(cat) + x_j^(cat)·W_j^(cat); T = stack of tokens → Transformer + [CLS] head. Training: Optuna Bayesian optimization on validation, 10 random seeds averaged, no model-agnostic DL tricks (no pretraining/augmentation/distillation/LR schedules) to isolate architecture. Metrics: MAE, MSE.
## Data sources named
Dream11 proprietary "User Round Spends" data: train 7,074,749 tuples; validation 1,165,011; test 831,583. Schema: 21 categorical + 120 numerical + 60 proximity-aware contextual features. No public release. Code availability asserted in paper but no URL in the extract.
## Findings (numbers and facts, not vibes)
Test MAE / MSE: GBDT Baseline 42.4 / 500.35; MLP 40.4 / 362.53; ResNet 41.34 / 397.48; TabTransformer 37.99 / 442.74; FT-Transformer 38.07 / 448.90; Proposed 37.13 / 351.01 (best both). Headline deltas verified in file: 2.5% MAE, 21.8% MSE over FT-Transformer. Train-fraction → MAE: 0.05 → 38.56; 0.5 → 37.13; 0.9 → 36.78 (monotone). Error-distribution reading: MLP higher MAE but lower MSE (fewer extremes); TabTransformer/FT-Transformer good MAE but worse MSE (more large errors). Gaps noted in file: split not stated to be time-ordered (leakage risk); NO ablation of the novelty (FT-Transformer + contextual features as plain inputs is the missing baseline); weak GBDT baseline (no Optuna-level tuning disclosed); no calibration/uncertainty.
## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- OTHER: the proximity-aware contextual feature pattern — explicitly windowing neighboring events (t−5..t+5) as first-class features — ports to nflverse play/drive sequences (rolling EPA momentum, success-rate trend, score-delta trajectory) and is the cheapest testable win (feed into existing XGBoost, no architecture change).
- OTHER: large-scale (7M-row) DL-vs-GBDT benchmark protocol (Optuna, 10 seeds) GSE can copy for its own model comparisons.
- TRUST-SIGNAL: the paper's missing-ablation failure is the exact trap GSE must avoid — test features-vs-architecture separately before crediting the transformer.
