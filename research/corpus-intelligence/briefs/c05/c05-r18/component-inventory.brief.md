# docs/design/redesign-2026-09/component-inventory.md
## What it is (1-2 sentences)
A file-level audit mapping a design brief's 12-component library list (from `8970241d-claudedesignprompt.md` §9) to what actually exists in `apps/web/components` — every file path and prop quoted from a file opened — with verdicts: reuse as-is, reuse with restyle, or missing.
## Key metrics/methods (formulas where given, else "not specified")
Not specified. Method: `grep`/`find` across `apps/web/components` and `apps/web/app`, cross-checked against `.design-sync/entry.tsx` (53 named components counted: 50 export statements, one exporting three names, two exporting two names each, plus 21 `export type` statements).
## Data sources named
None external. Audited internal paths: `apps/web/components/ui/tabs.tsx` (`Tabs`, `FilterBar`), `apps/web/components/ui/data-table.tsx` (`DataTable`, `ToneCell`), `apps/web/components/ui/tool-page-skeleton.tsx` (`ToolPageSkeleton`), `apps/web/components/picks/pick-card.tsx` (`PickCard`), `apps/web/components/picks/evidence-audit-drawer.tsx` (`EvidenceAuditDrawer`), plus badge fragments (`LineFreshnessBadge`, `ValueGapBadge`, `BoardHealthBadge`, `BoardSurfaceChip`, `JarvisDiffBadge`, `JarvisTrend`), chart bodies (`CalibrationCurve`, `ReliabilityChart`, `HealthRing`), and `accessibility-audit.md`.
## Findings (numbers and facts, not vibes)
- Reuse as-is (3): Tabs, Tables (`DataTable`), Skeleton (`ToolPageSkeleton`) — typed, light/dark variants, pass accessibility checks.
- Reuse with restyle (2): Pick row (`PickCard`) — gating/factor-breakdown/receipt logic functionally sound but internal badges (`ResultBadge`, `LockedValue`) are private and the visual language is the old neon-on-black palette; Drawer (`EvidenceAuditDrawer`) — the only drawer in the app, but its focus trap is missing (Tab not constrained despite `aria-modal="true"`).
- Missing (7): Buttons (no generic `<Button>`; only `.btn-primary/.btn-secondary/.btn-ghost` CSS classes + one-offs), Inputs (no shared component; all hand-rolled per page), Chart frame (no unifying wrapper — `CalibrationCurve`, `ReliabilityChart`, `HealthRing` each define own title/axis/accessible-alternative conventions; `BarChart`/`ScoreRing` page-local), Badge set (win/loss/void/push/stale/locked/verified implemented in 7+ independent one-offs, no shared `state` prop), Sheet (zero matches for "sheet" anywhere), Toast (no transient-notification pattern at all; errors are inline persistent `role="alert"` blocks), Empty state as standalone (only `DataTable`'s built-in tabular empty state is solved).
- `.design-sync/entry.tsx` carries real implementations of Tabs, DataTable, PickCard, EvidenceAuditDrawer, ToolPageSkeleton, most badge fragments, and `CalibrationCurve`/`ReliabilityChart`/`HealthRing` — but nothing for Buttons, Inputs, Sheet, or Toast, which do not exist anywhere in the codebase to bundle.
## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- TRUST-SIGNAL: The chart-frame gap means calibration/reliability charts have inconsistent accessible alternatives (some `aria-label`s carry no numbers) and no enforced "title states the claim + axis labels with units + sample size + timestamp" contract — the proof surfaces' credibility depends on fixing this.
- OTHER: Frontend component inventory for the redesign — no sports intelligence content.
## Engine-actionable? (yes/no + one-line what)
No — a UI component audit for the redesign; the only engine-adjacent note is that calibration charts need a shared chart-frame contract to stay credible.
