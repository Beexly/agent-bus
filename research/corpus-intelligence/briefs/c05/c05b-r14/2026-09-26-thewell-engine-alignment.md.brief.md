# engine/research/2026-09-26/2026-09-26-thewell-engine-alignment.md
## What it is (1-2 sentences)
A research alignment doc (2026-09-26) transferring training-protocol techniques — not data, not weights — from The Well physics-simulation ML benchmark (Ohana et al., NeurIPS 2024, arXiv:2412.00568) into GSE's movement/tracking module spec, with a license audit and five explicit integration points.
## Key metrics/methods (formulas where given, else "not specified")
- The Well benchmark protocol: forward problem = predict next snapshot from 4-step history; baselines FNO, Tucker-factorized FNO, U-Net, CNextU-Net (ConvNeXt blocks); 12-hour single-H100 time-box; metric **VRMSE** = RMSE / std(target), so predicting the field mean scores exactly 1.0 (preferred over NRMSE because centered normalization doesn't downweight nonzero-mean fields).
- Key empirical result (paper Table 3): autoregressive rollouts from one-step-trained models degrade badly — "notably worse performance overall even on relatively short rollouts." CNextU-Net wins 8/17 one-step experiments; rollout rankings shuffle.
- Integration points (all methods-only, no code copied):
  - §3.1 Pushforward-style stability training (Brandstetter et al., ICLR 2022): unroll 2 steps, gradients flow only through last step (stop-grad on first); equivalently adversarial-style stability loss on perturbed inputs A(u+ε); plus temporal bundling (predict K steps at once, backprop last). Proposed: optional stability fine-tune — with p=0.5, feed model's own detached 10-frame displacement prediction back as pseudo-history for the 20-frame head; backprop only through 20-frame head. Cost: ~1 extra forward pass/step when active.
  - §3.2 Scheduled input-noise (pushforward analog): reframe existing σ=0.1 yd position jitter as pushforward-noise analog (Brandstetter σ ≈ 1% of input range); add noise schedule σ ramps **0.05 → 0.2 yd over first 30 epochs**; log σ per epoch. Cost: zero extra compute.
  - §3.3 VRMSE diagnostic: add **VRMSE per horizon** to training log alongside raw RMSE; gate suggestion: require **VRMSE < 0.9 on every horizon** before Phase 2 (beat mean predictor by a real margin everywhere). Cost: one division.
  - §3.4 Rollout-stability probe: new `test_rollout_stability` — chain own outputs (5f displacement → advance pseudo-history → next 5f → repeat to 20f); assert chained 20f error within **2× the direct 20f-head error**. Diagnostic, not training target; failure triggers §3.1. Also windowed evaluation: early (5f) vs late (20f, landing) windows reported separately. Cost: inference-only.
  - §3.5 Acceleration-consistency loss: implied acceleration `a_impl = 2·(d̂ − v·Δt)/Δt²` must satisfy `|a_impl| ≤ a_max`, a_max = **8 yd/s²**, hinge loss, weight **0.1**; penalizes "teleport-then-stop" predictions passing velocity cap. Acceptance: `L_cap ≈ 0` and accel-hinge ≈ 0 at convergence, no RMSE regression.
- Architecture note (§3.6): FNO/spectral operators are grid-only — do NOT apply to 22 discrete agents; spec's set-transformer (permutation-invariant, relational) is the correct discrete analog; spec already requires no entity positional encoding (test 8).
## Data sources named
The Well: Ohana et al. 2024 (NeurIPS Datasets & Benchmarks), arXiv:2412.00568 (v2 Feb 2025); repo github.com/PolymathicAI/the_well (4,465 stars, `pip install the-well`); 16 datasets, 15 TB total (6.9 GB–5.1 TB each), HDF5 `(n_traj, n_steps, *spatial_dims)`, fp32, uniform grids, constant Δt, 0.8/0.1/0.1 trajectory splits; only `active_matter` arguably relevant (256×256 grid, 81 timesteps, 360 trajectories, 51.3 GB — continuum rod-like particle field theory, not discrete agents). Big Data Bowl 2026 (zohebwaghu/nfl-big-data-bowl-2026-csi) referenced for license contrast. Brandstetter et al. ICLR 2022 (pushforward); PDE-Refiner NeurIPS 2023 (stability loss). Walrus (Polymathic foundation model on the Well) noted as PDE-targeted.
## Findings (numbers and facts, not vibes)
- License audit: repo code **BSD-3-Clause** (commercial OK with attribution); 16 datasets **CC BY 4.0** (commercial allowed with attribution — more permissive than BDB-2026's CC BY-NC 4.0); checkpoints unverified/irrelevant.
- Verdicts: do NOT download any Well dataset for pretraining — no published evidence of cross-domain transfer (fields→discrete agents); optionally download `active_matter` train split (~40 GB) only as a protocol sandbox to validate §3.1/§3.2 recipes before NGS-GPU spend.
- Adopt: §3.2 scheduled jitter, §3.3 VRMSE + 0.9 gate, §3.4 rollout-stability probe, §3.5 accel-consistency loss — all cheap, additive, no architecture change. §3.1 pushforward held in reserve, triggered only if §3.4 probe fails.
- Honest limits (5 listed): fields vs agents; deterministic PDEs vs decision-making humans (Well has no uncertainty — GSE outputs calibrated uncertainty); noise-free sims vs 10 Hz NGS measurement noise/dropouts/0.1s quantization; problem shape differs (spec's bundled heads already avoid the rollout-collapse failure mode); scale mismatch (12-hour H100 vs <2M params overnight).
- Core lesson: "one-step training lies about multi-step stability" — VRMSE keeps the "are we actually learning dynamics vs. predicting the mean" question honest.
