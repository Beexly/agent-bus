# arxiv-program/research/2026-09-21/arxiv-deep/2183-unsupervised-feature-construction-anomaly-detection-time-series.md
## What it is (1-2 sentences)
Research ledger for "Unsupervised Feature Construction for Anomaly Detection in Time Series — An Evaluation" (arXiv:2501.07999v2, Orange Innovation), which asks whether it's better to build an anomaly detector on raw sliding-window vectors or on tsfresh auto-constructed tabular features — and proves (Wilcoxon-significant across 5 datasets) that the window→tsfresh→tabular-detector pipeline beats raw temporal representations for Isolation Forest. Ledger verdict: ADAPT — the 7-step pipeline is directly reusable as GSE's anomaly detector for line-move / injury-news shocks and as a windowed auto-feature-construction recipe for odds-trajectory sequences.
## Key metrics/methods (formulas where given, else "not specified")
- No equations stated for the core method (uses library defaults).
- Seven-step pipeline per series: (1) sliding windows of size W (tested W = 32, 64, 128, 256); (2) F windows into tabular DB (rows = windows, columns = raw time points); (3) horizontal normalization within windows — tested no-normalization vs Min-Max vs Median-IQR vs Mean-Std (IF needed no normalization, LOF did); (4) feature extraction with tsfresh "Efficient" (q = 777 features; columns with missing values at small W dropped); (5) windows described by q features; (6) detector: Isolation Forest or LOF, PyOD 1.1.3, default settings, no tuning; (7) window-level anomaly prediction.
- Evaluation: window labeled anomalous if any anomaly point falls inside it; AUC computed per series from detector confidence scores (threshold-free, chosen deliberately); paired comparisons via Wilcoxon signed-rank test; mean ranks + critical diagrams. Setting: strictly agnostic — no expert feedback, no hyperparameter tuning, no anomaly-type distinction; offline exploratory protocol (train and evaluate on all data, explicitly stated).
- GSE transfer: W = 32 samples for intraday odds moves, W = 8 games for EPA windows; flag rule = window anomaly score in top 1% of trailing-4-week distribution → "shock" event, cross-checked against news/weather before routing to the engine as a prior-reset trigger.
## Data sources named
- Five public benchmarks (387 series total), via TimeEval datasets portal (https://timeeval.github.io/evaluation-paper/notebooks/Datasets.html): SVDB (MIT-BIH Supraventricular Arrhythmia ECG: 76 series, length 230–400, anomaly rate 0.008–0.34%); NAB (Numenta: 46 series, lengths 1127–22695, anomaly rate 8.30–10.29%); AIOPS 2018 (web-service indicators: 13 series, lengths 16441–295414, anomaly rate 0.06–7.50%); NormA (aerospace/health/body-language/electricity: 5 series, lengths 2000–35040, anomaly rate 3.08–9.13%); UCR Anomaly Archive 2020 (247 series, lengths 6674–300262, anomaly rate 0.0005–4.9%). tsfresh and PyOD are open source; paper's own reproduction code was anonymized at time of writing.
- GSE data: odds-trajectory series per game (spread/total sampled every 15 min from open to close, 2023–2026, OddsAPI archive) + per-team rolling EPA/play windows (nflverse); injury-report timestamps as shock ground truth.
## Findings (numbers and facts, not vibes)
- Isolation Forest (Table III, mean ranks over series per dataset): tsfresh features (FE) beat raw windows (TS) in all 16 dataset×window cells; 14/16 statistically significant (e.g., SVDB/W=32: p = 1.522×10⁻¹²; UCR/W=128: p = 1.792×10⁻³²). Non-significant: SVDB/W=256 (p=0.1161), NAB/W=32 (p=0.05059).
- LOF: FE best mean rank in only 4/16 cells, 2 significant — no consistent benefit from tsfresh features for the distance-based detector.
- Headline effect: on UCR, IF's AUC jumped 0.586 → 0.746 (+36%) with tsfresh features.
- Preprocessing: IF needed no normalization and no hyperparameter tuning; LOF needed normalization and still lagged; vertical (column) normalization of extracted features helped LOF-FE on NAB (surpassed LOF-TS) but hurt on SVDB — inconclusive overall.
- Critical diagrams: IF-FE ranked first on 3 of 4 datasets; on UCR, LOF-TS (raw) still best overall.
- Adversarial notes from file: offline train-on-all protocol doesn't measure generalization to future data; window-level labeling inflates effective anomaly mass; tsfresh's 777-dim blowup hurts distance-based models; W grid was fixed, not tuned; no LOF tuning (k unexplored); labels in NAB/NormA are known to be noisy.
## Intelligence connections (tag each: QB-BEHAVIOR, COACHING, OL, TRUST-SIGNAL, SCHEME, OTHER)
- OTHER — unsupervised anomaly detection, two direct GSE problems: (a) anomalous line-move detection — windows of odds-trajectory series (opening→closing spreads/totals) to flag steam/sharp-action shocks before kickoff; (b) team-performance regime breaks — windows of rolling EPA series to flag injury/weather-driven structural breaks that should down-weight stale priors in the engine.
## Engine-actionable? (yes/no + one-line what)
Yes — replicate the 7-step pipeline on closing-line/in-week spread trajectories for all 2024–2025 games (W = 32, 64; tsfresh Efficient; PyOD Isolation Forest defaults), labeling windows anomalous if a starting-QB injury report or >2-point steam move occurs within; adopt the window→tsfresh→IF shock detector iff it achieves AUC ≥ 0.70 on steam/shock windows AND beats raw-window IF with Wilcoxon p < 0.05, with per-window inference < 5 s; reject if precision@top-1%-flagged < 0.30 (too many false alarms to route to the engine); improvement experiment: swap tsfresh for catch22 (22 features, ~0.1 ms each per ledger 2182) and re-run the comparison — if catch22-FE matches tsfresh-FE on AUC at 1/30th the feature count, GSE gets a real-time-capable shock detector instead of a batch one.
