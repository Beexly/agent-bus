# arxiv-program/research/2026-09-21/arxiv-deep/0370-towards-unconstrained-2d-pose-estimation-of.md
## What it is (1-2 sentences)
Introduces SpineTrack (a dataset with nine vertebral keypoints: C1, C4, C7, T3, T8, L1, L3, L5, sacrum — existing datasets collapse the spine to a single rigid segment) and SpinePose, a teacher–student distillation model extending RTMPose that estimates fine-grained 2D spine pose in unconstrained in-the-wild images without degrading standard body-pose performance. Verdict recorded: ADAPT — spine-curvature keypoints are a novel biomechanical feature source for QB throwing-mechanics / OL posture analysis from video, but GSE has no video-pose pipeline today, so bank as a future CV idea, not an immediate build.

## Key metrics/methods (formulas where given, else "not specified")
SpinePose: teacher–student distillation on RTMPose; student head expanded to K_student = K_body ∪ K_spine (Eq. 1); new head rows initialized from normal statistics of existing weights (not zeros). Loss (Eq. 9): L_total = α L_pos + β L_distill + γ_1 L_structure + γ_2 L_spine, ablations use α=5, β=2.5, γ_1=0.1, γ_2=0.5. L_pos = Σ_{k∈K_student} KL(p_{s,k}, g_k) (Eq. 2, KL vs GT heatmaps). L_distill = Σ_{k∈K_body} KL(p_{s,k}, p_{t,k}) (Eq. 3, distill Body8 teacher on body joints). L_structure = (1/(π|B|)) Σ_b |Δφ_b|, Δφ_b = atan2(sin(φ^p_b−φ^g_b), cos(φ^p_b−φ^g_b)) (Eq. 4–5, bone-angle orientation penalty vs horizontal). L_spine = MSE({s_i}, {s̃_i}), s̃_i = s̃_{i−1} + w_i(s_i − s̃_{i−1}), w_i = 1 − 0.5σ(α(‖s_i − s̃_{i−1}‖ − T)) (Eq. 6–8, differentiable smoothing dampening abrupt spinal bends). Training: 10 epochs fine-tune, AdamW, LR 4e−3, 1000-iteration linear warmup, cosine annealing to 5% of initial LR, batch 1024, input 256×192 (some 384×288); GT bboxes for SpineTrack, 56.4-AP detector for COCO/Halpe26, flip test. Input: single RGB image (person crop); target: 37-keypoint heatmaps; evaluated per subset (Body/Feet/Spine/Overall) with COCO-style AP/AR.

## Data sources named
SpineTrack-Unreal (synthetic, ~25k frames): Unreal Engine 5, 16 avatars × 10 motion sequences, 5 camera views, UE5 skeleton projected to 2D, biomechanically aligned via OpenSim IK, backgrounds composited with 1,000 real images via SAM segmentation of OpenImagesV7. SpineTrack-Real (33k+ annotations): images from COCO and YogaPose datasets; pseudo-labels from RTMPose-L + curve-fit spine guesses; active-learning human-correction loop. Total: 50,962 images, 58,766 annotated humans, 35 keypoints; biomechanical validation: triangulated keypoints vs OpenSim IK RMSE 2–4 cm; keypoints >10 cm RMSE manually refined. Project page: https://saifkhichi96.github.io/research/spinepose/ (no code repo link stated).

## Findings (numbers and facts, not vibes)
- SpineTrack Spine AP: SpinePose-s 89.6 (AR 90.7), -m 91.4 (92.5), -l 91.0 (92.2), -x 89.3 (91.0); overall AP: s 84.2, m 88.0, l 88.4, x 88.3 (same-family baselines score 0.0 on spine — they lack the keypoints)
- Retention: SpinePose-l COCO AP 75.2 / AR 79.5 vs RTMPose-l 76.9/81.5; Halpe26 77.0/81.1 vs 78.4/82.9 — spine extension costs ~1.5–2.1 AP points vs same-size RTMPose
- Ablation (SpinePose-l, COCO/Halpe26/SpineTrack AP): no-distill baseline 69.6/72.2/87.0 → +distill 70.8/73.2/87.3 (+1.0–1.2 benchmarks) → +distill+spine-smooth 74.7/76.6/88.7 (spine smoothness adds +3.9/+3.4 on benchmarks — the paper's most surprising claim, attributed to "rule-based knowledge" preventing interference) → +distill+structure 71.2/73.4/87.7 → all losses 75.2/77.0/88.4 (best on all three)
- Limitations recorded: spine pseudo-labels model-generated (residual bias toward curve-fit prior could inflate AP); GT bboxes at validation (real detector performance lower); 10-epoch fine-tune only credible via Body8 teacher init; biomechanical "validation" partially circular; qualitative sports evidence only (hockey, squat, dive, archery); NFL caveat: helmets/pads/jerseys occlude torso landmarks entirely — pads likely defeat the visual cues
