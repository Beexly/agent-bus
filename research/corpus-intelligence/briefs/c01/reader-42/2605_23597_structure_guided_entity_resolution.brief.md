# docs/dfs/research/2026-09-25/arxiv-deep/2605.23597-structure-guided-entity-resolution.md
## What it is (1-2 sentences)
A Motif research-ledger (ADAPT verdict) on arXiv 2605.23597 (Chourasia, Kapoor, Patil — Dream Sports/Dream11, accepted ACL 2026): a two-phase curriculum fine-tuning method (SGER) for robust LLM name matching on noisy Indian KYC identity data. Verdict: reject the LLM fine-tuning machinery, adapt the transferable ideas (structure-guided parsing, three domain-informed augmentation invariances) into a deterministic player-name resolver for GSE's prop ingestion.
## Key metrics/methods (formulas where given, else "not specified")
- SGER: two-phase curriculum fine-tuning of Meta Llama 3 8B Instruct with LoRA rank 4, alpha 8, fp16, early stopping on validation F1, single A100 80GB. Phase 1: name→JSON structure parsing {first_name, middle_name, last_name}; Phase 2: binary pair classification from Phase 1 checkpoint; output "Yes"/"No" token scores softmaxed to match probability; decision threshold selected to maximize F1 on the validation set. No equations stated.
- Augmentation: 20,000 labeled pairs → >50,000 via (1) Pair Swapping (order invariance), (2) Component Permutation, (3) Random Space Removal (OCR/data-entry simulation). Held-out: 50,000 pairs, name-level disjointness from train.
- Baselines: Levenshtein (th 0.8, F1 0.726), BERT fine-tuned (F1 0.806), GPT-4o few-shot (F1 0.911), Llama 3 8B few-shot (0.839), single-stage SFT (0.946), SFT+aug (0.973), SGER (0.994). Exact: SGER accuracy 99.02%, precision 99.95%, recall 98.9%, F1 0.994. Ablation deltas: augmentation 0.946→0.973; +curriculum 0.973→0.994.
- Deployment: Kubernetes, 3× L4 GPUs, vLLM, 10,000 RPM, P99 latency 120 ms; claimed >$500K annual savings; 99.95% precision enables fully automated decisions.
- Paper limitations (adversarial review in the ledger): augmentation leakage vs name-level disjointness; augmentation provenance underspecified; no CIs/seeds; threshold-selection discipline unclear; weak classical baseline (Levenshtein 0.8 strawman); domain = Indian KYC only; self-reported production claims unverifiable.
- GSE implementation spec (non-LLM adaptation): deterministic `player-name-resolve.ts` — Stage 1 tokenizer → {given, middles[], family, suffix, raw} (lowercase, punctuation strip, Unicode fold, suffix extraction); Stage 2 component matcher: family Jaro-Winkler weight 0.6 + given JW 0.3 + middle-initial bonus 0.1, order-invariant max; merge only if family JW ≥ 0.92 AND combined ≥ τ; τ chosen by max-F1 on labeled validation; fail-closed (else null); canonical spelling from source-reliability ordering; unit + synthetic-augmentation test plan (F1 ≥ 0.97, precision ≥ 0.995 on ~5,000 synthetic pairs; threshold argmax guard).
- Acceptance gate: F1 ≥ 0.98 with precision ≥ 0.995 on ≥500 hand-labeled real book-to-book pairs (DK Pick6, Underdog, PrizePicks, Sleeper, Action Network); ≥20% more true duplicates resolved than current normalization at equal-or-better precision; median added latency < 1 ms. REJECT if precision < 0.995 or labels unavailable.
- Improvements proposed: closed-vocabulary roster-anchored resolution; position/team as hard disambiguation constraints; logistic regression over {family JW, given JW, middle-initial, suffix, token-count delta, order-inversion} instead of fixed weights; temporal alias table with source attribution.
## Data sources named
Dream11 proprietary historical KYC name pairs (not public); ~10,000 manually annotated Phase 1 Indian names (proprietary); no code/data/model weights released. GSE-side: ingestion-layer identity code (game-identity.ts, kalshi-team-abbr.ts), five live pick'em prop intakes (DK Pick6, Underdog, PrizePicks, Sleeper, Action Network).
## Findings (numbers and facts, not vibes)
- Curriculum gain is 2.1 F1 points (0.973→0.994); augmentation gain is 2.7 points (0.946→0.973) — augmentation contributed more than the curriculum.
- Precision 99.95% claimed on 50K held-out pairs; LoRA rank 4/alpha 8 on Llama 3 8B; P99 120 ms at 10K RPM on 3× L4.
- GSE status per ledger: no dedicated player-name alias/normalizer module exists in ingestion — identified gap; `source-reliability` is the closest neighbor module (un-read at ledger time); the six named engine modules are downstream of identity resolution.
- Challenge taxonomy (Table 1) examples: transliteration variants match ("Subham"/"Shubham"); patronymic variants NO match ("Rajesh So Hari" vs "Hari"); honorifics match ("Rameshbhai Patel"/"Ramesh Patel"); truncations match ("Rajeshk"/"Rajesh Kumar").
