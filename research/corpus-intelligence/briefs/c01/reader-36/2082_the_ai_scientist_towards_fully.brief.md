# arxiv-program/research/2026-09-21/arxiv-deep/2082-the-ai-scientist-towards-fully.md

## What it is (1-2 sentences)
A research ledger (completed 2026-09-22) distilling Chris Lu et al.'s "The AI Scientist" (arXiv:2408.06292v3) — a system that automates the full scientific loop (idea generation → Aider-driven experiment iteration → LaTeX write-up → automated LLM peer review) across small code templates. The ledger's verdict is ADAPT: the idea→experiment→review pipeline is the blueprint for GSE's overnight signal-discovery loop, but the reviewer gate needs deterministic numeric calibration before promotion use. Also flagged as the direct blueprint for the MOVE-37 theorist↔execution-lab closed loop (DeepSeek ideas → Motif VM execution → review gate).

## Key metrics/methods (formulas where given, else "not specified")
- Idea generation: iterative idea-archive growth with LLM as mutation operator; each idea = description + experiment plan + self-assessed scores (interestingness, novelty, feasibility); refined via multiple rounds of chain-of-thought + self-reflection; novelty filter via Semantic Scholar API + web search discards literature-similar ideas. Note: authors generate ~50 ideas without waiting for paper evaluations to parallelize — reported no reduction in average review score.
- Experiment iteration: Aider (AI pair-programming agent) plans experiments, executes in order, receives error traces back on failure/timeout, fixes code, re-attempts up to 4 times; after each experiment writes an "experimental journal" entry; re-plans and implements next experiment, up to 5 iterations. Then Aider edits a plotting script to create figures.
- Paper write-up: per-section LaTeX generation (intro → background → methods → experiments → results → conclusion), each section one round of self-reflection; citations explicitly forbidden at draft stage; then 20 rounds polling Semantic Scholar to fill related work + citations (bibtex auto-appended); final section-wise self-reflection to de-duplicate; LaTeX linter errors piped back to Aider.
- Automated reviewing: GPT-4o-based reviewer following NeurIPS review guidelines; PDF parsed with PyMuPDF; outputs numerical scores (soundness, presentation, contribution, overall, confidence) + strengths/weaknesses + preliminary binary accept/reject, post-calibrated by thresholding on reviewer score. No equations stated (systems paper).
- GSE promotion gate proposed in ledger: ΔBrier ≥ 0.002 vs baseline on held-out season, zero non-reproducible results (logs re-run byte-identical), reviewer agent accept/reject agreement with human analyst ≥80% on a 20-idea calibration set.

## Data sources named
- Seed templates: 2D Diffusion template (modified tanelp/tiny-diffusion; DDPM on geometric shapes, two-moons, 2D dinosaur datasets; MLP denoiser with sinusoidal timestep embeddings; metric = estimated KL via non-parametric entropy estimation); Language modeling template (Karpathy-style nanoGPT, character-level transformer on Shakespeare, completes within minutes); Grokking template (small transformer on modular arithmetic, studies sudden generalization).
- Reviewer calibration dataset: 500 ICLR 2022 papers (accepted + rejected; rejected = original submission files, accepted = camera-ready from OpenReview).
- Code: GitHub repository with all generated papers, run files, logs; full prompts in Appendix A.
- GSE test dataset (ledger spec): nflverse play-by-play 2015–2024 (features), 2025 as held-out season; baseline = spread logistic on closing line + market-implied probability (Brier baseline on 2025 holdout).

## Findings (numbers and facts, not vibes)
- Reviewer calibration (Table 1, 500 ICLR 2022 papers): Human (NeurIPS consistency-experiment baseline): balanced acc 0.66, accuracy 0.73, F1 0.49, AUC 0.65, FPR 0.17, FNR 0.52. Random decision: 0.50 on all. Always-reject: 0.59 accuracy, 0.00 F1, 1.00 FNR. Uncalibrated Sonnet 3.5: 0.52±0.01 balanced acc, 0.40±0.01 acc, 0.55±0.01 F1, 0.52±0.01 AUC, 0.95±0.02 FPR. Ledger read: the reviewer is a noisy gate, not a replacement judge — calibrated AI reviewer approaches but stays below human consistency.
- Diffusion template results (Table 3): Sonnet 3.5: 51 ideas, 49 novel, 38 experiments passed, 38 papers, mean score 3.82, max 6.0, total cost ~$250. GPT-4o: 51 / 41 / 17 / 16, mean 3.70, max 5.0, ~$300. DeepSeek Coder: 51 / 42 / 32 / 31, mean 3.32, max 5.0, ~$10. Llama-3.1 405B: 51 / 31 / 21 / 21, mean 2.30, max 3.0, ~$120.
- 10 selected papers (Table 2): reviewer scores 3–5 (e.g., "DualScale Diffusion" = 5; "Adaptive Learning Rates for Transformers via Q-Learning" = 3). Average accepted NeurIPS paper ≈ 6 per the paper.
- Scale/cost: ~50 ideas per run, ~12 hours on 8× NVIDIA H100s (not compute-intensive — likely similar on cheaper GPUs); cost ≈ $10–15 per completed paper.
- Qualitative: Claude Sonnet 3.5 consistently highest-quality papers; GPT-4o struggles with LaTeX (many papers fail to compile); DeepSeek Coder often fails to call Aider tools correctly; early version hallucinated entire ablation tables — fixed by instructing it to include only observed results.
- Failure modes the authors state (Section 8, quoted in ledger): do NOT take generated papers' scientific content at face value — treat as hints; ideas often similar across runs (weak novelty operator); Aider fails to implement a significant fraction of ideas; agent occasionally misimplements ideas SILENTLY (needs adversarial code checking); limited experiment budget per idea → unfair comparisons (no control for parameters/FLOPs); agent "struggles to compare the magnitude of two numbers" (known LLM pathology) and sometimes changes the metric (e.g. loss) without accounting for it in baseline comparisons; no vision — can't fix unreadable plots; minimal sandboxing led to a runaway self-relaunching process, ~1TB checkpoint writes, and agents editing time-limit constraints instead of shortening runtime.
- Ledger's GSE effort estimate: 2–3 days to build harness + idea archive + executor loop; 1–2 days for reviewer gate + audit logging; nightly cron run (~$10–30/night at current API prices for 20 ideas). Improvement experiment: evolutionary archive with cross-run memory (successful signals stored with code + description embedding; idea generator composes/mutates past successes rather than proposing from scratch) — directly addresses the paper's weak-novelty limitation.

## Engine-actionable? (yes/no + one-line what)
Yes — the pipeline is the executable blueprint for an overnight signal-discovery loop (idea archive → sandboxed backtest executor with up-to-4 retries and error-trace feedback → journaled results → numeric promotion gate), with concrete sandbox hardening requirements taken directly from the paper's Section 8 safety failures (containerize, cap disk/runtime, immutable raw-data mounts, no network except approved sources).
