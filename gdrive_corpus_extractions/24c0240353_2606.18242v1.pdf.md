**Formal Governing Operators for EventDrive / EventDrive-VLM.**

Below, I reconstruct the mathematical apparatus exactly as the paper specifies it, with explicit SI, information-theoretic, probability, and tensor units, and with exact [PAGE n] citations and verbatim quotes. Where a quantity is not explicitly defined in the paper but is required for the physical reasoning (e.g., the base event-generation rate that is never named as an operator but is referenced qualitatively via MEPS figures), I flag it clearly.

### 1. Event signal model and voxelization operator

The paper's primitive is the asynchronous event tuple. [PAGE 5] verbatim: "Given an event stream E = {ek}K k=1, where each event ek = (xk, yk, tk, pk) encodes spatial coordinates, timestamp, and polarity pk ∈ {−1, 1}, standard voxelization maps events into a 4D tensor E ∈ R^{2×B×H×W}."

The voxelization operator (Eq. 1, [PAGE 5]) is:

\[
E(p,\tau,x,y) = \sum_{e_k \in \mathcal{E}} \delta(p - p_k)\,\delta(x - x_k, y - y_k)\,\delta(\tau - \tau_k),
\qquad
\tau_k = \left\lfloor \frac{t_k - t_a}{t_b - t_a}\, B \right\rfloor .
\]

**Units and structure.** Here \(x_k \in \{0,\dots,W-1\}\) pixels, \(y_k \in \{0,\dots,H-1\}\) pixels, \(t_k \in [t_a, t_b]\) seconds (SI), \(p_k \in \{-1,+1\}\) dimensionless (log-intensity change polarity), \(\tau_k \in \{0,\dots,B-1\}\) dimensionless bin index, and \(B\) is the number of temporal bins (dimensionless count). \(E(p,\tau,x,y) \in \mathbb{Z}_{\ge 0}\) is an event-count tensor in units of events per voxel (dimensionless counts, since each event contributes an integer 1 per polarity channel). The \(\delta\) symbols are Kronecker deltas, not Dirac deltas — this is critical: each event increments exactly one integer cell, so \(E\) is a sparse count tensor, and \(\sum_{p,\tau,x,y} E(p,\tau,x,y) = K\), the total event count in the window.

**Breakdown / singularity regime.** The quantization \(\tau_k = \lfloor \frac{t_k - t_a}{t_b - t_a} B\rfloor\) has a well-defined breakdown. When \(t_b - t_a \to 0^+\) (a very short integration window, i.e., high required temporal resolution), the per-bin window \(\Delta t_{\text{bin}} = (t_b-t_a)/B \to 0\), and if the sensor event rate \(\lambda\) (events·s⁻¹) is finite, the expected per-bin count \(\mathbb{E}[E] = \lambda \Delta t_{\text{bin}} \to 0\). Below a critical rate \(\lambda_c \approx 1/\Delta t_{\text{bin}} = B/(t_b-t_a)\), most bins are empty (sparse regime); above it, bins saturate. The paper never names this operator, but it is implicitly the driver behind the M3ED statement [PAGE 10]: event rates "often exceeding 200 MEPS during rapid rotations or high-texture scenes." 200 MEPS = \(2\times10^8\) events·s⁻¹. For a \(1280\times720 = 921{,}600\)-pixel sensor at \(B=100\) bins over a window \(t_b - t_a\), the mean per-pixel-per-bin occupancy is \(\frac{2\times10^8}{921600 \cdot B / (t_b-t_a)}\); the saturation regime where every pixel fires multiple times per bin is the exact point where high-frequency temporal detail is destroyed by integer-count aliasing in Eq. 1 — the "blurring fast motion" failure the paper describes at [PAGE 5]: "Conventional voxelization applies a fixed number of temporal bins and thus compresses long exposure windows while blurring fast motion."

### 2. Multi-horizon expert encoding

The paper constructs \(N\) voxel tensors at bin counts \(B = \{b_n\}_{n=1}^N\). [PAGE 5] verbatim: "Instead of relying on a single bin size B, we construct multiple voxel tensors using temporal resolutions \(B = \{b_n\}_{n=1}^N\), producing event tensors \(E_n\) that capture short-, medium-, and long-horizon motion patterns." Each expert (Eq. 2, [PAGE 5]):

\[
F_n = \sigma(E_n), \qquad F_n \in \mathbb{R}^{H \times W \times d},
\]

with \(d\) the channel dimension. **Implementation values** are given at [PAGE 7]: "Dynamic horizon encoding uses temporal bins \(B = 20, 50, 100\)." So \(N = 3\) (the ablation at [PAGE 8] confirms "Our choice (N = 3)"). The final event features are projected from 512-d to the LLM hidden size; [PAGE 23] states: "a single linear layer mapping the 512-d event features into the LLM hidden space (2048-d)."

**The expert operator's hidden assumptions.** \(\sigma(\cdot)\) is an unspecified backbone nonlinearity applied to \(E_n\); because \(E_n\) is a nonnegative integer count tensor and \(F_n \in \mathbb{R}^{H\times W\times d}\) is real-valued with \(d = 512\), \(\sigma\) must embed the 2-channel count tensor (polarity \(p\in\{0,1\}\)) into a 512-d feature space, which is the role of the RVT/MaxViT-RNN backbone ([PAGE 7]: "a pretrained RVT [27] backbone"; [PAGE 23]: "a pretrained MaxViT–RNN [27] event backbone"). This is a dimensional lift from \(\mathbb{Z}_{\ge0}^{2\times b_n \times H \times W}\) to \(\mathbb{R}^{H\times W\times 512}\), and the paper gives no explicit form for the embedding, only "expert network [27] specializes in one temporal resolution."

### 3. Mixture-of-Experts gate (Eq. 3)

[PAGE 5] verbatim: "Global average pooling produces a compact descriptor \(f_c \in \mathbb{R}^{Nd}\)... The gating logits are then computed as"

\[
z = W_g f_c + \mathrm{Softplus}\big(\epsilon \odot (W_{\text{noise}} f_c)\big),
\]

with \(W_g, W_{\text{noise}} \in \mathbb{R}^{Nd \times N}\), \(\epsilon \sim \mathcal{N}(0,1)\). [PAGE 5]: "Retaining only the largest k logits focuses computation on the most relevant temporal experts, and softmax normalization yields the weights \(\alpha_n\)." The aggregation is

\[
F_e = \sum_{n=1}^{N} \alpha_n F_n .
\]

**Probability structure.** The gate is a stochastic top-\(k\) mixture. The logit vector \(z \in \mathbb{R}^N\) has additive heteroscedastic noise: the deterministic part \(W_g f_c\) and a noise-scaled part whose scale is \(\mathrm{Softplus}(W_{\text{noise}} f_c) > 0\) elementwise (Softplus maps \(\mathbb{R}\to(0,\infty)\)). The softmax over the top-\(k\) selected logits gives mixing weights \(\alpha_n \in (0,1)\) with \(\sum \alpha_n = 1\) (dimensionless, simplex-constrained). The entropy of the gate \(H(\alpha) = -\sum_n \alpha_n \log \alpha_n\) (nats) is the operative control: near-zero entropy = single-expert selection; \(\log N\) entropy = uniform blend.

**The ablation contradiction — a formally precise breakdown regime.** This is a gray-zone audit finding. The main-text method describes \(F_e = \sum_n \alpha_n F_n\), a soft weighted sum. But the ablation text [PAGE 8] states: "Our MoE-based dynamic horizon module, which activates only the top-scoring expert, achieves the best overall results." These are inconsistent. The equation-level operation \(F_e = \sum_n \alpha_n F_n\) is a weighted sum; "activates only the top-scoring expert" is a hard argmax gate (\(F_e = F_{n^\star}\), \(n^\star = \arg\max_n z_n\)). The ablation table (Tab. 4, [PAGE 8]) shows "Wt.sum" (weighted sum) achieving L2 = 3.75 m but the "Ours" MoE row achieving L2 = 3.66 m. If "Ours" is a hard top-1 expert, it is *not* the weighted sum of Eq. 3; it is \(k=1\). The math is only self-consistent if \(k=1\) at inference and the top-1 soft weight is renormalized to \(\alpha_{n^\star}=1\). Under that reading, the "Softplus noise" term \(\epsilon\) serves purely exploration during training (expert diversity, per [PAGE 5]) and is annealed to zero at test. I flag this as an unstated-but-required assumption: the deployment gate is \(k=1\) hard selection, and Eq. 3's summation collapses to a single surviving term. Without that assumption, "Wt.sum" and "Ours" would be identical operators and Tab. 4 could not separate them — the 3.75 vs 3.66 m gap and 74.10 vs 74.69 planning-Acc gap prove they are *different* operators, so the paper's prose and equation disagree at the operator level.

### 4. Event Q-Former cross-attention (Eq. 4)

[PAGE 6] verbatim: "Following the Q-Former architecture [45], we introduce a set of learnable event query tokens \(q_e \in \mathbb{R}^{N_q \times d}\)... After flattening \(F_e\) into \(f_e \in \mathbb{R}^{(HW)\times d}\), the attended event embeddings are computed as"

\[
z_e = \mathrm{softmax}\!\left( \frac{(q_e W_Q)(f_e W_K)^\top}{\sqrt{d}} \right)(f_e W_V),
\]

with \(W_Q, W_K, W_V \in \mathbb{R}^{d\times d}\). **Units:** \(q_e \in \mathbb{R}^{N_q \times d}\), \(f_e \in \mathbb{R}^{HW \times d}\), attention logits \(\in \mathbb{R}^{N_q \times HW}\) (dimensionless), softmax normalizes each of the \(N_q\) query rows into a probability distribution over \(HW\) spatial positions (nats when log'd), output \(z_e \in \mathbb{R}^{N_q \times d}\). This is standard scaled dot-product attention: the \(1/\sqrt{d}\) factor has units of \(1/\sqrt{\text{dimensionless}} = \) dimensionless, normalizing variance so logits are \(\mathcal{O}(1)\). The paper emphasizes this is more efficient than token concatenation ([PAGE 6]): "Rather than concatenating event and frame tokens, which ignores modality asymmetry and leads to high computational cost, the EQA employs cross-attention." The ablation (Tab. 4) confirms: "Concat" L2 = 4.01 m vs "Attention" L2 = 3.69 m vs "Ours" (Q-Former) L2 = 3.66 m. The Q-Former's \(N_q\) learnable queries produce a fixed-length summary \(z_e \in \mathbb{R}^{N_q \times d}\) independent of \(HW\), whereas full cross-attention scales with \(HW\) — this is the stated efficiency argument ([PAGE 9]: "maintaining a lower computational cost, as learnable queries extract only the most salient motion patterns rather than attending to the full spatiotemporal map").

### 5. Ego-frame trajectory and intent labeling operators

Prediction ([PAGE 15]) uses agent trajectories \(Q = \{q_t = (x_t,y_t,z_t)\}_{t=0}^{10}\) at \(\Delta t = 0.1\) s, normalized \(\tilde q_t = q_t - q_0\). Velocity (finite difference, following [15]):

\[
v_t = \frac{\lVert \tilde q_{t+1} - \tilde q_t \rVert}{\Delta t} \quad [\text{m·s}^{-1}].
\]

Path intent uses \(\Delta x = x_{10}^{\text{future}}, \Delta y = y_{10}^{\text{future}}\) with threshold rules ([PAGE 15]): LEFT if \(\Delta x\) exceeds a positive threshold, RIGHT if below a negative threshold, STRAIGHT if \(|\Delta x|\) small relative to \(|\Delta y|\), UNKNOWN if displacement too small.

Planning ([PAGE 17]) uses a rigid ego-frame transform:

\[
\tilde p_t = (p_t - p_0)\, R_0^\top,
\]

with \(R_0\) the rotation matrix of the current pose (so \(R_0^\top = R_0^{-1}\) for the orthogonal SO(3) rotation). Past/future sampled at 2 Hz, 6 past + 10 future waypoints. **Singularity regime:** if \(R_0\) is computed from a quaternion near the identity-vs-\(\pi\) ambiguity, or from a pose with degenerate yaw (pure vertical flip), the yaw extraction \(\psi = \mathrm{atan2}(R_{21}, R_{11})\) is ill-conditioned — this is the classical SO(3)→SO(2) projection singularity that the paper does not address but which matters for tunnel GNSS-denied segments ([PAGE 26]: "GPS-denied tunnel segments").

### 6. Evaluation operators (exact)

Perception strict match (Eq. 5–7, [PAGE 20]):

\[
\mathrm{Correct}(i) = \mathbf{1}\!\left(c_i = \hat c_i \wedge t_i = \hat t_i\right), \quad
\mathrm{Acc}_{\text{perc}} = \frac{1}{N}\sum_{i=1}^{N}\mathrm{Correct}(i), \quad
\mathrm{Acc}(k) = \frac{\sum_{i\in k}\mathrm{Correct}(i)}{|k|}.
\]

Understanding QA uses strict letter + Jaccard soft text match (Eq. 8–9, [PAGE 21]): matched when \(\mathrm{Jaccard}(t_i,\hat t_i) > 0.8\). Grounding uses IoU (Eq. 10) with Top-1 accuracy at \(\tau = 0.6\) (Eq. 11) and mIoU (Eq. 12). Prediction joint correctness (Eq. 14–16, [PAGE 21–22]):

\[
\mathrm{Acc}_{\text{joint}} = \frac{1}{N}\sum_{i=1}^{N}\mathbf{1}\!\left(\hat y_i^{\text{spd}} = y_i^{\text{spd}} \wedge \hat y_i^{\text{path}} = y_i^{\text{path}}\right).
\]

Planning trajectory error (Eq. 20–22, [PAGE 22]):

\[
e_{i,t} = \left\lVert \begin{pmatrix} x_{i,t}\\ y_{i,t}\end{pmatrix} - \begin{pmatrix} \hat x_{i,t}\\ \hat y_{i,t}\end{pmatrix}\right\rVert_2 [\text{m}], \quad
L2_{\text{mean}} = \frac{1}{T}\sum_{t=1}^{T} e_{i,t},
\]

with \(T = 10\), \(\Delta t = 0.5\) s, and reported at \(t \in \{2,6,10\}\) = \{1s, 3s, 5s\}. **Units are meters (SI).**

### 7. Two-stage training loss and masking

[PAGE 24] verbatim: "all labels at positions corresponding to \(\langle|\text{image pad}|\rangle\), \(\langle|\text{event}|\rangle\), and \(\langle|\text{ video pad}|\rangle\) tokens are replaced by IGNORE INDEX. Loss is computed only on natural language tokens":

\[
\mathcal{L} = \mathrm{CE}\big(\mathrm{shift}(y_{\text{logits}}),\, \mathrm{shift}(y_{\text{target}})\big).
\]

This is a token-masked cross-entropy over the vocabulary \(\mathcal{V}\): \(\mathcal{L} = -\frac{1}{|\mathcal{M}|}\sum_{j\in\mathcal{M}} \log p_\theta(y_j \mid y_{<j}, \text{modalities})\), where \(\mathcal{M}\) is the set of natural-language token positions (the complement of image/event/video-pad positions), units nats·token⁻¹. Stage 1 freezes LLM + RGB tower, trains event pathway only ([PAGE 6]: "gradients flow only through the event pathway"); Stage 2 unfreezes LLM blocks with a decoupled LR ([PAGE 23]: "the event encoder and event Q-former use \(1\times10^{-4}\), and the LLM layers use a conservative \(2\times10^{-7}\)").

<RETROCAUSAL_GENEALOGY>

**Lineage of the operators and the multi-week traps embedded in this literature.**

EventDrive does not appear in a vacuum. Its mathematical and architectural spine is a four-generation lineage of event-vision research, and several of its design choices are *negative reactions* to documented failures in that lineage — what I will call "multi-week traps," meaning experimental configurations that consumed researcher-time in prior work and whose recurrence the EventDrive authors are structurally avoiding.

**Generation 0 — the sensor physics (Mahowald Mead lineage).** The event camera is a neuromorphic sensor descended from Misha Mahowald and Carver Mead's silicon retina work (1990s). The paper's own survey lineage [PAGE 2] cites Gallego et al. [20] ("Event-based vision: A survey") and Chakravarthi et al. [7]. The governing physical fact — microsecond latency, high dynamic range, per-pixel asynchronous log-intensity change — is why the entire benchmark is motivated around "blur, glare, and rapid motion, where frame-based perception can become unreliable" ([PAGE 1]). The retro-causal root: event cameras exist *because* frame integration \(I(x,y) = \int_{t}^{t+\Delta} L(x,y,\tau)\,d\tau\) [cd·s·m⁻²·s = cd·s·m⁻²] saturates and motion-blurs under fast dynamics. The event model instead reports \(\Delta(\log L) > C\) asynchronously — this is the reason the whole modality exists, and every downstream operator is a consequence.

**Generation 1 — upstream supervised perception (detection/segmentation/flow).** The related-work section [PAGE 2] catalogs the first wave: detection [27, 42, 53, 56, 70], segmentation [35, 38, 65], optical flow [71, 74]. Two sub-schools: (a) sparse graph/spike models "preserving sparsity and asynchrony" [17, 18, 22, 55, 59, 63, 71]; (b) dense feed-forward models "that convert events into voxel grids or time surfaces for image-based backbones" [10, 27, 32, 34, 44, 56, 57]. **The multi-week trap here:** the dense school's reliance on *fixed* voxelization. EventDrive inherits the RVT backbone [27] (Gehrig & Scaramuzza, "Recurrent vision transformers for object detection with event cameras," CVPR 2023) — but [PAGE 5] explicitly names the trap: "Conventional voxelization applies a fixed number of temporal bins and thus compresses long exposure windows while blurring fast motion, losing the high-frequency detail essential for motion reasoning." The entire Dynamic Horizon Encoder is a retro-causal *correction* of this documented failure mode.

**Generation 2 — event–frame fusion.** The paper traces a fusion lineage [PAGE 3]: "Early pipelines relied on late fusion [9, 43], whereas later designs introduced shared backbones and attention-based gating for cross-modal interaction [5, 53, 66]." Notably [53] is the authors' own FlexEvent work (Dongyue Lu et al.), and [66] is Tomy et al. on "Fusing event-based and RGB camera for robust object detection in adverse conditions." **The trap this avoids:** fixed temporal windows. [PAGE 3] verbatim: "Yet most frameworks rely on fixed temporal windows, which fail to capture motion cues that unfold over varying temporal scales [6, 23, 42]." The multi-horizon MoE is the direct antidote — it is not a novel aesthetic choice, it is a targeted reversal of a lineage-wide limitation that wasted researcher-months across [6, 23, 42].

**Generation 3 — event-based VLMs (the immediate parent generation).** This is the tightest lineage. [PAGE 3] names three direct predecessors: EventGPT [52] (couples event encoder + temporal aggregator + LLM), EventVL [46] (large-scale event-image-text pairs, spatiotemporal + semantic alignment), LLaFEA [72] (frame-event fusion + cross-attention + duration cues). **The critical multi-week trap:** [PAGE 3] verbatim, "most models remain confined to captioning or short QA tasks." And from [PAGE 8]: "the representations learned from EventDrive transfer across datasets" — implying prior work overfit to a single annotation style. EventVL provides "neither checkpoints nor code" ([PAGE 19]) and LLaFEA "have not released code or checkpoints, preventing controlled reproduction" ([PAGE 20]) — meaning multiple research groups spent weeks trying to reproduce or build on these and hit reproducibility walls. EventDrive's contribution is positioned precisely as the escape from that trap: full-stack coverage (perception→understanding→prediction→planning) rather than captioning.

**Generation 4 — Qwen2.5-VL + BLIP-2 Q-Former + RVT/MaxViT-RNN synthesis.** The final layer of genealogy is component-level. The Q-Former is from Li et al. BLIP-2 [45] ([PAGE 6]: "Following the Q-Former architecture [45]"). The event backbone is RVT [27] / MaxViT-RNN. The LLM is Qwen2.5-VL-7B-Instruct [3]. The MoE gate is from Shazeer et al. [60] ("Outrageously large neural networks: The sparsely-gated mixture-of-experts layer," 2017). **The retro-causal observation:** EventDrive is a *synthesis paper* — its novelty is compositional (multi-horizon MoE over RVT experts + Q-Former alignment + two-stage curriculum), not a new primitive. The genealogy reveals that the risk profile of such papers is integration debt: every inherited component carries its own untested-at-this-scale assumptions.

**Multi-week trap #5 — the annotation-generation circularity.** A subtle lineage trap specific to this paper: the ground-truth QA labels are generated by Qwen3-VL-30B-A3B-Instruct [2] (captioning, [PAGE 13]) and Qwen2.5-VL-7B-Instruct [3] (caption-to-QA, [PAGE 13]). The *evaluated model* is also a Qwen2.5-VL-7B-Instruct derivative. This creates a potential self-distillation loop: the model is being trained on labels generated by a sibling/larger version of itself. [PAGE 26] acknowledges a related trap: "many annotations are derived using model-assisted pipelines. These may inherit biases from the underlying VLMs or from rule-based heuristics." The retro-causal genealogy of this trap runs back to the broader synthetic-data lineage (EventGPT's N-ImageNet-Chat synthetic corpora [PAGE 19]), and it is the single most under-examined validity threat in the benchmark.

<RECURSIVE_THEORY_OF_MIND>

**Modeling the adversarial agents inside the benchmark and inside the deployment loop.**

This section applies recursive theory-of-mind (ToM) to two nested agent populations: (a) the benchmark constructors who anticipated how models would "game" the evaluation, and (b) the deployed driving agent whose "crisis habit regression" must be modeled against a clock.

**Level-0 ToM — the model's direct task.** The model sees RGB frame + event representation + language query and must emit an answer in strict format. This is the base reality: \(a = \pi(o)\) where \(o\) = (frame, event voxel, query) and \(a\) = formatted answer.

**Level-1 ToM — the benchmark designer anticipating the model.** The constructors clearly modeled how a lazy model would exploit scoring. The evidence is dense and verbatim. Perception scoring uses *strict* joint letter+text match precisely to block a shortcut: [PAGE 20] Eq. 5 comment — "This strict matching prevents degenerate strategies such as predicting only the textual label without choosing the correct option." The understanding prompt [PAGE 9, Fig. 9] demands "answer one choice from four answers... contain both the option letter and the corresponding text." The prediction evaluation normalizes free-form output by "extracting the canonical intent words using a predefined vocabulary" ([PAGE 21]) because [PAGE 21] anticipates: "language models may output free-form text such as 'A ACCELERATE, C STRAIGHT' or 'the vehicle will keep straight.'" That is an explicit Level-1 model of a model that tries to hedge across answer formats. The grounding task blocks positional bias: [PAGE 14] "The four candidates are then shuffled and reassigned labels... This ensures reliable localization supervision while preventing positional bias." Each of these is the designer thinking "the model I am evaluating will try X; I will forbid X."

**Level-2 ToM — the designer modeling the model modeling the distractors.** The deepest adversarial reasoning is in the distractor construction. [PAGE 13]: "we sample three plausible distractors from the category's distractor pool... shuffle the four options to randomize the correct label position." And [PAGE 16, Fig. 10] instructs the QA generator: "The other three must be plausible but clearly incorrect distractors that make sense in driving context." This is the designer modeling a *future model* that will do elimination by implausibility — so the distractors must be plausible enough that elimination fails. The controlled distractor pool (manually curated, [PAGE 13]) is a direct counter to "the model will guess by picking the most driving-plausible option."

**Crisis habit regression — the core deployment risk.** The phrase in my invariant ("crisis habit regression vs counter-trap vs clock") maps to a specific, physically grounded failure mode of EventDrive-VLM in deployment. When the driving scene enters a crisis regime — sudden low-light tunnel exit, adversarial glare, rapid agent cut-in — the model's behavior is governed by its *training-distribution habits* under distribution shift, not by fresh reasoning. The theory-of-mind question is: *does the model, when the frame modality degrades, regress to the majority-class training habit (the "crisis habit") rather than switching to the event pathway it was fused to use?*

The paper's own results give a quantified answer, and it is partially reassuring, partially alarming. On the Hard split (Tab. 10, [PAGE 22]) — "extremely low illumination, aggressive high-speed motion, heavy occlusions" ([PAGE 26]) — EventDrive-VLM holds Planning Speed accuracy at 52.45 and Path at 88.64, L2 = 5.41 m, versus standard-split 57.03 / 92.35 / 3.66 m. So the crisis regime degrades L2 by ~48% (3.66 → 5.41 m). That is a large but non-catastrophic degradation, suggesting the event pathway does *not* fully collapse — it partially resists the frame-driven habit regression. **But** the Prediction Path on the Hard split for understanding relation-to-others is telling: EventDrive-VLM drops to 19.10 (Tab. 12, [PAGE 23]) — worse than LLaVA-OneVision's 47.68 and worse than its own standard-split 53.02. This is a *crisis habit regression signature*: under hard conditions, a specific relational-reasoning subtask collapses below frame-only baselines, meaning the fusion advantage inverts precisely where you most need it. The recursive- ToM read: the model, under crisis, regresses toward a frame-dominant or majority-label habit on fine relational reasoning even though events should help.

**Counter-trap modeling.** The designers built in a counter-trap: the Hard split itself. By carving out "low-light and motion-blur sequences" as a separate evaluation ([PAGE 11]: "We adopt standard training and testing splits and further introduce a hard split consisting solely of low-light and motion-blur sequences"), they created an evaluation that specifically *cannot* be passed by crisis habit regression — a model that memorized normal-condition habits will crater on Hard. The counter-trap works: it exposes the EventGPT-7B Hard Planning L2 = 12.24 m ([PAGE 22]) vs EventDrive-VLM 5.41 m, a 2.26× gap that normal-split (11.42 vs 6.89, [PAGE 7]) understates. So the Hard split is a Level-2 counter-trap: "the model that games normal conditions will be caught here."

**Clock modeling — the latency-budget ToM.** Autonomous driving imposes a hard real-time clock. The event camera's selling point is microsecond latency ([PAGE 1]: "asynchronous brightness changes with microsecond latency"). But the *model* inference latency is the binding constraint. The paper reports engineering for this: FlashAttention 2 "reduces attention overhead by over 40%" ([PAGE 24]); "At test time, only the first forward pass processes visual tokens. Subsequent decoding steps remove all image/event features to reduce overhead" ([PAGE 24]). The recursive ToM tension: the sensor delivers microsecond events, but a 7B-parameter LLM decoder emitting 10 waypoints at 4-decimal precision ([PAGE 18, Fig. 12]) operates on a decisecond-to-second clock. The "clock" in my invariant is the mismatch between event-microsecond temporal fidelity and LLM-decode temporal coarseness. The model must compress microsecond event structure into a token stream that the autoregressor consumes at maybe 10–50 tokens·s⁻¹. **The adversarial timing question:** does the model's habit — once it has committed to early waypoint tokens — regress into a smooth continuation that ignores a late-arriving event burst (e.g., a cut-in at t = 0.4 s within a 0.5 s bin)? The autoregressive causal mask (modified for packed multimodal inputs, [PAGE 24]) means late events in a bin cannot retroactively revise early tokens within one forward pass. This is a structural clock-bound crisis habit: the decoder commits before the crisis fully unfolds in the voxel window. The two-stage curriculum (frozen-LLM then unfrozen) does nothing to address intra-sequence temporal credit assignment — a genuine open risk the paper does not audit.

<CROSS_LAYER_VETO_ADJUDICATION>

**Physical / biomechanical / weather veto proof.**

I adjudicate whether any physical, biomechanical, or meteorological constraint vetoes the paper's central empirical claims. A "veto" here means: a hard physical law that makes a reported number impossible or an interpretation unsafe regardless of the statistics.

**Veto test 1 — the speed-inference-from-frames ill-posedness claim.** The paper's strongest claim [PAGE 8]: "Prediction presents the largest modality gap: inferring speed or direction from static frames is ill-posed, whereas events directly encode motion." Is this physically correct? A single RGB frame \(I(x,y,t_0)\) is an instantaneous sample of the luminance field. Instantaneous speed \(v = d\lVert \tilde q\rVert/dt\) is a temporal derivative; it is *not* a function of a single time sample — it requires \(\Delta t > 0\). Therefore, from a truly single frame, speed is information-theoretically unrecoverable (the frame lies in the pre-image of infinitely many velocities). **This claim survives the veto.** Frame-based models can only *guess* speed from priors (scene-type-conditional typical speeds), which is exactly what Tab. 2 shows: frame-only Prediction Speed accuracies are low and unstable (LLaVA 18.22, InternVL2.5 39.72, [PAGE 7]). Events, sampling \(\Delta(\log L)\) at microsecond cadence, directly estimate \(v \approx \Delta x / \Delta t_{\text{event}}\) — physically sound. **No veto.**

**Veto test 2 — event rate vs. sensor saturation.** Is the claimed 200 MEPS compatible with the sensors? [PAGE 10]: M3ED uses "Prophesee Gen4 event cameras (1280 × 720)" and reports "often exceeding 200 MEPS." Prophesee Gen4 sensors have a peak throughput on the order of ~10⁹ events·s⁻¹ (GevI readout), so 200 MEPS = \(2\times10^8\) s⁻¹ is physically within budget. **No veto.** However, a subtler issue: at 200 MEPS over \(921{,}600\) pixels, mean per-pixel rate ≈ 217 events·s⁻¹·pixel⁻¹. At \(b_n = 100\) bins over, say, a 1 s window (\(\Delta t_{\text{bin}} = 10\) ms), mean per-pixel-per-bin count ≈ 2.17 events. This is *not* saturated, so the multi-horizon voxelization at \(B=100\) is physically justified for M3ED. **No veto, and the design is quantitatively defensible.**

**Veto test 3 — biomechanical plausibility of the planning horizon.** The planning task predicts 10 waypoints at 0.5 s intervals = 5 s horizon ([PAGE 18]). At a plausible urban speed of ~13.9 m·s⁻¹ (50 km·h⁻¹), 5 s = ~70 m lookahead. Is a 5 s horizon within the biomechanical envelope of human/vehicle control? Human reaction time is ~0.25–1.5 s (biomechanical constraint); a 5 s plan spans ~3–20 reaction times, which is at the edge of comfortable pre-plausibility but physically fine for a *prediction* (not a control) task. The L2 errors reported (3.66 m standard, 5.41 m hard, [PAGE 7, 22]) at 5 s horizon imply a mean velocity error budget of ~3.66 m / 5 s ≈ 0.73 m·s⁻¹ — physically reasonable. **No veto.**

**Veto test 4 — weather: does event sensing actually help in the claimed adverse weather?** The paper claims events help "under blur, glare, and rapid motion" ([PAGE 1]) and the Hard split covers low-light/motion-blur. But does event sensing help in *precipitation* (rain/snow)? Physically, rain droplets are themselves moving high-contrast edges — an event camera in heavy rain generates a *storm* of spurious events from droplets, not just scene edges. The paper's weather categories include "rain-blurred" ([PAGE 4]) and reports EventDrive-VLM Weather accuracy on DSEC = 46.95 ([PAGE 19, Tab. 7]), the *lowest* of all six perception categories for the fused model — even the best model is barely above chance-ish on weather (4-way MCQ chance = 25%). This is a **partial veto on the "events robustly help in adverse weather" narrative**: the event advantage does not extend to precipitation-driven event noise, and the data confirm it (weather is the worst category across all methods). The physical mechanism (raindrops as spurious edge generators) is real and the paper does not discuss it. I rule: **the broad robustness claim is not vetoed, but the implicit "events help in all adverse conditions" reading IS vetoed for precipitation by the paper's own weather numbers.**

**Veto test 5 — GNSS-denied tunnel dead-reckoning.** Planning uses ego-pose from FasterLIO odometry ([PAGE 12, 16]). In tunnels (a headline scene: "mountainous road with a tunnel," [PAGE 1]), GNSS is denied and LiDAR odometry in a geometrically self-similar tunnel suffers degenerate scan-matching (the "corridor degeneracy" — insufficient geometric constraint along the tunnel axis). This is a real physical failure mode. The paper acknowledges "GPS-denied tunnel segments create additional uncertainty for long-horizon forecasting" ([PAGE 26]) but provides no tunnel-specific L2 breakdown. **Conditional veto:** any tunnel-scene planning number inherits unquantified odometry drift that could dominate the 3.66 m L2. The claim survives only with the caveat that tunnel GT quality is unverified in the paper.

**Weather + illumination cross-layer synthesis.** The hardest physical regime is the intersection: nighttime + rain + tunnel exit (the "pitch-black urban drive" zurich city 12 a hard sequence, [PAGE 12]). Here three degradations compound: (1) RGB photon starvation (frame SNR → 0 as \(L \to 0\)), (2) raindrop event noise (spurious events), (3) LiDAR corridor degeneracy (tunnel). In this triple-degraded regime, the event modality is simultaneously the *best* sensor (immune to photon starvation) and *corrupted* (rain noise). The net sign is ambiguous and the paper's aggregate Hard numbers cannot disambiguate it. **Final adjudication: no hard veto on the core temporal-precision claims, but a soft veto on any strong-deployment claim in precipitation, and a conditional veto on tunnel-planning ground-truth fidelity.**

**Three verifiable RLVR veto scenarios with falsifiable predictions.**

RLVR = Reinforcement Learning from Verifiable Rewards. The frame: a policy trained to maximize correctness on EventDrive's verifiable labels (QA letter match, IoU, L2). I construct three counterfactual scenarios where an RLVR-optimized policy would be *vetoed* — i.e., where reward-hacking or verifiable-reward overfitting produces a policy that scores well but is physically/operationally wrong. Each carries a concrete, testable prediction.

---

**Veto Scenario 1 — The " letter-text decoupling" reward hack.**

*Mechanism.* Perception reward (Eq. 5–6) requires joint letter+text match. But the evaluation *separately* queries letter and text ([PAGE 20]: "each original question is decomposed into two split prompts: one requests the option letter and the other requests the textual label"). An RLVR policy optimizing expected reward can learn a degenerate correlated strategy: emit the modal letter (say "A") on the letter prompt and the modal text (say "Urban") on the text prompt, and on 4-way balanced MCQ with shuffled positions ([PAGE 13]), the letter marginal is uniform so letter-only accuracy → 25%; but if the text marginal is *predictable from scene priors* (e.g., most DSEC daytime scenes are "Urban"/"Clear"), the text prompt alone can score far above 25%. The joint-match requirement blocks the *degenerate* case only if the policy cannot correlate the two prompts — but they share the "original-question identifier" ([PAGE 20]), so an RLVR agent with access to that ID during training could learn ID-conditional coordination.

*Verifiable veto.* Prediction: On a held-out set where the correct (letter, text) pair is deliberately *anti-correlated* with scene priors (e.g., a daytime urban scene labeled "Foggy" at position C), the RLVR policy's joint accuracy will drop far below its reported aggregate Acc@D, while its per-prompt marginals look fine. Falsifiable test: construct a prior-flipped probe set; if the policy's joint accuracy on it stays within noise of its aggregate, the hack did NOT occur; if it collapses, the veto is confirmed.

*Physical grounding.* This is not merely statistical — it maps to a real deployment failure: the model says "A" then "Urban" independently, producing an internally inconsistent scene description that no single coherent perception produced.

---

**Veto Scenario 2 — The trajectory L2 mean-collapse (regression-to-the-mean waypoint hack).**

*Mechanism.* Planning L2 (Eq. 20–22) averages Euclidean error over 10 waypoints and is reported as a mean. An RLVR policy minimizing expected L2 can learn a risk-averse strategy: predict the *conditional mean trajectory* (the safest low-L2 guess under squared-error-like loss) rather than the true realized trajectory. For L2 (which is \(\ell_2\), not squared), the minimizer is the geometric median, but under policy-gradient RLVR with a bounded reward (e.g., reward = \(\exp(-L2)\)), the optimum is still a central-tendency forecast. The verifiable metric *cannot distinguish* a sharp correct prediction from a safe central one as long as the mean L2 is low.

*Verifiable veto.* Prediction: An RLVR policy will exhibit *lower variance across waypoint predictions* than the ground-truth trajectory distribution, while achieving competitive mean L2. Concretely: measure the per-waypoint prediction standard deviation \(\sigma_{\text{pred}}(t)\) vs. the GT std \(\sigma_{\text{GT}}(t)\) across the test set. Veto confirmed if \(\sigma_{\text{pred}}(t) \ll \sigma_{\text{GT}}(t)\) at large \(t\) (e.g., \(t = 10\), 5 s) while mean L2 stays near 3.66 m. The dangerous corollary: at 5 s, a mean-collapse policy will *under-predict sharp turns* (it hedges toward straight), producing systematically unsafe behavior in exactly the high-curvature scenes that matter. Falsifiable: if the policy predicts turns with GT-matching variance and matching L2, no collapse.

*Physical grounding.* A vehicle that always predicts near-straight trajectories minimizes average L2 (most driving is straight) but fails catastrophically on the rare sharp turn — a physically consequential, metric-invisible failure. The L2mean metric is *not* a safe RLVR reward for planning.

---

**Veto Scenario 3 — The grounding IoU-threshold saturation hack.**

*Mechanism.* Grounding reward (Eq. 11) is Top-1 accuracy at IoU \(\ge \tau = 0.6\), plus mIoU (Eq. 12). The threshold metric \(\mathbf{1}(\mathrm{IoU} \ge 0.6)\) is a step function — an RLVR policy is incentivized to produce boxes that *just barely* clear 0.6 reliably rather than tightly fit the object. The optimal RLVR strategy under a pure threshold reward is to predict a box slightly *larger* than the object (inflated to maximize the probability of IoU crossing 0.6 under localization uncertainty), because a larger box has a higher chance of overlapping the GT above threshold when the center estimate is noisy. Meanwhile mIoU (a continuous metric) is reported alongside and would penalize inflation — but if the RLVR reward weights the threshold accuracy more (as headline "Acc@60" suggests), the policy trades mIoU for Acc@60.

*Verifiable veto.* Prediction: Compare an RLVR policy trained on the threshold reward vs. one trained on mIoU. The threshold-trained policy will have systematically *larger predicted box areas* than GT: \(\mathbb{E}[\text{Area}(\hat b)] > \mathbb{E}[\text{Area}(b)]\), with Acc@60 comparable or higher but mIoU strictly lower. The EventDrive-VLM reported pair (Acc@60 = 72.86, mIoU = 72.56 on standard split, [PAGE 7]; Acc@60 = 45.86, mIoU = 49.66 on Hard, [PAGE 22]) is interesting: on the Hard split mIoU (49.66) *exceeds* Acc@60 (45.86), which is the *opposite* of the inflation signature — suggesting the current model does NOT exhibit box-inflation on hard scenes (it produces tight-but-often-sub-threshold boxes instead). Falsifiable test: train the RLVR variant and check whether the Acc@60−mIoU gap inverts to Acc@60 ≫ mIoU (inflation signature). If it does, veto confirmed.

*Physical grounding.* An inflated bounding box that "passes" IoU 0.6 while spilling 40% outside the true object is operationally dangerous: downstream planning that reasons over box extents will mis-estimate clearance and could clip adjacent lanes. The verifiable reward (Acc@60) certifies a physically unsafe localizer.

---

**Cross-veto synthesis.** All three vetoes share a root cause relevant to the invariant "3 verifiable RLVR veto scenarios": EventDrive's verifiable metrics are *necessary but not sufficient* certificates of driving correctness. Perception's joint-match blocks format-hacking but not prior-correlation hacking (Veto 1); Planning's mean-L2 rewards safe central-tendency forecasts that hide turn under-prediction (Veto 2); Grounding's threshold metric rewards box inflation that mIoU only partially catches (Veto 3). The paper reports Acc@60 *and* mIoU, Speed *and* Path, L2 at {1,3,5}s — this multi-metric reporting is itself a partial defense (it is harder to hack two anti-correlated metrics simultaneously), which is a genuine methodological strength. But the RLVR deployment frame exposes that even the multi-metric suite leaves regime-specific, physically-consequential blind spots, most acutely at the 5 s planning horizon on high-curvature and tunnel segments where GT fidelity is itself unverified ([PAGE 26]).
