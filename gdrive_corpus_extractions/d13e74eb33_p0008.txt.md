If T_compute > τ_max, where T_compute is measured in seconds and τ_max is a fixed engineering constant (e.g., 0.2 seconds), the physical layer vetoes personalized scoring and serves a static cache of popular items. This veto is deterministic and monotonic: higher N_i or denser neighborhoods increase T_compute linearly, so the veto condition is a hard boundary in compute time, not a probabilistic threshold.

Biomechanical layer veto: Human visual search and clicking obey bounded working memory and Hick's Law, where decision time grows with the logarithm of choice count. The visible UI on [PAGE 1] displays exactly five items. A biomechanical veto triggers if the candidate list exceeds the cognitive channel capacity, approximately seven plus or minus two chunks, conservatively capped at nine items. If N_display > 9, the layer vetoes the excess items to prevent abandonment. Units: decision time in seconds; cognitive load in chunks. This veto operates independently of content relevance; it is a human-interface constraint.

Weather/exogenous context layer veto: Although the item domain is digital books and music, seasonal context acts as an exogenous veto on category relevance. For example, recommending a seasonal travel guide in a climate or calendar window mismatched to the user's location yields near-zero click-through because the item is physically unusable or irrelevant. The veto is a boolean context match: if category c is incompatible with the current weather or season vector w, then all items in c are suppressed. Units: categorical boolean, dimensionless.

Adjudication hierarchy and proof: The veto chain is ordered by physical latency first, biomechanical capacity second, and exogenous context third. Proof: if T_compute > τ_max, no personalized list exists to display, so biomechanical and weather layers are moot. If T_compute ≤ τ_max but N_display > 9, the list is truncated before weather filtering can meaningfully apply. Weather veto applies only after the first two layers pass. Because each veto condition is expressed in SI units (seconds, chunks, categorical match) and the hierarchy is a strict total order on layer priority, the system avoids hidden trade-offs where a weather match could justify exceeding latency or cognitive caps. No betting lines, spreads, moneylines, or odds are invoked in this adjudication.

<RLVR_COUNTERFACTUAL_VETOES>
RLVR denotes reinforcement learning with verifiable rewards; the veto rules below are verifiable through logged interaction metrics (click-through rate, precision@k, conversion rate, coverage) without reference to betting lines or odds.

Scenario 1: Cold-start item veto. Rule: If item i has interaction count n_i < k_min with k_min = 5, veto item-item similarity computation for i and exclude i from personalized recommendation slots. Counterfactual: In the no-veto world, cold items enter the candidate pool with noise-dominated similarity vectors. Prediction: CTR for cold-item slots falls to the global background rate because the affinity signal is indistinguishable from random; precision@5 for warm items increases by a positive margin δ_p, while catalog coverage decreases by N_cold / N_i. Verifiable by A/B testing k_min = 5 versus k_min = 0 over a four-week window and measuring precision@5 and coverage.

Scenario 2: Co-rated user singularity veto. Rule: For candidate pair (i,j), if |U_{ij}| = 0, set sim(i,j) to undefined and veto propagation of score from item i to item j. Counterfactual: Without the veto, the system imputes sim(i,j) = global mean similarity. Prediction: The imputation injects spurious cross-category links (for example, connecting a technical book to a romance novel solely because both are sparse), degrading precision@10 by ε_impute > 0. The veto preserves precision but reduces the effective edge count in the item graph. Verifiable by isolating item pairs with zero co-rated users in a holdout set and comparing rank precision between vetoed and imputed conditions.

Scenario 3: Stale user profile veto. Rule: If Δt_since_last_interaction > T_stale with T_stale = 4 weeks, veto personalized ranking and serve non-personalized category bestsellers. Counterfactual: Stale users retain personalized scores computed from an old profile vector. Prediction: Conversion rate for the no-veto stale group decays approximately as exp(−λ·Δt) with λ > 0 because the profile no longer reflects current taste, whereas the vetoed group converts at the flat bestseller baseline with lower variance. Verifiable by logging last_interaction timestamps, segmenting users at Δt = 4 weeks, and comparing conversion rates under veto versus no-veto over a six-week observation window. All three scenarios produce falsifiable predictions in observable units (CTR, precision, conversion) and contain no odds or betting terminology.
