The source’s central move is to separate evidence interpretation from evidence aggregation. The task tuple is \(T=(q,t_{\text{freeze}},\tau,O)\), where \(q\) is the question, \(t_{\text{freeze}}\) is the information cutoff, \(\tau\) is the output type, and \(O\) is an optional option set [PAGE 4]. The evidence set is \(E=\{e_1,\dots,e_n\}\), and the prediction stage must map \((T,E)\) to a forecast without further retrieval [PAGE 4]. Monolithic Prediction instead reads \((T,E)\) together in one prompt and emits \(f\) in a single pass. The paper’s stated failure mode is that this “can obscure how individual evidence items affect the result and collapse uncertainty across competing outcomes” [PAGE 1]. LEAP reorganizes the prediction stage: “Rather than asking the LLM to forecast from the full evidence bundle, LEAP uses it as a local interpreter” [PAGE 2]. That sentence is the hinge. The LLM is not the final probabilistic computer; it is a local elicitation device that returns likelihood parameters, while a deterministic conjugate update performs the posterior calculation.

The multi-hop derivation is therefore: first, define a prior \(P_0(\theta)\) and per-evidence likelihood factors \(P_i(e_i\mid\theta)\); second, assume conditional independence \(e_i\perp e_j\mid\theta\); third, form \(P(\theta\mid E)\propto P_0(\theta)\prod_{i\in R}P_i(e_i\mid\theta)\) over a retained set \(R\); fourth, read out the forecast as quantiles, categorical probabilities, or Bernoulli marginals; fifth, compute leave-one-out contributions \(\Delta_j\). The critical audit property is not that the LLM explanation is persuasive, but that \(\Delta_j\) is reproducible by rerunning the deterministic update on \(R\setminus\{j\}\) [PAGE 5][PAGE 13]. The paper states the design goal directly: “The LLM never makes the final prediction; it only produces likelihood parameters” [PAGE 6].

The gray-zone audit has several layers. First, conditional independence is a working assumption, not a discovered fact. The paper admits that “duplicated or common-source evidence can violate this” and responds with dependency clustering [PAGE 4-5]. But clustering depends on an LLM-returned dependency key, and canonicalization only handles surface variation such as lowercasing, stopword removal, token sorting, and delimiter joining [PAGE 13-14]. It does not prove semantic independence. If a syndicated report is paraphrased under a different key, the posterior can still double-count the same underlying signal. Second, reliability sampling measures agreement across repeated local queries, not truth. A consistently wrong local interpretation can be reliably wrong. Third, the prior call is forbidden from conditioning on specific evidence because “letting the prior call read evidence would count that evidence twice in Equation (4)” [PAGE 5]. But prompt-level blindness is not a formal guarantee against background leakage. Fourth, outlier rejection is only for continuous targets with a data-derived prior: “An item whose elicited mean lies more than four standard deviations of the prior away from \(\mu_0\) is excluded from \(R\)” [PAGE 14]. If the prior itself is misspecified, this rule can veto valid evidence. If the prior is blind, the rule is not applied, so there is no numerical anchor.

The singularity regimes are equally important. For continuous targets, \(\tau_i=1/\sigma_i^2\). If \(\sigma_i\to0\), then \(\tau_i\to\infty\), and one evidence item can dominate the posterior; if two zero-variance likelihoods disagree at different means, the product is zero everywhere and the posterior is undefined. The engineering map clamps relative standard deviation \(r_i\) to \([0.03,1.25]\), which prevents literal zero variance but not practical domination [PAGE 14]. If \(\eta\to0\), the likelihood product is suppressed and the posterior collapses toward the prior; if \(\eta\to\infty\), the posterior is driven by the likelihood product and can become overconfident. Table 5 shows empirically that \(\eta=1.0\) has ECE \(0.0876\), while \(\eta=0.5\) gives \(0.1012\) and \(\eta=2.0\) gives \(0.1094\) [PAGE 9]. For categorical targets, log-space aggregation avoids underflow, but \(\log L_i(k)=-\infty\) is still a hard exclusion; if every option receives \(-\infty\), normalization is undefined. For multi-choice targets, independent Bernoulli updates ignore correlations among options. Thus LEAP’s auditability is real but bounded: it exposes evidence-level influence under a model, not causal identification of the evidence’s truth.
</THINK_TRACE>

<SOURCE_OPERATORS_AND_EQUATIONS>
The source defines the forecasting tuple and evidence set as
\[
T=(q,t_{\text{freeze}},\tau,O),\qquad E=\{e_1,\dots,e_n\},
\]
where usable information must be timestamped no later than \(t_{\text{freeze}}\), and \(\tau\) is continuous, single-choice, or multi-choice [PAGE 4]. The Bayesian model is
\[
\theta\sim P_0(\theta),\qquad e_i\mid\theta\overset{\text{indep}}{\sim}P_i(e_i\mid\theta),\qquad i=1,\dots,n,
\]
with the working conditional-independence assumption \(e_i\perp e_j\mid\theta\) for \(i\ne j\) [PAGE 4]. For a retained subset \(R\subseteq\{1,\dots,n\}\), the unweighted posterior is
\[
P(\theta\mid E)\propto P_0(\theta)\prod_{i\in R}P_i(e_i\mid\theta).
\]
The paper states: “The prior \(P_0\) encodes a base rate for \(\theta\) before any evidence is examined” [PAGE 4]. It also states: “The LLM estimates parameters of \(P_0\) and each \(P_i\); it does not output a forecast over \(\theta\)” [PAGE 5]. The isolation condition is explicit: “Each evidence item \(e_i\) is sent to the LLM in isolation: the model sees \(T\) and exactly one evidence item, never other sources, accumulated evidence, or partial posteriors” [PAGE 5].

For continuous targets, the conjugate Gaussian update uses
\[
\theta\sim\mathcal N(\mu_0,\sigma_0^2),\qquad \tilde L_i(\theta)\propto\mathcal N(\theta;\mu_i,\sigma_i^2),
\]
with precision \(\tau_x=1/\sigma_x^2\). The tempered posterior has
\[
\tau_{\text{post}}=\tau_0+\eta\sum_{i\in R}\tau_i,
\qquad
\mu_{\text{post}}=\frac{1}{\tau_{\text{post}}}\left(\mu_0\tau_0+\eta\sum_{i\in R}\mu_i\tau_i\right).
\]
The forecast reports quantiles of \(\mathcal N(\mu_{\text{post}},1/\tau_{\text{post}})\), and the per-evidence contribution is
\[
\Delta_j=\mu_{\text{post}}-\mu_{\text{post}}^{(-j)},
\]
where \(\mu_{\text{post}}^{(-j)}\) is recomputed over \(R\setminus\{j\}\) [PAGE 13]. Units: \(\mu_0,\mu_i,\mu_{\text{post}},\Delta_j\) are in target units \(u\); \(\sigma_0,\sigma_i\) are in \(u\); \(\tau_0,\tau_i,\tau_{\text{post}}\) are in \(u^{-2}\); \(\eta\) and \(w_i\) are dimensionless.

For single-choice targets, with categorical prior \(\pi_0\in\Delta^{K-1}\) and likelihoods \(L_i(k)=P(e_i\mid\theta=k)\),
\[
\log\pi_{\text{post}}(k)\propto \alpha\log\pi_0(k)+\eta\sum_{i\in R}w_i\log L_i(k),
\]
followed by softmax normalization. The per-evidence contribution is
\[
\Delta_j=\pi_{\text{post}}(\hat k)-\pi_{\text{post}}^{(-j)}(\hat k),
\qquad
\hat k=\arg\max_k\pi_{\text{post}}(k)
\]
[PAGE 13]. Probabilities are dimensionless; if logarithms are natural, log-likelihood terms are in nats; \(\alpha,\eta,w_i\) are dimensionless.

For multi-choice targets, with independent Bernoulli prior \(\pi_0(k)\) and per-evidence pair \((p^{\text{true}}_{i,k},p^{\text{false}}_{i,k})\),
\[
\ell_i(k)=\log\frac{p^{\text{true}}_{i,k}}{p^{\text{false}}_{i,k}},
\qquad
\operatorname{logit}\pi_{\text{post}}(k)=\operatorname{logit}\pi_0(k)+\eta\sum_{i\in R}w_i\ell_i(k),
\]
and \(f_k=\sigma(\operatorname{logit}\pi_{\text{post}}(k))\), not constrained to sum to one. The contribution is
\[
\Delta_j=\sum_{k=1}^K\left|\pi_{\text{post}}(k)-\pi_{\text{post}}^{(-j)}(k)\right|
\]
[PAGE 13]. The log-likelihood ratio \(\ell_i(k)\) is in nats under natural log; \(\Delta_j\) is dimensionless.

The paper’s safeguards alter these equations only through \(R\), \(w_i\), and \(\sigma_i\). Dependency clustering retains one representative per common-source group; reliability sampling shrinks likelihood magnitudes toward less extreme values; outlier rejection excludes a continuous item when its elicited mean is more than four prior standard deviations from \(\mu_0\), but not when the prior is blind to evidence [PAGE 6][PAGE 14]. The metadata map initializes relative standard deviations \(r_i\) at 0.08, 0.18, or 0.45 for direct-target, proxy-signal, and other/context scope, then multiplies by factors for observation type, source tier, strength, reliability, target match, and recency, with final clamp \(r_i\in[0.03,1.25]\) [PAGE 14].

Breakdown regimes are formal. If \(\sigma_i\to0\), then \(\tau_i\to\infty\); the posterior can collapse onto one item, and contradictory zero-variance factors make the product zero everywhere. If \(\eta\to0\), the posterior approaches the prior term; if \(\eta\to\infty\), the posterior approaches the likelihood product and can become brittle under misspecification. If \(L_i(k)=0\) for an option, \(\log L_i(k)=-\infty\) excludes that option; if all options are excluded, softmax is undefined. If evidence items are dependent but unclustered, the product overcounts shared information and inflates precision or log-posterior magnitude. If the prior is misspecified, the posterior is biased, and outlier rejection can discard valid evidence that disagrees with a bad prior. The paper’s own ablation confirms the prior’s importance: “Removing the prior drops FutureX below Monolithic (0.643 versus 0.651) and raises ECE to 0.213” [PAGE 8]. Dependency clustering removal “lowers FutureX by 1.9 points and raises ECE from 0.088 to 0.158” [PAGE 8]. Reliability sampling removal “lowering FutureX to 0.714 and raising ECE to 0.122” [PAGE 8]. The method also costs more inference: “LEAP also uses more inference calls than Monolithic, since evidence items are interpreted separately and may be sampled more than once for local verification” [PAGE 10].
</SOURCE_OPERATORS_AND_EQUATIONS>

<RETROCAUSAL_GENEALOGY>
The lineage is Bayesian inverse inference plus proper scoring and faithful explanation. The conjugate Gaussian-normal, categorical-multinomial, and independent Bernoulli constructions are classical Bayesian updating; the paper’s novelty is not the algebra but the placement of LLM judgments inside the algebra. The scoring lineage is explicit: Brier score [PAGE 7], spherical score and CRPS/NCRPS from Gneiting and Raftery [PAGE 7], calibration diagnostics following Guo et al. [PAGE 7]. The auditability lineage is ERASER-style rationalized evaluation and faithful chain-of-thought: a rationale is more trustworthy when coupled to the computation that produces the answer, rather than written after the fact [PAGE 3]. The retrieval/agent lineage is also explicit: retrieval-augmented generation, passage retrieval, WebGPT, ReAct, decomposition, tool use, and agent benchmarks such as GAIA and BrowseComp [PAGE 3]. The forecasting lineage includes AutoCast, AutoCast++, ForecastBench, Prophet Arena, FutureX, and LLM ensemble forecasting [PAGE 2-3]. The LLM-assisted Bayesian lineage includes BIRD, Nafar et al., and the Bayesian Linguistic Forecaster [PAGE 2-3].

Retrocausally, the paper’s design is a response to failures that were already visible before LEAP: long-context underuse, hallucination relative to supplied sources, unsupported factual claims in long outputs, and monolithic overconfidence [PAGE 3]. The “retrocausal” trap is that a later audit can make an earlier forecast look more justified than it was. LEAP’s \(\Delta_j\) is a defense only if the evidence set and \(t_{\text{freeze}}\) are frozen. If an auditor recomputes after new evidence appears, the posterior changes and the apparent contribution of an old item changes. The paper’s temporal leakage audit is therefore essential: it checks every retrieved page timestamp against \(t_{\text{freeze}}\) and reports “no cutoff violations and no suspected leakage cases” in the audited snapshots [PAGE 15-16].

Multi-week traps are horizon traps. The paper reports that as the horizon between evidence collection and resolution lengthens, “All four curves rise monotonically” for LEAP’s improvement over Monolithic, with FutureX gain rising from 6.8 to 11.9 points and the overconfidence gap widening from 13.3 to 23.3 points [PAGE 7]. The interpretation is not that LEAP becomes more accurate in absolute terms; it is that Monolithic “continues to commit firmly to a single option, while LEAP recognises weaker support in \(E\) and produces wider posteriors—degrading by becoming conservative rather than confidently wrong” [PAGE 7]. Over multi-week horizons, three traps recur: stale priors, syndicated duplicate evidence, and horizon-dependent calibration drift. A data-derived prior can be stale by the time of resolution; a common-source report can be reprinted across many pages and inflate the posterior if dependency keys fail; and calibration that is adequate at seven days may be overconfident at sixty days if \(\eta\) and likelihood strengths are not rechecked. The paper’s diagnostic subset is only 60 tasks and uses GPT-5.4-mini for the horizon analysis, so the multi-week conclusion is a controlled benchmark result, not a universal law [PAGE 14].

Another retrocausal trap is the “audit trail fallacy”: because \(\Delta_j\) is reproducible, a user may treat it as causal proof that evidence \(j\) caused the forecast. It is not causal; it is a leave-one-out sensitivity under the model. If two evidence items are correlated, their individual \(\Delta_j\) values can be small while their joint effect is large, or both can appear influential because each removal changes the posterior. The paper’s own component ablation shows that removing dependency clustering raises ECE from 0.088 to 0.158, which is exactly the signature of overcounted shared source information [PAGE 8]. The correct genealogy is therefore: Bayes gives the update; proper scoring gives the evaluation; faithful explanation gives the audit norm; and the paper’s contribution is to make the LLM a local parameter estimator rather than a global narrator.
</RETROCAUSAL_GENEALOGY>

<RECURSIVE_THEORY_OF_MIND>
In crisis, the Monolithic habit regresses to a single confident answer. The paper’s Figure 1 contrast is exactly this: Monolithic is “Holistic, high-confidence, hard to audit,” while LEAP exposes per-evidence support and a posterior distribution [PAGE 1]. The recursive theory-of-mind issue is that the LLM is asked to model the forecasting problem, the aggregator is asked to model the LLM’s local reliability, and the user is asked to model the aggregator’s audit. Each level can fail. At the LLM level, the local interpreter may overread one passage; at the aggregator level, reliability sampling may mistake consistency for correctness; at the user level, a clean \(\Delta_j\) table may be mistaken for truth. LEAP’s counter-trap is procedural: do not ask the LLM for the final answer; ask it for likelihood parameters, then let a deterministic model combine them [PAGE 5-6]. The paper states the safeguard against prior contamination directly: “The prompt forbids conditioning on specific evidence, since the prior should record a base rate before evidence is examined” [PAGE 5].

The clock is \(t_{\text{freeze}}\). Recursive forecasting must distinguish what the model knew at the cutoff from what the auditor knows after resolution. The paper enforces this with temporal isolation: retrieval is restricted to material available no later than the task timestamp, base models are chosen so their knowledge cutoffs precede evaluated timestamps, and a temporal leakage audit checks every retrieved page against \(t_{\text{freeze}}\) [PAGE 6][PAGE 15-16]. This clock discipline matters more than any single prompt. If the clock is violated, the posterior can look calibrated for retrocausal reasons. If the clock is respected, a wider posterior is not a failure; it is an honest representation of weak evidence.

The counter-trap is adversarial duplication. An attacker or careless pipeline can inject the same underlying report under several surface forms. LEAP’s dependency clustering is designed to retain one representative per common-source group [PAGE 6], and canonicalization handles “different word order, hyphenation, or stopwords” [PAGE 13-14]. But an adversary can paraphrase the dependency key semantically while preserving the source. Then the posterior overcounts, and the recursive model of the attacker–aggregator interaction fails. The defense is not another LLM call; it is source-key verification and domain clustering checks. Table 13 shows the tradeoff: no clustering gives ECE \(0.1578\), source-key clustering gives \(0.0876\), and domain clustering gives \(0.0798\) while retaining only 72.6% of evidence [PAGE 19]. The clock also interacts with reliability sampling: repeated local queries at different times may see different evidence, so the samples are only exchangeable if the evidence item is fixed. The paper’s reliability sampling is applied to the same \((T,e_i)\), not to a changing evidence stream [PAGE 6].

The deepest recursive point is that LEAP changes the user’s model of the model. A Monolithic forecast invites “Why this answer?” with no isolable answer. LEAP invites “Which evidence item moved the posterior, and by how much?” The paper’s case studies make this concrete: in one case, “Grave slabs identification \(\Delta=+0.249\), Christ Church search \(\Delta=-0.248\), Maps summary \(\Delta=+0.190\)” [PAGE 19]. That is an audit signal, not a proof. The user must still ask whether the evidence itself is valid, whether the dependency clustering is correct, and whether the prior is appropriate. The counter-trap is therefore over-trusting the audit. The correct recursive stance is: trust the arithmetic conditional on the elicited parameters; verify the parameters and the evidence; and keep the clock fixed.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
The source contains no physical, biomechanical, or weather model. LEAP’s probability space contains \(\theta\) and \(E\); it does not contain a physical state variable \(X_{\text{phys}}\), a biomechanical state \(X_{\text{bio}}\), or a weather state \(X_{\text{weather}}\). Therefore, any claim that LEAP “proves” a physical, biomechanical, or weather veto is out of model. Formally, if an external constraint \(C(X)\) is not a factor in \(P_0(\theta)\prod_i P_i(e_i\mid\theta)\), then \(P(\theta\mid E)\) is invariant to \(C\) unless \(C\) changes \(E\), \(P_0\), or some \(P_i\). LEAP can record a constraint only as evidence or as a likelihood parameter; it cannot adjudicate the constraint’s physical validity.

The only in-model hard-ish veto is statistical outlier rejection for continuous targets with a data-derived prior. The paper states: “An item whose elicited mean lies more than four standard deviations of the prior away from \(\mu_0\) is excluded from \(R\) as a likely elicitation error” [PAGE 14]. In the expanded audit trace, the rule fires as
\[
z=\frac{|190.00-250.74|}{7.5222}=8.07>4,
\]
so the item is rejected [PAGE 19]. That is a statistical veto, not a physical one. It catches unit mismatch, stale memory, or confused asset reference, but it does not prove that a weather event is impossible or that a biomechanical claim is invalid. If the prior is blind to evidence, the rule is not applied, so there is no numerical anchor for a veto [PAGE 14].

For a true cross-layer veto, an external verifier must intervene before elicitation: remove the invalid evidence, replace it with a verified constraint, or set a likelihood that is effectively zero for incompatible \(\theta\). But exact zero likelihoods create singularities: if all options receive zero likelihood, the posterior is undefined; if one option receives zero, the log-space update sends it to \(-\infty\). The paper’s calibration table avoids exact 0/1 for most paths, using base values such as 0.99/0.01 for deterministic verifier support and 0.90/0.08 for direct option results [PAGE 14]. Thus LEAP’s practical behavior is soft veto, not absolute veto. Weather and biomechanics should be treated as external evidence layers with their own verification; LEAP can aggregate their implications, but it cannot supply the physical proof. The paper’s limitations support this reading: if evidence is “sparse, outdated, or only weakly relevant, LEAP will usually express that uncertainty in a wider posterior rather than recover information that was never retrieved” [PAGE 9]. That is not a physical veto; it is calibrated uncertainty.
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
A verifiable veto is a deterministic check that accepts or rejects a LEAP configuration by recomputing an observable quantity. Three such counterfactual vetoes follow.

1. Duplicate-evidence injection veto. Intervention: duplicate a high-support evidence item under a paraphrased dependency key that canonicalization does not collapse. Under the product update, the duplicate adds another \(\log L_i(k)\) term in the categorical case or another \(\tau_i\) term in the continuous case. Prediction: the posterior becomes sharper than the evidence warrants; ECE rises relative to source-key clustering. Empirical anchor: “No clustering” gives ECE \(0.1578\), FX \(0.7089\), Brier \(0.2299\); source-key clustering gives ECE \(0.0876\), FX \(0.7284\), Brier \(0.2057\) [PAGE 19]. Veto rule: if a new item has no new source key but changes \(\Delta_j\) materially, reject it or force source-key clustering. Prediction under veto: the duplicate is excluded from \(R\), its leave-one-out contribution is zero, and the posterior remains at the clustered value.

2. Prior-ablation veto. Intervention: remove the prior from LEAP. The posterior update loses its base-rate anchor. Prediction: structured likelihood aggregation alone falls below Monolithic on the diagnostic subset. The paper reports: “Removing the prior drops FutureX below Monolithic (0.643 versus 0.651) and raises ECE to 0.213” [PAGE 8]. Full LEAP on the same subset gives FutureX \(0.7284\) and ECE \(0.0876\) [PAGE 8]. Veto rule: reject any deployment variant that claims LEAP reliability while omitting the prior or using an evidence-contaminated prior. Prediction under veto: re-enabling a blind or data-derived prior restores the ordering and lowers ECE toward the full-LEAP value.

3. Unit-mismatch outlier veto. Intervention: include the E12 analyst target price with \(\mu_i=190.00\), \(\sigma_i=47.50\), against a data-derived prior \(\mathcal N(250.74,7.5222)\). The verifiable check is
\[
z=\frac{|190.00-250.74|}{7.5222}=8.07>4,
\]
so E12 is rejected [PAGE 19]. If it were retained, the posterior mean would be pulled downward and the audit trace would include a semantically mismatched item. The paper’s expanded trace reports the accepted posterior as \(P(\theta\mid R)=\mathcal N(250.157,5.70312)\) [PAGE 20]. Veto rule: for continuous targets with a data-derived prior, reject any item with \(z>4\). Prediction under veto: the posterior remains near 250.157, and the rejected item is absent from the \(\Delta_j\) table. These three vetoes are verifiable because each depends on a recomputable statistic: a source-key match, a prior-ablation score, or the standardized deviation \(z\).
</RLVR_COUNTERFACTUAL_VETOES>
