The drive source is not a sports document and contains no betting market information; it is a control-theory paper on a reach-set formulation of model predictive control, motivated by coordinated motion of multiple Autonomous Underwater Vehicles. The audit therefore has to reason about dynamical systems, optimization, reachability, value functions, sampling, and real-time computation rather than about event outcomes. The core multi-hop derivation is as follows. First, the paper starts from a long-horizon optimal control problem on [0,T_f], with terminal cost g, running cost l, dynamics \dot{x}=f(t,x,u), control constraint u∈Ω L-a.e., and terminal target x(T_f)∈C_f [PAGE 4]. Second, it invokes the Principle of Optimality to replace the long-horizon problem by a finite-horizon problem whose terminal cost is the value function V(t+T,x(t+T)) plus the running integral over [t,t+T] [PAGE 4]. Third, it defines V(t,z) as the minimum future cost from state z at time t to a terminal state in C_f [PAGE 4]. Fourth, it states the Hamilton-Jacobi-Bellman equation for V, with the important gray-zone caveat that V is at most merely continuous, so derivatives must be interpreted in a generalized or nonsmooth sense [PAGE 4]. Fifth, it eliminates the running cost by augmenting the state with y such that \dot{y}=l(t,x,u) and y(0)=0, so that the finite-horizon problem becomes: minimize V(t+T,x(t+T)) subject to x(t+T) being in the forward reachable set R_f(t+T;t,x(t)) [PAGE 5]. Sixth, it defines forward reach sets R_f(t;t_0,x_0) and backward reach sets R_b(t;t_1,C_1) [PAGE 4]. Seventh, the basic reach-set MPC applies the first control segment over the control horizon Δ, samples, slides time, and repeats [PAGE 5]. The multistep variant sets T=N_T Δ, computes a terminal optimizing point z*_{N_T} in the forward reachable set, and then constructs intermediate points z*_i in the intersection of a forward reach set from z*_{i-1} and a backward reach set from the terminal target [PAGE 6]. The gray-zone audit is where the real risk lies. The scheme is not an exact oracle: the reachable set and value function are estimated offline, and the paper explicitly says that "The reachable set and the value function can be estimated oﬄine by taking into account all the (state and control) constraints as a function of the initial state" [PAGE 3]. It also says that polyhedral approximations are used to obtain affine constraints for efficient online optimization [PAGE 5]. Therefore the mathematical object actually used online may be an inner or outer polyhedral approximation, not the exact reach set. If the approximation is too tight, a feasible state can be excluded and the optimization can become infeasible. If the approximation is too loose, a state that violates a hard constraint can be accepted. The paper also acknowledges that "the value function might have to be updated when there are changes in the environment or in the system that aﬀect the formulation of the underlying optimal control problem" [PAGE 4]. That is a direct warning against treating the offline look-up table as permanent truth. Another gray zone is sampling failure: the paper says that if sampling fails, the basic scheme "does not provide recently computed controls, and the only possibility is to proceed with totally simulated data" [PAGE 5]. The multistep scheme mitigates this by requiring only feasibility at intermediate steps and by reoptimizing when the measured state deviates too much from the reference [PAGE 6]. But the mitigation depends on a clock: the control horizon Δ, the prediction horizon T, the number of intermediate steps N_T, and the reoptimization threshold. If Δ is longer than the real-time computational budget, the controller applies stale controls. If Δ is too short, computation and communication overhead dominate. If the threshold for "x(t) is close to z*_i" is badly chosen, the system either reoptimizes too often or drifts along an invalid reference. The paper's robustness and stability claims are qualified: "Under mild assumptions on the data and, by using the fact that the value function is continuous, it has been shown that this scheme is robust" [PAGE 5], and stability is proved through a generalized Lyapunov inequality in a uniform neighborhood [PAGE 5]. These are not unconditional guarantees for arbitrary uncertainty, arbitrary sampling loss, or arbitrary polyhedral approximation error. The gray-zone audit therefore concludes: the source supports a rigorous receding-horizon architecture with offline reach-set and value-function precomputation, but it does not justify blind trust in the precomputed table, in convexity, in a fixed horizon, or in a fixed sampling clock.

<SOURCE_OPERATORS_AND_EQUATIONS>
The paper's formal operator is a receding-horizon optimal control operator built from three mathematical layers: dynamic optimization, value-function propagation, and reach-set approximation. The long-horizon problem is stated as

\[
(PT_f)\quad \operatorname{Minimize}\quad g(x(T_f))+\int_{0}^{T_f} l(t,x(t),u(t))\,dt
\]

subject to

\[
\dot{x}(t)=f(t,x(t),u(t)),\qquad u(t)\in\Omega,\quad L\text{-a.e.},\qquad x(T_f)\in C_f,\quad x(0)\ \text{given}.
\]

This appears verbatim in substance on [PAGE 4]. The units are: t,T_f in seconds (s); x(t) in the state units of the vehicle, for example position in metres (m), velocity in metres per second (m/s), depth in m, heading in radians (rad); f(t,x,u) in state units per second; u(t) in actuator units, for example thrust in newtons (N), rudder angle in rad, or normalized command dimensionless; l(t,x,u) in cost per second, for example J/s if cost is energy, or dimensionless/s if normalized; g and V in the same cost unit as the integral, for example J or dimensionless. The control constraint set Ω is a subset of the control space. The state constraint in the shorter problem is written on [PAGE 2] as "h(t, x(t))≤0, ∀t", with h in the units of the constrained quantity, for example m for depth limits or rad for attitude limits.

The finite-horizon replacement is

\[
(PT)\quad \operatorname{Minimize}\quad V(t+T,x(t+T))+\int_{t}^{t+T} l(\tau,x(\tau),u(\tau))\,d\tau
\]

subject to

\[
\dot{x}(\tau)=f(\tau,x(\tau),u(\tau)),\qquad u(t)\in\Omega,\quad L\text{-a.e.},\qquad x(t)\ \text{given},
\]

where T is the prediction horizon in seconds. The value function is defined on [PAGE 4] as

\[
V(t,z):=\min_{u\in U,\ \xi\in C_f}\left\{g(\xi)+\int_{t}^{T_f} l(\tau,x(\tau),u(\tau))\,d\tau:\ x(T_f)=\xi,\ x(t)=z,\ \dot{x}(\tau)=f(\tau,x(\tau),u(\tau)),\ L\text{-a.e.}\right\}.
\]

The Hamilton-Jacobi-Bellman equation is

\[
\frac{\partial}{\partial t}V(t,x)+\min_{u\in\Omega}\left\{\left\langle \frac{\partial}{\partial x}V(t,x),f(t,x,u)\right\rangle+l(t,x,u)\right\}=0,
\qquad V(T_f,x(T_f))=g(x(T_f)).
\]

The units of each term are cost per second: \partial V/\partial t is cost/s; \langle \nabla_x V,f\rangle is (cost/state unit)(state unit/s)=cost/s; l is cost/s. The paper explicitly warns that "In general, the value function is, at most, merely continuous, which means that the partial derivatives have to be understood in some generalized sense, and the solution concept has to be cast in a nonsmooth context" [PAGE 4]. Thus the classical HJB equation is a formal representation; the rigorous object is a viscosity or generalized solution.

The forward reach set is

\[
R_f(t;t_0,x_0):=\{x(t):\dot{x}=f(t,x,u),\ u\in U,\ x(t_0)=x_0\},
\]

and the backward reach set is

\[
R_b(t;t_1,C_1)=\{z\in\mathbb{R}^n:\ R_f(t_1;t,z)\cap C_1\neq\varnothing\}.
\]

These definitions appear on [PAGE 4]. The running cost is removed by the augmentation

\[
\tilde{V}(t,\tilde{x})=V(t,x)+y,\qquad \tilde{x}=(x,y),\qquad \dot{y}=l(t,x,u),\qquad y(0)=0,
\]

so that the reach-set form becomes

\[
(PT)\quad \operatorname{Minimize}\quad V(t+T,x(t+T))
\quad\text{subject to}\quad x(t+T)\in R_f(t+T;t,x(t)).
\]

This is the key operator conversion on [PAGE 5]: optimization over controls is replaced by optimization over a reachable set, and the long-term cost is represented by the back-propagated value function. The paper describes this as "Replacing the optimization over the control space by another one over a local polyhedral approximation to the reachable set" and "Back-propagating the long term cost functional to the ﬁnal time of the current control horizon, via the associated value function" [PAGE 3]. The polyhedral approximation is written schematically as \hat{R}_f=\{x:A x\le b\}; rows of A have reciprocal state units if b is dimensionless, or both sides are normalized before optimization. The paper says the advantage is that the approximation "yields aﬃne constraints in the optimization problems to be solved on-line" [PAGE 5].

The multistep algorithm is formalized on [PAGE 6]. Let T=N_T Δ, with N_T a dimensionless integer and Δ the control horizon in seconds. The optimization step computes z*_0=x(t), then R_f^N(t+T;t,x(t)), then

\[
z^*_{N_T}=\arg\min_{z\in R_f^N(t+T;t,z^*_0)}\{V(t+T,z)\}.
\]

For i=1,\ldots,N_T, set t_i=t+iΔ, compute

\[
R_f^N(t_i;t_{i-1},z^*_{i-1})\quad\text{and}\quad R_b^{\bar N}(t_i;t+T,z^*_{N_T}),
\]

choose

\[
z^*_i\in R_f^N(t_i;t_{i-1},z^*_{i-1})\cap R_b^{\bar N}(t_i;t+T,z^*_{N_T}),
\]

and compute u*_i driving z*_{i-1} to z*_i on [t_{i-1},t_i]. Only u*_1 is applied on [t,t+Δ]. The paper then says: "If x(t) is close to z∗ i , then goto 4, otherwise goto 2" [PAGE 6]. This is a thresholded feedback law: the reference trajectory is trusted only while the measured state remains in a neighborhood of the planned intermediate point.

Assumptions and breakdown regimes must be stated exactly. The scheme assumes a model f, a control constraint set Ω, state constraints h≤0, a terminal set C_f, an offline-computable value function V, and a reach-set approximation that is rich enough to contain a feasible point. The paper's robustness statement is qualified by "mild assumptions on the data" and continuity of V [PAGE 5]. Breakdown regimes include: (i) nonsmoothness of V, where classical gradients do not exist and finite-difference gradients can be invalid [PAGE 4]; (ii) polyhedral approximation error, where inner approximations exclude feasible states or outer approximations admit unsafe states [PAGE 5]; (iii) dimensional explosion of reach-set computation, because the paper explicitly notes "the diﬃculties inherent to the Reach Set complexity" [PAGE 5]; (iv) sampling failure, where the controller lacks recent measurements and may have to use simulated data [PAGE 5]; (v) model or environment drift, where the value function must be updated [PAGE 4]; (vi) infeasibility, when the forward reachable set and the terminal target or backward reach set do not intersect; (vii) real-time deadline violation, when the optimization over the control horizon cannot be completed before the next sample; and (viii) excessive min-max conservatism, where worst-case uncertainty protection rejects otherwise feasible controls. The paper's min-max statement is: "uncertainties and perturbations can be dealt with by considering mini-max optimization schemes where the synthesized control optimizes the worst case due to the their potential eﬀect" [PAGE 3]. That is a set-based robust formulation, not a probabilistic guarantee; the source does not provide probability units or information-theoretic units for the uncertainty set, so any claim of probabilistic optimality would exceed the source.
</SOURCE_OPERATORS_AND_EQUATIONS>

<RETROCAUSAL_GENEALOGY>
The genealogical lineage runs from deterministic optimal control and Bellman's Principle of Optimality through Hamilton-Jacobi-Bellman theory, viability and reachability analysis, level-set computation, polyhedral approximation, hybrid-system modeling, and networked formation control. The paper cites the Principle of Optimality on [PAGE 4] and cites Bardi and Capuzzo-Dolcetta for Hamilton-Jacobi-Bellman equations and viscosity solutions [PAGE 7]. It cites Kurzhanski and Varaiya for the interplay between value functions and forward and backward reach sets [PAGE 4] and for Hamilton-Jacobi type equations for nonlinear target control [PAGE 8]. It cites level-set and fast-marching methods through Sethian and Mitchell [PAGE 8] and polyhedral approximation of reachable-set boundaries through Baturin, Goncharova, Lobo Pereira, and Sousa [PAGE 7]. It also connects to hybrid and mixed logical dynamical modeling through Bemporad and Morari and the HYSDEL tool [PAGE 2 and PAGE 8], and to decentralized receding-horizon formation control through Keviczky, Borrelli, Fregene, Godbole, and Balas [PAGE 3 and PAGE 8]. The applied lineage is the C4C AUV work by Sousa, Lobo Pereira, Gomes, Sujit, Estrela da Silva, and Marques, cited as a technical report [PAGE 8], with the paper stating that "the main motivation relies on the coordinated control of the motion of multiple Autonomous Underwater Vehicles (AUVs)" [PAGE 1].

The retrocausal lesson is that the present reach-set MPC is a downstream compression of several older research programs: dynamic programming compressed long-horizon optimization into a value function; reachability analysis compressed constraints into geometric sets; level-set and polyhedral methods compressed those sets into computable approximations; hybrid-system methods compressed logical and continuous constraints into a common modeling language; and networked formation control compressed multi-vehicle coordination into decentralized or cooperative receding-horizon problems. The paper's novelty is not the invention of reach sets or value functions; it is the specific reordering of computation: move the expensive long-horizon value-function and reach-set work offline, store tables, and perform only short-horizon optimization online over a polyhedral approximation [PAGE 3 and PAGE 6].

The multi-week traps follow directly from that genealogy. First, the offline table trap: a value function computed for one environment can become invalid when currents, acoustic propagation, obstacle fields, or vehicle dynamics change; the paper itself says the value function "might have to be updated when there are changes in the environment or in the system" [PAGE 4]. A multi-week deployment that never refreshes the table can gradually drift into suboptimal or infeasible behavior. Second, the convexity trap: polyhedral approximations are affine and computationally convenient, but the true reachable set need not be polyhedral or convex; a long deployment can encounter operating points where the approximation error dominates. Third, the dimensionality trap: reach-set computation scales badly with state dimension, and the paper acknowledges reach-set complexity [PAGE 5]; a multi-week mission that adds many state variables for battery, hull stress, communication state, and formation geometry can make the offline computation intractable. Fourth, the horizon trap: T=N_T Δ is a design choice; if T is too short, the controller is myopic, and if T is too long, the offline value function must cover a larger state space and the approximation burden grows. Fifth, the sampling and communication trap: the paper explicitly notes sampling failure in networked control of multiple vehicles [PAGE 5]; over weeks, packet loss, acoustic latency, and clock drift are not rare exceptions but recurring events. Sixth, the min-max conservatism trap: robust worst-case optimization can protect against perturbations but also shrink the feasible operating envelope; over a long mission, conservative vetoes can cause unnecessary aborts or energy waste. Seventh, the formation-coupling trap: each vehicle's reachable set depends on the others through collision avoidance and communication constraints; treating vehicles independently can produce locally feasible but globally inconsistent plans. Eighth, the model-drift trap: actuator efficiency, battery voltage, buoyancy, and drag change over time; a fixed f and fixed V are only valid within a validity envelope. These traps are not speculative; they are implied by the paper's own distinctions between offline estimation, online short-horizon optimization, polyhedral approximation, and the need to update when the environment or system changes.
</RETROCAUSAL_GENEALOGY>

<RECURSIVE_THEORY_OF_MIND>
The recursive theory-of-mind layer concerns how the controller and the human operator model their own computational limits, the environment's future behavior, the other vehicles' intentions, and the verifier's acceptance conditions. The paper's multistep scheme already contains a primitive metacognitive check: after applying u*_1 and sampling, the algorithm asks whether "x(t) is close to z∗ i" and either continues the intermediate plan or returns to the full optimization step [PAGE 6]. That is a model of the controller's own reference-tracking validity. The crisis habit regression is the tendency, under time pressure or uncertainty, to fall back to the most familiar control habit: solve the full conventional MPC problem online, or replay the last computed control sequence, even when the paper's entire motivation is that the conventional scheme is "computationally intensive" and potentially prohibitive for "real-time requirements under very strict power constraints" [PAGE 2]. The regression is dangerous because it consumes the very computational and energy budget that the reach-set formulation was designed to protect. In a crisis, the correct behavior is not to abandon the architecture but to invoke the precomputed reach sets, check feasibility, and reoptimize only when the deviation threshold is crossed.

The counter-trap is the opposite failure: over-trusting the offline reach-set and value-function tables. The paper says the reachable set and value function "can be estimated oﬄine" [PAGE 3], and that the multistep scheme ensures robustness "without having to perform heavy optimization computations" [PAGE 6]. A naive recursive model can convert that into "the table is always right." That is false whenever the environment changes, the polyhedral approximation is stale, the sampling clock slips, or the disturbance leaves the modeled uncertainty set. The counter-trap is especially seductive because the table is fast, quiet, and apparently authoritative. The correct recursive model must represent the table as a conditional policy with a validity domain, not as an unconditional oracle. The controller should model its own uncertainty about the table and should model the verifier's checks: Bellman residual, reach-set intersection, constraint satisfaction, sampling deviation, and energy feasibility.

The clock is the third pole. The paper's horizons are explicit: T is the prediction horizon, Δ is the control horizon, T=N_T Δ, and the multistep scheme uses intermediate times t_i=t+iΔ [PAGE 6]. The clock determines whether the controller has enough time to compute, whether the sample is fresh, whether the intermediate reference is still valid, and whether the next control can be applied before the deadline. A recursive theory of mind must model the clock at three levels: the physical clock of the vehicle's sensors and actuators, the computational clock of the optimizer, and the communication clock of the network. If the computational clock exceeds Δ, the controller is late. If the communication clock exceeds the sampling interval, the controller is stale. If the physical clock drifts, the horizon indexing is wrong. The paper's warning about sampling failure in networked control [PAGE 5] is therefore a clock warning, not merely a sensor warning. The crisis habit regression says "solve harder"; the counter-trap says "trust the table"; the clock says "you have Δ seconds, and the answer must be feasible before the deadline." The correct adjudication is a hierarchy: first check hard feasibility and freshness, then use the precomputed value function and reach sets, then reoptimize only if the deviation or uncertainty exceeds the validity threshold. This hierarchy is consistent with the paper's own algorithm: optimization step, intermediate control steps, sampling, and conditional return to either step 4 or step 2 [PAGE 6].
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
The cross-layer veto adjudication must be grounded in the paper's hard constraints, not in invented ratios. The paper's admissible trajectory must satisfy \dot{x}=f(t,x,u), u∈Ω L-a.e., and h(t,x(t))≤0 for all t [PAGE 2]. A physical or environmental veto is therefore a set constraint that must be intersected with the state and control constraints before any optimization result is accepted. For an AUV, define the physical veto set X_phys(t) by actuator thrust limits, power and energy limits, depth and pressure limits, buoyancy and trim limits, and hull or actuator loading limits. Define the weather and ocean veto set X_env(t) by current velocity bounds, wave height and period bounds, wind bounds if surfaced, visibility or acoustic propagation bounds, and obstacle exclusion zones. The formal feasibility condition is

\[
\exists u(\cdot)\in\Omega\ \text{such that}\ x(\tau)\in X_{\mathrm{phys}}(\tau)\cap X_{\mathrm{env}}(\tau)\cap\{x:h(\tau,x)\le 0\}\quad\forall \tau\in[t,t+T],
\]

and x(t+T)\in C_f. In reach-set language, the plan is admissible only if

\[
R_f(t+T;t,x(t))\cap C_f\cap X_{\mathrm{phys}}(t+T)\cap X_{\mathrm{env}}(t+T)\neq\varnothing,
\]

with the pathwise constraints enforced along the whole horizon, not only at the terminal time. If the intersection is empty, no control can satisfy the hard constraints, and the correct adjudication is veto, not optimization. The proof is immediate from the definitions: if a proposed trajectory violates h≤0, or uses u∉Ω, or leaves X_phys or X_env at some time τ, then it is not in the admissible trajectory set defined by the paper's constraints [PAGE 2]. Therefore any optimizer that returns such a trajectory has optimized over the wrong set. The paper's polyhedral approximation statement is relevant here: "The reachable set and the value function can be estimated oﬄine by taking into account all the (state and control) constraints as a function of the initial state" [PAGE 3]. If the veto set is omitted from the offline computation, the resulting reach set is an over-approximation relative to the true admissible set, and the online optimizer can select a state that is mathematically reachable but physically or environmentally forbidden.

The cross-layer veto must also handle uncertainty. The paper proposes min-max optimization for uncertainties and perturbations [PAGE 3]. In set terms, if the disturbance w belongs to a bounded set W, then robust feasibility requires

\[
\forall w\in W,\quad \exists u(\cdot)\in\Omega\ \text{such that}\ x_w(\tau)\in X_{\mathrm{phys}}(\tau)\cap X_{\mathrm{env}}(\tau)\cap\{x:h(\tau,x)\le 0\}
\]

for all \tau in the horizon. This is stronger than nominal feasibility. A weather veto is not a soft cost; it is a hard restriction on W. If the observed current or wave state lies outside the modeled W, the robust guarantee is void, and the controller must either expand W and recompute or veto the plan. The "biomechanical" layer is not native to the paper's AUV vocabulary; the legitimate mapping is to vehicle-dynamics and actuator-loading constraints, or to biofouling drag if explicitly modeled. It must not be introduced as a fake ratio such as force divided by fatigue. The correct form is an explicit state or control constraint, for example a hull-load constraint h_hull(t,x,u)≤0 with units of stress or force, or an energy constraint E(t)≥0 with units of joules. The veto proof is then the same: if the constraint is violated, the trajectory is outside the admissible set.

The adjudication order should be: hard physical and environmental veto first; safety and collision constraints second; terminal target and stability third; performance cost last. The paper's reach-set formulation supports this order because the offline computation can include "all the (state and control) constraints" [PAGE 3], and the multistep scheme uses forward and backward reach sets to keep intermediate states feasible [PAGE 6]. If the hard veto set and the forward-backward intersection are disjoint, the controller must not apply u*_1. It must hold, replan, or relax only a formally designated soft constraint. This is the cross-layer veto: no amount of value-function optimality can override a physical, actuator, power, depth, obstacle, or weather constraint that the source itself treats as part of the admissible trajectory definition.
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
RLVR-style verifiable veto scenario 1: value-function Bellman-residual veto. The verifier computes a finite-difference or generalized residual for the stored value function on sampled states in the operating envelope:

\[
\mathcal{B}(t,x)=\left|\frac{\partial V}{\partial t}(t,x)+\min_{u\in\Omega}\left\{\left\langle \frac{\partial V}{\partial x}(t,x),f(t,x,u)\right\rangle+l(t,x,u)\right\}\right|.
\]

Veto if \mathcal{B}(t,x) exceeds a declared tolerance \tau_B, or if the finite-difference gradient is undefined at a nonsmooth point and no generalized subgradient check is available. This is directly tied to the paper's warning that the value function is "at most, merely continuous" and that derivatives must be understood in a "nonsmooth context" [PAGE 4]. Counterfactual prediction: with the veto enabled, the controller will reject table-derived controls in regions where the table is stale or nonsmooth; after table regeneration or local repair, the measured Bellman residual quantile should decrease, and hard-constraint violations should not increase. If the veto is disabled, the controller may apply controls that are optimal for a value function that no longer satisfies the HJB residual within tolerance. The verifier can test this by replaying the same state sequence with and without the veto and comparing the count of applied controls whose residual exceeds \tau_B.

RLVR-style verifiable veto scenario 2: forward-backward reach-set intersection veto. For each intermediate step i, the verifier checks whether

\[
R_f^N(t_i;t_{i-1},z^*_{i-1})\cap R_b^{\bar N}(t_i;t+T,z^*_{N_T})\cap X_{\mathrm{phys}}(t_i)\cap X_{\mathrm{env}}(t_i)\neq\varnothing.
\]

If the intersection is empty, the verifier vetoes the intermediate plan and forces a return to the full optimization step or a safe hold. This is exactly the structure of the paper's multistep scheme, which requires z*_i to lie in the intersection of the forward and backward reach sets [PAGE 6]. Counterfactual prediction: with the veto enabled, the rate of infeasible intermediate commands should fall to zero by construction, and the number of reoptimization events should rise when disturbances are large. If the veto is disabled, the controller may attempt to drive toward a z*_i that is outside the feasible intersection, producing a constraint violation or an actuator saturating command. The verifier can test this by logging intersection emptiness and comparing the subsequent trajectory to the pathwise constraint h≤0. The prediction is falsifiable: if disabled vetoes produce no additional violations in a given environment, then the approximation was not binding there; if they do, the veto is causally necessary.

RLVR-style verifiable veto scenario 3: sampling-clock and reference-deviation veto. After applying u*_1 on [t,t+Δ], the verifier checks the measured state x(t+Δ) against the planned intermediate state z*_1 and against a clock-jitter bound:

\[
\|x(t+\Delta)-z^*_1\|\le \varepsilon_s,\qquad |\Delta_{\mathrm{actual}}-\Delta|\le J_{\max}.
\]

If either condition fails, the verifier vetoes continued use of the stored intermediate sequence and forces the "otherwise goto 2" branch [PAGE 6]. This directly addresses the paper's sampling-failure warning [PAGE 5] and its conditional reoptimization rule [PAGE 6]. Counterfactual prediction: with the veto enabled, the controller will not keep applying stale open-loop controls after packet loss or clock slip; the count of stale-control applications should decrease, and the count of step-2 reoptimizations should increase under high loss or high disturbance. If the veto is disabled, the controller may continue along z*_i even when the measured state has departed the validity neighborhood, producing drift and eventual constraint violation. The verifier can test this by injecting known sampling delays and comparing the number of threshold crossings, the maximum pathwise constraint violation, and the number of reoptimization calls with and without the veto. These three vetoes are formal, measurable, and tied to the source: the Bellman residual to the HJB/value-function layer [PAGE 4], the reach-set intersection to the multistep scheme [PAGE 6], and the sampling-clock deviation to the paper's explicit sampling-failure and reoptimization logic [PAGE 5 and PAGE 6].
