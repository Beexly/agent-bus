The core task requires synthesizing the `BUILD-HELP-028` methodology into a verifiable, mathematical framework for "method-safe public explanations." The fundamental problem is translating high-dimensional, proprietary GSE predictive logic (which likely involves non-linear Bayesian updating of team/player performance) into low-dimensional, trust-maximizing visualizations that users can parse in under 10 seconds. This necessitates a compression algorithm that balances information density with cognitive load.

Step 1: Analyze the Source Constraints. The source [PAGE 1] explicitly mandates a "Duplicate Gate" check, confirming this is an extension of `BUILD-GV2-085`, focusing on "page-level teachability" rather than generic documentation. The critical boundary is "No founder-only methodology leakage." This implies that while we can explain *what* a metric represents and *why* it matters, we cannot expose the exact weighting factors or hyperparameters used to generate it. This creates a gray zone: how much "truth" can be revealed without exposing the intellectual property?

Step 2: Formalize the "10-Second" Requirement. Human working memory can typically hold 4±1 chunks of information (Miller's Law). To achieve comprehension within 10 seconds, the explanation must map to a maximum of three primary concepts: The Metric (What), The Implication (So What), and The Action (Now What). Any deviation into historical derivation or complex formulaic breakdown violates the time constraint and increases cognitive friction. Therefore, the design system must enforce a strict schema: One Summary, One Action, One Trust Note.

Step 3: Develop the Information-Trust Equilibrium. We can model the user's state as a vector $\mathbf{u} = [comprehension, trust, engagement]^T$. The goal is to maximize $J(\mathbf{u})$ subject to the constraint that the exposed feature space $F_{pub}$ is a subset of the internal feature space $F_{priv}$ such that $|F_{pub}| \ll |F_{priv}|$. If $F_{pub}$ contains too much noise (over-explanation), comprehension drops. If it contains too little signal (under-explanation), trust drops. The "Method-Safe" boundary acts as a hard constraint on the allowable projection matrix $P$ where $F_{pub} = P \times F_{priv}$. The operator must find $P$ such that the Kullback-Leibler divergence between the user's posterior belief and the true distribution is minimized without revealing the prior structure.

Step 4: Audit Accessibility and Motion. The requirement for "reduced-motion behavior" suggests that many current sports analytics interfaces rely heavily on parallax scrolling, rapid number ticking, or complex animated graphs to convey momentum. These are vetoed by accessibility standards (WCAG 2.1). The explanation system must provide a static equivalent—perhaps a simplified Sankey diagram or a static confidence interval bar—that conveys the same probabilistic spread without temporal dependency.

Step 5: Establish Verification Vectors. How do we prove the system works? The source mentions "visual screenshot QA" and "help coverage scan." We need to define an automated metric for "teachability." This could be derived from heatmaps showing interaction duration on help affordances. If a user spends >15 seconds on a specific rating explanation, the 10-second rule has failed. The rollback plan ("hide behind a feature flag") indicates this is a highly visible UI change; any regression in readability must be instantly reversible to prevent churn.

Step 6: Synthesize the Pipeline. The ultimate output is not just text, but a structured data object containing the summary, the action link, the trust disclaimer, and the media URI. This object must be validated against a JSON Schema before deployment. The "Claude Code Prompt" essentially asks for an agent that audits the existing React/Vue components, identifies surfaces lacking these objects, and injects them using the established design tokens, ensuring no direct manipulation of billing or secret keys occurs during the process.

<SOURCE_OPERATORS_AND_EQUATIONS>
To formalize the "Method-Safe Public Explanation" generation process, we define an optimization problem over the user's cognitive state. Let $S$ be the set of all possible proprietary metrics generated by GSE. For any metric $m \in S$, we seek an explanation tuple $E_m = (T_{sum}, A_{next}, T_{trust}, M_{vis})$ corresponding to the Implementation Plan requirements [PAGE 1].

**Operator 1: The Cognitive Load Constraint**
We assume human visual processing speed limits comprehension to a bandwidth $B_{max} \approx 10$ bits/second for complex textual data. The total information entropy $H(E_m)$ of the explanation must satisfy:
$$ H(E_m) = -\sum_{i \in E_m} p(i) \log_2 p(i) \leq B_{max} \cdot \Delta t_{target} $$
where $\Delta t_{target} = 10$ seconds [PAGE 1]. If $H(E_m) > 100$ bits, the "10-second comprehension" acceptance criterion is violated. This forces the "smallest help pattern" [PAGE 1] to be highly compressed.

**Operator 2: The Methodological Leakage Boundary**
Let $\Theta$ represent the vector of proprietary parameters (founder-only methodology) and $\Phi$ represent the public-facing features. The explanation must be constructed such that the conditional probability of inferring $\Theta$ given $E_m$ remains below a safety threshold $\epsilon$:
$$ P(\Theta | E_m) \leq \epsilon $$
Practically, this means $T_{sum}$ and $M_{vis}$ cannot contain derivatives or explicit coefficients linking inputs directly to outputs. They must present aggregated results (e.g., "High Confidence" rather than "0.87 Win Probability based on X factor").

**Operator 3: The Trust-ACTION Coupling**
The utility function $U$ for the product surface (ratings/methodology) combines user retention $R$ and support ticket reduction $K$:
$$ U(E_m) = \alpha \cdot R(t|E_m) - \beta \cdot K_{support}(t|E_m) + \lambda \cdot \mathbb{I}(\text{Accessibility Pass}) $$
The implementation requires adding "mobile and reduced-motion behavior" [PAGE 1]. Mathematically, the motion component $M(t)$ of the visual slot must satisfy the Web Content Accessibility Guidelines (WCAG) preference: if `prefers-reduced-motion: reduce` is true, then $\frac{d}{dt}M(t) = 0$ for all dynamic elements, relying instead on static spatial encoding.

**Units and Dimensions:**
- Time: Seconds ($s$). Target $\leq 10s$.
- Information: Bits ($b$). Max entropy per explanation $\approx 100b$.
- Probability: Dimensionless ratio $[0, 1]$. Leakage bound $\epsilon < 0.05$.

**Breakdown Regimes:**
1. **Over-Compression Singularity:** If attempts to reduce $H(E_m)$ strip away necessary context, $T_{trust}$ fails, leading to user skepticism (Trust Collapse).
2. **Motion Dependency Failure:** If the visualization $M_{vis}$ relies entirely on temporal animation to convey magnitude (e.g., a filling gauge), enforcing reduced-motion reduces the information transmission rate to zero, violating the comprehension constraint.
3. **Legal Boundary Breach:** If $T_{sum}$ inadvertently reveals the relative weight of a specific input variable (e.g., "Injuries matter more than recent form"), $P(\Theta | E_m)$ spikes, violating the legal boundary and potentially exposing trade secrets.

<RECURSIVE_THEORY_OF_MIND>
From a crisis habit regression perspective, new users encountering complex ratings (e.g., "GSE Power Rating: 74.2") often experience cognitive dissonance. Their instinctive reaction (Level 1 Theory of Mind) is to assume the number is arbitrary or manipulated. Without immediate context, they enter a "search mode," scanning for familiar anchors (team names, recent scores). If the page lacks an inline explanation, they bounce.

The counter-trap deployed by `BUILD-HELP-028` is proactive scaffolding. By placing a "help affordance" [PAGE 1] directly adjacent to the rating, we anticipate this panic. The explanation copy must sound "human" [PAGE 1], avoiding robotic jargon. Instead of "Our algorithm weighs defensive efficiency at 0.4," it says, "This score reflects how well the team stops opponents, adjusted for strength of schedule." This addresses the user's implicit question: "Why should I trust this?"

However, there is a "clock" ticking. The 10-second window [PAGE 1] is the lifespan of the user's initial curiosity. If the explanation takes longer than that to parse, the user's attention shifts to competing stimuli (notifications, other tabs). The system must balance depth with brevity. Over-explaining triggers "expert fatigue," while under-explaining triggers "novice anxiety." The recursive loop involves the user glancing at the number, seeing the icon, reading the tooltip (3 seconds), absorbing the visual cue (2 seconds), and feeling empowered to click "See Methodology" (Action) or simply accept the rating (Trust). The goal is to transition the user from a state of skepticism to a state of informed reliance within that strict temporal budget.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
The viability of `BUILD-HELP-028` is subject to strict vetoes from physical, biomechanical, and environmental layers.

**Biomechanical Veto:** On mobile devices, the "thumb zone" dictates interaction areas. If the help affordance (icon) is placed outside the reachable arc of the thumb while holding the phone one-handed, the usability collapses. The implementation must verify "mobile readability checks" [PAGE 1] to ensure touch targets are $\geq 44 \times 44$ CSS pixels. Furthermore, visual acuity varies; font sizes in tooltips must scale appropriately with device pixel ratio to avoid squinting, which breaks the 10-second immersion.

**Weather/Environmental Veto:** Sports fans often consume content in high-glare environments (stadiums, outdoor tailgates). Complex gradients or low-contrast text in the "trust note" [PAGE 1] will fail to render legibly under direct sunlight. The design system must enforce a minimum contrast ratio of 4.5:1 (WCAG AA) for all explanation text. If the background of the rating card is dynamic (e.g., video feed), the explanation overlay must include a semi-opaque backing to guarantee readability regardless of external luminance.

**Physical Infrastructure Veto:** In regions with poor network connectivity (3G/edge), loading heavy "media/visual slots" [PAGE 1] (like Lottie files or embedded videos) may timeout. The system must implement lazy loading with a lightweight SVG fallback. If the visual component fails to load, the textual summary must still convey the full meaning independently. The "rollback plan" [PAGE 1] to hide the component via feature flag serves as the ultimate circuit breaker if these physical constraints cause widespread rendering errors or layout shifts (CLS).
</CROSS_LAYER_VETO_ADJUDICATION>
