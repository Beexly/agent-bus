Their exact 4-significant-figure equality across eight configurations is a measure-zero event. The appendix blocks carry the signature of placeholder values. This is the single most load-bearing audit finding.

**1. Structural recursion (tree grammar with a threefold bound).**

Let the node state be the quadruple \(s=(T,\mathrm{OH},\mathrm{OP},D)\) where \(T\) is a set of tables, \(\mathrm{OH}\) an operation history, \(\mathrm{OP}\) the residual operation pool, and \(D\in\mathbb{N}\) the depth. Define the expansion operator \(\Phi\):

\[
\Phi: s \mapsto \{\,s_i'\,\}_{i=1}^{d},\qquad s_i'=\bigl(O_i(T,A_i),\ \mathrm{OH}+O_i(A_i),\ \mathrm{OP}\setminus\{O_i\},\ D+1\bigr)
\]

subject to the joint feasibility set [PAGE 3, PAGE 14]:

\[
\mathcal{F}(s)=\Bigl\{\,(O_1(A_1),\dots,O_d(A_d))\ \Bigm|\ d\le K,\ \ O_i\in \mathrm{OP},\ \ \mathrm{OP}\setminus\{O_i\}\ \text{well-defined},\ \ D<L\,\Bigr\}
\]

with \(K=\texttt{MAX\_DEGREE}=5\), \(L=\texttt{MAX\_DEPTH}=5\) [PAGE 6]. **Units:** \(K\) and \(L\) are dimensionless cardinalities; \(\mathrm{OP}\) is a set of arity-1/2 operator symbols; no SI units enter the structure.

**Assumption A1 (pool monotonicity).** Because [PAGE 14] specifies `OP′i ← OP − Oi()`, the map \(D\mapsto|\mathrm{OP}|\) is strictly decreasing along any root-to-leaf path. Consequently the *effective* depth obeys

\[
L_{\mathrm{eff}}=\min\!\bigl(L,\ |\mathrm{OP}_0|,\ \ell\bigr),\qquad |\mathrm{OP}_0|=7,
\]

so \(L_{\mathrm{eff}}=5\) and **depth, not degree, is the binding constraint** — matching [PAGE 12]: "max depth has a greater impact on the generated text than max degree."

**2. Realized tree size and its breakdown.**

Upper bound on nodes and leaves for a full \(K\)-ary tree of depth \(L\):

\[
|V|_{\max}=\sum_{\ell=0}^{L}K^{\ell}=\frac{K^{L+1}-1}{K-1}=3{,}906,\qquad |V_{\mathrm{leaf}}|_{\max}=K^{L}=3{,}125 .
\]

The realized cost (\(5.71\times10^{-3}\,\mathrm{USD}\), \(29.04\,\mathrm{s}\)) is incompatible with a node count near \(10^{3}\), so the realized tree satisfies \(|V|_{\mathrm{realized}}\ll|V|_{\max}\). **Singularity S1 (chain degeneracy):** when \(d=1\) at every internal node, \(\Phi\) reduces to unary composition; the tree collapses to Chain-of-Table and, by [PAGE 5], "if a node has only one child node, there is no need to use the LLM for merging," so the Content-Generating operator becomes the identity and the framework's ordering advantage vanishes. **Singularity S2 (pool exhaustion):** Algorithm 1 line 6 calls `CONTENT_PLANNING(T,OH,OP)` with no \(\mathrm{OP}=\varnothing\) guard; the prompt constraint [PAGE 15] "Only select Operations from the Operation Pool" makes \(\mathcal{F}(s)=\varnothing\), and the recursion is formally undefined rather than terminating.

**3. Cost and latency functionals.**

\[
C=\sum_{n\in V}\Bigl(p_{\mathrm{in}}\tau_{\mathrm{in}}(n)+p_{\mathrm{out}}\tau_{\mathrm{out}}(n)\Bigr)\quad[\mathrm{USD}],\qquad T_{\mathrm{serial}}=\sum_{n\in V}\bigl(\lambda_{\mathrm{pre}}(n)+\lambda_{\mathrm{dec}}(n)\bigr)\quad[\mathrm{s}]
\]

with \(p_{\mathrm{in}},p_{\mathrm{out}}\) in USD·token⁻¹ and \(\tau\) in tokens. The parallel bound follows from critical-path analysis: \(T_{\parallel}\ge \max_{\pi\in\Pi}T(\pi)\) where \(\Pi\) is the set of root-to-leaf paths, giving an achievable speedup \(S\le T_{\mathrm{serial}}/\max_\pi T(\pi)\) bounded by the tree height, not the node count — relevant to [PAGE 9]: "using multi-threaded parallel processing might be a potential method."

**4. Evaluation functionals.**

Relation Generation precision and count [PAGE 6]:

\[
P_{\mathrm{RG}}=\frac{100}{|\mathcal{R}(\hat t)|}\bigl|\mathcal{R}(\hat t)\cap\mathcal{R}(T)\bigr|\ \ [\%],\qquad \#_{\mathrm{RG}}=|\mathcal{R}(\hat t)|\ \ [\text{relations}]
\]

Content Selection \(P,R,F_{1}\) over \(\mathcal{R}(\hat t)\cap\mathcal{R}(t)\); Content Ordering as the Damerau–Levenshtein complement [PAGE 6]:

\[
\mathrm{CO}=100\cdot\Bigl(1-\frac{D_{\mathrm{DL}}(\pi_{\hat t},\pi_{t})}{\max(|\pi_{\hat t}|,|\pi_{t}|)}\Bigr)\ \ [\%]
\]

with \(\pi\) the induced relation sequence and \(D_{\mathrm{DL}}\) the Damerau–Levenshtein distance in edit operations. A derived **fidelity functional** (mine, not the paper's), for audit use:

\[
\mathcal{F}=1-\frac{\#_{\mathrm{Cont}}}{\#_{\mathrm{Supp}}+\#_{\mathrm{Cont}}}\in[0,1]
\]

yielding ShuttleSet+ Gold 0.8289, Tree-of-Text 0.8915, Chain-of-Table 0.7683; RotoWire-FG Gold 0.9534, Tree-of-Text 0.9681; MLB Gold 0.9529, Chain-of-Table 0.8986, **Tree-of-Text 0.8888** — i.e., on MLB the proposed method is *below* a baseline it claims to beat on contradictions.

**5. Breakdown regime of the metric.** Under the definitions above, \(P_{\mathrm{CS}},R_{\mathrm{CS}},F_{\mathrm{CS}},\mathrm{CO}\) are functionally independent: \(F\) is a harmonic mean of selection precision/recall, CO is an edit-distance complement. The appendix ([PAGE 13], Tables 4–7) reports for the gpt-4o-mini / All-operations / CSV configuration the degenerate identity \(P_{\mathrm{CS}}=R_{\mathrm{CS}}=F_{\mathrm{CS}}=\mathrm{CO}=93.94\%\), whereas Table 1 [PAGE 7] reports \(73.74,85.16,78.03,69.30\) for the same configuration at identical \(T=29.04\,\mathrm{s}\), \(C=5.71\). This is a **metric singularity**: the constraint set that forces four independent statistics into exact 4-figure agreement has measure zero, and the paper offers no normalization that would produce it. Source text supporting the definitions: "Relation Generation (RG) evaluates the count (#) and precision (P%) of information extracted from \(\hat t\) that is present in the input table \(T\)" and "Content Ordering (CO) quantifies the complement of the Damerau-Levenshtein Distance (DLD%)" [PAGE 6].

**6. Serialization cost law.** Token-count inflation from table format raises latency superlinearly in observed data: CSV 29.04 s / $5.71 → PIPE 78.53 s / $9.63 → HTML 104.99 s / $19.26 [PAGE 13, Table 7]. Ratios 2.704× and 3.615× latency for equivalent information content confirm that \(T\) is dominated by \(\tau_{\mathrm{in}}\), i.e., by prompt length, not by generation.

<RETROCAUSAL_GENEALOGY>
The framework's ancestry runs on two independent rails that were only recently cross-wired.

**Rail I — algorithmic genealogy.** [PAGE 1] and [PAGE 9] both name the source explicitly: "inspired by the 'divide and conquer' concept of merge sort (Bron, 1972)." Bron's *Communications of the ACM* Algorithm 426 is a pure sorting procedure with no natural-language semantics; the retrocausal move is to reinterpret its recursion schema — decompose, solve on leaves, merge — as a *prompt orchestration* schema. The merge step is where the analogy is weakest and the paper knows it: merge sort's merge is order-preserving and lossless, whereas Tree-of-Text's merge is an LLM rewrite with a soft constraint, "The New Report must include all the content from the input Reports; do not omit any information" [PAGE 16, Figure 6]. A soft constraint is not a monoid; the merge is not associative and not idempotent, so the "merge sort" lineage is rhetorical rather than structural.

**Rail II — data-to-text genealogy.** Wiseman et al. (2017) supplies both the RotoWire task and the IE-metric family \((table|column|value)\) [PAGE 6]; Puduppully et al. (2019b) supplies MLB; Puduppully et al. (2019a, NCP), Chen et al. (2021, NDP), Gong et al. (2020, DUV), Puduppully & Lapata (2021, Macro), and Puduppully et al. (2022, SeqPlan) supply the content-planning lineage the paper explicitly declines to benchmark, on the stated ground that "ShuttleSet+ contains only 58 samples. This makes model training highly challenging" [PAGE 3]. Wang et al. (2023, ShuttleSet22) supplies the stroke-level substrate, and the transcoding from stroke-level to rally-level is stated with unusual candour: "we retain only the final stroke of each rally" [PAGE 10] — a lossy reduction that later becomes an audit lever.

**Rail III — prompting genealogy.** Brown et al. (2020) → Wei et al. (2022, CoT) → Yao et al. (2023, ToT) → Wang et al. (2024, Chain-of-Table). The paper's four inherited operations `select_row/select_col/count/sort` are attributed verbatim to Wang et al. (2024) [PAGE 4], and the four additions `root/select_table/filter/write` are the actual delta.

**Multi-week traps.** (T1) The **n = 9 trap**: ShuttleSet+ is split 40:9:9 [PAGE 5], so a one-document swing moves RG# by ~1.1 and CS F by several points; every ShuttleSet+ ranking is a nine-sample ranking. (T2) The **single-run trap**: "All of our experiments are single-run" [PAGE 6] means delta-comparisons such as MLB RG P% 87.04 vs 88.61 (Chain-of-Thought) or RG# 80.11 vs 84.67 carry no error bar and cannot adjudicate. (T3) The **LLM-as-IE circularity trap**: the evaluator is itself an LLM validated against "a set of information" annotated manually, achieving "over 70% on all evaluation metrics" [PAGE 6] — a 70% floor on the measuring instrument propagates directly into the measured quantity. Table 3 [PAGE 11] shows the Few-shot IE configuration scoring RG P% = 100.00 exactly, an extreme that itself warrants scrutiny. (T4) The **gold-is-not-grounded trap** described above: gold reports contain off-table world knowledge (An Seyoung, Tai Tzu Ying, dates) that the paper's own metric penalizes.
</RETROCAUSAL_GENEALOGY>

<RECURSIVE_THEORY_OF_MIND>
Model the planner as an agent holding a belief \(b\) over "which sub-table is report-relevant," updated only from \(\mathrm{OH}\) and \(\mathrm{OP}\) — it never observes the target article's rhetorical type. The three competing policies are:

**(a) Crisis habit regression.** Under distribution shift to a larger, more heterogeneous corpus, the planner regresses to the shallow habitual plan `select_table → write`. The signature is unambiguous in Table 1 [PAGE 7]: on RotoWire-FG, Tree-of-Text attains the **best** CS P% (74.65) and RG P% (95.11) while recording the **worst** CS R% (55.88) and the **lowest** RG# (34.68). On MLB the same shape appears: RG P% 87.04 against RG# 80.11 (the lowest RG# of any method). Precision rises because the agent says less; recall falls because it never expands. The paper's own diagnosis is consistent but under-described: "using the same set of configurations can not adapt well to different types of articles" [PAGE 8].

**(b) Counter-trap.** The over-corrected policy maxes \(K\) and \(L\) to chase CS R. Table 5 [PAGE 12] prices this precisely: \(L=5,K=5\) yields the best quality at \(29.04\,\mathrm{s}\); \(L=3,K=5\) collapses to \(16.60\,\mathrm{s}\) with a larger quality loss than \(L=5,K=3\) at \(29.48\,\mathrm{s}\). So the counter-trap is *asymmetric*: buying recall through depth costs latency roughly linearly in \(L\), while buying richness through degree costs almost nothing in time but yields less. An agent that does not know this asymmetry will over-pay.

**(c) The clock.** The only arbiter that cannot be negotiated is the budget: 29.04 s and \(5.71\times10^{-3}\,\mathrm{USD}\) per report [PAGE 7], against Few-shot's 6.00 s and \(2.20\times10^{-3}\,\mathrm{USD}\). [PAGE 9] concedes the gap and defers it: "we leave the efficiency aspect as future work." A recursive agent that models its *own* evaluation budget would set \(L=\lceil \log_K(N_{\text{tables}}) \rceil\) rather than a constant 5 — the paper's constant setting is precisely the "manually tuning configurations" limitation it lists first [PAGE 9].
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
**Physical veto (conservation law).** Under BWF rally scoring, every rally yields exactly one point, so a set ending 21–11 contains exactly 32 rallies. Combined with the retention rule "we retain only the final stroke of each rally" [PAGE 10], the set-1 sub-table must contain exactly 32 rows, and therefore

\[
\sum_{v\in\mathcal{V}_{\text{ball\_type}}}\mathrm{count}(\texttt{ball\_type}=v)\;=\;N_{\text{rallies}}(\text{set})\;=\;32 .
\]

The Figure 9 Tree-of-Text output [PAGE 18] enumerates set 1 as "return net 7, lob 6, clear 4, drop 3, smash 2" plus "single instances of cross-court net shot, net shot, and rush," summing to 25 — a 7-count deficit against the conservation law. Set 2 (21–13 ⇒ 34 rallies) is enumerated as 7 + 4 + 4 + 3 + 3 + 2 + 1 = 24, a 10-count deficit. Either the enumeration is partial (a recall defect, consistent with the RotoWire-FG recall signature) or the counts are unsupported (a hallucination). **Neither reading is benign**, and the aggregate RG P% cannot distinguish them.

**Biomechanical veto.** Stroke-type taxonomy is closed: `ball_type`, `win_reason`, `lose_reason` are the only stroke-semantic columns, translated from Chinese [PAGE 11]. Any biomechanical assertion not expressible as a value in those columns — racket-head speed, shuttle spin rate, jump height, grip pressure — is structurally unverifiable in this pipeline and is vetoed *by construction* by the generation constraint "The Report can only describe the content included in the Tables and cannot describe anything not included in the Tables" [PAGE 16, Figure 5, req. 5]. This is the strongest veto the paper offers: it is enforced at prompt level, not metric level.

**Meteorological veto.** No table schema anywhere in the paper — neither the `match` table (`tournament, round, winner, loser` [PAGE 2]), the `set_*` tables (`rally, winner_score, loser_score, player`), nor the enumerated nine retained columns [PAGE 11] — contains hall temperature, humidity, altitude, draught, or shuttle-basket conditioning. Any claim attributing drift, slow shuttles, or "heavy air" to a result is an out-of-schema injection. The prompt-level veto is total; the metric-level veto is partial, since the IE extractor is itself an LLM [PAGE 17] and can emit plausible-but-ungrounded relations if the `{TABLE_RELATION}` set is not closed. Corroborating evidence of leakage: the Figure 9 Tree-of-Text output asserts the match "lasted 41 minutes" and names the "YONEX All England Open Badminton Championships 2022," while the only tournament string in the tables is "All England Open 2022" [PAGE 2] and no duration column exists in any described schema. Both tokens are outside the derivable closure.
</CROSS_LAYER_VETO_ADJUDICATION>

**Veto 2 — Conservation-law veto.** *Rule:* \(\sum_v \mathrm{count}(\texttt{ball\_type}=v)=N_{\text{rallies}}(\text{set})\), with \(N=21+\text{loser\_score}\). *Counterfactual:* instrument the Content-Planning step to force `select_table(set_1) → count(ball_type)` and compare the returned multiset against the set-1 row count. *Prediction:* the multiset sums to 32 (set 1) and 34 (set 2), not 25 and 24 as printed; the discrepancy is a *generation-stage* omission, not a *retrieval-stage* error, because `count()` is executed deterministically by the Python program [PAGE 4–5] while the prose is written by the LLM [PAGE 16].
