units: dimensionless contrast ratio; L = 0.2126 R_{lin} + 0.7152 G_{lin} + 0.0722 B_{lin} after sRGB linearization. Assumption: standard sRGB display, normal viewing distance, no glare. Breakdown: CR < threshold fails AA; singularity at L_{max} = L_{min} = 0, where 0.05/0.05 = 1 but perceptual contrast is undefined because both channels are black; display gamma mismatch also invalidates L.

Keyboard / focus reachability:

R = |V_{focusable} ∩ V_{keyboard}| / |V_{focusable}|

units: dimensionless in [0,1]. Assumption: DOM tab order matches visual order and no focus traps exist on team pages. Breakdown: R < 1 violates accessibility basics; singularity at |V_{focusable}| = 0 (a page with no interactive elements is vacuously unreachable but also fails the “what to do next” customer value).

Performance budget:

L_{total} = L_{net} + L_{parse} + L_{layout} + L_{paint} ≤ T_{budget}

units: seconds (or ms); T_{budget} is the mobile performance budget. Assumption: measurements on the real shipping clone, mobile viewport, representative network. Breakdown: if L_{total} > T_{budget}, the performance budget is worsened, violating an acceptance criterion despite “Performance risk: LOW” [PAGE 1]; singularity as T_{budget} → 0.

Public/private separation operator. Let W_{method} denote founder-only source weights and private methods. The public view operator f must satisfy:

V_{pub} = f(S) , where f strips W_{method}; V_{adm} = (S, W_{method})

Requirement: I(V_{pub} ; W_{method}) = 0 for public renders. Breakdown: any detectable mutual information between public team-page copy/DOM and W_{method} constitutes method leakage (risk rated MEDIUM) [PAGE 1] and triggers isolated rollback or feature-flag disable.

<RECURSIVE_THEORY_OF_MIND>
Crisis habit regression versus counter-trap versus clock. Under P2 priority and M difficulty [PAGE 1], the developer faces nested models: model the new user (must understand surface within 10 seconds), model the reviewer/legal gate (accessibility, no method leakage, no affiliate links, no guaranteed-win copy), and model future self (must roll back isolated change without production data rollback).

Crisis habit regression: when time pressure mounts, the habitual regression is to copy founder-only methodology into public team pages, insert placeholder affiliate-style links to satisfy “monetization” business value, use fake team data to avoid locating the real clone, skip reduced-motion and keyboard/focus checks, and treat “cinematic” as license for heavy motion. Each regression directly violates [PAGE 1]: no method leakage, no live sportsbook/casino affiliate links, no fake data, accessibility basics, and isolated rollback.

Counter-trap: the opposite failure is over-engineering the “premium sports intelligence command center” into a multi-week redesign with custom motion systems, unscoped design tokens, and broad visual refactoring. This mistakes visual polish for clarity (the rated design risk) and risks blowing the performance budget while missing the route-level scope [PAGE 1].

Clock layering: there are three clocks. User clock: t ≤ 10 s for comprehension; if I(S ; U_{10}) < required bits, the surface fails. Developer clock: implementation steps (verify clone, locate route, smallest change, add states, run checks, screenshots) must fit the P2 timebox without expanding into BUILD-GV2-024 scope. Rollback clock: the feature flag or component revert must be executable instantly, with no production data rollback, because “Rollback is isolated” [PAGE 1]. Failure occurs if any clock is misread: building a beautiful page that no user can parse in 10 seconds, or building a compliant page so slowly that the card never ships, or shipping a change that cannot be rolled back without touching production data.

<CROSS_LAYER_VETO_ADJUDICATION>
Physical, biomechanical, and environmental veto proof. A team-page change is admitted only if every layer passes; failure in any layer vetoes the change regardless of design merit.

Physical layer (device constraints): viewport meta tag must set width=device-width; touch targets must be at least 44×44 CSS px to accommodate finger-pad motor error; the prefers-reduced-motion media query must be honored so “cinematic” motion can be disabled; low-power and reduced-data modes must not break layout. Veto condition: touch target < 44 px, or motion not reducible, or viewport not adaptive.

Biomechanical layer (human perception): body text should render at a minimum effective size comparable to 16 CSS px at normal reading distance (~40–70 cm); visible focus indicators must contrast at least 2 CSS px against adjacent backgrounds; contrast ratio CR must satisfy WCAG thresholds. Veto condition: CR < 4.5:1 for normal text or < 3:1 for large text, or focus indicator lost. Effective contrast under glare is modeled as CR_eff = CR · η_glare, where η_glare ∈ [0,1] is the environmental transmission factor; if CR_eff falls below threshold under bright-sunlight or low-angle glare, the contrast guarantee is void.

Weather/environment layer (viewing conditions and network): on constrained networks (4G/3G) or low-battery thermal throttling, L_net and script parse time dominate L_total. If L_net + L_parse + L_layout + L_paint > T_budget on mobile, the performance budget is worsened [PAGE 1]. Veto condition: measured L_total > T_budget, or CLS > 0.1, or FCP exceeds the mobile budget on representative network conditions.

Adjudication function: Veto = 1 iff (CR < threshold) ∨ (R < 1) ∨ (L_total > T_budget) ∨ (touch < 44 px) ∨ (motion not honored) ∨ (method leakage detected in public DOM). Proceed only if Veto = 0. This makes the implementation proof against single-layer optimism: a high-contrast design that traps keyboard focus is vetoed; a fast page with casino-style affiliate links is vetoed; a cinematic page that blinds users in glare is vetoed.
</CROSS_LAYER_VETO_ADJUDICATION>
