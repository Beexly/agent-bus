Crisis habit regression occurs when the ranking system, under load, latency pressure, or partial component failure, reverts to a pure relevance-ordered fallback and skips the affinity-graph and richness-selection stages. This regression is psychologically coherent for operators: relevance-only ranking is faster, simpler, and historically validated, so during an outage the system “returns to habit.” The counter-trap is that the diversification layer itself can be manipulated by adversarial topic fragmentation—publishing many near-duplicate pages across pseudo-clusters to capture multiple first-page slots—thereby converting a diversity safeguard into a surface-area attack vector. The clock constraint is the real-time serving budget: the full pipeline (affinity construction, clustering, argmax richness, interleaving) must complete within the query latency SLA, typically on the order of 100–200 ms end-to-end. If the graph construction phase consumes most of that budget, the clock forces the crisis habit regression described above.

From the user’s recursive theory of mind, the searcher assumes that the first page reflects a distribution of plausible intents. When the system regresses to relevance-only ranking under crisis, the user’s internal model is violated: the dominant topic monopolizes positions 1–K, and the minority intent disappears from the visible horizon. The user then either refines the query or abandons the session. The system designer must therefore model not only document relevance but also the user’s belief about result diversity, because repeated violations of that belief degrade trust even when the fallback ranking is technically correct for the majority intent.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
Physical-layer veto: the affinity-graph stage is O(N^2) in the candidate count and memory-bound. If data-center thermal or power throttling pushes p99 query latency above the hard SLA (e.g., 250 ms), the physical infrastructure vetoes graph construction; the system must fall back to precomputed topic labels or relevance-only ranking. Biomechanical-layer veto: users scan results in an F-pattern, with fixation concentrated on the top ~5 positions. If diversification pushes the single most relevant document for the dominant intent below position 5, the expected user fixation on that document drops sharply, producing a biomechanical failure even though the list is diverse. Pogo-sticking rate and time-to-longest-click above threshold constitute observable veto signals. Weather layer: the patent contains no meteorological input; however, extreme ambient temperature events that force cooling failure and load shedding in the data center are physical-environment triggers that enact the same latency veto as above. Adjudication hierarchy: (1) hard real-time SLA veto overrides all enrichment; (2) correctness veto applies when M=1 or N=0, where diversity is mathematically undefined; (3) user-experience veto applies when biomechanical telemetry indicates that diversity is harming dominant-intent satisfaction. Any veto event must be logged with the triggering layer, the latency or metric value, and the fallback path executed.

Scenario 1 — Single-topic collapse. Verifiable condition: clustering yields M = 1 for query q because all N candidates share the same topic signature. Veto: disable diversification and rank solely by richness \(\rho_i\), because the coverage constraint \(\bigcup_m \text{topics}(d_m^{\star}) \supseteq \mathcal{T}(q)\) is already satisfied by one document. Prediction: topic entropy of the top-K list remains flat (no diversity gain possible), but click-through rate on position 1 does not degrade; the system avoids wasted O(N^2) graph work.

Scenario 2 — Richness-length confound. Verifiable condition: Pearson correlation between richness score and document word count satisfies r(\(\rho\), |d|) > 0.7 over a rolling 7-day window, indicating that length is a proxy for richness. Veto: replace raw richness with normalized richness \(\rho'(d_i) = \rho(d_i) / \log(1 + |d_i|)\) and re-rank each group. Prediction: average word count of top-K documents decreases; user time-to-longest-click improves; spam pages with verbose templating are demoted within their clusters.

Scenario 3 — Latency breach. Verifiable condition: affinity-graph construction time t_graph(q) exceeds τ_max = 150 ms for the p95 of queries in production telemetry. Veto: skip on-the-fly graph construction; assign documents to precomputed topic buckets or rank by relevance r_i only. Prediction: p99 latency returns below τ_max; topic entropy of the top-K drops by an expected \(\Delta H > 0\); availability and SLA compliance are preserved at the cost of reduced diversity for the affected query fraction.

Each scenario is falsifiable from standard search logs (cluster counts, document term counts, latency histograms, click models) and requires no hidden parameters.
