<THINK_TRACE>
The source paper constructs its calibration argument as a chain of modeling assumptions, inverse-projection constraints, and operational compromises. The first hop is physical: a PTZ camera is not a single rigid camera but a composite of a moving platform, a zoom lens, and an image sensor. The paper states this explicitly: “This method models the PTZ camera system and accurately pre-estimates unknown parameters in the model.” [PAGE 2]. The second hop is kinematic: the camera extrinsics are decomposed into world-to-platform, platform-to-pan-tilt, and pan-tilt-to-camera transformations. This decomposition is only meaningful if the pan-tilt axes intersect at a rotational center. The source says: “Supposing that the pan-tilt axes are orthogonal at one point in the platform, this point is defined as a rotational center.” [PAGE 3]. If that mechanical assumption fails, the simplified extrinsic chain becomes biased.

The third hop is optical: intrinsics depend on zoom. The paper defines the zoom counter as the sensor value n: “the counter value of the zoom lens measured by the sensor is defined as the zoom value n.” [PAGE 2]. The intrinsic vector κ(n) includes focal length, aspect ratio, principal point, and distortion coefficients. The extrinsic decomposition assumes that only the camera-to-pan-tilt translation along the optical axis changes with zoom: “we assume that only the translation vector in the direction of the optical axis, namely the z-axis direction, depends on the zoom value.” [PAGE 3]. This is a major gray zone. Real lenses may exhibit zoom-dependent lateral decentering, focus breathing, asymmetric distortion, or sensor-plane shifts. The paper acknowledges later that real tele-end calibration can become conspicuous when the model is imperfect: “the camera model was not perfect, and the estimation error of the parameters was conspicuous” [PAGE 11].

The fourth hop is estimation theory. The unknowns are packed into camera model parameters (CMPs) φ and then into the ICC parameter vector η. The paper estimates them by repeated initial guesses, nonlinear optimization, and progressive data expansion. It states: “We conduct nonlinear optimization to refine the parameters φi by minimizing the projection error using the Levenberg–Marquardt algorithm” [PAGE 6]. The objective is reprojection error in image coordinates, measured in pixels. The optimization landscape is therefore not abstract: it is a high-dimensional, nonlinear, rank-sensitive inverse problem where missing calibration data create null directions. The paper explicitly warns: “ICC estimates a large number of parameters. Therefore, it cannot work well with a small amount of calibration data.” [PAGE 10].

The fifth hop is operational. The method separates initial camera calibration (ICC) from on-location camera calibration (OCC). ICC is expensive and offline; OCC is lightweight and location-specific. The paper says ICC is performed beforehand and OCC updates only location-dependent parameters. This is the key systems move: it transforms a computationally heavy bundle-adjustment problem into a real-time sensor lookup after pre-estimation. The paper states: “After the pre-estimation, accurate camera parameters can be calculated in real time using the pan-tilt angles and zoom values acquired from the sensors in the camera system.” [PAGE 2].

A gray-zone audit shows three main fragility layers. First, mechanical: pan-tilt axes, encoder accuracy, backlash, and structural deflection. The paper targets cameras with precise sensors: “platforms and lenses that can obtain precise pan-tilt angles and zoom values, known as sensor values, by using sensors, such as rotary encoders.” [PAGE 2]. If encoders are noisy, the real-time path inherits sensor error directly. Second, optical: zoom interpolation. The paper uses sampled zoom values and spline interpolation: “We use spline interpolation.” [PAGE 7]. If sampling is sparse, especially near tele end, interpolation can oscillate or underfit. Third, informational: epipolar or reprojection error is the observable diagnostic. In CG tests, the detailed model achieved a mean error of “1.24” pixels with maximum “5.81” pixels [PAGE 9], while a simplified model produced a mean error of “24.77” pixels [PAGE 9]. In real data, ICC reprojection error was “1.18 pixels” [PAGE 11], but OCC errors rose to “3.43” and “2.74” pixels [PAGE 12]. These numbers are not decorative; they define the epistemic envelope of the method.

Finally, the deepest inference is that the paper’s calibration quality is bounded by the product of mechanical exactness, optical model sufficiency, and calibration-data coverage. The method is robust when sensors are reliable, patterns cover the needed zoom range, and the location update is constrained. It becomes fragile when live constraints force sparse data, when tele-end operation combines with extreme pan-tilt angles, or when the camera hardware violates the ideal PTZ decomposition.

6. Statistical and information-theoretic reading

Let observed feature coordinates be:

\[
u_{ijklm}^{obs} =
\hat u_{ijklm}(\eta) + \varepsilon_{ijklm}
\]

Assume:

\[
\varepsilon_{ijklm}\sim \mathcal{N}(0,\sigma^2 I_2)
\]

with σ in pixels. Then the least-squares objective corresponds to negative log-likelihood up to constants:

\[
\ell(\eta) =
-\frac{1}{2\sigma^2}
\sum \|u^{obs}-\hat u(\eta)\|^2 + C
\]

If log base e is used, information is in nats; if log base 2 is used, information is in bits.

The Jacobian is:

\[
J = \frac{\partial \hat u}{\partial \eta}
\]

with units pixels per parameter unit. The Fisher information matrix is:

\[
\mathcal{I}(\eta) =
\sigma^{-2}
\sum J^T J
\]

with units inverse parameter variance. The Cramér-Rao lower bound is:

\[
\mathrm{Cov}(\hat\eta) \succeq \mathcal{I}(\eta)^{-1}
\]

This gives the formal breakdown condition: if the calibration data do not populate directions in parameter space, J loses rank, \mathcal{I} becomes singular, and the covariance diverges. The paper’s warning that ICC “cannot work well with a small amount of calibration data” is exactly a rank-deficiency statement [PAGE 10].

- Lens distortion is representable by the four coefficients in the paper. [PAGE 4]

<RETROCAUSAL_GENEALOGY>
The paper sits inside a long lineage of camera calibration: from fixed intrinsic/extrinsic estimation to zoom-aware and PTZ-aware models. The source traces this lineage explicitly. Tsai’s method uses known 2D-3D correspondences; Zhang’s method uses planar patterns and multiple poses; Ueshiba and Tomita extended Zhang to multi-camera systems; Willson modeled zoom lenses with polynomial functions. [PAGE 2] The paper states that these are effective for fixed or zoom cameras but difficult to apply to PTZ cameras because PTZ cameras combine changing intrinsics, changing extrinsics, and platform kinematics.

A key historical branch is the move from image-based calibration to sensor-based calibration. SLAM and SfM are cited as high-operability methods because no calibration object is required, but the paper rejects them as primary solutions for this broadcast use case because “most SLAM methods assume that the intrinsic parameters are known and cannot handle zoom changes” and “SfM ... cannot do so in real time because it has many variables to estimate.” [PAGE 2] This is a crucial retro-causal insight: the paper chooses a calibration-object and encoder-sensor approach because live broadcast demands deterministic runtime performance, not open-ended scene reconstruction.

Another lineage is the PTZ-specific motion model. Surveillance literature often uses a simple motion model where pan-tilt axes pass through the optical center. The paper cites this simplification and rejects it: “we use a more detailed camera model to improve the accuracy of camera calibration.” [PAGE 2] The detailed model’s importance is quantified by the CG experiment: the simple model produced a mean error of “24.77” pixels, while the detailed model produced “1.24” pixels. [PAGE 9] This is a multi-week trap for engineers: if they assume a zero offset between rotational center and optical center, the error can become unusable at tele end or large pan-tilt angles.

The immediate predecessor is Okubo et al., whose single-camera virtual-studio method models a PTZ camera and estimates unknown parameters beforehand. [PAGE 2] The source acknowledges that Okubo’s method could achieve accurate CG synthesis for a 13x zoom lens but had two issues: the initial guess method was unspecified, and accuracy was verified only over a narrow pan-tilt range. The new paper responds by specifying repeated initial guesses, nonlinear optimizations, calibration-data expansion, and wide-range evaluation. [PAGE 2]

Multi-week traps in production are structural:
1. Treating PTZ calibration like fixed-camera calibration. Fixed methods assume static intrinsics/extrinsics, which is invalid because PTZ parameters change constantly. [PAGE 1]
2. Ignoring zoom-dependent extrinsics. The optical center can translate relative to the pan-tilt rotational center as zoom changes. The paper’s model includes t^C_z(n); omitting it caused large errors in the simple model. [PAGE 9]
3. Assuming encoder values are perfect. The method depends on “precise pan-tilt angles and zoom values” from sensors. [PAGE 2]
4. Under-sampling tele zoom. The real experiment showed that lack of calibration data beyond a certain zoom range degraded accuracy: “calibration data with a zoom range greater than 750 (n > 750) were not used” and accuracy declined in that range. [PAGE 13]
5. Using ICC at the filming location. The paper shows that ICC needs many parameters and many data; using OCC-sized data for ICC causes large error, especially between sampled zoom points. [PAGE 10]

Thus, the genealogical lesson is that live PTZ calibration is not a minor extension of fixed calibration; it is a new estimator with separate offline and online phases.

<RECURSIVE_THEORY_OF_MIND>
The paper’s requirements form a model of operator behavior under crisis: “Robustness: cameras can always be calibrated without fail,” “Real time: camera parameters can be obtained during operation in real time,” “Accuracy: 3D position analysis and CG synthesis can be conducted over a wide pan-tilt-zoom range without causing discomfort to the viewer,” and “Operability: to accommodate the restrictions of live TV, the system must be as simple as possible to be set up at the filming location.” [PAGE 1] These are not merely technical targets; they encode the psychology of live production. The crew is under time pressure, the cameras must be ready quickly, and failure must not happen on air.

A recursive theory of mind would predict a crisis habit regression: when time is short, operators tend to reduce preparation actions and rely on familiar heuristics. In this domain, the regression is likely to be one of the following:
- Use fewer calibration patterns because setting them up is laborious.
- Capture only wide-angle calibration data because it is easier.
- Skip tele-end calibration because patterns are too small to see or capture.
- Trust the camera’s internal presets without verifying epipolar consistency.
- Use image-based tracking or manual tracking instead of geometric calibration.

These habits are dangerous because the paper explicitly says a large pattern is captured over the wide zoom range and a small pattern is captured in the tele zoom range. [PAGE 4] If tele coverage is skipped, the interpolated parameters become unreliable. The paper also shows that ICC with insufficient data fails: “ICC estimates a large number of parameters. Therefore, it cannot work well with a small amount of calibration data.” [PAGE 10]

The counter-trap is the ICC/OCC division. ICC absorbs the expensive estimation burden before the filming location. OCC then estimates only the new world-to-platform extrinsics. The paper says OCC estimates “the extrinsic parameters CPiµW′ when transitioning from the new world coordinate system 6W′ to the camera platform coordinate system 6CPi of each camera.” [PAGE 7] This counter-trap converts a high-dimensional crisis into a low-dimensional location update. The operational evidence is strong: ICC required “490” captures per camera, while OCC(1) used “125” and OCC(2) used “50.” [PAGE 13] The source says this reduced captures to approximately one-tenth. [PAGE 13]

The clock is explicit. Live preparation time is insufficient for many fixed cameras, which is why PTZ cameras are chosen. [PAGE 1] The method must produce camera parameters in real time from sensor values. [PAGE 2] The final application reports “the total delay from capture to output was approximately 0.3 seconds.” [PAGE 13] This clock constraint changes the epistemic equilibrium: the system cannot run full bundle adjustment during the broadcast; it must use precomputed CMPs and only update small location parameters.

A recursive agent model would therefore represent the operator as facing a tradeoff between epistemic completeness and temporal feasibility. Let the posterior over calibration quality be p(η|data). If the clock is tight, the operator must reduce expected uncertainty quickly. The paper’s design does this by making the offline phase high-information and the online phase low-information but targeted. The OCC experiments show the price: mean error increases from ICC to OCC, but remains usable. In CG data, ICC mean error was “1.24” pixels and OCC mean error was “1.95” pixels. [PAGE 9] In real data, ICC reprojection error was “1.18” pixels, while OCC(1) and OCC(2) were “3.43” and “2.74” pixels. [PAGE 11][PAGE 12]

The gray-zone crisis behavior is not irrational; it is locally rational but globally risky. Skipping tele data saves time, but produces the exact failure mode observed in real data: errors become conspicuous when panning or tilting is large and zoom is on the tele side. [PAGE 11] The counter-trap is not simply “calibrate more.” It is “calibrate the right low-dimensional subset under the clock.”

<CROSS_LAYER_VETO_ADJUDICATION>
The method’s validity depends on physical, biomechanical, and environmental layers. A veto adjudication must prove that any layer violation can invalidate the mathematical calibration even if the algorithm runs without numerical failure.

Physical layer veto:
The model assumes precise sensor values. The source says the method targets PTZ cameras with “platforms and lenses that can obtain precise pan-tilt angles and zoom values, known as sensor values, by using sensors, such as rotary encoders.” [PAGE 2] If encoder quantization, backlash, or mechanical hysteresis causes the true pan-tilt angle to differ from the reported sensor value, the runtime projection uses the wrong rotation matrix. The resulting image-space error is approximately first-order:

\[
\delta u \approx
J_{\theta}\delta\theta +
J_n\delta n +
J_{\mu}\delta\mu
\]

where J_theta is sensitivity to angle error [px/deg], J_n is sensitivity to zoom-counter error [px/count], and J_mu is sensitivity to extrinsic error [px/mm]. If δθ is outside the calibrated noise regime, the calibration cannot veto itself because it trusts the sensor.

Mechanical layer veto:
The extrinsic decomposition requires the pan-tilt axes to intersect at one rotational center. The source states: “Supposing that the pan-tilt axes are orthogonal at one point in the platform, this point is defined as a rotational center.” [PAGE 3] If the axes do not intersect, or if the intersection moves due to structural flex, the assumption that the platform-to-pan-tilt translation is zero fails. The source says: “the translation vector of PTµCP becomes 0” only under the crossing-axis assumption. [PAGE 3] This is a hard veto: if the physical machine violates the model’s kinematic topology, no amount of numerical optimization can fully compensate without expanding the model.

Optical layer veto:
The model assumes that only t^C_z depends on zoom. The source says: “we assume that only the translation vector in the direction of the optical axis, namely the z-axis direction, depends on the zoom value.” [PAGE 3] Real zoom lenses can produce lateral decentering, asymmetric distortion, principal-point drift, and focus-related changes. The paper itself says focus is not considered: “focus is not taken into consideration.” [PAGE 2] If the shot requires autofocus or depth-of-field changes, the intrinsics may vary with focus, violating the κ(n) model.

The real-data experiment provides a direct veto signal: “the camera model was not perfect, and the estimation error of the parameters was conspicuous” when panning or tilting was large and zoom was on the tele side. [PAGE 11] This is an empirical breakdown regime: large pan-tilt plus tele zoom exposes model imperfections.

Biomechanical layer veto:
The operator is part of the control loop. A cameraman under live pressure may pan quickly, overshoot, or operate near mechanical limits. If the camera platform has vibration or settling time, the encoder may report a transient pose that is not yet mechanically stable. The calibration model assumes quasi-static geometry: a given (p,t,n) maps to a fixed camera pose. If vibration or operator-induced motion violates quasi-staticity, the projection matrix is temporally inconsistent. The paper’s real-time claim depends on sensor values being usable immediately, but the physical layer can veto this by introducing delay or oscillation.

Environmental layer veto:
Weather and stadium conditions can veto the method through sensor degradation, pattern visibility, and mechanical stability. The paper’s calibration requires feature-point extraction from calibration patterns. [PAGE 5] If rain, condensation, fog, glare, or low illumination prevents reliable feature extraction, the calibration data are invalid. Wind can cause platform vibration or long-lens oscillation. Thermal drift can change focal length or principal point relative to the calibrated model. The source does not model weather explicitly, so any weather-induced deviation outside the calibration distribution is an unmodeled error source.

Proof of veto logic:
Let the calibrated model produce predicted pixel coordinate \hat u(η; p,t,n). Let the physical system produce true coordinate u_phys. If the layer violation creates a model mismatch m such that:

\[
u_{phys} = \hat u(η; p,t,n) + m
\]

and m exceeds the tolerance required by CG synthesis, the calibration fails for that operating condition. The paper’s CG results define a plausible tolerance band: detailed model mean error “1.24” pixels and maximum “5.81” pixels. [PAGE 9] The simple model fails with mean error “24.77” pixels. [PAGE 9] Real-data epipolar deviations of several pixels at tele end are already visible as accuracy loss. [PAGE 11]

Therefore, the cross-layer veto adjudication is:
- Encoder error veto: sensor values not precise enough. [PAGE 2]
- Axis-intersection veto: pan-tilt axes do not cross at one point. [PAGE 3]
- Zoom-translation veto: optical center shift is not purely axial. [PAGE 3]
- Focus veto: focus changes intrinsics but is not modeled. [PAGE 2]
- Tele-pan-tilt veto: large pan-tilt plus tele exposes model imperfection. [PAGE 11]
- Feature-extraction veto: weather or illumination prevents reliable pattern detection. [PAGE 5]
</CROSS_LAYER_VETO_ADJUDICATION>

The following are three verifiable RLVR veto scenarios. Each scenario defines a counterfactual failure mode, a physical or algorithmic test, and a predicted measurable outcome. The purpose is not to create betting lines or odds but to specify falsifiable veto conditions for a calibration policy.

Scenario 1: Non-intersecting or drifting pan-tilt axes

Counterfactual:
The platform’s pan and tilt axes do not intersect at a stable rotational center, or the intersection drifts under load. The calibration still uses the paper’s decomposition where the platform-to-pan-tilt translation is zero. [PAGE 3]

Formal veto condition:
Let the true platform-to-pan-tilt transform contain a nonzero translation τ(p,t):

\[
{}^{PT}M_{CP}^{true}(p,t)
=
\left(R_{pan}(p)R_{tilt}(t),\ \tau(p,t);\ 0,1\right)
\]

The calibrated model assumes τ=0. The induced reprojection error grows with lever arm Z and angle-dependent offset.

Verification test:
Use CG data or a motion-capture stage to inject a known offset τ. Re-run ICC/OCC. Measure epipolar-line error or reprojection error at multiple pan-tilt angles. Compare the detailed model with a model that estimates τ.

Predicted result:
If τ exceeds the mechanical tolerance implied by the paper’s high-accuracy regime, the error will increase with pan-tilt angle and distance from the rotational center. The source already shows that simplified models fail when rotational and optical centers differ: the simple model had mean error “24.77” pixels versus “1.24” for the detailed model. [PAGE 9]

Veto decision:
Reject the calibrated model for live CG synthesis if the measured error under injected offset exceeds the operational threshold derived from the detailed model’s envelope, for example the maximum CG trial error of “5.81” pixels [PAGE 9]. A stricter policy would require mean error below “1.24” pixels plus a safety margin for real optics.

Scenario 2: Sparse tele zoom sampling and missing small calibration patterns

Counterfactual:
The operator omits tele-end calibration patterns because they are hard to arrange or because the required range is assumed to be wide-only. The calibration data contain sampled zoom points only up to some n_max, or the small patterns are missing.

Formal veto condition:
The zoom-dependent parameter vector is interpolated:

\[
\phi_z(n) = \mathcal{I}_{spline}(\{(N_k,\hat\phi_z(N_k))\}_{k=1}^K)
\]

If the interpolation interval [N_k,N_{k+1}] is too wide or lacks tele support, the extrapolation error can diverge. The source explicitly notes poor interpolation when “the number of sampled zoom points was insufficient.” [PAGE 10]

Verification test:
Using the real or CG dataset, remove calibration data above a threshold, such as n > 750, then rerun OCC or ICC. Measure projection or epipolar error by zoom bin. The paper’s OCC(2) experiment did exactly this: accuracy declined when “calibration data with a zoom range greater than 750 (n > 750) were not used.” [PAGE 13]

Predicted result:
Error will remain acceptable in the calibrated zoom range but increase sharply near and beyond the missing tele interval. The paper also says that capturing calibration data in the required range only is efficient. [PAGE 13] Therefore, the veto should be range-specific: do not use tele extrapolation beyond the highest reliably calibrated zoom point.

Veto decision:
Reject operation at zoom values where the interpolated parameter uncertainty exceeds a pixel-error threshold. For real broadcast use, a conservative veto would require measured epipolar or reprojection error in the tele range to remain within the observed OCC regime: mean around “2.74” to “3.43” pixels or better, depending on CG tolerance. [PAGE 12]

Scenario 3: Focus-linked intrinsic drift or zoom-lens model mismatch

Counterfactual:
The lens changes effective focal length, distortion, or principal point with focus, or the zoom lens violates the assumption that only t^C_z changes with zoom. The paper’s model ignores focus: “focus is not taken into consideration.” [PAGE 2]

Formal veto condition:
The true intrinsic vector is not κ(n) but κ(n,z_focus), where z_focus is focus setting. The calibration model uses κ(n) only. The mismatch term is:

\[
\Delta\kappa = \kappa(n,z_{focus}) - \kappa(n)
\]

This mismatch maps to pixel error through the intrinsic Jacobian.

Verification test:
Fix zoom n and vary focus while imaging a calibration target or static scene. Estimate reprojection or epipolar error as a function of focus. Alternatively, collect calibration data at two focus states and test whether the CMPs remain stable.

Predicted result:
If focus changes intrinsics, the error will not be constant across focus states. The real-data experiment already shows model imperfection at tele end: “the camera model was not perfect, and the estimation error of the parameters was conspicuous.” [PAGE 11] Focus drift is a plausible contributor.

Veto decision:
Reject real-time calibration use if the measured focus-dependent error exceeds the CG synthesis tolerance. Since the source’s detailed CG model achieved mean “1.24” pixels and maximum “5.81” pixels [PAGE 9], a focus-veto policy could require that focus-induced error remain below the maximum detailed-model error or below a tighter application-specific threshold.

Cross-scenario RLVR policy:
A robust calibration agent should refuse or flag operation when any of the following verifiable conditions occurs:
1. Encoder or pose repeatability error produces image-space error beyond the calibrated residual envelope.
2. Calibration data do not cover the requested pan-tilt-zoom operating range, especially tele zoom.
3. Feature-point extraction fails due to weather, illumination, occlusion, or motion blur.
4. Epipolar-line verification shows systematic deviation correlated with pan-tilt magnitude or tele zoom.
5. The simplified camera model is required but the rotational-optical center distance is non-negligible; the source shows this causes large error. [PAGE 9]

These vetoes are verifiable because they rely on measurable outputs: reprojection error in pixels, epipolar-line deviation, zoom-bin error curves, and capture counts. They do not depend on undefined ratios or speculative heuristics.
