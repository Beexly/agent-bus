<CROSS_LAYER_VETO_ADJUDICATION>
Adjudicate veto authority across three layers. Define binary veto variables $V_i \in \{0,1\}$; the system permits a state transition only if $\neg (V_{\text{phys}} \lor V_{\text{bio}} \lor V_{\text{net}})$.

Physical layer: customer computer 108, merchant Web server 132, shopping cart database 152, and customer database 148 [PAGE 13]. Veto condition $V_{\text{phys}}=1$ upon storage-media failure, server outage, or client hardware loss. If database 152 is unreachable, event E3 cannot insert a product selection entry, and the cart relation remains undefined.

Biomechanical/human layer: governed by inter-touch interval $\Delta t_{\text{human}}$. Veto condition $V_{\text{bio}}=1$ iff $\Delta t_{\text{human}} > 604800 \text{ s}$ [PAGE 13]. This is a hard temporal veto: even if the physical and network layers are perfectly healthy, a human who does not access the cart for eight days triggers irreversible data destruction [PAGE 13]. No application-layer logic can override this because the purge predicate is monotonic in elapsed seconds.

Network/weather layer: adverse conditions can delay or corrupt the HTTP call carrying cookie information 140 [PAGE 13]. If the HTTP exchange for event E2 times out, program 144 cannot determine whether a cart exists, potentially creating a duplicate cart structure. Network partition thus vetoes exactly-once cart association.

Adjudication hierarchy: $V_{\text{bio}}$ is absolute and time-irreversible; $V_{\text{phys}}$ and $V_{\text{net}}$ are transient and recoverable upon restoration. The source text provides no mechanism to resurrect a purged cart [PAGE 13], proving that biological time dominates software state in this architecture.
</CROSS_LAYER_VETO_ADJUDICATION>
