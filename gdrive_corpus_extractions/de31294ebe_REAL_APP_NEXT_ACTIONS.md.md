<DESCRIPTION>This classic paper critiques the Internet Engineering Task Force's modular design philosophy, where each protocol (TCP, IP, UDP) adds headers and processing overhead. Clark argues that this layered approach inevitably introduces inefficiencies and points of failure. In our case, the Webpack -> HTML -> CDN -> Shim.js pipeline is a four-layer overlay on top of HTTP/HTTPS. Each layer is supposed to provide encapsulation, but the reality is that attackers need only breach one layer to compromise the entire chain. For instance, a man-in-the-middle can strip the CDN's TLS termination and rewrite the shim.js before re-encrypting, rendering the HTTPS certificate invalid but leaving the flow technically functional because the browser accepted the cert originally.</DESCRIPTION>

<DEFINITION>The simultaneous existence of multiple implementation paths for identical functionality (e.g., local optimization scripts and CDN-hosted shims) undermines the ability to reason monolithically about program correctness. SRPF forces developers to maintain duplicate state machines (one in build.js, one in cdn.jsdelivr.io), increasing cognitive load and likelihood of oversight.</DEFINITION>
