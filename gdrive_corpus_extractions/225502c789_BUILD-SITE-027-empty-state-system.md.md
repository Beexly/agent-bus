<CROSS_LAYER_VETO_ADJUDICATION>
Physical, biomechanical, environmental veto logic.

Three layers are adjudicated before any empty-state change is merged into the shipping clone.

Layer 1 — Physical. Viewport and device constraints: mobile layout must work at small breakpoints (implementation requirement: mobile layout works, [PAGE 1]); device pixel ratio and screen size affect rendering of high-contrast design tokens; ambient light (outdoor/sunlight exposure) demands high contrast and calm reading states per Design Direction [PAGE 1]; reduced-motion preference (prefers-reduced-motion: reduce) must be honored to avoid vestibular triggers. Veto predicate φ_physical = (viewport < mobile breakpoint) ∨ (reduced-motion ignored) ∨ (contrast insufficient for bright ambient light).

Layer 2 — Biomechanical. Touch target width W ≥ 44 css px (Fitts's law, MT = a + b log₂(D/W + 1) [seconds]); reading distance ≈ 40 cm requires legible type scale and strong hierarchy [PAGE 1]; keyboard focus order and visible focus indicators; screen-reader labels for empty-state illustrations and CTAs; no focus traps. Veto predicate φ_biomech = (W < 44 css px) ∨ (focus trap detected) ∨ (missing screen-readable label).

Layer 3 — Environmental / weather-adjacent. Bright sunlight readability: high-contrast calm reading states must remain legible under high ambient luminance; low-light readability must not rely on color alone; no casino/tout visual noise that increases cognitive load in stressed or distracted contexts [PAGE 1]. Veto predicate φ_env = (C_lum < 4.5:1 normal or < 3:1 large) ∨ (color-only signaling under variable lighting).

Adjudication rule. Let VETO = φ_physical ∨ φ_biomech ∨ φ_env. If VETO = true, the change is blocked and the isolated rollback plan executes: "Revert the isolated component/route/style change or disable behind a feature flag. No production data rollback should be needed." [PAGE 1] Pass condition: all three layers satisfy Acceptance Criteria (mobile layout works, accessibility basics pass, no method leakage or betting-hype copy, performance budget not worsened) within the Test Plan checks [PAGE 1]. This veto is route-isolated: it does not require production DB rollback, billing changes, or secret rotation [PAGE 1].
