<CROSS_LAYER_VETO_ADJUDICATION>
A cross-layer veto is a physical/biomechanical condition under which the AI recommendation must be flagged "no-go" regardless of its confidence. Four provable vetoes follow, plus an honest note on the "weather" layer.

Veto 1 — Depth-ambiguity (contact proxy failure). The impact operator's contact test is 2D IoU > 0.3 [PAGE 7]. In 3D, contact requires the foot-head Euclidean distance to reach ~0. A trajectory that crosses in front of the head at depth separation δ > 0 yields high IoU with zero contact. Proof: IoU is invariant to depth ordering; contact is not; therefore IoU > 0.3 does not imply contact. Veto condition: single-view geometry with no depth term ⇒ recommend "insufficient evidence" whenever |foot−head| depth is unobservable.

Veto 2 — Frame-rate singular regime. Because a_i = Δv/Δt [PAGE 7], for fixed Δv the computed deceleration diverges as Δt → 0 and shrinks as Δt grows. The worked 106 m/s² assumes Δt = 0.033 s [PAGE 7], yet acquisition is ">60 fps" [PAGE 10] (Δt ≤ 0.0167 s). At 120 fps the same Δv over one frame doubles a_i; at 30 fps it halves. Near a_threshold the impact Boolean is frame-rate-determined, not physics-determined. Veto: unless a_threshold is re-derived per fps, flag decisions where a_i lies within one frame-quantization band of threshold.

Veto 3 — Motion-blur / occlusion collapse. Deblurring assumes an invertible kernel H [PAGE 11]; at peak kick velocity the foot spans multiple pixels per frame, keypoint confidence C_ankle degrades (nominal 0.91 [PAGE 6]), and the Kalman filter free-runs on its prior (Eq. 2 innovation → 0 under occlusion [PAGE 12]). The smoothed trajectory attenuates the true deceleration spike, producing a false *negative* on the highest-speed impacts — the exact events that score 5. Veto: when C_ankle falls below detector threshold for ≥2 frames around the candidate impact, suppress auto-scoring.

Environmental layer ("weather" analog): indoor Taekwondo has no weather, so the honest substitution is arena lighting and camera placement. The wide-angle, upper-body-focused rig [PAGE 10–11] plus variable illumination stresses the confidence operator C_i ("varied lighting and occlusion scenarios" [PAGE 6]). Veto: recalibrate C_i thresholds per venue; do not port a threshold tuned under one lighting rig to another without revalidation.

Net adjudication: none of these vetoes are hypothetical — each maps to a specific operator in the source. A defensible system must gate every 3- or 5-point suggestion behind Veto-1 (depth), Veto-2 (fps-consistent threshold), and Veto-3 (confidence floor) checks before the jury prompt.
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
RLVR framing: treat the jury/ground-truth confirmation as the verifiable reward and ask where the policy's action would be provably wrong. Each scenario below is falsifiable against an external oracle (3D motion capture, high-speed camera, or rulebook) and paired with a concrete prediction.

Veto Scenario A — Depth-crossing false positive.
Setup: attacker's foot crosses in front of the head in image space; true minimum 3D foot-head distance d_min = 0.15 m (no contact).
Verifiable oracle: marker-based 3D mocap giving d_min.
Prediction: FST.ai computes IoU > 0.3 [PAGE 7] → outputs Impact = True, and if φ_torso > threshold → Score = 5. Ground truth = no contact, score 0. Falsifiable test: replay crossing trajectories with known depth; measure false-positive rate. Expected failure because IoU has no depth term (Veto 1).

Veto Scenario B — Frame-rate threshold flip.
Setup: one physical kick, Δv fixed, replayed at 30, 60, 120, 240 fps.
Verifiable oracle: a single canonical deceleration computed from continuous mocap velocity.
Prediction: a_i = Δv/Δt [PAGE 7] takes four different values; for a_threshold placed near the 60-fps value, the impact Boolean is True at 30 fps and False at 240 fps (or vice versa) for the *same* physical event. Falsifiable test: sweep fps, log the score decision; a decision that changes with fps alone proves frame-rate dependence (Veto 2). Concrete number: if Δv = 3.5 m/s, a_i = 106 m/s² at 30 fps but ≈ 424 m/s² at 120 fps.

Veto Scenario C — Occlusion-induced false negative.
Setup: at peak velocity the ankle is occluded for 2–3 frames; C_ankle < detector floor; Kalman filter (Eq. 2, [PAGE 12]) interpolates across the gap.
Verifiable oracle: 240 fps ground-truth ankle deceleration.
Prediction: the smoothed trajectory reduces the observed Δv, so a_i falls below a_threshold → Impact = False (missed 5-point turning kick), even though contact occurred. Falsifiable test: inject synthetic keypoint dropouts and measure recall on true impacts; recall should drop sharply for ≥2-frame gaps (Veto 3).

Cross-cutting prediction: because all three vetoes bias the same pipeline, the aggregate confusion matrix should show *asymmetric* error — false positives concentrated in crossing/foreshortened trajectories (Scenario A) and false negatives concentrated in high-speed occluded impacts (Scenario C). A validation study reporting only per-example confidences (as the paper currently does [PAGE 7, 12, 13]) cannot detect either; the verifiable target is a per-scenario precision/recall table against 3D ground truth, which the present document does not yet provide.
