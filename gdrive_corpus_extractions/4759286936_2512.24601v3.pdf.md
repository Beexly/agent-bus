Algorithm 1 (RLM):
```
state ← InitREPL(prompt=P)
state ← AddFunction(state, sub_RLM_M)
hist ← [Metadata(state)]
while True do
    code ← LLM_M(hist)
    (state, stdout) ← REPL(state, code)
    hist ← hist ⧺ code ⧺ Metadata(stdout)
    if state[Final] is set then

```

This severs the identity $|P| \le K$ that binds every prior scaffold, which is why the abstract's claim is "inputs more than an order of magnitude beyond model context window limits" [PAGE 1] — with $K = 272\text{K}$ tokens for GPT-5 and runs at $10\text{M}{+}$ tokens, the ratio $|P|/K \approx 37\times$.

Multi-hop chain. (1) *Why compaction is structurally lossy, not merely suboptimal.* Compaction is a repeated map $C:\Sigma^{\le K}\to\Sigma^{\le K}$. For a task whose answer is a function of $\Omega(|P|)$ items, any summary obeying $|{\cdot}|\le K < |P|$ must be non-injective on the answer-relevant features; information is destroyed with probability bounded away from zero. The paper states this qualitatively: "compaction is rarely expressive enough for tasks that require dense access throughout the prompt. It presumes that some details that appear early in the prompt can safely be forgotten" [PAGE 2]. (2) *Why the symbolic handle is the real primitive.* Algorithm 1 keeps $P$ as a REPL variable and lets the model emit code that slices $P$ and calls `llm_query` on each slice. The access pattern shifts from attention-with-decay over a monolithic sequence to *random access* over indices — precisely the regime where context rot [Hong et al. 2025] does not apply, because no slice is ever longer than $K_{\text{sub}}$. (3) *The complexity-class lens is the paper's deepest idea.* Difficulty is not length but the scaling of answer-relevant information with length: S-NIAH is $O(1)$, OOLONG is $\Theta(|P|)$ ("the answer depends explicitly on almost every line" [PAGE 4]), OOLONG-Pairs is $\Theta(|P|^2)$ ("requires processing quadratically-many items" [PAGE 5]). This dissolves the apparent paradox that GPT-5 is fine at 1M on S-NIAH yet near-zero on OOLONG-Pairs — same length, different $\kappa$. (4) *Recursion depth is an expressivity/reliability dial, not a free good.* Depth increases decomposition fidelity but multiplies per-call failure probability; the crossover is model-dependent. (5) *The training insight is a factorization.* Because "being an effective sub-call model is roughly similar to being a general purpose reasoning model" [PAGE 5], only the *root policy* (probe, chunk, recurse, finalize) is hard, so 1,000 trajectories suffice to lift an 8B model.

Gray-zone audit. (i) Asymmetry: GPT-5 runs root, GPT-5-mini runs sub-calls [PAGE 5]; Qwen runs the same model at all depths — the GPT-5-vs-Qwen depth curves are not measuring identical interventions. (ii) Baseline costing: compaction baselines used GPT-5-nano for summarization [PAGE 5], so cost comparisons on BrowseComp+ are not apples-to-apples. (iii) LongCoT-mini uses a *different harness* (Prime Intellect rlm-harness) and a different finalization mechanism [PAGE 24], so Table 2 is not directly comparable to Table 1. (iv) Small-$n$: OOLONG-Pairs has $n=20$, OOLONG/S-NIAH $n=50$ — a single task is 5% or 2%. (v) No variance is reported on the 28.3% median training gain, and it is a single recipe. These are real limits on the strength of the headline deltas.
</THINK_TRACE>

<SOURCE_OPERATORS_AND_EQUATIONS>
Notation/units: $K$ = root window (tokens, T); $c$ = per-turn history trim (T/turn); $K_{\text{sub}}$ = sub-model window (T); $|P|$ = prompt length (T); $s$ = sub-call payload (T); costs in USD; runtimes in s; probabilities dimensionless.

**1. Iteration bound (quoted, [PAGE 3] fn.2).** "if we trim each turn to $c$ tokens, we will have at most $K/c$ root iterations, each of which can launch arbitrarily many sub-calls."
$$N_{\text{root}} \le \left\lfloor \frac{K}{c} \right\rfloor \quad [\text{dimensionless}].$$
This is the only *finite* budget at the root; sub-call fan-out is unbounded by design.

**2. Chunking constraint and sub-call count.** Partition $P$ into $m=\lceil |P|/s\rceil$ slices with feasibility constraint
$$s \le K_{\text{sub}} \quad [\text{T}].$$
Linear tasks (OOLONG): $N_{\text{sub}} = \Theta(m) = \Theta(|P|/s)$. Pairwise tasks (OOLONG-Pairs): $N_{\text{sub}} = \Theta(m^2) = \Theta(|P|^2/s^2)$. These instantiate the stated goal of "$\Omega(|P|)$ or even $\Omega(|P|^2)$ processes" [PAGE 4].

**3. Semantic work.** Total sub-model token throughput $W$:
$$W = \Theta(N_{\text{sub}}\cdot s) = \begin{cases}\Theta(|P|) & \text{linear-complexity task}\\ \Theta(|P|^2/s) & \text{quadratic-complexity task.}\end{cases}$$

**4. Cost model (analytical, consistent with data).** With root cost $c_{\text{root}}$, sub cost $c_{\text{sub}}$:
$$\mathbb{E}[C_{\text{RLM}}] = c_{\text{root}}\,\mathbb{E}[N_{\text{root}}] + c_{\text{sub}}\,\mathbb{E}[N_{\text{sub}}] = \Theta(|P|) \text{ on linear tasks.}$$
Source anchors: "RLM costs scale proportionally to the complexity of the task" [PAGE 7]; on BrowseComp+ the linearly extrapolated cost of GPT-5-mini ingesting 6–11M tokens is "$1.50−\$2.75$, while RLM(GPT-5, depth=1) has an average cost of $\$0.99$" [PAGE 6] — i.e. the $\Theta(|P|)$ incumbent slope exceeds the RLM constant-factor-prefixed slope.

**5. Error-propagation model (analytical; explains Table 1 depth reversal).** Let $p$ = per-node failure probability (syntax error, bad decomposition, output overflow). If a correct root answer requires correctness along a critical path whose expected length grows with depth $d$,
$$P_{\text{success}}(d) \approx (1-p)^{\,g(d)}, \qquad g'(d) > 0.$$
Benefit of depth (finer decomposition) $B(d)\uparrow$; cost (compounded error + latency) $L(d)\uparrow$; choose $d^\star = \arg\max_d [B(d)-L(d)]$.
- GPT-5 ($p$ small): Table 1 OOLONG-Pairs is monotone increasing $43.9 \to 58.0 \to 65.5 \to 76.0$ for $d=0,1,2,3$, so $d^\star \ge 3$.
- Qwen3-Coder ($p$ large): OOLONG-Pairs $17.3 \to 23.1 \to 19.0 \to 21.1$, non-monotone, $d^\star \le 1$. Mechanism is stated: "Qwen3-Coder-480B-A35B often makes syntax errors that result in failed outputs, and having sub-RLM calls propagates this issue to sub-calls" [PAGE 9].

**6. Information lower bound.** For an answer functional $f:\Sigma^\star\to\mathcal Y$ depending on all $\Theta(|P|)$ items, any correct algorithm reads $\Omega(|P|)$. OOLONG-Pairs is *engineered* to force the quadratic bound: "each question is created such that the model must return all pairs satisfying some properties, rather than just counting" [PAGE 26] — defeating the inclusion–exclusion shortcut that would collapse $\binom{n}{2}$ to $O(n)$.

**Breakdown/singularity regimes.** (a) $|P|$ contains an item $> K_{\text{sub}}$: the map $s\le K_{\text{sub}}$ is infeasible without intra-item chunking (unmodeled hard failure). (b) Per-call output ceiling $<$ node reasoning length: sub-calls truncate (observed for Qwen3-235B, [PAGE 17]). (c) $p \to$ high: $(1-p)^{g(d)} \to 0$, depth becomes strictly harmful. (d) Iteration exhaustion: $N_{\text{root}} \to K/c$ before `Final` is set — the "outlier trajectories where the RLM struggles to find an answer" driving the cost tail [PAGE 7]. Context-rot decay $A(L,\kappa)$ is described qualitatively (decreasing in length $L$ and complexity class $\kappa$, [PAGE 7]) but **not** given a closed form in-source; I decline to fabricate one.
</SOURCE_OPERATORS_AND_EQUATIONS>

<RETROCAUSAL_GENEALOGY>
Lineage of the core primitive. The REPL-as-external-memory idea descends from program-aided reasoning: PAL and Program-of-Thoughts (write code, execute, read result), CodeAct [Wang et al. 2024, cited PAGE 5], and ReAct [Yao et al. 2023] — all of which execute code but, per the paper, do not offload the *user prompt* into the environment. Recursive/sub-agent delegation descends from ViperGPT [Surís et al. 2023], THREAD, ReDel [Zhu et al. 2024], Context Folding [Sun et al. 2025], AgentFold, and DisCIPL [Grand et al. 2025]; the paper's stated delta is that these "are unable to handle long context inputs beyond the length of the base LM" and "verbalize sub-calls autoregressively rather than producing them programmatically" [PAGE 3, PAGE 9]. The lossy-management lineage is Baleen [Khattab et al. 2021] → ReSum [Wu et al. 2025] → memory hierarchies (MemGPT, Mem0, G-Memory); RLM differs because "all context window management is implicitly handled by the LM itself" [PAGE 9]. The expressive-power justification leans on Merrill & Sabharwal [2024] (chain-of-thought adds formal power to transformers) — RLM positions recursion as the next such axis. The training lineage is STaR / Quiet-STaR [Zelikman et al.] bootstrapping, instantiated here as rejection fine-tuning plus one RLVR run.

Multi-week traps (pitfalls that require sustained work to escape, several documented as negatives in Appendix B [PAGE 17]): (1) *The bigger-window trap* — assuming architectural/long-context models (Infini-attention, SSMs) solve the problem; context rot persists *within* the window, so a 10M window does not imply 10M effective. (2) *The verbalized-delegation trap* — sub-agents that emit calls in prose are bounded by the parent's output length; the fix is *programmatic* recursion. (3) *The compaction-compressibility trap* — treating dense tasks as summarizable; OOLONG-Pairs was explicitly built to defeat shortcut aggregation [PAGE 26]. (4) *The prompt-portability trap* — reusing GPT-5's RLM prompt for Qwen3-Coder caused runaway sub-calling ("the model will try to perform a subcall on everything, leading to thousands of LM subcalls") [PAGE 18]; a one-line warning was required. (5) *The protocol trap* — `FINAL()` vs `FINAL_VAR()` confusion (16% and 13% of turns, [PAGE 16]) required programmatic patching before distillation would work.
</RETROCAUSAL_GENEALOGY>

<RECURSIVE_THEORY_OF_MIND>
Mapping to model self-modeling under pressure: does the RLM, when a sub-task fails or an answer stalls, *regress to a habit*, execute a *counter-trap*, or run out the *clock*?

Crisis habit regression. Under failure the model reverts to lower-level, cheaper behaviors that are locally plausible but globally wrong. Documented instances: Qwen3-Coder on OOLONG-Pairs already had the correct answer assembled in a REPL variable, yet "attempts to re-generate the answer with more recursive sub-LM calls... repeats this process 5 times" and finally returns a *root-generated* (wrong) answer, "never returned the answer it built up in its code environment" [PAGE 35]. Without sub-calls, the depth-0 ablation is "forced to use keyword heuristics" on information-dense tasks [PAGE 7] — a regression from semantic transformation to string matching. This is habit regression driven by the model's imperfect self-model of where its own state lives ("If a value isn't in `answers`, it doesn't exist" is the corrective the LongCoT prompt tries to install [PAGE 24]).

Counter-trap (the trained/prompted override). Two mechanisms counteract regression: (a) prompt-level — the Qwen3-Coder warning line, and the LongCoT "Orchestrate; don't solve" contract forcing memoized `answers={}` dict lookups, per-node verification, and "if you catch yourself writing Python that enumerates, solves, simulates... STOP and delegate" [PAGE 25]; (b) weight-level — RLVR on MRCRv2 (train 32k–64k / 2-needle → eval 512k–1M / 8-needle) generalized, i.e. the policy learned *not* to regress to short-context habits [PAGE 8, PAGE 17]. The counterfactual is explicit: base GPT-5.2 *with* decomposition hints but *without* a REPL gets confused and drops to 28.6 overall [PAGE 24] — hints alone are a counter-trap that backfires without the isolation the REPL provides.

The clock. Runtime is the pressure variable: all LM calls are "blocking / sequential" [PAGE 7], so the 95th-percentile runtime explodes on runaway trajectories (Figures 12–13), and iteration exhaustion at $N_{\text{root}} = K/c$ is the hard stop. The model's implicit theory-of-mind over its *own* remaining budget is weak: it neither reliably recognizes a completed sub-answer nor bounds its verification loops, which is why an 8B model needs distillation to acquire the "stop and finalize" self-model. Recursive depth compounds this: a depth-$d$ sub-RLM must model its children's completion, and per the $(1-p)^{g(d)}$ law, each additional layer of self-modeling is another opportunity to regress.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
The "vetoes" here are hard system constraints that can nullify RLM quality regardless of algorithmic cleverness — the physical-layer analogs of weather/biomechanics. No-veto proof: RLM achieves its stated gains **iff all four constraints hold**.

V1 — Sub-model window $K_{\text{sub}}$ (hard, physical). Requirement $s \le K_{\text{sub}}$. The prompt hard-codes the value: sub-LLMs "can handle around 500K chars" for GPT-5-mini [PAGE 18] and "~32k tokens (approximately ~24k characters)" for Qwen3-8B [PAGE 20]. Proof of binding-ness: the Qwen3-8B prompt had to lower feed guidance to "2-3 documents per sub-LLM query" versus "10 documents" for GPT-5 — same algorithm, tighter veto. If any answer-relevant item exceeds $K_{\text{sub}}$, the decomposition is infeasible without intra-item splitting (unmodeled).

V2 — Per-call output ceiling (hard). Thinking models emit long reasoning; if max output $<$ required node reasoning, the sub-call truncates. This vetoed Qwen3-235B: "multiple trajectories running out of output tokens while producing outputs due to thinking tokens exceeding the maximum output token length" [PAGE 17], shrinking its OOLONG gain to 30%→38% versus larger gains for non-truncating models.

V3 — REPL syntactic validity (hard). Every root action is `code ← LLM_M(hist)` executed by `REPL(state, code)` [PAGE 4]. Invalid code is a hard veto on that turn. This is the dominant reason depth reverses for Qwen3-Coder: "trajectories contain significantly more syntax errors... having sub-RLM calls propagates this issue to sub-calls" [PAGE 9]. Coding ability below threshold ⇒ V3 fires constantly ⇒ RLM $\le$ base.

V4 — Finalization protocol (protocol-level veto). Terminating requires setting `state[Final]`; the classifier between "next turn" and "answer" is "brittle for RLMs" (Appendix B, [PAGE 17]). Misclassified finals cause both premature returns (Qwen3-Coder returning a root guess over its correct REPL variable [PAGE 35]) and non-termination feeding the cost tail.

Feasibility (not correctness) veto — latency: sequential calls make wall-clock the practical constraint; "the tail end (e.g. 95th percentile) shows extremely long runtimes, which is mainly due to sequential sub-LLM calls" [PAGE 41]. Adjudication: RLM survives iff (coding ability $\ge$ threshold) $\wedge$ (every item $\le K_{\text{sub}}$) $\wedge$ (per-call output $\ge$ node reasoning) $\wedge$ (valid FINAL protocol). Each veto, when fired, drives RLM toward or below the base-model floor — which is exactly the observed pattern where base RLM (depth-0) still wins on non-dense CodeQA but collapses on dense tasks.
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
Three falsifiable veto hypotheses, each grounded in source evidence with a concrete, checkable prediction. (RLVR here = the reinforcement-learning-with-verifiable-rewards axis the paper opens in Figure 3(b), [PAGE 8].)

Veto-1: Coding-ability veto. *Claim:* if a base model's code-generation ability is below a threshold, RLM underperforms even its own vanilla baseline. *Evidence:* "smaller models like Qwen3-8B struggled without sufficient coding abilities" (Appendix B, [PAGE 17]); gains appear only after distillation. *Prediction (verifiable):* rank a suite of base models by pass@1 on a code benchmark; RLM-minus-vanilla delta should be negative below the threshold and positive above, with the sign change monotone in code ability. Falsifier: a non-coding-strong model showing positive RLM delta with $p_{\text{syntax}}$ high.

Veto-2: Output-budget veto. *Claim:* capping per-call output tokens below node reasoning length collapses RLM specifically on compositional tasks, and the effect is larger for RLM than for vanilla. *Evidence:* Qwen3-235B truncation [PAGE 17]. *Prediction (verifiable):* re-run Qwen3-235B RLM while raising max output tokens; the OOLONG/OOLONG-Pairs gap to Qwen3-Coder should shrink monotonically. Symmetric test: cap GPT-5 output low; RLM depth $\ge 2$ should degrade faster than base (more nodes ⇒ more truncations), consistent with the $(1-p)^{g(d)}$ law where $p$ now includes truncation.

Veto-3: Sub-call-window veto. *Claim:* setting chunk payload $s > K_{\text{sub}}$ drives sub-call accuracy toward the base-model-at-that-length, erasing the RLM advantage. *Evidence:* prompts fix $s$ near $K_{\text{sub}}$ ("~500K chars" GPT-5, "~24k chars" Qwen3-8B, [PAGE 18/20]). *Prediction (verifiable):* sweep $s \in \{0.5, 1, 2\}\times K_{\text{sub}}$ on OOLONG; accuracy should be flat then fall sharply once $s > K_{\text{sub}}$ (context rot inside the sub-call). Corollary on the RLVR run: the MRCRv2 2-needle→8-needle generalization [PAGE 8] should break if per-call needle density at eval exceeds sub-call reliable-counting capacity — i.e. generalization is contingent on the task fitting under $K_{\text{sub}}$ per chunk, not on the RL objective alone.

Cross-check against Table 1 supports all three: RLMs win decisively where coding is strong (GPT-5), output fits, and $s \le K_{\text{sub}}$ (BrowseComp+ 91.3, OOLONG-Pairs up to 76.0), and lose or tie where a veto fires (Qwen3-Coder at depth $>1$; base models $\le 0.1$ on OOLONG-Pairs). Each veto is independently testable by a single controlled ablation.
</RLVR_COUNTERFACTUAL_VETOES>

Bottom line: the paper's contribution is a type-level reframing (prompt as environment state, not model input) that makes $|P|$ independent of $K$, with task *complexity class* — not raw length — as the correct predictor of degradation. The rigorous caveats are the GPT-5-root/GPT-5-mini-sub asymmetry, nano-based baseline costing, the separate LongCoT harness, small-$n$ benchmarks, and the absence of variance on the training gains; the hard vetoes ($K_{\text{sub}}$, output ceiling, code validity, FINAL protocol) bound where the method holds.
