The source is a systems-integration paper, not primarily a new empirical state-of-the-art claim. Its central object is the operator defined on [PAGE 2]: “Formally, an action spotting algorithm is defined as a function F : V →A × T, mapping the video V to a set of action-timestamp pairs (ai, ti).” The paper immediately factorizes this operator into a three-stage computational graph: “The algorithmic structure can be segmented into three primary components: the backbone, the neck, and the head.” [PAGE 2]. This factorization is the main conceptual invariant: any integrated method must be expressible as video → frame features → refined temporal features → discrete action-time outputs.

A first gray-zone issue is notation overloading. The paper uses T both for the total number of frames and for timestamps. For derivation, I separate them: let video length be T frames, and let timestamps be t ∈ ℝ≥0 seconds. The output is then a finite set of pairs (class, timestamp), not a single continuous curve. This matters because the evaluation section introduces two different temporal tolerances, so the output space must be scored under a matching relation rather than simple frame-wise equality.

From [PAGE 4], SoccerNet-v2 contains “videos for 500 football games” and “more than 110,458 temporally-anchored actions, from 17 common action classes.” Dividing total actions by games gives an average event density of at least 110458 / 500 ≈ 220.9 actions per game. The test set is described as “100 videos of 45min” [PAGE 4], i.e. 100 × 45 × 60 = 270,000 seconds of video. If actions were uniformly distributed, the mean spacing would be 2700 / 220.9 ≈ 12.2 seconds per action within a 45-minute match. This is an assumption, not a source claim, but it exposes a metric gray zone: with loose tolerance as large as 60 seconds [PAGE 4], a random timestamp has a high chance of falling inside some event window. For tight tolerance, the random-chance problem is smaller but still nontrivial.

The evaluation semantics are explicitly asymmetric. “Loose Average mAP” allows predictions “within a broad temporal window around the actual event, ranging from 5 to 60 seconds,” while “Tight Average mAP” enforces “within a 1 to 5 second tolerance” [PAGE 4]. Therefore, a method can improve loose mAP by detecting coarse event neighborhoods, while tight mAP measures precise temporal alignment. The table on [PAGE 5] shows this distinction starkly: feature-based pooling methods have loose mAP values from 20.8 to 51.5 but tight mAP values only from 2.1 to 8.3. PTS reaches 70.4/63.9 and 72.2/66.2 loose/tight. The large tight-loose gap for pooling methods is not merely a performance fact; it indicates that their temporal heads may localize the correct semantic context without satisfying the strict timestamp requirement.

A second gray-zone audit concerns reproducibility. The abstract says the integrated methods achieve “performance metrics that match those of the original, disparate codebases” [PAGE 1]. However, Table I reports only OSL-ActionSpotting results, not side-by-side original numbers. Thus the source supports internal consistency of reproduced numbers but does not provide enough evidence for external equivalence unless original results are known from cited papers. This is a reproducibility boundary: the paper demonstrates that the library can run the methods and produce plausible benchmark values, but the table alone does not prove exact numerical identity.

A third audit concerns timing. The DALI section claims “around 33% time improvement for the training steps and 50% improvement for each epoch’s validation steps” compared with OpenCV loaders [PAGE 5]. This is a relative wall-clock claim, not an absolute throughput law. It depends on hardware, disk, decoding path, and whether frames are cached. The paper also states that timing was estimated on “1 GPU RTX1080, 2 CPU cores and 32GB RAM, except for the PTS that required 4 GPU RTX A500 and 80GB of RAM” [PAGE 4]. Therefore, PTS timing cannot be directly compared with feature-based timing as if hardware were identical. The timing table is a reproducibility artifact, not a hardware-normalized efficiency proof.

A fourth multi-hop derivation links temporal sampling to possible localization limits. PTS uses “224p videos at 25fps as input” and the backbone processes “frames at 2fps” [PAGE 4]. At 2 fps, the sampling interval is 0.5 seconds. Under a Nyquist-like assumption, temporal features can support localization precision down to a scale comparable to the sampling interval, but not arbitrarily below it without interpolation or recurrent accumulation. Since tight tolerance is 1 to 5 seconds [PAGE 4], 2 fps is nominally sufficient for the tight regime. The breakdown regime appears if future tasks require sub-0.5-second precision: then 2 fps becomes a physical bottleneck unless the head learns sub-frame regression or higher frame rate is used.

The deepest gray-zone issue is the relation between semantic correctness and timestamp correctness. Action spotting is defined as “the task of identifying and anchoring temporally specific actions semantic within a video” [PAGE 2], and football regulation motivates precise timestamps [PAGE 2]. But the library’s evaluation collapses this into two scalar mAP regimes. The paper does not report calibration, confidence intervals, per-class breakdown, or camera-cut robustness. Those omissions do not invalidate the source, but they define the outer boundary of what can be rigorously inferred from the six pages.

<SOURCE_OPERATORS_AND_EQUATIONS>
Let a broadcast video be represented as an ordered frame sequence
\[
V = (i_1, i_2, \ldots, i_T), \qquad i_t \in \mathcal{I}, \quad t = 1,\ldots,T,
\]
where \(T\) is the total number of frames, as in [PAGE 2]. The paper’s spotted output is a set of action-timestamp pairs. To avoid notation collision, write
\[
\widehat{A} = \{(\widehat{c}_m, \widehat{t}_m)\}_{m=1}^{\widehat{n}},
\qquad
\widehat{c}_m \in \mathcal{C}, \quad \widehat{t}_m \in \mathbb{R}_{\ge 0},
\]
where \(\mathcal{C}\) is the set of action classes and \(\widehat{t}_m\) has SI unit seconds. The ground truth is
\[
A^\star = \{(c_k, t_k^\star)\}_{k=1}^{n}.
\]
The source defines the spotting map as
\[
F : V \mapsto A \times T
\]
[PAGE 2], which operationally becomes
\[
F_\theta : V \mapsto \widehat{A}.
\]

The backbone, neck, and head equations are given qualitatively on [PAGE 2]:
\[
F_{\text{feat}} = \mathrm{Backbone}(i_1, i_2, \ldots, i_T),
\]
\[
F'_{\text{feat}} = \mathrm{Neck}(F_{\text{feat}}),
\]
\[
(\widehat{A}, \widehat{T}) = \mathrm{Head}(F'_{\text{feat}}).
\]
In tensor units, if the backbone emits \(D_b\) channels per sampled frame, then
\[
F_{\text{feat}} \in \mathbb{R}^{M \times D_b},
\]
where \(M\) is the number of processed temporal positions. The neck maps
\[
\mathrm{Neck} : \mathbb{R}^{M \times D_b} \rightarrow \mathbb{R}^{M \times D_n},
\]
and the head maps
\[
\mathrm{Head} : \mathbb{R}^{M \times D_n} \rightarrow \mathcal{P}(\mathcal{C} \times \mathbb{R}_{\ge 0}),
\]
where \(\mathcal{P}\) denotes a finite predicted set.

For PTS, the source states: “PTS ... use the 224p videos at 25fps as input. The backbone processes the frames at 2fps with RegNetY (RNY) and a GSM temporal shift.” [PAGE 4]. If the original video has frame rate \(f_v = 25\ \mathrm{frames/s}\), the frame interval is
\[
\Delta_v = \frac{1}{f_v} = 0.04\ \mathrm{s}.
\]
If the backbone samples at \(f_s = 2\ \mathrm{frames/s}\), the temporal stride in original frames is approximately
\[
S = \frac{f_v}{f_s} = \frac{25}{2} = 12.5\ \text{original frames per sampled frame}.
\]
The number of sampled frames is approximately
\[
M \approx \left\lfloor \frac{T}{S} \right\rfloor,
\]
with exact indexing depending on endpoint handling. The temporal quantization scale of the sampled stream is
\[
\Delta_s = \frac{1}{f_s} = 0.5\ \mathrm{s}.
\]
This is not a fake ratio; it is a sampling interval derived from the stated 2 fps backbone processing rate.

The evaluation metrics can be formalized. For tolerance \(\delta\) in seconds, define the matching indicator
\[
\mathbf{1}_{\delta}(\widehat{c}, \widehat{t}; c^\star, t^\star)
=
\begin{cases}
1, & \widehat{c} = c^\star \ \text{and}\ |\widehat{t} - t^\star| \le \delta,\\
0, & \text{otherwise}.
\end{cases}
\]
The source defines loose tolerance as “ranging from 5 to 60 seconds” and tight tolerance as “within a 1 to 5 second tolerance” [PAGE 4]. Thus
\[
\delta_{\text{loose}} \in [5, 60]\ \mathrm{s},
\qquad
\delta_{\text{tight}} \in [1, 5]\ \mathrm{s}.
\]

For class \(c\), let \(N_c\) be the number of ground-truth instances. At a decision threshold producing \(\mathrm{TP}_c\) true positives and \(\mathrm{FP}_c\) false positives,
\[
p_c = \frac{\mathrm{TP}_c}{\mathrm{TP}_c + \mathrm{FP}_c},
\qquad
r_c = \frac{\mathrm{TP}_c}{N_c}.
\]
These are dimensionless probabilities or rates. Average precision for class \(c\) is
\[
\mathrm{AP}_c = \int_0^1 p_c(r)\,dr,
\]
and mean average precision over \(C\) classes is
\[
\mathrm{mAP} = \frac{1}{|C|}\sum_{c \in C} \mathrm{AP}_c.
\]
The source reports “loose” and “tight Average-mAP” [PAGE 4], so the same ranked predictions are evaluated under two matching tolerances.

A useful breakdown regime is the random-hit bound under uniform timestamp prediction. Assume \(n\) ground-truth events in a video of duration \(L\) seconds, non-overlapping tolerance intervals, and a uniformly random predicted timestamp. Then the probability of falling within at least one event window is approximately
\[
P_{\text{hit}}(\delta) \approx \min\left(1, \frac{2\delta n}{L}\right).
\]
Using the dataset totals from [PAGE 4], \(n/L\) is at least
\[
\frac{110458}{500 \times 2700} \approx 0.0818\ \text{events/s}.
\]
For \(\delta = 1\ \mathrm{s}\),
\[
P_{\text{hit}}(1) \approx \min(1, 2 \times 1 \times 0.0818) \approx 0.164.
\]
For \(\delta = 5\ \mathrm{s}\),
\[
P_{\text{hit}}(5) \approx \min(1, 2 \times 5 \times 0.0818) \approx 0.818.
\]
For \(\delta = 60\ \mathrm{s}\), the expression saturates at 1. This calculation is an assumption-based probabilistic audit, not a claim that the paper’s mAP is random chance. It shows why loose mAP can be inflated relative to tight mAP.

The DALI speedup claim can also be formalized. Let \(T_{\text{base}}\) be baseline wall-clock time and \(T_{\text{DALI}}\) the DALI wall-clock time. A relative time reduction is
\[
R = \frac{T_{\text{base}} - T_{\text{DALI}}}{T_{\text{base}}}.
\]
The paper states “around 33% time improvement for the training steps and 50% improvement for each epoch’s validation steps” [PAGE 5]. If “improvement” means reduction in elapsed seconds, then
\[
R_{\text{train}} \approx 0.33,
\qquad
R_{\text{val}} \approx 0.50.
\]
The corresponding throughput speedups are
\[
S_{\text{train}} = \frac{T_{\text{base}}}{T_{\text{DALI}}}
= \frac{1}{1 - R_{\text{train}}}
\approx \frac{1}{0.67}
\approx 1.49,
\]
\[
S_{\text{val}} = \frac{1}{1 - 0.50} = 2.
\]
Breakdown occurs if the bottleneck is not decoding, cropping, or resizing but disk metadata access, model compute, or GPU transfer. In that case DALI cannot produce the claimed relative improvement.

The dataset size and test duration give another exact unit calculation. The test set is “100 videos of 45min” [PAGE 4], so
\[
L_{\text{test}} = 100 \times 45 \times 60 = 270{,}000\ \mathrm{s}.
\]
If a method predicts one timestamp per second over the full test set, it produces
\[
270{,}000\ \text{predictions},
\]
before class filtering or NMS-style suppression. This matters because evaluation is ranking-based, but timestamp density strongly affects false-positive load.
</SOURCE_OPERATORS_AND_EQUATIONS>

<RETROCAUSAL_GENEALOGY>
The lineage of OSL-ActionSpotting is a consolidation lineage. The task originates with SoccerNet: the paper says SoccerNet was introduced by Giancola et al. and “has set benchmarks for over 12 specific tasks in soccer video analytics,” including action spotting [PAGE 2]. The source also states: “Giancola et. al. [19] introduced the task of action spotting, defined as the process of localizing key actions within long untrimmed videos, such as penalties, goals, or corner kicks in football.” [PAGE 2]. This establishes the scientific ancestry: dataset construction, task definition, and benchmark evaluation preceded the library.

The methodological lineage proceeds from pooling-based spotting to temporally aware pooling, then to context-aware loss and end-to-end precise spotting. The paper explicitly re-implements “feature-based and end-to-end methods from cornerstone action spotting algorithms [36], [33], [42], [48] into a unified library” [PAGE 2]. The three named cornerstone methods are Temporally-Aware Learnable Pooling [33], CALF [36], and PTS [42]. The historical trap is to treat these as interchangeable modules. They are not: the pooling methods use pre-extracted CNN features, CALF uses pre-extracted CNN features with a segmentation-style neck and localization head, and PTS learns spatio-temporal features end-to-end [PAGE 3]. A unified API can hide these architectural differences, making benchmark comparisons appear more apples-to-apples than they are.

A second lineage is infrastructural. The paper introduces a “video data loader based on DALI” [PAGE 1] and a “novel action spotting dataset format in a unique JSON” [PAGE 1]. The JSON format is inspired by COCO: “Inspired by the COCO format for image understanding, it is a single JSON file that includes the path of all videos or features, along with their annotations and associated metadata.” [PAGE 4]. The trap here is standardization without semantic normalization. A JSON container can preserve paths and timestamps, but it cannot by itself guarantee that different datasets have the same event ontology, camera behavior, frame rate, or broadcast production style.

A third lineage is evaluation-driven. Loose and tight mAP are inherited from SoccerNet-style benchmarking, but their exact operational definitions matter. Loose mAP tolerates 5 to 60 seconds, tight mAP tolerates 1 to 5 seconds [PAGE 4]. Over multiple research weeks, a team can accidentally optimize for loose mAP because it is easier to improve, then claim progress in action spotting without demonstrating temporal precision. The countermeasure is to report tight mAP, per-class mAP, and temporal error distributions.

A fourth trap is hardware lineage. The timing table on [PAGE 4] says most methods were timed on “1 GPU RTX1080, 2 CPU cores and 32GB RAM, except for the PTS that required 4 GPU RTX A500 and 80GB of RAM.” This means PTS timing is not directly comparable to feature-based timing. A multi-week project can mistakenly compare PTS training cost to CALF or pooling cost without normalizing for hardware, batch size, or preprocessing path. The correct historical audit is to separate algorithmic complexity from engineering throughput.

Finally, there is the SoccerNet-v2 dataset lineage. The paper states: “SoccerNet-v2 provides videos for 500 football games from the big five European leagues, fully annotated with more than 110,458 temporally-anchored actions, from 17 common action classes.” [PAGE 4]. This anchors the benchmark in elite European football. The trap is assuming that a library validated on SoccerNet-v2 automatically transfers to handball, basketball, badminton, or lower-tier football. The source mentions that the library is “suitable for football and other sports” [PAGE 3], but the experimental evidence is SoccerNet-v2 only. Therefore, cross-domain claims remain unproven within the six pages.
</RETROCAUSAL_GENEALOGY>

<RECURSIVE_THEORY_OF_MIND>
The paper’s authors occupy a field position between algorithm developers and sports analytics practitioners. Their stated goal is not merely to report a new model but to “unify different action spotting algorithms to streamline research and applications in sports video analytics” [PAGE 1]. This creates a recursive incentive structure: the library’s value depends on whether users can plug in datasets, train models, and reproduce known results without reconstructing fragmented codebases.

A first mental model is the researcher who wants a quick baseline. Under deadline pressure, that researcher will likely choose the strongest headline number, often loose mAP, because it is easier to improve and more visually impressive. The paper itself provides evidence for why this is tempting: loose mAP values for PTS are 70.4 and 72.2, while tight values are 63.9 and 66.2 [PAGE 5]. For pooling methods, loose values can be moderate while tight values collapse to single digits. A habit-regression agent would therefore optimize loose mAP and report it as “action spotting performance.” A counter-trap agent would insist on tight mAP, especially because the paper defines tight mAP as measuring “precision in accurately localizing actions in time” [PAGE 4].

A second mental model is the infrastructure engineer. This agent cares about DALI and the JSON dataset format. The paper claims DALI “improved the processing of the video data, overcoming the inefficiencies of traditional CPU-based loading methods like OpenCV video and PyTorch image data loaders” [PAGE 4]. The engineer’s habit is to trust wall-clock improvements as universal. The counter-trap is to demand controlled ablations: same disk, same GPU, same batch size, same model. The clock here is validation time: the paper says DALI gives “50% improvement for each epoch’s validation steps” [PAGE 5], which matters if the workflow is hyperparameter-heavy.

A third mental model is the sports analyst. This agent cares about tactical usefulness. A timestamp that is five seconds late may be useless for immediate tactical review, even if loose mAP is high. The paper defines loose tolerance as “5 to 60 seconds” [PAGE 4], which is too broad for some operational uses. The recursive failure mode is that analytics dashboards inherit loose metrics and present them as if they were decision-grade. The counter-trap is to separate detection from actionable timestamping. For example, a goal detected within 30 seconds may be useful for indexing, but not for automated highlight clipping if the clip requires sub-second alignment.

A fourth mental model is the reviewer or maintainer. The maintainer wants long-term relevance, as the abstract says: “The scalable and modularized design of the library ensures its long-term relevance and adaptability to future technological advancements in the domain.” [PAGE 1]. The recursive risk is API stagnation: the library may unify old methods but fail to absorb newer end-to-end transformers or multimodal models. The paper acknowledges multimodal work in related work, citing Vanderplaetse and Xarles, but the integrated methods listed are mostly video-feature-based or PTS-style [PAGE 2], [PAGE 3]. The counter-trap is to design plugin boundaries that accept audio, text commentary, player tracking, or game-state reconstructions as additional modalities.

The clock dimension is threefold. First, training clock: PTS training epochs are reported as 1200 seconds for RNY002 and 1500 seconds for RNY008, with total training times 140700 and 249780 seconds respectively [PAGE 5]. These are large costs compared with pooling methods, whose training times are around 886 to 1639 seconds total [PAGE 5]. Second, inference clock: PTS testing times are 1500 and 1800 seconds on the described hardware, while feature-based methods are around 118 to 120 seconds [PAGE 5]. Third, deployment clock: a sports analytics system may need near-real-time processing, in which case DALI acceleration and lightweight backbones matter more than marginal mAP gains.

The strongest recursive recommendation is to treat OSL-ActionSpotting as a reproducibility and integration layer, not as proof of universal optimality. Its own abstract says it “achieving performance metrics that match those of the original, disparate codebases” [PAGE 1], but the evidence is a reproduced benchmark table, not a new performance frontier. A mature mental model therefore uses the library to standardize experiments, while separately validating temporal precision, domain transfer, and hardware-normalized efficiency.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
The physical layer imposes temporal quantization constraints. PTS uses videos at 25 fps [PAGE 4]. The frame interval is
\[
\Delta_v = \frac{1}{25}\ \mathrm{s} = 0.04\ \mathrm{s}.
\]
If timestamps are assigned to the nearest visible frame, the maximum quantization error is
\[
e_{\max} = \frac{\Delta_v}{2} = 0.02\ \mathrm{s}.
\]
The tight evaluation tolerance is 1 to 5 seconds [PAGE 4]. Since
\[
0.02\ \mathrm{s} \ll 1\ \mathrm{s},
\]
frame quantization alone cannot veto tight action spotting under the stated broadcast frame rate. The breakdown regime is clear: if a future task requires \(\delta < 0.02\ \mathrm{s}\), the 25 fps video layer becomes the dominant error source unless sub-frame interpolation or higher frame rate is introduced.

The backbone sampling layer imposes a coarser constraint. PTS processes frames at 2 fps [PAGE 4]. The sampled-frame interval is
\[
\Delta_s = \frac{1}{2}\ \mathrm{s} = 0.5\ \mathrm{s}.
\]
This is still below the tight lower bound of 1 second, so 2 fps is not automatically disqualifying for tight mAP. However, if an event’s visual signature is shorter than 0.5 seconds, or if the event is partially occluded in the sampled frames, the model may miss it. The singularity appears when the event duration \(d_e\) satisfies
\[
d_e < \Delta_s.
\]
In that regime, the sampling operator may never observe a frame with sufficient evidence. The paper does not report event-duration distributions, so this remains an unresolved physical risk.

The biomechanical layer concerns event semantics. The source says action spotting focuses on “the precise moment of an event, with a single timestamp, in accordance with football regulations” [PAGE 2]. For a goal, the regulatory event may be ball crossing the line; for a penalty, the kick; for a foul, the contact. These events can be visually ambiguous because broadcast cameras do not always show the exact physical cause. A model can learn proxy cues, such as crowd reaction or replay insertion, but those proxies can lag or lead the true timestamp. This creates a layer mismatch: the regulatory timestamp is a physical event time, while the video observation is a broadcast-mediated signal.

Formally, let \(Y\) be the true action label-time pair and \(X\) the observed video frames. If weather, occlusion, or camera cuts remove the causal visual evidence, the conditional distribution \(P(Y \mid X)\) becomes flatter. In information-theoretic units, the useful information is
\[
I(Y;X) = H(Y) - H(Y \mid X),
\]
measured in bits if logarithms are base 2, or nats if natural logarithms are used. In a pathological occlusion limit, \(I(Y;X) \rightarrow 0\), and no model can infer the action from the observed frames alone. The source does not quantify weather, rain, snow, lighting, or camera-cut frequency, so no numerical weather veto can be proven from the six pages. However, the structural veto is valid: if the visual evidence is destroyed, the spotting task becomes unlearnable from that modality alone.

Camera cuts create an instance-level veto. Let \(E\) be the set of frames showing the event evidence. If
\[
E \cap [t^\star - \delta, t^\star + \delta] = \emptyset,
\]
then a purely visual model cannot directly verify the event inside the tolerance window. It may still infer from context, but the direct evidence is absent. This does not necessarily veto aggregate mAP, because other instances may remain visible, but it imposes a hard upper bound on per-instance performance.

The weather layer can be expressed as an observation degradation operator. Let \(O_w\) be the weather-degraded observation. Then
\[
X_w = O_w(X).
\]
If rain, snow, glare, or floodlight failure reduces the probability of detecting the ball, players, or referee signals, then the effective channel capacity from true event to observed features decreases. The source does not provide weather annotations, so this is not a source-verified veto. It is a deployment veto: any claim of robust action spotting across all conditions must be tested with weather-stratified evaluation. Within the stated SoccerNet-v2 experiments, there is no explicit weather breakdown, so the paper cannot prove weather robustness.

The final cross-layer adjudication is this: physical frame quantization at 25 fps does not veto tight spotting at 1 to 5 seconds. Backbone sampling at 2 fps does not automatically veto tight spotting, but it creates a breakdown regime for very short events. Camera cuts and adverse weather can veto individual predictions or entire domains, but the source does not provide enough stratified evidence to quantify those vetoes. Therefore, the paper’s benchmark claims are physically plausible inside the stated temporal tolerances, but not physically universal across all broadcast conditions or sports domains.
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
RLVR here means reinforcement learning with verifiable rewards: a claim is accepted only if an experiment can produce a checkable reward signal. The following three veto scenarios are verifiable from the source’s stated artifacts.

Veto Scenario 1: Reproduction mismatch.  
Claim under test: OSL-ActionSpotting reproduces original methods. The abstract says the integration achieves “performance metrics that match those of the original, disparate codebases” [PAGE 1]. Verifiable reward: run the original CALF, Temporally-Aware Learnable Pooling, and PTS implementations on SoccerNet-v2, then run the corresponding OSL-ActionSpotting configurations with the same features, splits, and evaluation tolerances. Reward condition: if the absolute tight mAP difference exceeds a predeclared variance band, the reproduction claim is vetoed. A reasonable verifiable threshold is \(|\Delta \mathrm{mAP}_{\text{tight}}| > 1.0\) percentage point after controlling for random seeds, because table values are reported to one decimal place [PAGE 5]. Prediction: for feature-based methods using the same pre-extracted ResNet-152/PCA-512 features [PAGE 4], differences should be small if preprocessing matches. For PTS, differences may be larger because end-to-end training is sensitive to initialization, batch size, and hardware. If PTS tight mAP differs by more than several points, the library is not reproducing the original method faithfully enough for benchmark claims.

Veto Scenario 2: DALI speed claim fails under controlled I/O conditions.  
Claim under test: DALI improves training and validation time. The paper states: “Compared to OpenCV video data loaders, best cases result in around 33% time improvement for the training steps and 50% improvement for each epoch’s validation steps.” [PAGE 5]. Verifiable reward: measure wall-clock time \(T_{\text{base}}\) and \(T_{\text{DALI}}\) under identical model, GPU, CPU, RAM, batch size, and dataset location. Compute
\[
R = \frac{T_{\text{base}} - T_{\text{DALI}}}{T_{\text{base}}}.
\]
If \(R_{\text{train}} < 0.10\) or \(R_{\text{val}} < 0.10\) in a repeated benchmark, the DALI improvement claim is vetoed for that environment. Prediction: DALI will show large gains when video decoding, cropping, and resizing are CPU-bound and disk reads are slow. DALI will show small gains when the dataset is cached in RAM, when frames are already pre-extracted, or when the model’s GPU compute dominates. The source’s own statement that PTS required different hardware [PAGE 4] warns that timing is environment-sensitive.

Veto Scenario 3: JSON dataset conversion loses or shifts annotations.  
Claim under test: the unified JSON format harmonizes datasets and preserves annotations. The paper says the format “includes the path of all videos or features, along with their annotations and associated metadata” [PAGE 4]. Verifiable reward: convert SoccerNet-v2 annotations into the OSL JSON format, then convert back or parse both formats and compare action counts, class labels, and timestamps. If the number of actions changes, or if any timestamp drift exceeds the numerical precision of the source annotation, the format claim is vetoed. Because the source reports “more than 110,458 temporally-anchored actions” [PAGE 4], a lossless conversion should preserve all action instances and their timestamps within the original file precision. Prediction: if the JSON format is merely a container, conversion should be lossless. If the library requires resampling, clipping, or class remapping, then some timestamps may shift. Any systematic shift larger than one video frame, \(0.04\ \mathrm{s}\) at 25 fps [PAGE 4], should trigger a veto for precise action spotting.

These RLVR vetoes are not abstract criticisms; they are operational tests. The first tests scientific reproducibility, the second tests systems efficiency, and the third tests data integrity. Together they define the minimal verifiable reward structure needed before OSL-ActionSpotting’s claims can be treated as robust beyond the source text.
</RLVR_COUNTERFACTUAL_VETOES>
