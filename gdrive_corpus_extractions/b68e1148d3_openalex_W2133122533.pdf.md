This is a theory-of-mind failure at the algorithmic level: the objective rewards altitude gain and noise reduction, but it fails to reward leaving the TMA promptly. The clock then interacts with the objective: if the horizon is too short, the aircraft may remain in the degenerate mode longer before the optimizer detects that leaving the TMA is preferable.

Thus, recursive audit requires three simultaneous checks: first, does the algorithm predict the physical consequences of its controls? Second, does it predict the operational consequences of human expectations? Third, does it respect the real-time clock? The source’s architecture can satisfy the first and third only under strict particle, constraint, and GPU limits. It does not fully satisfy the second unless an external priority model is added.

It also assumes an isotropic wind field with uncorrelated wind speeds in the South-North and East-West directions [PAGE 23]. If the real atmosphere contains strong vertical gusts, mountain-wave activity, convective updrafts, or non-isotropic turbulence, the predicted trajectories can violate separation or flight-envelope constraints even though the simulated particles appeared feasible. The model also relies on Cholesky decomposition of the covariance matrix; if the covariance is not positive definite, the wind generation breaks down [PAGE 24]. Thus, weather uncertainty can veto the solution if the actual wind process leaves the assumed probability model.

The landing-envelope veto concerns terminal geometry. Arriving aircraft must satisfy radial distance, approach-angle, heading, and speed constraints before being considered landed. The source states: “The first 3 of these constraints define the landing sector” and “Constraint 2d ensures that the aircraft is pointing towards the runway assuming an East to West landing without significant crosswind” [PAGE 14]. If crosswind exceeds the assumed landing geometry, the terminal constraint set may no longer represent a safe landing. In that case, the algorithm’s predicted feasible landing particle is physically or operationally invalid.

The computational veto concerns the clock. The source says: “the optimisation problem is time-critical; it needs to be solved within the control-update interval” [PAGE 10]. The TMA implementation required many particles and reported that “1024 particles was not enough to reliably find feasible solutions” [PAGE 24]. The GPU block constraint also matters: “The current maximum number of threads a block can hold is 512” [PAGE 27]. If the solve time exceeds the update interval, the controller may apply stale commands. A stale command can be unsafe because aircraft states evolve between updates. Therefore, the cross-layer veto is:

\[
\text{Safe output only if }
\hat{l}\in\mathcal{F}_k
\text{ and }
\tau_{\text{solve}}\leq \tau_{\text{control}}
\text{ and }
\text{wind model covers actual disturbance}
\]

where \(\tau_{\text{solve}}\) is the optimizer solve time and \(\tau_{\text{control}}\) is the control-update interval, both in seconds. If any condition fails, the trajectory must be vetoed or flagged for human arbitration.

Three verifiable counterfactual veto scenarios can be constructed directly from the report’s equations and stated limitations.

Scenario 1: Final-particle safety veto.
Verifiable test: For the selected final particle, compute all predicted aircraft trajectories over the horizon and check unary constraints, mass constraint, landing-envelope constraints, and pairwise separation. If any violation exists, veto the solution. The report’s rule is explicit: “If an aircraft fails any of its unary constraints then its weight stored in the particle is set to 0. If a pair of aircraft fail a binary constraint then both aircraft have their weights set to 0” [PAGE 15]. The final particle is selected by maximum weight product, so any zero weight should eliminate that particle [PAGE 21].
Prediction: In high-density scenarios with fixed departure times, separation violations near the landing envelope will increase. The source already reports: “In cases where departing aircraft joined the problem when a landing aircraft was due to enter the landing envelope separation constraints were violated and no valid solution could be found” [PAGE 31]. Counterfactual: If a runway scheduler or departure-delay mechanism is added, the fraction of zero-weight particles should decrease, and the feasible-solution rate should increase. The verifiable metric is the fraction of particles with all aircraft weights positive before final selection.

Scenario 2: Wind-covariance Cholesky veto.
Verifiable test: Construct the wind covariance matrix \(\hat{R}\) from the correlation kernel. Compute its eigenvalues and condition number. If \(\hat{R}\) is not positive definite, or if the condition number is so large that numerical Cholesky failure is likely, veto the wind-generation module. The report says the covariance factors satisfy \(QQ^{T}=(1-a^2)\hat{R}\) and \(\hat{Q}\hat{Q}^{T}=\hat{R}\) [PAGE 24]. These factorizations require positive definiteness. Also check units: if \(\lambda\) is used with time in seconds but quoted as \(\mathrm{m^{-1}}\), the exponent \(\exp(-\lambda|t-t'|)\) is dimensionally inconsistent [PAGE 23].
Prediction: If duplicate grid points, degenerate altitudes, or invalid parameters produce a singular covariance, wind sampling fails or becomes numerically unstable. If the time-correlation parameter \(G_t\) is zero, \(a=\exp(-\delta t/G_t)\) is undefined. Counterfactual: Replace the covariance with a strictly positive-definite kernel and use time units consistently. Expected result: wind samples become reproducible, interpolation errors remain bounded, and fuel-saving comparisons become more reliable. The verifiable metric is successful Cholesky completion and nonnegative minimum eigenvalue of \(\hat{R}\).

Scenario 3: Objective-weight degeneracy veto.
Verifiable test: For a departure aircraft assigned a 0-degree desired bearing, simulate with a high noise-reduction weight. Measure radial distance from the airport over the horizon. If radial distance does not increase monotonically enough to exit the TMA while altitude increases, the trajectory is exhibiting the reported circling-climb degeneracy. The source states: “The 0°bearing simulation finds the degenerate case where the altitude gain at roughly the right bearing can be achieved by continuously circling and climbing” [PAGE 61].
Prediction: With a 20% noise-reduction weighting, the departure may remain inside the TMA longer, may reach the altitude constraint, or may terminate by constraint violation. With a lower noise weighting or an added reward for increasing distance from the airport, the aircraft should leave the TMA more directly. Counterfactual: Add a verifiable progress reward based on radial distance or TMA-exit time. Expected result: reduced circling, fewer altitude-constraint terminations, and more stable aggregate fuel savings. The verifiable metric is the time derivative of radial distance, \(\dot{r}>0\) over a required fraction of the horizon, with \(r=\sqrt{x^2+y^2}\) in metres.

These veto scenarios are verifiable because they rely on quantities already present in the source: constraint weights, covariance factorization, particle selection, radial geometry, and bounded objective functions. They also expose the main failure modes of the method: unsafe final particles, invalid wind uncertainty, and objective-induced degenerate trajectories. A safe deployment would need to enforce all three vetoes before accepting the optimizer’s selected control sequence.
