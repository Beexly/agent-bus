The following are formalizations of operations the source describes; they are not claimed as source-original equations. Let the sports domain be \(\mathcal{S}\) and the data-mining domain be \(\mathcal{D}\). The performance-analysis mapping is
\[
M:\mathcal{S}\to\mathcal{D},\qquad M(\text{sport rules, tactics, conditions, abilities})=\text{RTS representation}.
\]
This formalizes the source’s statement that performance analysis “implies a mapping ... from the sports domain to the data analytical domain” [PAGE 9]. For athlete or team \(i\) in event \(e\), the RTS vector is
\[
\mathbf{x}_{i,e}=(r_{i,e},t_{i,e},s_{i,e})\in \mathbb{R}\times\mathbb{R}_{\ge 0}\times\mathbb{R},
\]
where \(r\) is ordinal rank and is dimensionless, \(t\) is time in seconds, and \(s\) is score in points or dimensionless count units. The source names these “RTS (ranking, time, score) measures” [PAGE 9].

The pre-processing operator is a composition
\[
\mathcal{P}=C_{\mathrm{desc}}\circ C_{\mathrm{struct}}\circ E\circ C_{\mathrm{fmt}}\circ F,
\]
where \(F\) filters records by competition category, \(C_{\mathrm{fmt}}\) converts units such as hh:mm:ss to seconds via \(t_s=3600h+60m+s\), \(E\) extracts new variables, \(C_{\mathrm{struct}}\) coarse-grains labels, and \(C_{\mathrm{desc}}\) creates sport-descriptive variables. The source defines filtering as “Filtering data records considering certain categories of competitions” [PAGE 9], and descriptive conversion as “Converting specific parts of data to a format that better describes the nature of the specific sport/problem” [PAGE 10]. Units: \(t_s\) is seconds; structural labels are dimensionless categories; filtered records retain original RTS units.

For successive multiple-event sports, the source’s key descriptive conversion is differential time:
\[
\Delta t_{i,k}=t_{i,k}-\min_{j} t_{j,k},
\]
where \(k\) indexes the component event and \(\Delta t\) is seconds. This is the formal version of the triathlon argument that raw times and ranks are misleading when events occur in succession [PAGE 11]. The source’s empirical triathlon rule is
\[
\hat P(M_i=1\mid \Delta t_{\mathrm{run},i}\le 26\ \mathrm{s})\approx 0.87
\]
for male triathletes, and
\[
\hat P(M_i=1\mid \Delta t_{\mathrm{run},i}\le 28\ \mathrm{s})\approx 0.86
\]
for female triathletes [PAGE 12]. Here \(M_i=1\) denotes medal outcome, and the probability is a dimensionless empirical estimate. Assumption: the estimate is conditional on the source’s analyzed triathlon corpus and pre-processing choices; it is not a causal effect. Breakdown: the estimate is undefined if no athletes satisfy the threshold cell, and it is not transportable if course, weather, or competition structure changes the meaning of \(\Delta t\).

Clustering is formalized by the within-cluster objective
\[
J=\sum_{k=1}^{K}\sum_{i:z_i=k}\lVert \mathbf{x}_i-\mu_k\rVert^2,
\]
with \(\mathbf{x}_i\) in RTS units and \(J\) in squared RTS units. This represents the source’s description of clustering as finding groups whose members are similar under “similarity attributes” [PAGE 6]. Breakdown: \(J\) is not identified under arbitrary rescaling of mixed units, empty clusters make \(\mu_k\) undefined, and ordinal ranks should not be treated as Euclidean without justification.

Classification is a learned map
\[
g:\mathcal{X}\to\mathcal{Y},\qquad \hat R(g)=\frac{1}{n}\sum_{i=1}^{n}L(g(\mathbf{x}_i),y_i),
\]
where \(y_i\) is a pre-defined class label and \(\hat R\) is dimensionless empirical risk. The source says classification is “used to predict group memberships for data instances” [PAGE 6]. Breakdown: if training and deployment conditionals differ, \(P_{\mathrm{train}}(Y\mid X)\ne P_{\mathrm{deploy}}(Y\mid X)\), empirical risk is not a valid deployment estimate. Base-rate neglect is an explicit source warning [PAGE 3].

Relationship modeling is
\[
y=h_\theta(\mathbf{x})+\varepsilon,\qquad \theta^*=\arg\min_\theta \sum_i L(y_i,h_\theta(\mathbf{x}_i))+\lambda\Omega(\theta),
\]
where \(\varepsilon\) is error in the target’s units, \(\lambda\) is a dimensionless regularization weight, and \(\Omega\) is a complexity penalty. This matches the source’s aim “to find a function or model that can define the data and describe the inter-relationships between predictor and dependent attributes” [PAGE 7]. Breakdown: if the design matrix is rank deficient, linear least-squares is singular; if the relationship is strongly non-linear, the source warns that regression may be inappropriate [PAGE 7].

The requirement-to-technique mapping is ordinal, not arithmetic:
\[
q_{\mathrm{req}}=(I,P,F)\in\{\text{low, moderate, high, very high}\}^3,
\]
where \(I\) is interpretability, \(P\) is precision, and \(F\) is flexibility. The source defines interpretability as “how easily the results achieved by employing a certain method can be interpreted” [PAGE 17]. Table 2 maps real-time decision-making to “very high” interpretability, “high” precision, and “very low” flexibility [PAGE 28]. Breakdown: these are not interval quantities; averaging them or summing them would be invalid. The correct operation is a constraint check: a technique is admissible only if its profile satisfies the requirement profile and any clock constraint \(L\le L_{\max}\), where \(L\) is latency in seconds.

<RECURSIVE_THEORY_OF_MIND>
The crisis habit regression is explicit in the source: “much of the coaches’ decision-making in sport has been based on tradition and emulation” [PAGE 3]. Under time pressure, a coach may regress to familiar routines even when systematic analysis is available. The analyst’s counter-trap is to respond with more sophisticated modeling, but that can worsen the gap: the source identifies “the lack of confidence and mutual understanding between sports data analysts and professional coaches/athletes” [PAGE 4]. A second-order model is required: the analyst must reason about the coach’s belief about the analyst’s output, and the coach must reason about whether the analyst’s model respects sport context. If the analyst ignores this recursion, a technically precise model can be socially rejected.

The clock changes the admissible recursion. For real-time decision-making, Table 2 requires “very high” interpretability, “high” precision, and “very low” flexibility [PAGE 28]. This means the analyst cannot run a long exploratory search during the event; the exploratory work must have happened before the clock starts. The source argues that clustering, classification, and rule mining tend to produce results “that can better be used prior to major events,” while relationship modeling can be employed in real time [PAGE 19]. The recursive decision rule is lexicographic: first satisfy the clock and interpretability veto, then maximize precision. A highly precise but opaque model that cannot be explained within the event clock is inadmissible under the source’s own requirement mapping.

The counter-trap is overcorrecting for coach habit regression by hiding uncertainty. If the analyst presents a single class label without the source’s pre-processing rationale, the coach may over-trust it or dismiss it. The safer recursive strategy is to expose the RTS mapping, the conversion applied, and the method’s known breakdown regime. This aligns with the source’s insistence that domain knowledge inheritance is necessary “not only to evaluate the results of their analysis but also to validate processes” [PAGE 9]. In recursive terms, the analyst should optimize for calibrated trust, not maximal model complexity. The clock then determines whether the explanation must be precomputed, cached, or reduced to a small decision rule.

<CROSS_LAYER_VETO_ADJUDICATION>
Let \(Z\) be a cross-layer variable representing physical state, biomechanics, or weather. A data-mining model learned on \((\mathbf{X},Y)\) is admissible only if the deployment conditional is stable:
\[
P_{\mathrm{train}}(Y\mid \mathbf{X})=P_{\mathrm{deploy}}(Y\mid \mathbf{X}).
\]
If \(Z\) affects \(\mathbf{X}\), \(Y\), or the \(\mathbf{X}\to Y\) relation, and \(Z\) is omitted, then
\[
P(Y\mid \mathbf{X})=\sum_z P(Y\mid \mathbf{X},z)P(z\mid \mathbf{X}),
\]
so a change in \(P(z\mid \mathbf{X})\) changes the predictive relation. This is the formal veto: an omitted cross-layer variable that is not constant across training and deployment invalidates the mapping. The source supports the need for domain-knowledge inheritance: “the mapping has to enable the possibility of inheriting required (sports) domain knowledge” [PAGE 9]. It also separates biomechanics, which applies “mechanical principles to human’s biological system” [PAGE 3], from purely statistical match analysis.

Physical and biomechanical veto proof: if a model treats RTS variables as sufficient statistics for performance, but biomechanical constraints or injury states alter the attainable time or score, then the model can assign probabilities to mechanically impossible or physiologically unavailable states. The source’s rectangular model requires sport-specific requirements to constrain method choice [PAGE 18, PAGE 29]; omitting biomechanics violates that constraint. A biomechanical veto is triggered when an athlete’s movement pattern, equipment, or fatigue state changes the mapping from observed RTS to outcome. The source does not provide a biomechanical equation, so the veto must be implemented as a stratum or covariate, not as an invented formula.

Weather veto proof: the source mentions “environmental context (i.e., open versus closed)” [PAGE 8] and rowing examples involving “fast, medium, and slow courses” [PAGE 9], but it does not specify weather variables or a weather model. Therefore, a weather-layer veto cannot be proven from the paper’s text alone. It must be treated as an external validity condition. The logical form is still clear: if wind, water, heat, or surface conditions shift \(t\) or \(s\) for reasons not captured by pre-processing, then the RTS representation no longer means the same thing across events. The veto is triggered when the deployment distribution of \(Z_{\mathrm{weather}}\) differs from the training distribution and the model has no stratifying variable. In that regime, the correct adjudication is not to “adjust” the prediction by an invented coefficient, but to re-estimate or restrict the claim.
</CROSS_LAYER_VETO_ADJUDICATION>
