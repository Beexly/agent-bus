<CROSS_LAYER_VETO_ADJUDICATION>
Veto authority applies across three layers: physical (infrastructure), biomechanical (human operations), and weather (external dependency environment). Any single layer failure is sufficient to veto production deployment.

Physical layer. The source mandates five preconditions for production self-host: database, queue/worker mode, credentials policy, execution isolation, backups [PAGE 1]. Veto condition: if any one is missing, n8n must not run production workflows. In queueing terms, absence of execution isolation makes \(p_{\text{escape}}\) non-zero for code nodes [PAGE 1], and absence of backups makes \(RPO = \infty\) [s]. Webhook endpoints must not be publicly exposed before privacy, auth, and rollback review [PAGE 1]; a public, unauthenticated webhook surface is an automatic physical/network veto.

Biomechanical layer (human). SRE on-call load is the biomechanical constraint: queue workers must be monitored, credentials rotated, backups verified, and rollback runbooks executed under fatigue. Veto condition: no on-call rotation, no runbook, or no owner-approval gate for production keys/customer data/public exposure [PAGE 1]. Crisis habit regression (manual ops glue bypassing the credential store) is a biomechanical veto trigger because it produces credential sprawl outside the policy boundary [PAGE 1]. “Do not connect production customer data during prototype” [PAGE 1] is a human-behavior veto: if engineers attach real customer payloads to local fixtures, the instance must be quarantined.

Weather layer (external). n8n is a webhook-first layer between CRM, support, newsletter, docs, analytics, and build queues [PAGE 1]. External dependencies constitute the weather: upstream API degradation, OAuth revocation, rate-limit changes, or regional cloud outage affecting the self-hosted database/queue. In queueing terms, a downstream slowdown reduces \(\mu\), driving \(\rho = \lambda/\mu \to 1^{-}\) and eventually \(\rho \ge 1\), where the execution queue saturates [PAGE 1]. Veto condition: no circuit-breaker or rate-limit handling for upstream services, or no backup region for database/queue, means weather events cascade into operational blast radius across all 400+ integrations [PAGE 1].

Veto proof summary: The conjunction (database \(\land\) queue/worker \(\land\) credentials policy \(\land\) execution isolation \(\land\) backups) is necessary; its negation is sufficient for veto. Separately, public exposure before privacy/auth/rollback review [PAGE 1], production customer data during prototype [PAGE 1], and fork/embed/white-label without legal approval [PAGE 1] are each independent veto conditions regardless of infrastructure health.
