<RECURSIVE_THEORY_OF_MIND>
Orders of intentionality in the council, crisis habit regression, counter-trap, and the clock.

Zero-order intentionality. Each adapter $m_i$ models only the user query: it computes $P(Q^* \mid Q)$ using its base weights $\theta_i$ and system prompt $p_i$, with no model of other agents.

First-order intentionality (Round 1). Per [PAGE 1], agents answer "without seeing each other," so each $m_i$ performs zero-order modeling of the user but does not model other models. The Round 1 vector $\{A_i^{(1)}\}$ is a collection of independent first-order guesses about $Q^*$.

Second-order intentionality (Round 2). Per [PAGE 1], "each agent sees all Round 1 answers and can revise its position." Now $m_i$ computes $P(Q^* \mid Q, \{A_j^{(1)}\}_{j=1}^N)$: it models how other models answered and anticipates how they will revise. This is recursive theory of mind — model $i$ models model $j$ modeling the user.

Third-order intentionality (Synthesis). Claude, as synthesizer, computes $P(Q^* \mid Q, \{A_i^{(2)}\}, \{m_i\})$: it models the models, models how they modeled each other, and collapses the result into a structured answer. This is the deepest recursive layer and also the most fragile, because it concentrates all third-order inference in a single model.

Crisis habit regression. Under time pressure (the `timeout` option on [PAGE 1]), adapters may regress to base-model priors — short, unrevised, high-confidence answers — rather than paying the computational cost of genuine Round 2 deliberation. The council then collapses to effectively Round 1 outputs mislabeled as deliberated, and the synthesizer treats regressed answers as if they had undergone second-order revision.

Counter-trap: synthetic consensus. If all five adapters share pretraining data that encodes a common error $\hat{A} \neq Q^*$, Round 1 produces $\{A_i^{(1)} = \hat{A}\}$. Round 2 revision, instead of correcting $\hat{A}$, reinforces it through mutual confirmation. Claude's synthesis then launderers the shared error into a structured, confident final answer. The `skeptic` role listed on [PAGE 1] is the nominal antidote, but without published role-weighting mathematics or a formal dissent mechanism, its counter-trap efficacy is unverified.

Clock. The `timeout` parameter is a hard real-world boundary. If Round 2 does not complete before $\tau$, the council must synthesize with an incomplete set $\{A_i^{(2)}\}_{i \in \mathcal{K}}$, $\mathcal{K} \subsetneq \mathcal{M}$, or fall back to Round 1. The clock thus truncates the recursion depth: second-order intentionality is replaced by first-order or zero-order outputs, breaking the assumption that every adapter has modeled every other adapter.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
Physical, biomechanical, and environmental veto layers with adjudication rules for the SupaAgent council system.

Physical layer (compute and transport). The `owlex/server.py` MCP entry point runs on host hardware subject to CPU, RAM, NIC bandwidth, and stdio pipe buffer limits. A veto occurs if the pipe between Claude Code and `owlex-server.py` overflows, if the host OOM-kills the Python process, or if network latency between the MCP client and any model-adapter endpoint exceeds the `timeout`. Physical veto proof: if transport fails, no Round 1 answer $A_i^{(1)}$ can be transmitted, so the synthesis input $\{A_i^{(2)}\}$ is undefined and $S = \varnothing$. No redundancy across physical hosts is described on [PAGE 1].

Biomechanical layer (human operator). The end user operates within Claude Code, reads the structured synthesis, and decides whether to act on it. Veto conditions: operator aborts the council call, misreads the structured output, or abandons because effective latency $T_{\text{eff}} = T_{\text{council}} + T_{\text{human}}$ exceeds task deadline. Biomechanical veto proof: even a technically perfect council output has zero decision value if the human does not receive or trust it within the operational clock.

Weather layer (external model providers). "Weather" here denotes the volatile external environment of model APIs: Codex, Gemini, OpenCode, ClaudeOR, and AiChat endpoints can suffer regional outages, rate limits (HTTP 429), or schema deprecations. [PAGE 1] lists no circuit breaker, fallback provider, or cached-response mechanism in `council.py` or `engine.py`. A veto at this layer occurs when any single adapter's $\mathcal{F}_i$ becomes non-terminating or returns an error, and `council.py` either blocks the full Round 1 vector or degrades silently to $N-1$ agents. Because all five adapters could be affected simultaneously by a regional cloud event, the weather-layer veto is not idiosyncratic; it can be systemic.

Adjudication rule. A veto at any one layer is sufficient to invalidate council output for that call. The system has no listed cross-layer redundancy: no spare physical host, no alternate human channel, and no backup model provider. Therefore the council's availability is the minimum of layer availabilities, and its correctness is bounded by the weakest unvetoed layer. Any production deployment must instrument all three layers and treat a single-layer failure as a council-wide veto unless `timeout`-mediated partial synthesis is explicitly acceptable.
</CROSS_LAYER_VETO_ADJUDICATION>
