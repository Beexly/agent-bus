The paper’s formal evaluation operator is the key-element recall function. For a metric type \(ki\), with annotated key-element set \(E_{ki}\), generated summary \(s\), and entailment discriminator \(\Gamma\), the recall is:

\[
\mathrm{Recall}_{ki}
=
\frac{1}{|E_{ki}|}
\sum_{e \in E_{ki}} \Gamma(e,s),
\qquad
\Gamma(e,s)=
\begin{cases}
1, & \text{if } e \subseteq s,\\
0, & \text{else.}
\end{cases}
\]

This appears as equations (1) and (2) on [PAGE 5]. The units are dimensionless rates in \([0,1]\). The denominator \(|E_{ki}|\) counts annotated key elements of type \(ki\). The exact singularity is \(|E_{ki}|=0\): if an instance has no annotated elements of a given type, the metric is undefined. A practical breakdown rule is to exclude that instance from that metric, otherwise report undefined rather than substituting zero.

The dataset construction operator can be written as:

\[
i = [D, r, T],
\]

for automatically constructed training data, where \(D\) is the input document set, \(r\) is the reference summary, and \(T\) is automatically annotated temporal relations [PAGE 3]. For the manually annotated test set, the operator becomes:

\[
i = [D, r', T, G],
\]

where \(r'\) is the manually written summary and \(G\) is the manually annotated global structured information [PAGE 3]. The source states that the annotated data contain “2,345 sub-events, 4,787 arguments, and 1,107 causal relationships” [PAGE 3]. These counts define the finite support of the evaluation predicates.

Input scale is explicitly quantified. The paper reports an average of “11.4 related news articles” and “13,471 input characters” [PAGE 2]. The maximum input length is “174,152 characters” [PAGE 4]. The average reference summary length is “161 characters” [PAGE 4]. A source-grounded compression operator is:

\[
C = \frac{L_{\text{out}}}{L_{\text{in}}},
\]

where \(L_{\text{out}}\) is output length in characters and \(L_{\text{in}}\) is input length in characters. Using the paper’s averages:

\[
C \approx \frac{161}{13471} \approx 1.195 \times 10^{-2}
\]

characters of summary per input character. This is dimensionless. The breakdown regime is \(L_{\text{in}}=0\); if there are no input characters, compression is undefined. The paper also notes that “the number of input documents was controlled between 5 and 20” [PAGE 3], so \(5 \leq |D| \leq 20\) in the released data.

The retrieval-cleaning operator includes a similarity threshold. The authors used sentence-transformers and filtered “low-relevance documents with a similarity score below the preset threshold of 0.5” [PAGE 3]. Formally, for document \(d\) and reference summary \(r\), if \(\mathrm{sim}(d,r) < 0.5\), then \(d\) is rejected or down-weighted. The units of \(\mathrm{sim}\) depend on the embedding model, but the threshold is a dimensionless cutoff. Breakdown occurs if all candidate documents have similarity below 0.5; then no valid input set exists unless additional retrieval is performed.

The NLI-based recall estimator has a measurable error model. Let \(Y\in\{0,1\}\) be the true entailment label and \(\hat{Y}=\Gamma(e,s)\) be the NLI decision. Define false-negative error:

\[
\epsilon_1 = P(\hat{Y}=0 \mid Y=1),
\]

and false-positive error:

\[
\epsilon_0 = P(\hat{Y}=1 \mid Y=0).
\]

If true recall is \(R=P(Y=1)\), then the observed recall is:

\[
\hat{R}
=
P(\hat{Y}=1)
=
R(1-\epsilon_1) + (1-R)\epsilon_0.
\]

If \(\epsilon_1=\epsilon_0=\epsilon\), then:

\[
\hat{R}=R(1-2\epsilon)+\epsilon.
\]

This is a probability-unit equation, with all terms dimensionless. The breakdown regime is \(\epsilon=1/2\): the estimator becomes uncorrelated with true recall. More generally, if \(\epsilon_1+\epsilon_0=1\), then \(\hat{R}=\epsilon_0\) independent of \(R\), which is a total breakdown of discriminative information. The paper reports NLI test-set scores of “96.8, 92.9, 94.3, 92.1” for the four recall discriminators [PAGE 6], suggesting low but nonzero error. It also reports consistency between NLI predictions and human judgment: Event Recall 95.0, Argument Recall 97.0, Causal Recall 90.9, Temporal Recall 92.9 [PAGE 6]. These are consistency percentages, not proof of perfect entailment detection.

The quality-control operator is:

\[
P_{\text{pass}}
=
\frac{N_{\text{pass}}}{N_{\text{total}}} \times 100\%,
\]

with units of percent. The paper states that “The pass rate is calculated as (number of data meeting the criteria / total data) * 100%” [PAGE 3]. Breakdown occurs when \(N_{\text{total}}=0\). The observed pass rates are 81% for automatic data and 93% for human-annotated data [PAGE 3].

For temporal structure, the paper says it “only label[ed] events that are directly adjacent in time” because of “the transitivity of temporal information” [PAGE 3]. A formal temporal constraint is:

\[
(e_i, e_j) \in T_{\text{before}}
\implies
\tau(e_i) \prec \tau(e_j),
\]

where \(\tau(e)\) is the event time and \(\prec\) is strict temporal precedence. The annotated total is “14,932 temporal relationships” [PAGE 3]. The breakdown regime is a temporal cycle:

\[
\tau(e_i) \prec \tau(e_j)
\wedge
\tau(e_j) \prec \tau(e_k)
\wedge
\tau(e_k) \prec \tau(e_i),
\]

which is unsatisfiable under a strict partial order.

<RETROCAUSAL_GENEALOGY>
The scientific lineage of EventSum is a convergence of three older lines: news multi-document summarization, event extraction, and timeline summarization. The paper explicitly positions itself against Multi-News, DUC, TAC, WikiSum, and timeline datasets. It says existing Multi-document Summarization research faces challenges because news datasets are “organized around general news content rather than the specific dynamic event in chronological order” [PAGE 1]. It also criticizes automatically constructed large datasets such as WikiSum because they “compromise dataset quality and increase the risk of data leakage in the test set” [PAGE 1]. EventSum therefore inherits the multi-document integration problem but changes the target from topical coverage to dynamic-event reconstruction.

The event-understanding lineage comes from ACE-style event and argument annotation. The paper says the annotated arguments include “time”, “location”, “person”, and “organization”, and that “The definitions of the event and arguments mentioned above are widely adopted, similar to those in ACE 2005” [PAGE 3]. However, it also says “our work does not define any specific event schema” [PAGE 3]. This is important: EventSum borrows event-argument structure without forcing a rigid ontology. The causal lineage comes from MAVEN-ERE. The paper states that annotated causal relationships follow MAVEN-ERE and include “cause” and “precondition”, where “cause” indicates a sufficient condition and “precondition” indicates a necessary condition [PAGE 3]. This gives the dataset a causal logic that goes beyond sentence similarity.

The temporal lineage comes from timeline summarization. The paper discusses Timeline Summarization and notes datasets such as Timeline17 and Crisis, but says available data is limited: “Available data for TLS is limited, which impedes relevant research” [PAGE 7]. EventSum extends this by requiring “a clear and comprehensive view” of event dynamics, not merely daily summaries [PAGE 8]. The result is a hybrid task: MDS plus event extraction plus temporal ordering plus causal annotation.

The multi-week trap is already visible in the source example. The “2023 Hebei Heavy Rain” event begins with “Starting from July 27, heavy rainfall affected most of Hebei Province due to Typhoon Doksuri and the interaction of cold and warm air masses” [PAGE 2]. Casualty information evolves: “As of 12:00 PM on August 1st…… the heavy rainfall has resulted in 9 deaths…… and 6 missing persons” and later “By August 10, 29 people had died in Hebei, including 6 previously missing persons” [PAGE 2]. Reconstruction information extends further: “By June 30, all 2,895 post-disaster transportation reconstruction projects in Hebei were completed” [PAGE 2], while the summary line says “By July 2024” [PAGE 2]. These are multi-week and multi-month traps. A model trained to compress crisis narratives may collapse the timeline, confuse preliminary casualty counts with final counts, or treat reconstruction completion as contemporaneous with the disaster.

Another trap comes from retrieval scope. The authors “specifically selected 20 news articles published within a month of the event date” [PAGE 3]. But the reference summary may include later updates, as shown by reconstruction completion [PAGE 2]. This creates a mismatch between retrieval window and event horizon. The dataset also contains long spans: “Nearly 40% of the data spans more than one day, and 13% spans more than one month” [PAGE 4]. Therefore, a historically naive model will fail whenever the event’s authoritative information arrives after the initial retrieval window. The retro-causal lesson is that event summaries must be treated as evolving state estimates, not static snapshots.

<RECURSIVE_THEORY_OF_MIND>
The recursive theory-of-mind problem in EventSum has three main agents: the generating LLM, the NLI-based evaluator, and the human annotator. The generating LLM must infer what the evaluator will treat as evidence. The evaluator must infer whether the generated summary entails annotated event elements. The human annotator must infer what information is essential despite source noise, duplicate reports, and temporal drift. The paper’s designed metrics make these recursive expectations explicit because they judge entailment of structured elements, not mere fluency.

Crisis habit regression is the model’s tendency to reproduce familiar crisis-report language: rescue, response, casualties, reconstruction, government action. This is dangerous because EventSum’s test set was manually annotated to reduce leakage and require comprehensive event information [PAGE 1][PAGE 3]. If the model has memorized generic disaster phrasing, it may achieve high ROUGE or BERTScore while missing exact sub-events. The paper observes common failure categories: “Incomplete or Missing Information”, “Over or Under generalization”, and “Irrelevance” [PAGE 6]. These are precisely the failures that crisis habit regression produces. The model says something plausible about a disaster, but it does not preserve the event’s unique annotated structure.

The counter-trap is the EventSum evaluation protocol itself. It forces the generator to satisfy four structured recall operators: Event Recall, Argument Recall, Causal Recall, and Temporal Recall [PAGE 1]. The summary prompt also requires chronological organization and inclusion of “key event information and related temporal and causal relationships” [PAGE 15]. This changes the model’s strategic environment. If the model knows that only lexical similarity is measured, it can hedge and paraphrase. If it knows that entailment of sub-events and arguments is measured, it must preserve specific entities, times, locations, persons, organizations, causal links, and temporal order. The counter-trap is therefore a structured-information trap: the model must not merely sound like a summary; it must contain verifiable event predicates.

The clock is the temporal dimension. The paper says summaries are “organized in chronological order” [PAGE 3]. It also annotates only temporally adjacent event pairs and relies on transitivity [PAGE 3]. In the Hebei example, the clock is nontrivial: rainfall starts July 27, casualty counts are reported August 1, revised August 10, affected counties are reported August 11, and reconstruction completion appears by June 30 or July 2024 [PAGE 2]. A model that treats all events as a single unordered bag will fail Temporal Recall. The clock also creates a theory-of-mind conflict: the model must distinguish report time, event time, and reference-summary time. For example, a document published after reconstruction may be included because it was published within a month of the event date, but the event it describes occurred much later [PAGE 3][PAGE 2]. The model must infer which timestamp governs the summary clause.

The deepest recursive layer is evaluator anticipation. The paper’s NLI discriminators are trained to judge whether key elements are entailed [PAGE 5]. They are not perfect: NLI scores are high but not absolute, and human consistency is high but below 100% for Causal Recall at 90.9 [PAGE 6]. A sophisticated model might exploit this by generating text that is semantically close but not strictly entailing, or by omitting difficult causal links. The countermeasure is not merely better fluency; it is better alignment with annotated predicates. Thus, the optimal crisis-summary behavior is not maximal eloquence but maximal verifiable event-state coverage under temporal and causal constraints.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
The cross-layer veto adjudication uses the source example “2023 Hebei Heavy Rain” to prove that physical, biomechanical, and weather constraints can invalidate a summary even when lexical metrics look acceptable. The source states: “Starting from July 27, heavy rainfall affected most of Hebei Province due to Typhoon Doksuri and the interaction of cold and warm air masses” [PAGE 2]. It also states: “By August 10, 29 people had died in Hebei, including 6 previously missing persons” [PAGE 2]. It further states: “By June 30, all 2,895 post-disaster transportation reconstruction projects in Hebei were completed” [PAGE 2]. These are not decorative details; they are veto predicates.

First, weather-layer veto. Let \(H\) be the event “2023 Hebei Heavy Rain”. Let \(\mathrm{hazard}(H)\) be the primary hydrological hazard. The source says “heavy rainfall” caused by typhoon and air-mass interaction [PAGE 2]. Therefore:

\[
\mathrm{hazard}(H) = \text{heavy rainfall}.
\]

If a generated summary asserts:

\[
\mathrm{hazard}(s) = \text{snowstorm},
\]

or asserts that the primary cause was an earthquake, then the summary contradicts the source predicate. This veto is not merely textual; it is meteorological. A heavy-rain event in late July in Hebei, associated with Typhoon Doksuri and cold/warm air interaction, cannot be replaced by a snowstorm without violating the physical season and hazard type. If the summary says “heavy snow caused the Hebei disaster”, it should be vetoed even if it contains the words “Hebei”, “disaster”, and “July”.

Second, temporal-layer veto. Define \(\tau_{\text{rain}}\) as the start of heavy rainfall and \(\tau_{\text{recon}}\) as the completion of reconstruction. The source says rainfall started July 27 [PAGE 2], while reconstruction completion is reported by June 30 or July 2024 [PAGE 2]. Therefore:

\[
\tau_{\text{rain}} \prec \tau_{\text{recon}}.
\]

If a summary says reconstruction was completed before the rainfall began, it violates the temporal partial order. Formally, if the annotated pair requires \(\tau_{\text{rain}} \prec \tau_{\text{recon}}\) but the summary entails the reverse, then the temporal discriminator returns:

\[
\Gamma(e_{\text{temp}},s)=0.
\]

This is a direct Temporal Recall veto.

Third, biomechanical/casualty-layer veto. Let \(D(t)\) be cumulative death count at report time \(t\). The source reports 9 deaths and 6 missing as of August 1, then 29 deaths by August 10, including the 6 previously missing [PAGE 2]. Under ordinary cumulative reporting, absent a new revision source, death counts should not decrease. Formally, for report times \(t_1 \prec t_2\):

\[
D(t_2) \geq D(t_1).
\]

If a summary says “deaths fell from 29 to 9 after August 10” without a revision statement, it violates cumulative casualty logic. This is a biomechanical and evidential veto: casualty figures are integer counts with reporting monotonicity unless explicitly revised. The source shows a revision from missing to dead, not a decrease: “including 6 previously missing persons” [PAGE 2].

The proof structure is as follows. Suppose a summary \(s\) satisfies ROUGE or BERTScore by reusing many source words but asserts \(\mathrm{hazard}(s)=\text{snowstorm}\). Since the source predicate says \(\mathrm{hazard}(H)=\text{heavy rainfall}\), \(s\) is physically inconsistent with the event record. Therefore, \(s\) must be vetoed by the weather layer. Suppose \(s\) preserves hazard and entities but reverses temporal order. Then \(s\) violates the temporal partial order and must be vetoed by the clock layer. Suppose \(s\) preserves order but reports impossible casualty dynamics. Then \(s\) violates cumulative count constraints and must be vetoed by the casualty layer. The breakdown regime is explicit: if the input documents contain genuinely conflicting authoritative reports, the veto should become an abstention or human-adjudication flag, not a forced summary. The paper’s manual annotation and quality control are designed precisely for this gray zone: “The annotated data is iteratively checked and corrected to ensure high annotation quality” [PAGE 3].
</CROSS_LAYER_VETO_ADJUDICATION>

\[
V(s)
=
\left[
\bigwedge_{ki} \mathrm{Recall}_{ki}(s) > 0
\right]
\wedge
\neg \mathrm{PhysicalVeto}(s)
\wedge
\neg \mathrm{TemporalVeto}(s).
\]

This is a binary gate, not a fake ratio. The exact thresholds can be set by the evaluator, but the veto logic remains exact: if a required predicate is false, the summary fails that layer. Below are three verifiable RLVR veto scenarios with predictions.

The source states that the Hebei rainfall was caused by “Typhoon Doksuri and the interaction of cold and warm air masses” [PAGE 2]. Suppose the generated summary is:

This is fluent and partially correct, but it omits the causal event information. Let \(e_{\text{cause}}\) be the annotated cause sentence or argument. Then:

\[
\Gamma(e_{\text{cause}},s)=0.
\]

If the instance has \(N_{\text{ER}}\) annotated Event Recall elements, the maximum local Event Recall loss is:

\[
\Delta \mathrm{ER}
=
-\frac{1}{N_{\text{ER}}}.
\]

Prediction: Event Recall decreases, while ROUGE-1 and BERTScore may remain relatively high because many source words are retained. Human judgment should agree that the cause is missing, consistent with the paper’s high human-NLI consistency for Event Recall at 95.0 [PAGE 6]. This veto trains the model to include causal triggers, not just weather nouns.

Scenario 2: Temporal inversion veto.

“All 2,895 post-disaster reconstruction projects were completed before the July 27 heavy rainfall began.”

The source gives rainfall beginning July 27 and reconstruction completion by June 30 or July 2024 [PAGE 2]. The required temporal relation is:

\[
\tau_{\text{rain}} \prec \tau_{\text{recon}}.
\]

The summary entails:

\tau_{\text{recon}} \prec \tau_{\text{rain}},

so the temporal discriminator returns:

\[
\Gamma(e_{\text{temp}},s)=0.

\Delta \mathrm{TR}
=
-\frac{1}{N_{\text{TR}}}.

Suppose the generated summary says:

“The Hebei disaster was a snowstorm caused by an earthquake.”

\neq

\[
\Gamma(e_{\text{cause}},s)=0,
\]

and, depending on annotation, one or more Event Recall elements also fail. Prediction: Event Recall and Causal Recall decrease. BERTScore might not fully collapse if the summary still contains generic disaster vocabulary such as “Hebei”, “disaster”, or “July”, but the physical veto should override lexical similarity. This scenario is verifiable because the source explicitly names the hazard and cause [PAGE 2]. It also demonstrates why EventSum’s designed metrics are needed: “Common evaluation metrics such as the ROUGE for lexical evaluation and BERTScore for semantic evaluation, are insufficient to adequately assess the completeness and comprehensiveness of summaries that focus on dynamic events” [PAGE 1].

The RLVR implication is that reward should not be based only on similarity to a reference summary. A verifiable reward must check structured entailment, temporal order, causal inclusion, and physical consistency. If any veto triggers, the summary should receive zero or negative reward for that layer, even if it is fluent. This matches the paper’s empirical finding that commercial and open-source models can perform well on common metrics while still failing Event Recall, which the authors note was “significantly lower compared to other metrics” [PAGE 6].
