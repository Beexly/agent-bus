<RETROCAUSAL_GENEALOGY>
Historical and scientific lineage, plus multi-week traps.

The patent US 6,266,649 B1 belongs to the item-to-item collaborative filtering lineage that emerged as a scalability response to early user-user collaborative filtering systems such as GroupLens (Resnick et al., 1994). Rather than computing similarity between pairs of users across the full item space, the Amazon approach inverts the computation: the system precomputes item-item similarity offline and serves recommendations by intersecting the user’s known-interest set with rows of the similar items table [PAGE 8]. This shifts the online computational burden from \(O(|\mathcal{U}|)\) user comparisons to \(O(|K_u|)\) table lookups, a critical adaptation for a Web-scale catalog [PAGE 5, 8].

The text explicitly acknowledges conceptual permeability between paradigms: cart-content recommendation techniques can be incorporated into pure content-based systems [PAGE 5], and items of known interest may be identified via Web logs, browser favorites, or credit-card records in non-book domains [PAGE 8]. Thus the boundary between collaborative and content-based filtering is treated as a design choice, not a fundamental ontological divide.

Multi-week traps arise because the system encodes three fixed temporal constants into a signal stream that arrives at sub-second latency. First, the similar items table is regenerated periodically, e.g. once per week [PAGE 8]. During the interval between generations, newly trending items are invisible to \(T_{\text{sim}}\), creating a cold window of up to seven days for community-driven discovery. Second, the shopping cart process prunes dormant cart items after a predetermined period such as two weeks [PAGE 5]. A user who pauses a purchase decision for more than two weeks loses that cart signal entirely, even if the intent remains latent. Third, recently removed items are retained for roughly six months [PAGE 5], which is an order of magnitude longer than the cart-pruning window. This asymmetric memory—long retention of rejections, short retention of active consideration—means the system remembers “not bought” longer than it remembers “considering.” These are multi-week traps because they hard-code weekly and biweekly rhythms into an environment where user attention shifts on a minute-by-minute basis.

<RECURSIVE_THEORY_OF_MIND>
Crisis habit regression, counter-trap, and clock mismatches.

Crisis habit regression occurs when the recommendation service 44 becomes slow or unavailable. Under latency or outage pressure, users abandon the personalized recommendation widget and regress to habitual discovery channels explicitly modeled as external components 40: the search engine, direct URL navigation, order processing modules, or browser favorites [PAGE 5, 8]. At the moment the system’s model of the user is most needed for re-orientation, the user bypasses the model entirely. The recommendation system therefore experiences a crisis-induced distribution shift: the logged signals that return to the profile (purchases, cart adds, ratings) are no longer generated under the recommendation-conditioned policy but under a search-conditioned or direct-navigation policy, corrupting the very feedback used to train \(T_{\text{sim}}\).

The counter-trap is the off-line table generation process 66 [PAGE 8]. By precomputing \(T_{\text{sim}}\) once per week, the system avoids computing community-wide similarity at request time. This is a trap because it substitutes a batch-computed prior for real-time evidence. If a user’s taste shifts between batch cycles—triggered by a gift purchase, a seasonal need, or an external event—the system continues to serve recommendations from a stale similarity kernel. The counter-trap is that the optimization intended to guarantee speed (off-line precomputation) becomes the source of systematic recommendation error during periods of high preference volatility.

Two clocks govern the architecture and are not phase-aligned. The HTTP request/response clock operates at sub-second granularity as the Web server processes user requests [PAGE 5]. The similar-items table clock ticks once per week [PAGE 8]. The shopping cart pruning clock ticks on a two-week horizon [PAGE 5]. Because recommendation process 52 serves online requests from a table whose last update may predate the user’s current cart contents by days or weeks, the system can recommend items the user has already removed, or fail to recommend items just added to the cart. The recursive theory of mind is therefore: the system models the user; the user reacts to the model; the model updates on a weekly clock; the user’s behavior shifts between updates; and under crisis, the user exits the model’s observation loop entirely.
