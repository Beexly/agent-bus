<SOURCE_OPERATORS_AND_EQUATIONS>
The source operators are best stated as formal detection operators with explicit units. Let \(t\) be wall-clock time in seconds. Let \(t_e\) be the real event time and \(t_w\) the tweet timestamp. The Human Delay is
\[
D_i = t_{w,i}-t_{e,i}\quad [\mathrm{s}],
\]
which the paper describes as “the interval between the event occurrence and the tweet’s timestamp” [PAGE 2]. The post rate is the first difference of the tweet count:
\[
r(t)=\frac{1}{\Delta t}\,N\bigl([t,t+\Delta t)\bigr)\quad [\mathrm{s^{-1}}],
\]
where \(N\) is the number of event-related tweets in the interval and \(\Delta t\) is the bin width in seconds. The paper’s Figure 1 uses this rate on the y-axis: “the y-axis represents the volume of tweets posted per second” [PAGE 2].

For a window \(W\) in seconds, define the event template \(V_W(u)\), \(0\le u\le W\), in detector units. If the template is normalized to unit maximum, define
\[
\tilde V_W(u)=\frac{V_W(u)}{\max_{0\le s\le W}V_W(s)}\quad [\mathrm{dimensionless}].
\]
The matched filter is the time-reversed conjugate:
\[
H_W(t)=V_W^*(W-t).
\]
The paper states: “Take our event template V over the window W and take its time-reversed conjugate to form our matched filter H. \(H(t)=V^*(W-t)\)” [PAGE 4]. For a tweet stream \(X_i(t)\) in \(\mathrm{s^{-1}}\) from user group \(i\), the matched-filter output is
\[
m_i(t)=(X_i*H_i)(t)=\int_0^W X_i(t-\tau)H_i(\tau)\,d\tau.
\]
If \(H_i\) is dimensionless, \(m_i(t)\) has units \(\mathrm{s^{-1}}\); if the implementation uses discrete counts per sample, \(m_i\) has counts per sample and the threshold must share that scale. The paper does not state the unit of the “window size 30” or “threshold 8” [PAGE 5]; the formal assumption is that \(W=30\) is in seconds and \(\theta=8\) is in the same internal scale as \(m_i\). The decision rule is
\[
\hat y_i(t)=\mathbf{1}\{m_i(t)\ge \theta\}.
\]
The refractory rule is a same-event gate:
\[
\text{if } \hat y_i(t')=1 \text{ for any } t'\in(t,t+300\,\mathrm{s}],\quad \text{assign } t' \text{ to the same event}.
\]
The paper states the interval between adjacent events “is always larger than 5 minutes” and that remaining above threshold “within 5 minutes after a detected event” is treated as the same event [PAGE 4].

The combination operators are:
\[
m_{\max}(t)=\max_i\{m_i(t)\},
\]
\[
m_{\mathrm{mean}}(t)=\frac{1}{3}\sum_i m_i(t),
\]
\[
m_{\mathrm{prod}}(t)=\prod_i m_i(t),
\]
and the delayed-category combination
\[
m_{\mathrm{delay}}(t)=\frac{1}{2}\bigl(m_{\mathrm{inactive}}(t)+m_{\mathrm{short}}(t)\bigr).
\]
The paper evaluates these and reports that “the Mean Rule performs best” [PAGE 4]. The choice is justified by noise resilience and correlation: “the Mean Rule is known to be especially resilient to noise [23], and useful when inputs are highly correlated” [PAGE 4]. This is a formal operator with a clear assumption: the group outputs are sufficiently correlated that averaging reduces variance without cancelling the event signature.

The performance operators are standard detection rates:
\[
\mathrm{TPR}=\frac{TP}{TP+FN},\qquad
\mathrm{FPR}=\frac{FP}{FP+TN},
\]
both dimensionless. The reported values are “98% true positive, and 9% false positive rates” [PAGE 1], “97% true positive rate and less than 4% false positives rate” for the Touchdown parameter fit [PAGE 5], and “96% true positive rate and has 13% false positive rate” for a single matched filter [PAGE 6]. The detection delay is
\[
L=T_{\mathrm{detect}}-T_{\mathrm{event}}\quad [\mathrm{s}].
\]
The paper reports “an average delay around 45 seconds,” “60% of events within 40 seconds,” and “All detected events have delay less than 90 seconds” [PAGE 6]. It compares this with ESPN’s “about 90 seconds to update their webpage” [PAGE 6].

The window-size tradeoff is monotone in delay by construction: larger \(W\) requires more samples before a decision. The paper says “a short window will not allow for robust event detection” and “as the window size increases, the delay of event detection also increases” [PAGE 5]. The threshold tradeoff is:
\[
\theta\to 0 \Rightarrow \mathrm{FPR}\uparrow,\qquad
\theta\to\infty \Rightarrow \mathrm{TPR}\downarrow.
\]
The paper states this direction but swaps the labels: “A low threshold will recognize events when there are none (false negatives), while a high threshold will fail to recognize events (false positives)” [PAGE 5]. In standard terms, the low-threshold failure is false positive and the high-threshold failure is false negative. This terminology inversion is a source-level gray zone, not an equation error.

Exact breakdown regimes are:
1. \(W<W_{\mathrm{support}}\): the window is shorter than the template support, so the matched filter lacks enough pattern to discriminate; the paper says a short window “will not allow for robust event detection” [PAGE 5].
2. \(W>W_{\mathrm{delay}}\): the detection delay exceeds the 90-second operational target; the paper notes delay increases with window size [PAGE 5].
3. \(\theta\) too low: false alarms rise; the paper’s own label says “false negatives” but the operational meaning is false positives [PAGE 5].
4. \(\theta\) too high: misses rise; the paper’s own label says “false positives” but the operational meaning is false negatives [PAGE 5].
5. Adjacent-event interval \(<300\,\mathrm{s}\): the five-minute refractory rule merges distinct events [PAGE 4].
6. API rate near or above the “about 50 tweets per second” limit: the stream is censored and \(X(t)\) is compressed [PAGE 2].
7. Broad predicate at “~1% sample rate”: the observed \(X(t)\) is a sample, not the full population [PAGE 2].
8. Keyword collision: non-event tweets containing “touchdown” or “TD” inflate \(m(t)\); the paper’s keyword scoping retrieved “60% of the game related tweets with a false positive rate … below 5%” [PAGE 2], but that is not a zero-collision guarantee.
9. Correlated or adversarial noise: the matched filter’s optimality statement assumes independent additive noise [PAGE 4]; coordinated bursts violate that assumption.
10. Nonstationary user mix: templates fitted on one season or game set may shift when mobile share, activeness, or tweet length distributions change; the paper reports category-specific delays [PAGE 3], so template drift is a structural breakdown risk.

<RETROCAUSAL_GENEALOGY>
The scientific lineage is retrocausal in the sense that a 2010–2012 social-media system is legible only by tracing backward to signal detection theory and forward to later social sensing. The matched filter is an old radar and communications operator: correlate a received waveform with a known template, then threshold. The paper cites Hippenstiel’s detection theory text [PAGE 7] for this operator and explicitly says matched filtering “is proven to be the optimal linear filter when dealing with dealing with independent additive noise” [PAGE 4]. The combination rule lineage is also older: the paper cites Kittler et al. on combining classifiers [PAGE 7] and uses Maximum, Mean, and Product rules [PAGE 4]. The Mean Rule is selected because it is “especially resilient to noise” and “useful when inputs are highly correlated” [PAGE 4]. This is a classifier-fusion genealogy, not a sports-specific invention.

The social-sensing genealogy is equally visible. The introduction positions the work against earthquake detection [1], celebrity-death detection [2], and election detection [3], and says those efforts “have significant delays and usually perform their processing off-line” [PAGE 1]. It contrasts them with real-time detection of “less significant but more frequent events” such as NFL plays [PAGE 1]. The related-work section names TwitterStand [2], “Tweet the debates” [3], topical clustering [4], TwitInfo [12], and sports-video event detection [6, 13–16] [PAGE 1]. The paper’s contribution is not the invention of event detection from text; it is the measurement of human delay and post rate, the use of category-specific templates, and the deployment of a live web service. The service “has been evolving during the 2010-11 and 2011-12 NFL seasons” [PAGE 1], and the detection method “has also been evolving during this period” [PAGE 5]. The older temperature-based peak detector was replaced by variable window sizes and then by matched filtering. This is a retrocausal chain: current design choices are justified by older detection theory, while the two-season deployment supplies the operational confidence.

The multi-week traps are where the genealogy becomes a caution. First, the paper’s formal evaluation is LOOCV over 18 games, not a prospective multi-week holdout. It says “we use leave-one-out cross-validation (LOOCV) on all the 18 games” [PAGE 5]. That controls for game-specific overfitting only if games are exchangeable; it does not prove that a template fitted in week 4 remains calibrated in week 12. Second, the ground truth is manually marked from broadcasts: “we observed the broadcasts of 18 games … which include 100 touchdowns” and “We manually marked the real clock time of game events” [PAGE 2]. Broadcast timing, DVR delay, and local re-broadcast can shift the apparent delay distribution across weeks. Third, the API environment is nonstationary: broad predicates return “~1% sample rate,” and there is an “undocumented limit of about 50 tweets per second” [PAGE 2]. A threshold calibrated at low volume may fail during a high-salience game or a postseason game. Fourth, user behavior drifts with mobile adoption, platform changes, and team popularity; the paper’s own category results show that mobile, active, and short-tweet groups have different delay and rate profiles [PAGE 3]. A multi-week deployment that does not re-estimate templates can suffer silent calibration loss. Fifth, the paper’s “always larger than 5 minutes” adjacent-event assumption [PAGE 4] can fail in unusual game sequences, especially with review, injury, or replay stoppages. The correct multi-week protocol is therefore not “train once and deploy”; it is periodic held-out-week calibration, stream-saturation monitoring, and template refresh by user category.

<RECURSIVE_THEORY_OF_MIND>
The recursive theory-of-mind layer asks what the detector believes about users who themselves believe something about the event and their audience. There are three regimes: crisis habit regression, counter-trap, and clock.

Crisis habit regression is the paper’s most supported regime. Under an exciting event, users do not produce calm, long, analytical posts; they regress to short, exclamatory, mobile-friendly responses. The paper observes “users often post short tweets with exclamation marks and repeated letters to express their excitement,” with the example “New York Jets Touchdownnnnn!!!” [PAGE 3]. It reports that average word count “decreases from 12 words to 6 words within 60 seconds after an event” [PAGE 3], that short-tweet post rate is “twice that of the long tweets” [PAGE 3], and that mobile response magnitude is “twice as large” [PAGE 3]. In a recursive model, the detector should treat short/mobile/inactive bursts as high-likelihood evidence, not as noise. The delayed combination \(m_{\mathrm{delay}}(t)=\frac12(m_{\mathrm{inactive}}+m_{\mathrm{short}})\) is an explicit attempt to exploit this habit regression [PAGE 4]. But habit regression is a likelihood shift, not a veto: if a short mobile burst occurs without a physical event, it is still a false positive.

Counter-trap is the adversarial or semantic failure mode. The detector uses keywords such as “touchdown” and “TD” [PAGE 4], and keyword scoping retrieves “60% of the game related tweets with a false positive rate … below 5%” [PAGE 2]. That is good scoping, not immunity. A counter-trap occurs when users, bots, or sarcastic commenters generate the keyword without the event: a political “touchdown,” a replay of an old highlight, a fantasy-football complaint, or a coordinated burst. The recursive issue is that the detector’s model of “event talk” is learned from users who are themselves responding to an event; once the keyword becomes a token of commentary rather than a sensor reading, the likelihood model is misspecified. The Mean Rule is “especially resilient to noise” [PAGE 4], but resilience to independent noise is not resilience to a common-mode counter-signal. A counter-trap should therefore trigger a cross-layer check rather than an automatic acceptance.

Clock is the third regime: the user’s tweet clock, the broadcast clock, the game clock, and the real wall clock are not the same. The paper notes that media sources “only offer game clock timestamps of events,” and “because the game clock pauses and resumes during a game, we cannot use a game clock to determine the passage of time between events” [PAGE 2]. It therefore manually marks “the real clock time of game events” [PAGE 2]. The API delivery latency is “typically within one second” [PAGE 2], but human delay is not: first touchdown-related tweets arrive “between 7 seconds and 50 seconds,” and the aggregate peak is at 75 seconds [PAGE 2]. A recursive detector must maintain a belief over event time, not just tweet time. Formally, let \(g\) be the event type and \(X_{1:t}\) the tweet stream. A Bayesian sketch is
\[
P(g\mid X_{1:t}) \propto P(g)\prod_{\tau\le t}P(X_\tau\mid g,\text{user category},\text{clock offset}),
\]
with all probabilities dimensionless. If the clock offset is unknown or drifting, the likelihood is misaligned and the posterior peaks late. The correct adjudication is: accept a crisis-habit burst only when the clock model is synchronized and the counter-trap check is negative; otherwise downweight the burst. The paper’s average detection delay of about 45 seconds [PAGE 6] is therefore a joint statement about human reaction, template window, and clock alignment, not a pure property of the crowd.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
The paper is a single-layer Twitter detector. It does not provide independent physical, biomechanical, or weather sensors; it uses broadcasts and manual wall-clock marking for ground truth. The paper says the ground truth is “surprisingly not readily available” and that media sources “only offer game clock timestamps” [PAGE 2]. A cross-layer veto is therefore an external adjudication layer: the tweet detector proposes an event, and independent layers can veto it. Let \(A_t\in\{0,1\}\) be the tweet-detector acceptance at time \(t\). Let \(P_t\in\{0,1\}\) be physical confirmation from an official play-by-play or scoring feed. Let \(B_t\in\{0,1\}\) be biomechanical plausibility: possession, ball crossing the plane, kick trajectory, player down by contact, injury stoppage, or official review. Let \(W_t\in\{0,1\}\) be weather/venue permissiveness: no lightning delay, no power/network outage, no wind/rain condition that invalidates the play context. Let \(C_t\in\{0,1\}\) be clock synchronization within tolerance. The adjudicated event indicator is
\[
E_t=A_t\land P_t\land B_t\land W_t\land C_t.
\]
This is a veto conjunction, not a weighted score. If \(P_t=0\) for a claimed scoring event, the tweet burst is a false positive regardless of \(m(t)\). If \(B_t=0\), the claimed biomechanical event is impossible: a “touchdown” tweet burst during an injury stoppage or a replay review is not a scoring event. If \(W_t=0\), the venue or weather context invalidates the normal tweet-rate template: a lightning delay, power outage, or network failure changes both the event process and the observation process. If \(C_t=0\), the delay measurement is invalid even if the event occurred, because \(D_i=t_w-t_e\) is computed against a shifted \(t_e\).

The proof obligation is layer-specific. Physical proof is an official event log with timestamp and event type; it can veto a keyword collision. Biomechanical proof is a play-level constraint: the ball must cross the goal line while in possession, the kick must pass between the uprights, or the play must be ruled a turnover. Weather proof is an external record: lightning delay, stadium roof status, wind speed, precipitation, or outage log. Clock proof is a synchronization check between the official feed, the broadcast, and the detector’s wall clock. None of these are supplied by the paper; the paper’s evaluation is broadcast-based, not sensor-fused. That is the key cross-layer limitation: SportSense can detect “big plays” from tweets, but it cannot prove that the play physically occurred without an external layer.

The exact veto regimes are:
1. \(A_t=1, P_t=0\): keyword or sentiment burst without an official event; veto as false positive.
2. \(A_t=1, B_t=0\): biomechanically impossible or non-scoring play; veto even if the crowd reacts.
3. \(A_t=1, W_t=0\): weather, venue, power, or network disruption corrupts the rate template; veto or recalibrate.
4. \(A_t=1, C_t=0\): clock offset or broadcast delay makes \(D_i\) and \(L\) unreliable; veto the latency claim, not necessarily the event existence.
5. \(P_t=1, A_t=0\): missed event; this is a recall failure, not a veto of the physical event.
6. \(P_t=1, B_t=1, W_t=1, C_t=1, A_t=1\): accepted event with cross-layer support.
The adjudication should be asymmetric: a tweet-only acceptance is provisional; a physical or biomechanical veto is decisive. This is the only defensible way to use “cross-layer” language without pretending the paper measured layers it did not measure.
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
The following three counterfactual veto scenarios are verifiable with held-out data or replayed streams. They are stated as RLVR-style checks: a proposed detector action is rewarded only if an independent verifier confirms the event, and it is vetoed if the verifier contradicts it.

1. Keyword-collision counterfactual. Construct a held-out set of windows in which the keywords “touchdown” or “TD” appear but the official play-by-play has no scoring event. Verifier: official event log plus manual annotation. Veto rule: if \(P_t=0\), reject \(A_t\). Prediction: without the veto, the detector’s false-positive rate exceeds the paper’s reported 9% [PAGE 1] on collision-heavy windows; with the veto, collision-induced false positives fall toward zero. True positives should be unaffected when the official log confirms a scoring event. This scenario directly tests the paper’s keyword-scoping claim that it retrieved “60% of the game related tweets with a false positive rate … below 5%” [PAGE 2]; that claim is about retrieval, not about matched-filter acceptance.

2. Stream-saturation counterfactual. Replay or simulate a high-salience event where the API stream approaches the “undocumented limit of about 50 tweets per second” [PAGE 2], or where a broad predicate yields the “~1% sample rate” [PAGE 2]. Verifier: API rate log and sample flag. Veto rule: if the stream is censored or sampled, do not apply the fixed \(\theta=8\), \(W=30\) detector as if it were calibrated; either veto the decision or recalibrate on the observed rate. Prediction: under saturation, \(X(t)\) is compressed, \(m(t)\) is biased downward, and recall falls or delay increases relative to the 45-second average reported for the unsaturated evaluation [PAGE 6]. With saturation-aware calibration, the detector should recover part of the loss; without it, the threshold is not comparable to the paper’s operating point.

3. Clock/broadcast-offset counterfactual. Inject a known offset \(\delta\) between the official event timestamp and the timestamp visible to the detector, mimicking broadcast delay, DVR pause, or manual marking error. Verifier: the injected \(\delta\) is known exactly. Veto rule: if \(|\delta|>\tau\), where \(\tau\) is the synchronization tolerance, reject the Human Delay and detection-delay statistics for that window. Prediction: the measured Human Delay distribution shifts by approximately \(\delta\); the first-tweet interval and the 75-second peak shift in the same direction; the detector’s reported latency is biased by \(\delta\) even if the event is correctly detected. This is especially important because the paper itself says game clocks pause and resume and that the authors “manually marked the real clock time of game events” [PAGE 2]. The counterfactual makes the clock dependence explicit and verifiable.

A fourth optional check would be a weather/venue veto: if a lightning delay or power outage occurs, \(W_t=0\), and the tweet-rate template is invalid. The prediction is a rate collapse or burst unrelated to play, so the detector should abstain rather than report a play. The three scenarios above are the minimum verifiable set because they target the paper’s three most load-bearing assumptions: keyword specificity, stream completeness, and clock alignment.
</RLVR_COUNTERFACTUAL_VETOES>
