This source is a dataset-and-evaluation paper, not a contest-prediction text. The multi-hop derivation begins with a task distinction: multi-object tracking assigns persistent identity to the same object across frames, while recognition assigns a class label in individual frames. The paper states: “The former identifies the same object over multiple frames, while the latter identifies the type of object in individual frames” [PAGE 1]. That distinction is the causal root of the augmentation. Without persistent IDs, a detector can be scored for class label and bounding-box overlap, but cannot be scored for identity preservation, ID switches, or re-entry behavior. The benchmark gap is then established: MOT16 is pedestrian-centric, and “The MOT16 evaluation framework, however, filters out all objects not classified as pedestrian” [PAGE 2]; UA-DETRAC is dominated by moving vehicles [PAGE 2]; and Neovision2 Tower has five classes annotated in every frame but “the meta-data does not include unique object identifiers” [PAGE 3]. Thus the missing operator is not a new detector but an identity variable attached to each ground-truth object over the annotated temporal window.

The augmentation chain is explicit. Unique IDs are sequential integers starting at 1; new objects receive incremented IDs; IDs are not recycled when an older object leaves; and when an object re-enters, the former ID is re-assigned [PAGE 7]. The paper says: “The unique IDs are sequential integers starting with 1 and as new objects appear within a certain video, they are incremented” [PAGE 7]. It also says: “IDs are not recycled when an older object leaves the scene” and “Once an object re-enters, the former ID is re-assigned” [PAGE 7]. Two individuals independently verified uniqueness by visualizing every sequence [PAGE 7]. This matters because the evaluation operator is not merely counting boxes: it is matching system-track identities to ground-truth identities across occlusions and re-entry. The abstract states the intended invariant: “The unique IDs are maintained during occlusions between multiple objects or when objects re-enter the field of view” [PAGE 1]. Therefore the later MOTP/MOTA values are valid only if the ID field is used as an identity variable, not as a per-frame class proxy.

The evaluation chain is: oriented or region-based bounding boxes produce spatial overlap d_t; Munkres assignment produces one-to-one matches; matches above threshold T_d produce c_t; matched overlaps produce MOTP; false negatives, false positives, and ID switches produce MOTA [PAGE 8]. The paper states that matching uses “the Munkres algorithm13 to find an optimum mapping (in terms of total spatial overlap) between system tracks and unique ground truth objects” and that matches occur “when dt exceeds a user-defined threshold Td, which can range between 0 and 1” [PAGE 8]. This is a multi-hop dependency: no unique IDs means no IDSW term; no IDSW term means MOTA cannot measure identity preservation; no identity preservation means a multi-object tracker cannot be evaluated as a tracker, only as a per-frame detector. The paper’s own example applies CLEAR MOT to “Neovision2 Tower sequence 001 for all objects and for individual object classes” [PAGE 8].

The gray-zone audit has several traps. First, the printed overlap equation is “dt  = (Ri,t ∩Rj,t)/ (Rj,t ∪Rj,t)” [PAGE 8]. Read literally, the denominator is the union of the system region with itself, not the union of ground truth and system regions. A standard intersection-over-union requires Area(R_i,t ∪ R_j,t). The printed denominator is therefore a typographical or typesetting defect; copying it literally would not implement the stated “degree of spatial overlap” [PAGE 8]. Second, Table 1 lists Neovision2 bounding-box format as “Oriented” [PAGE 2], so an axis-aligned rectangle approximation is an assumption, not a neutral implementation detail. Third, the dataset is limited: “Although the Neovision2 Tower data set consists of 50 videos, we limit ourselves to the first 24 videos due to resource constraints associated with human annotation. This resulted in 20904 annotated image frames, containing 201690 object annotations and 463 unique objects” [PAGE 8]. Fourth, only the first 871 of 898 frames are annotated [PAGE 3]. Fifth, video 04 had a non-annotated target throughout the sequence, corrected with a purpose-built MATLAB tool [PAGE 3]. Sixth, the paper explicitly notes stationary pedestrians and a stationary car, “which present a challenge for systems whose object detection relies solely on motion-based image features” [PAGE 7]. Seventh, Person is “likely to be” the most difficult class because it has “both the smallest scale and highest maximum occlusion ratio of any class” [PAGE 5]. Eighth, weather and biomechanical variables are absent from the metadata schema in Table 2 [PAGE 4]. Any claim requiring those variables is not identifiable from this source. The correct conclusion is therefore narrow but strong: the source supports multi-class MOT evaluation with unique IDs, CLEAR MOT metrics, per-class filtering, and documented annotation limits; it does not support weather-robustness claims, biomechanical gait claims, or identity claims from class labels alone.

<SOURCE_OPERATORS_AND_EQUATIONS>
The source defines the spatial-overlap operator as a region intersection over a region union. The printed form is: “dt  = (Ri,t ∩Rj,t)/ (Rj,t ∪Rj,t)” [PAGE 8]. A faithful reconstruction, consistent with the paper’s description of “the degree of spatial overlap dt between each ground truth bounding box region Ri,t and each candidate bounding box region Rj,t” [PAGE 8], is:

\[
\operatorname{IoU}_{i,j,t}
=
\frac{\operatorname{Area}(R_{i,t}\cap R_{j,t})}
{\operatorname{Area}(R_{i,t}\cup R_{j,t})}
\]

Here \(\operatorname{Area}(\cdot)\) has units of \(\text{pixels}^2\), so \(\operatorname{IoU}_{i,j,t}\) is dimensionless and, for nondegenerate regions, lies in \([0,1]\). Assumption: \(R_{i,t}\) and \(R_{j,t}\) are the ground-truth and system track regions in frame \(t\). Because Table 1 lists Neovision2 bounding boxes as “Oriented” [PAGE 2], the areas should be polygon areas unless an explicit axis-aligned approximation is declared. Breakdown regime: if \(\operatorname{Area}(R_{i,t}\cup R_{j,t})=0\), the ratio is undefined; degenerate or self-intersecting polygons also make the area operator ambiguous. The printed denominator \(R_{j,t}\cup R_{j,t}\) is not the union of ground truth and system regions and is a source-level gray-zone defect [PAGE 8].

The object-scale operator is source-defined: “The size of an object is represented by its scale, which is calculated as the square root of the bounding box area, in units of pixels” [PAGE 5]. Thus:

\[
s_i = \sqrt{\operatorname{Area}(B_i)} \quad [\text{pixels}]
\]

where \(B_i\) is the object bounding box and \(\operatorname{Area}(B_i)\) is in \(\text{pixels}^2\). Assumption: the bounding-box area is the polygon area of the annotated region. Breakdown regime: zero-area boxes yield \(s_i=0\); malformed polygons yield undefined area.

The CLEAR MOT precision operator is:

\[
\operatorname{MOTP}
=
\frac{\sum_{t}\sum_{k=1}^{c_t} d_{t,k}}
{\sum_{t} c_t}
\]

The source states: “MOTP is calculated by averaging the matched ground truth and system track bounding box overlap across all matches and all frames” [PAGE 8], where \(c_t\) is the number of matches and \(d_{t,k}\) is the spatial overlap of the \(k\)th matched system track in frame \(t\). Units: dimensionless. Assumption: matches are one-to-one and satisfy \(d_{t,k} > T_d\), with \(T_d \in [0,1]\) [PAGE 8]. Breakdown regime: if \(\sum_t c_t = 0\), MOTP is \(0/0\) and undefined. At \(T_d=0\), any positive overlap can match; at \(T_d=1\), only exact overlap can match, so match count can collapse.

The CLEAR MOT accuracy operator is:

\[
\operatorname{MOTA}
=
1
-
\frac{\sum_t \left(FN_t + FP_t + IDSW_t\right)}
{\sum_t GT_t}
\]

The source states: “MOTA measures the overall accuracy of a system in tracking object configurations together with its ability to preserve object IDs across multiple frames” [PAGE 8], and defines \(GT_t\) as “the number of unique ground truth objects,” \(FN_t\) as false negatives, \(FP_t\) as false positives, and \(IDSW_t\) as ID switches [PAGE 8]. Units: dimensionless. Assumption: \(\sum_t GT_t > 0\); \(IDSW_t\) is an integer event count requiring unique ground-truth IDs. Breakdown regime: if \(\sum_t GT_t = 0\), MOTA is undefined. MOTA has no lower bound and can become negative when the error sum exceeds the ground-truth sum. Without the augmented ID field, \(IDSW_t\) is not computable, so MOTA cannot be interpreted as an identity-preservation metric [PAGE 3]. Per-class evaluation requires filtering: “The latter requires filtering out all ground truth and system tracks that correspond to all but the class under consideration” [PAGE 8]. The Unknown class is also relevant: the dataset contains five object classes plus “an Unknown class for moving objects that do not fit into these categories and are to be filtered out by the evaluation tool” [PAGE 4]. Finally, all metrics apply to the annotated window only: 871 of 898 frames [PAGE 3], and the paper’s augmented results cover 24 videos, 20904 frames, 201690 annotations, and 463 unique objects [PAGE 8].
</SOURCE_OPERATORS_AND_EQUATIONS>

<RETROCAUSAL_GENEALOGY>
The retrocausal genealogy runs from assignment algorithms to tracking metrics to dataset augmentation. The paper cites Munkres’ 1957 assignment algorithm [PAGE 9], Bernardin and Stiefelhagen’s 2008 CLEAR MOT metrics [PAGE 9], the DARPA Neovision2 benchmark from 2013 [PAGE 9], the 2014 Neovision2 object-recognition evaluation [PAGE 9], MOTChallenge 2015 [PAGE 9], UA-DETRAC 2015 [PAGE 9], and MOT16 in 2016 [PAGE 9]. The later metric layer is retrocausally dependent on the earlier annotation layer: CLEAR MOT’s IDSW term requires unique identity variables that the original Neovision2 Tower metadata did not contain [PAGE 3]. The paper’s contribution is therefore not a new matching algorithm but a metadata intervention that makes a 1957 assignment algorithm and a 2008 metric family applicable to a 2013 video corpus. The paper describes the result as enabling “a straightforward comparison of tracking system performance using the standard Multi Object Tracking (MOT) framework, and classification performance using the Neovision2 metrics” [PAGE 1].

The multi-week traps are historical and evaluation-design traps. First, using MOT16 alone conflates multi-object tracking with pedestrian-only tracking, because MOT16 filters out non-pedestrian objects [PAGE 2]. Second, using UA-DETRAC as a general stationary-object benchmark is unsafe because “the vast majority of the target objects are moving” and stationary handling is limited [PAGE 2]. Third, treating the original Neovision2 Tower as a tracking benchmark is invalid because it has class labels and boxes but no unique object identifiers [PAGE 3]. Fourth, assuming IDs are recycled is wrong: “IDs are not recycled when an older object leaves the scene,” and re-entry re-assigns the former ID [PAGE 7]. Fifth, treating the 24-video augmentation as the full 50-video corpus is wrong; the paper limits to the first 24 videos due to human-annotation resources [PAGE 8]. Sixth, using axis-aligned IoU on oriented Neovision2 boxes [PAGE 2] creates a systematic geometry mismatch. Seventh, failing to report the \(T_d\) threshold makes MOTP/MOTA non-comparable because \(T_d\) is user-defined over \([0,1]\) [PAGE 8]. Eighth, claiming weather or biomechanical robustness is genealogically unsupported: the metadata table lists frame, box coordinates, object type, occlusion, ambiguity, confidence, site information, and version, but no weather, illumination, gait, joint, force, or terrain variables [PAGE 4]. These traps compound over multi-week evaluation campaigns because each one changes the denominator, the match set, or the identity-event count without changing the visible aggregate score.
</RETROCAUSAL_GENEALOGY>

<RECURSIVE_THEORY_OF_MIND>
The recursive theory-of-mind layer here is about what the annotator, tracker, and evaluator each believe about object persistence. The annotator knows an object can leave and re-enter and therefore re-assigns the former ID [PAGE 7]. The tracker does not automatically know that the same physical object has returned; it must infer identity from appearance, motion, and context. The evaluator must model both: if the tracker assigns a new ID to a re-entering object, that can be an ID switch; if the tracker assigns an old ID to a different object, that can also be an ID switch or false positive. The paper’s ID policy is the clock that orders these beliefs: IDs are assigned sequentially as objects appear, are not recycled when objects leave, and are re-assigned on re-entry [PAGE 7]. The frame index is the only reliable clock in the source: 29.97 frames/s, 1920 x 1088 resolution, 898 frames per video, with the first 871 annotated [PAGE 3]. Any use of future frames to resolve an earlier identity violates the online-recognition framing that motivated Neovision2 [PAGE 2].

Crisis habit regression appears when a tracker under occlusion or clutter reverts to a habitual cue, usually motion-only detection or a class prior. The paper gives a direct counterexample: “the data set includes stationary pedestrians and a stationary car, which present a challenge for systems whose object detection relies solely on motion-based image features” [PAGE 7]. In that regime, the habitual motion cue produces false negatives, and a later re-detection can produce a new ID, inflating IDSW and depressing MOTA. The counter-trap is overcorrection: a tracker that tries to avoid IDSW by never issuing a new ID, or by aggressively matching every new detection to the nearest old track, can suppress genuine new objects and create false negatives or identity contamination. The evaluator’s counter-trap is similar: filtering out hard classes to make aggregate MOTA look stable hides the Person failure mode, even though Person is “likely to be” the most difficult class because it has the smallest scale and highest maximum occlusion ratio [PAGE 5]. The clock counter-trap is assuming that frame order is enough. It is not: re-entry requires memory of departed IDs, and the paper explicitly preserves former IDs on re-entry [PAGE 7]. A tracker with a short memory will look worse on re-entry; a tracker with an unlimited memory but no appearance model may over-match. The correct recursive model is therefore: annotator identity is persistent across gaps; tracker identity is inferred and fallible; evaluator identity must use the augmented ID field and report per-class results, not just an aggregate.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
Physical veto proof: the source provides two physical difficulty variables, object scale \(s_i=\sqrt{\operatorname{Area}(B_i)}\) in pixels [PAGE 5] and maximum occlusion ratio due to neighboring objects [PAGE 5]. Person has the smallest scale and highest maximum occlusion ratio, making it “likely to be” the most difficult class [PAGE 5]. A claim that a system is uniformly strong across all five classes is vetoed unless it survives the Person regime and the stationary-object regime. The stationary-object veto is explicit: stationary pedestrians and a stationary car challenge motion-only detectors [PAGE 7]. A motion-only system may pass on moving vehicles and fail on stationary objects; therefore aggregate results must be decomposed by class and by motion state. The physical veto is not a probabilistic guess; it is an identifiability condition: if the claimed mechanism depends on motion energy, then zero-motion objects are a breakdown regime.

Biomechanical veto proof: the source contains bounding boxes, class labels, frame indices, occlusion flags, ambiguity flags, confidence, site information, and version [PAGE 4], but it does not contain joint positions, gait phase, ground-force, muscle activation, body orientation, or cyclist-pedal kinematics. The paper’s speed distribution is only “average speed (in units of pixels/frame) of unique objects” [PAGE 7]. That is an image-plane kinematic summary, not a biomechanical measurement. Therefore any claim that a tracker or classifier is validated on biomechanical gait, pedestrian load, fatigue, or cyclist pedaling dynamics is vetoed for this dataset. The data can support scale, overlap, class, and image-plane speed; it cannot support biomechanical inference.

Weather veto proof: the source describes a fixed camera on the Stanford University Hoover tower [PAGE 3], but the metadata schema in Table 2 has no weather, rain, snow, fog, illumination, shadow, or wind variable [PAGE 4]. There is no reported weather stratification in the 24-video evaluation [PAGE 8]. Therefore a weather-robustness claim is not identifiable from this source. The veto rule is formal: if a proposed operator requires a variable \(V\) that is absent from the ground-truth schema, then \(V\)-conditional performance is unidentifiable and the claim is rejected for this dataset. The source can support occlusion, scale, class, and motion-state adjudication; it cannot adjudicate weather. The cross-layer verdict is thus: physical occlusion and stationary-motion vetoes are supported; biomechanical and weather vetoes are negative vetoes, meaning the source cannot prove them and therefore must not be used to certify them.
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
Scenario 1: ID-free MOTA claim. Suppose a system reports MOTA and IDSW on original Neovision2 Tower without the augmented ID field. Counterfactual: remove the ID column and rerun the evaluator. Prediction: IDSW is not computable, and any reported IDSW is fabricated or imported from an external annotation source. Verification: inspect the CSV schema; the original metadata lacks unique object identifiers [PAGE 3], while the augmented data add IDs [PAGE 1]. The veto is verifiable because the presence or absence of an ID field is a discrete, inspectable property. If the evaluator substitutes class labels for IDs, the resulting MOTA is not an identity-preservation metric and is vetoed.

Scenario 2: Motion-only stationary-object claim. Suppose a system claims strong multi-class tracking but relies solely on motion-based image features. Counterfactual: evaluate on stationary pedestrians and the stationary car. Prediction: false negatives increase and MOTA decreases in those strata, or the system re-detects the stationary object with a new ID and IDSW increases. Verification: per-class and motion-state stratification; the source explicitly warns that stationary pedestrians and a stationary car “present a challenge for systems whose object detection relies solely on motion-based image features” [PAGE 7]. A system that passes only moving objects but fails stationary objects cannot claim uniform multi-class tracking.

Scenario 3: Aggregate-class masking of Person. Suppose a system reports only a single aggregate MOTA across Bus, Truck, Car, Cyclist, Person, and Unknown. Counterfactual: filter all ground truth and system tracks except Person, as the paper’s per-class procedure requires [PAGE 8]. Prediction: Person MOTA is lower than the aggregate, because Person has the smallest scale and highest maximum occlusion ratio [PAGE 5]. Verification: compute the class-wise MOTA and compare to the aggregate; the paper’s own difficulty statement makes this a directional, falsifiable prediction. If the aggregate is stable while Person collapses, the aggregate claim is vetoed as a multi-class tracking claim, even if it remains a valid detection claim. A fourth-order check is threshold sensitivity: rerun at multiple \(T_d\) values in \([0,1]\) [PAGE 8]; if the ranking of systems changes with \(T_d\), the claim must report the threshold and cannot be treated as threshold-invariant.
</RLVR_COUNTERFACTUAL_VETOES>
