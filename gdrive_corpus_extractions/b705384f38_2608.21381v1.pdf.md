**Hop 1 — What is the actual unit of evidence?** The paper's grounding chain begins at GIST-Bench: "approximately every ten real users with overlapping interest profiles into one cohort, aggregates their engagement histories, and resamples from each pooled cohort to create synthetic users that preserve realistic behavioral distributions without retaining any individual user's traceable trajectory" [PAGE 3]. So the unit is *not* a real individual's traceable trajectory; it is a resampled cohort aggregate. PersonaMem-v3 then says "The user ID allows us to trace each unique user's full engagement history across events" [PAGE 3]. These two statements are in mild tension: traceability is asserted at the synthetic-user-ID level, while the upstream construction deliberately destroys individual traceability. The reconciliation is that "unique user" means unique *synthetic* user post-resampling. This matters because every downstream claim of the form "every persona claim traces to multiple real engagements" inherits cohort-level, not individual-level, provenance.

**Hop 2 — Why the threshold asymmetry?** The cross-reference score assigns "each explicit corroborating event contributes 1 point, while each implicit corroborating event contributes 0.5 points" [PAGE 5], with long-term admission thresholds of 20 (explicit) and 50 (implicit). The ratio 50/20 = 2.5 is *not* the reciprocal of the 1:0.5 weight ratio (which is 2.0). So the admission rule is strictly sub-proportional: an implicit-evidence claim needs 2.5× the raw event count but only 2.0× the credit, meaning implicit paths are admitted at a *slightly easier* credit level than the weighting alone would imply (50 × 0.5 = 25 credits vs. 20 × 1.0 = 20 credits; ratio 1.25). The paper concedes these are empirical: "We find these dataset-specific values empirically" [PAGE 5]. That is an honest admission, but it means the thresholds are tuned to this corpus's 63.8%-implicit-negative base rate [PAGE 3] and should not be transported as constants.

**Hop 3 — Scale non-invariance.** With "averaging more than 4,000 events per user over a 30-day observation window" [PAGE 3] and histories of "approximately 400,000 tokens on average" [PAGE 5], the fixed cross-reference thresholds (20/50/3) interact with tenure. A user with a longer or denser window accumulates more corroborating events for *every* candidate preference, so the fraction of candidate claims admitted rises monotonically with history length for a fixed threshold. The pipeline therefore has an implicit length-dependent persona-inflation term that the paper does not control for. This is a genuine gray zone: the benchmark's persona richness partially encodes observation-window size rather than preference strength.

**Hop 4 — The over-personalization tax is a non-commuting interaction, and that is the real result.** The headline is not "memory helps" or "memory hurts." It is that the sign flips by model: "GPT-5.5 Long Context scores 75.4%, but GPT-5.5 Textual Memory drops to 71.0%. However, Gemini-3.5-Flash shows the opposite behavior: Gemini-3.5-Flash Long Context scores only 57.0%, while Gemini-3.5-Flash Textual Memory rises to 69.9%" [PAGE 18]. The memory-swap ablation then isolates the interaction: "GPT-5.5 drops from 74.8% with its own memory to 66.4% with Gemini-3.5-Flash's memory, while Gemini-3.5-Flash rises from 63.5% with its own memory to 73.2% with GPT-5.5's memory" [PAGE 19]. Computing the difference-in-differences interaction term: (74.8 − 66.4) − (63.5 − 73.2) = 8.4 − (−9.7) = **+18.1 percentage points**. This is the paper's strongest quantitative claim: the *rendering function* that maps a memory document into a policy's attention is model-specific and non-substitutable. The paper states the mechanism in prose — "it is not simply whether a memory is good or bad, but that memory changes what becomes salient to the model's attention and how each foundation model interprets it" [PAGE 18–19] — but never computes the interaction term, which is the quantity that makes the claim falsifiable.

**Hop 5 — The lost-in-the-middle confound.** The paper reports a U-shape — "all model-mode configurations show a U-shaped pattern with accuracy drops in the middle over histories around 400k+ tokens" [PAGE 19] — and then, to its credit, pre-registers the confound: "evidence that first appears early often has more chances to be reinforced by later activity, so the farthest bins may contain stable, repeated preferences rather than one isolated old fact" [PAGE 19]. The right-hand rise of the U is therefore *not* clean evidence of positional robustness; it is a survivorship artifact of reinforcement. The left-hand rise (recency) is confound-free. So the defensible claim is a *monotone recency gradient plus a survivorship-inflated far tail*, not a symmetric U. The paper's own memory-cap experiment supports this reading: even at 8192 tokens with 90.8% semantic survival, "the middle dip remains 9%, 7%, and 10% in accuracy, respectively" [PAGE 19–20] — a dip that survives perfect recall must be an *attention/allocation* effect, not a *storage* effect. That is the load-bearing inference.

**E1. Time-masked accessibility set** [PAGE 9]. For user $u$, event set $\mathcal{E}_u$, event timestamp $\tau(e)$, test moment $t^*$:

$$\mathcal{H}_u(t^*) \;=\; \{\, e \in \mathcal{E}_u \;:\; \tau(e) \le t^* \,\}, \qquad r = \pi_\theta\!\left(q,\ \Phi(\mathcal{H}_u(t^*))\right)$$

Units: $\mathcal{H}$ in *events*; $\Phi$ is a rendering map into *tokens*; $\pi_\theta$ is the policy. **Breakdown regime:** leakage, $\exists\, e \in \mathcal{H}_u(t^*)$ with $\tau(e) > t^*$, which the paper excludes by construction — "The system can only access events before that timestamp, so it cannot see the future behavior" [PAGE 9]. The harness is therefore sound on this axis *provided* the per-app database cut is applied uniformly; the paper does not report an audit that the cut was verified per row.

**E2. Cross-reference evidence operator** [PAGE 5].

$$S(p) \;=\; \sum_{e \in E^{\text{exp}}_p} 1 \;+\; \sum_{e \in E^{\text{imp}}_p} \tfrac{1}{2}$$

Units: *evidence credits* (dimensionless, one credit = one explicit corroboration). Verbatim: "each explicit corroborating event contributes 1 point, while each implicit corroborating event contributes 0.5 points" [PAGE 5].

**E3. Admission predicate** [PAGE 5]. With initial confidence $c_0(p)$:

$$\text{Admit}(p) \;=\; \mathbb{1}\!\left[c_0(p) \ge \theta_{\sigma(p)}\right]\cdot \mathbb{1}\!\left[S(p) \ge \tau_{\ell(p)}\right]$$

$$\theta_{+}=0.75,\quad \theta_{-}=0.55,\quad \tau_{\text{long}}^{\text{exp}}=20,\quad \tau_{\text{long}}^{\text{imp}}=50,\quad \tau_{\text{short}}=3$$

**Breakdown regime (singularity):** $\tau_{\text{short}} = 3 \ll \tau_{\text{long}}^{\text{imp}} = 50$ makes short-term intents ~17× easier to admit on implicit evidence. In a high-density 30-day window this drives a *false-short-term-intent* regime, where episodic bursts get promoted to short-term intent and then must be expired. The paper's bursty-trajectory class is only "1%" of 1,554 trajectories [PAGE 17], which bounds the practical size of this regime for *this* corpus but not for denser ones.

On sensitive-event restraint: Gemini LC 38.0% with "privacy-leak violations in 36.6% of rows," rising to 63.3% with leaks at 6.5% [PAGE 18] — a 30.1 pp leak-rate collapse. The tax is therefore not a uniform scalar; it is a function of the *sensitivity class* of the retrieved fact.

**E8. Memory rewrite decay.** With per-update line-level drop/rephrase rate $q = 0.144$ [PAGE 19], the survival probability of unaltered exact wording after $n$ update epochs under an independent-rewrite model is

$$s_{\text{exact}}(n) \approx (1-q)^n = 0.856^{\,n}$$

Units: probability. $n=5 \Rightarrow 0.46$; $n=10 \Rightarrow 0.21$. **Breakdown regime:** the model is an approximation — rewrites are correlated (recently added lines are more fragile per the source, which says exact survival is low "especially for content added early or in the middle" [PAGE 19]), so $s_{\text{exact}}$ is not uniform across insert epochs. The paper's measured concept-level survival is higher and capacity-dependent: "63.2% to 83.1% to 90.8%" for caps 2048 → 4096 → 8192 tokens, corresponding to "35 to 66 to 102 bullet lines" [PAGE 19]. Note $s_{\text{concept}} > s_{\text{exact}}$ always, as semantic equivalence is a coarser equivalence class.

**E9. Positional dip statistic** [PAGE 19–20].

$$\delta_{\text{dip}} \;=\; \max\!\big(\bar A_{\text{near}},\ \bar A_{\text{far}}\big) - \bar A_{\text{mid}}$$

Measured: $\delta_{\text{dip}} \in \{9\%, 7\%, 10\%\}$ at caps 2048/4096/8192. **Key falsification-relevant structure:** $\partial \delta_{\text{dip}}/\partial(\text{cap}) \not\to 0$ but also does not vanish — the dip is capacity-invariant, which localizes the failure to attention allocation rather than storage.

**E10. Proactive decision rule** (grounded in the paper's cited mixed-initiative framework [PAGE 12], Horvitz 1999). Act iff expected utility is positive:

$$\mathbb{E}[U \mid \text{act}] = p_{\text{rel}}\,v - (1-p_{\text{rel}})\,c_{\text{intr}} - c_{\text{intr}} \;>\; 0 \;\Longleftrightarrow\; p_{\text{rel}} \;>\; \frac{2c_{\text{intr}}}{v + c_{\text{intr}}}$$

Units: decisional utils for $v$ (value of a grounded intervention) and $c_{\text{intr}}$ (interruption cost). **Breakdown regime:** as $c_{\text{intr}} \to v$, the threshold $p^\star \to 1$ — i.e., high-interruption contexts (sensitive events, idle moments) require near-certainty. The empirical signature matches: "mistake-prevention alerts stay only 8-13% accurate" while "Gemini and Claude models do better on idle-moment silence" [PAGE 17] — models are calibrated toward the conservative branch of this rule and fail the high-$v$ branch. Claude Code's under-action is the direct behavioral correlate: it "often chooses silence when the benchmark expects a grounded proactive message" [PAGE 22].

**E11. Cost-normalized accuracy** (descriptive measured ratio, **not** a law). Let $A$ = overall accuracy (dimensionless) and $T$ = tokens per query.

$$\eta = A / (T/10^3)\quad [\text{accuracy per }10^3\text{ tokens}]$$

Long context: 0.534 / 416 ≈ $1.28\times10^{-3}$; compact memory at ~4k tokens: 0.53 / 4 ≈ $1.3\times10^{-1}$ — a ~100× efficiency separation [PAGE 14–15]. **Explicit caveat:** agentic $\eta$ is inflated by the tool-result token exclusion noted in THINK_TRACE hop 7 and must not be compared naively.

</SOURCE_OPERATORS_AND_EQUATIONS>

<RETROCAUSAL_GENEALOGY>

**Genealogy, generation 0 — the LaMP line.** The paper positions itself against "LaMP introduces profile-conditioned personalized classification and generation, while LongLaMP and LaMP-QA extended this line to longer-form generation and question answering" [PAGE 27]. LaMP's epistemology is *given profile → conditioned output*. PersonaMem-v3's is *given behavior → inferred profile → conditioned output*. The retrocausal move is that the profile stops being an input and becomes a claim requiring evidence credit (E2/E3).

**Generation 1 — synthetic personas.** "PersonaMem-v1: 20 fully synthetic users … Explicit user preferences." "PersonaMem-v2: 1000 fully synthetic users … Implicit user preferences" [PAGE 26, Table 9]. The v1→v2 transition shifted the epistemic target from stated to revealed preference. The v2→v3 transition shifts the *substrate* from generated to sampled-and-resampled, and the *scope* from one channel to six.

**Generation 2 — the memory-systems lineage, which is orthogonal and partially incompatible.** LongMemEval and LoCoMo ("factual recall, temporal reasoning, knowledge updates, and long-range conversational consistency"), MemoryAgentBench ("retrieval, test-time learning, long-range understanding, and selective forgetting"), EvoArena, MemoryBank, Mem0, A-MEM, MIRIX, MemOS, Memory-R1, MemAgent, ReasoningBank, Evo-Memory, EvoMemBench [PAGE 26–27]. The incompatibility: memory benchmarks score *retrieval fidelity*; PersonaMem-v3 scores *retrieval + adjudicated appropriateness*. A system can win LongMemEval and lose PersonaMem-v3's sensitive-event restraint — and the data show exactly this decoupling, since Mem0 wins on cheapness yet has "the weakest, at 56.9% with a 51.4% outdated-stance rate" on preference tracking [PAGE 18].

**Generation 3 — the over-personalization critique.** "OP-Bench formalizes over-personalization in memory-augmented assistants as irrelevance, repetition, and sycophancy"; "RPEval studies rational preference utilization, showing that irrelevant personalized memories can interfere with intent understanding" [PAGE 27]. PersonaMem-v3's Table 6 [PAGE 12] extends the failure taxonomy to five classes by adding sensitive-event restraint and do-not-personalize follow-up, anchored respectively to Goffman's front/back-stage, Horton–Wohl parasocial theory, and Higgins's ought-self.

**Generation 4 — LLM-as-reranker and agentic recommendation.** Seq2Slate, PRM, DLRM, HSTU, PEAR in the deep-ranking lineage; then "Zero-shot ranking work showed that LLMs can rerank candidate sets without retraining the full recommender stack," LLM4Rerank, RecRanker, OneRec, OpenOneRec, OneReason, AgenticRec, MARS [PAGE 27–28]. PersonaMem-v3's deliberate position is *reranker-only*: "It does not assume an LLM should own the full recommender pipeline" [PAGE 27]. This is the correct architectural bet given that long-context reranking over 16 candidates is cheap relative to candidate generation.

**Multi-week traps, enumerated (each is a place where a system degrades on a horizon longer than a single session):**

- **Trap A — directive persistence horizons.** The @AI steering task is tested "after 24 hours, 72 hours, and 7 days" [PAGE 11]. A single-session system treats a directive as a prompt instruction; a 7-day system needs a *stored constraint with a decay law*. The paper reports this as one of the *easier* families ("many configurations score in the 70s or 80s there" [PAGE 17]) — which is itself suspicious and suggests the directives may be lexically recoverable rather than requiring genuine constraint maintenance.
- **Trap B — preference expiry.** "Short-term intents use a lower threshold of 3" [PAGE 5] means short-term items enter the profile easily and must be actively retired. The measured failure is "Failures often directly center an expired preference such as car shipping, Spanish practice, cruise planning, or resin art" [PAGE 18].
- **Trap C — compounding memory drift.** E8's $0.856^n$ gives ~79% exact-wording survivorship over 10 epochs; over a multi-week deployment with daily consolidation this is the dominant source of persona drift, and it is invisible to any evaluation that only checks final-state accuracy.
- **Trap D — reinforcement confound over weeks.** Because 77% of trajectories are reinforced [PAGE 17], a multi-week system's memory fills with high-credit stable preferences. The far tail of the U-curve (E9) is then populated by *reinforced* items, so the apparent "long-range robustness" is partly an artifact of the data-generating process — a trap for anyone who reads the U as an architectural property.
- **Trap E — the sensitivity ratchet.** If sensitive facts accumulate in memory and, per the GPT-5.5 pattern, "once sensitive facts or strong preferences enter the memory, everything in that document becomes salient and safe-looking evidence to reuse" [PAGE 18], then over weeks the over-personalization rate is *non-decreasing* in memory age. This predicts a monotone creep that the paper's cross-sectional design does not measure.

</RETROCAUSAL_GENEALOGY>

<RECURSIVE_THEORY_OF_MIND>

**The second-order belief object.** A personalized agent's utterance reveals not just what it knows but *that it knows*, and with what confidence. Formalize the agent's representation as $\mathcal{B}_a\big(\mathcal{B}_u(M)\big)$ — the agent's belief about the user's belief about the agent's memory content $M$. The canonical failure mode is named explicitly: "the output avoid[s] framing personalization in an overly explicit way, such as directly stating 'I know you like X'" [PAGE 10, Table 3]. That is a *second-order* violation: the content may be correct and the first-order utility positive, yet surfacing it exposes the depth of $\mathcal{B}_a$, which the user experiences as surveillance. No first-order accuracy metric can detect it, which is why the harness needs a separate hard check.

**Crisis habit regression.** Under sensitive-context pressure, models regress to the pretraining-favored habit of *using salient retrieved facts because they are salient*. The Gemini-3.5-Flash long-context result is the cleanest measurement of this regression: 38.0% on sensitive-event restraint with 36.6% privacy-leak rows; adding 40 raw sensitive posts costs a further 5.5 points, "while adding ordinary posts changes the score by less than one point" [PAGE 19]. The regression is *class-specific*: sensitivity-loaded context degrades restraint, ordinary context does not. Note the counter-intuitive corollary — the *same* model improves to 63.3% / 6.5% leaks when the identical facts are compressed into a profile [PAGE 18]. Habit regression is thus a function of *presentation format*, not of information content. That is the paper's most theoretically interesting finding and it is not fully exploited.

**Counter-trap design.** The harness builds explicit traps where the correct action is inaction: "Idle-moment silence — The user has recent history, but there is no clear reason to interrupt them" and "Sensitive-event silence — The backend contains recent evidence of a sensitive life event" [PAGE 13, Table 8]. The agent "is not told which trigger is being tested" [PAGE 12], so silence cannot be achieved by pattern-matching the prompt. This is a well-constructed counter-trap: the only way to pass is to actually compute E10's expected utility. Empirically, "Gemini and Claude models do better on idle-moment silence, suggesting that some models are better at restraint even when they still struggle to initiate the right helpful action" [PAGE 17] — i.e., they satisfy the low-$p_{rel}$ branch of E10 and fail the high-$v$ branch.

**The clock, in three registers.** (i) *Data clock*: the time-mask $\mathcal{H}_u(t^*)$ (E1) prevents future leakage. (ii) *Task clock*: directive persistence at 24h/72h/7d [PAGE 11]; short-term intent expiry. (iii) *Compute clock*: the harness enforces "15 turns and $0.30 by default for Sonnet-4.6; 30 turns and $0.60 for heavier tasks," a "600s subprocess timeout and a 900s worker hang guard," with "at most two attempts" [PAGE 15–16]. This third clock is a genuine confound for the proactiveness results: a proactive task where the correct action is to *search then decide* competes for turns with search itself. Claude Code's under-action ("often chooses silence when the benchmark expects a grounded proactive message" [PAGE 22]) may be partly a budget-exhaustion artifact rather than a policy preference — the paper does not ablate the turn cap against proactiveness accuracy, which is a missing control.

**Recursive audience modeling.** Bell's audience design is operationalized concretely — each sub-persona "records the expected audience and adjusts surface choices such as length, emoji use, self-censoring, and disclosure depth," constrained by two rules: "each sub-persona must stay within the shared voice, and at least two apps must differ" [PAGE 6]. This is a *bounded* theory-of-mind: the agent must model a different audience per surface while holding one identity spine fixed. The cross-app repost task [PAGE 13] is the direct test — "preserve the source post's meaning and create exactly one adapted post on the target app" — and it sits among the easier families, meaning audience-shifting per se is tractable. What is *not* tractable is deciding *whether* to shift, which is the E10 problem again.

</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>

**Scope statement.** The corpus has no biomechanical layer, no physical-load model, and no weather feed. I therefore do not adjudicate a physical veto; I adjudicate the *structurally analogous* cross-layer gates the paper does implement, and I flag that the analogy is structural, not physical. Any claim that this paper contains a physiological or meteorological constraint would be fabrication.

**V1 — The multiplicative hard-check veto** [PAGE 10, Table 3]. Four checks are Boolean, not scored: "Avoids disliked topics," "Protects private context," "Avoids outdated memory," "Avoids creepy framing." The scoring checks (relevant preferences, right amount, social context, voice) are judge-scored. The composition is therefore a veto-over-score structure:

$$V(r) \;=\; \prod_{j \in \{\text{disliked},\, \text{privacy},\, \text{stale},\, \text{creepy}\}} \mathbb{1}\big[\text{check}_j(r)=\text{pass}\big], \qquad \text{Score}(r) = V(r)\cdot \bar{s}(r)$$

**Breakdown regime:** if any hard check fails, a response that maximizes $\bar{s}$ scores zero. This is the correct design and it is what makes the over-personalization numbers interpretable — a 36.6% privacy-leak rate is not "slightly worse average quality," it is a 36.6% total-loss rate on those rows.

**V2 — Exogenous-context veto: geo shift.** The "Local recommendation after geo shift" task requires the system to "infer the current city from history, avoid anchoring on the old city, and still fit the user's general preferences" [PAGE 10, Table 4]. This is the closest thing in the corpus to a cross-layer veto: location is an exogenous state variable that *invalidates* an otherwise high-credit preference (long-term city-specific interests, which by E3's $\tau_{\text{long}}$ thresholds carry 20–50 credits of evidence). The veto is that accumulated evidence credit must be *overridden* by a single weak-but-recent signal (the move). No scalar evidence-credit function can represent this; it requires a regime-change detector. The paper asserts the task exists but does not report a per-task score, which is a reporting gap — the geo-shift row is absent from the Figure 4 breakdown described on [PAGE 14].

**V3 — Cross-signal contradiction veto: mistake prevention.** "noticing that the user's calendar shows a flight from JFK, New York while the user is asking the chatbot about buying a train ticket to Newark, New Jersey instead" [PAGE 12]. The veto fires on a *conjunction across layers* (calendar ∧ location ∧ chatbot intent), and the required action is a warning. Measured: "mistake-prevention alerts stay only 8-13% accurate" [PAGE 17]. This is the weakest result in the paper and it is the one most diagnostic of cross-layer reasoning: it requires (a) reading the calendar layer, (b) reading the geo layer, (c) parsing the current query, (d) detecting incompatibility, (e) deciding the interruption is worth it under E10, and (f) phrasing without revealing that the agent has been reading the calendar. Six conjoined requirements at 8–13% is approximately what you would expect if each step were individually ~70% reliable ($0.7^6 \approx 12\%$). The paper does not run this decomposition, but the number is arithmetically consistent with it — a useful diagnostic to flag for follow-up.

**V4 — Veto precedence and the privacy/utility tradeoff.** When the hard-check veto and the scoring rubric conflict, the harness resolves in favor of the veto. Evidence: Gemini-3.5-Flash's memory setting *improves* restraint while *not* necessarily improving general personalization — "Textual Memory does not necessarily remove those sensitive facts; it changes their form by compressing repeated private evidence into a bounded profile" [PAGE 18]. The paper is careful not to claim a general capability gain, which is methodologically correct.

**V5 — What a physical/biomechanical veto would require, and why it is absent.** A genuine cross-layer physical veto would need (i) a state variable measured in SI units with a stated sampling rate, (ii) a threshold with a documented derivation, and (iii) a demonstrated override of the primary score. The corpus's closest analogue — the geo-temporal stream — satisfies (iii) but presents location as categorical rather than physical, and the calendar stream as discrete events. I decline to construct a $\text{load}/\text{capacity}$ or similar ratio here: it would be a toy equation with no referent in the source, which the invariants forbid.

</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>

Each scenario below is stated as a *falsifiable* manipulation with a *predicted* outcome drawn from the paper's reported mechanism, plus the observation that would veto the mechanism.

**RLVR-1 — Memory-rendering swap (the interaction veto).**
*Intervention:* give GPT-5.5 Gemini-3.5-Flash's memory document, and vice versa, holding task rows fixed.
*Prediction (from [PAGE 19]):* GPT-5.5 restraint falls from 74.8% to ≈66.4% ($\Delta \approx -8.4$ pp); Gemini rises from 63.5% to ≈73.2% ($\Delta \approx +9.7$ pp); interaction term $\mathcal{I} \approx +18.1$ pp.
*Veto condition:* if $\mathcal{I}$ replicates near zero, the "memory reshapes salience in a model-specific way" hypothesis is false and the effect is a generic memory-quality effect. This is the single highest-value replication in the paper because it is the only design that separates memory *content* from memory *interpretation*.

**RLVR-2 — Sensitivity-class injection (the format-vs-content veto).**
*Intervention:* append 40 raw sensitive posts alongside compact memory; separately append 40 ordinary posts of matched length and recency.
*Prediction:* sensitive augmentation costs ≈2.5 pp for GPT-5.5 and ≈5.5 pp for Gemini-3.5-Flash; ordinary augmentation moves the score <1 pp [PAGE 19].
*Veto condition:* if ordinary and sensitive injections produce comparable degradation, the effect is context-length/recency, not sensitivity — and the "sensitive context is especially harmful" reading collapses. Note the paper also reports a *null* result that constrains the mechanism: adding explicit frequency counts for sensitive events "changes the score by less than one point" [PAGE 19], so the mechanism is not salience-through-frequency.

**RLVR-3 — Memory capacity sweep (the storage-vs-attention veto).**
*Intervention:* run GPT-5.5 Textual Memory at 2048/4096/8192-token caps.
*Prediction:* bullet lines 35 → 66 → 102; concept survival 63.2% → 83.1% → 90.8%; middle-position dip 9% → 7% → 10%; overall accuracy changes only modestly, largest cap slightly above baseline [PAGE 19–20].
*Veto condition:* the mechanism claims the dip is an allocation failure, not a storage failure. If a 4× capacity increase *eliminates* $\delta_{\text{dip}}$ (E9), the storage/attention separation is refuted and the correct diagnosis reverts to capacity-limited compression. The observed non-monotone dip (9 → 7 → 10) is itself a warning that $\delta_{\text{dip}}$ is noisy at this sample size, and any replication should report confidence intervals the paper does not provide.

**RLVR-4 — Exact-wording decay fit (the compounding-drift veto).**
*Intervention:* instrument the memory builder to log, per line, insertion epoch and survival status under exact and semantic match, over ≥10 update epochs.
*Prediction:* exact-wording survival tracks $s_{\text{exact}}(n) \approx 0.856^n$ (E8) with epoch-dependent deviation (early- and middle-inserted lines decaying faster than the pooled rate), while concept survival stays strictly above it and rises with cap.
*Veto condition:* if $s_{\text{exact}}$ is epoch-*independent* (constant hazard), the 14.4% figure is an artifact of the pooled averaging described on [PAGE 19] rather than a per-update rate, and E8's compounding model is invalid. This counterfactual also directly tests Trap C in the genealogy.

**RLVR-5 — Budget ablation on proactiveness (the clock-veto control the paper omits).**
*Intervention:* rerun the Claude Code proactive subset at 15, 30, and 60 turns, holding dollar budget proportional.
*Prediction:* if under-action is a *policy* preference, accuracy is flat in the turn cap; if it is *budget exhaustion*, accuracy rises monotonically and the reported "Claude Code often chooses silence" [PAGE 22] is misattributed.
*Veto condition:* flat curves veto the budget confound and validate the policy-preference reading; rising curves veto the paper's interpretation of its own agentic result. Given the paper explicitly caps at "15 turns and $0.30 by default … 30 turns and $0.60 for heavier tasks" [PAGE 15], this control is cheap and should have been run.
