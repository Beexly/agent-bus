The source document defines a multi-hop evaluation architecture rather than a single predictive task. The reasoning chain starts with raw engagement events, then moves through evidence-grounded preference extraction, layered persona synthesis, cross-platform digital-world construction, interactive evaluation, and finally failure-mode attribution. Each hop changes the epistemic status of the evidence: raw events are noisy and mostly implicit; extracted preferences are probabilistic claims; personas are theory-anchored latent structures; benchmark tasks are counterfactual probes; and model outputs are judged by task-specific metrics plus hard privacy and temporal constraints. The key derivation is therefore not “who will win” in any competitive sense, but whether a system can infer the correct latent user state at the correct time while avoiding invalid personalization.

A first multi-hop inference is that the benchmark’s statistical foundation is dominated by implicit negative evidence. The source states that “Only about five percent of the signal is explicit; the remaining ninety-five percent is implicit” [PAGE 2], and later that the sampled GIST-Bench events include “nearly 63.8% of which are implicit negative” [PAGE 3]. This creates a gray-zone audit problem: a skip may mean dislike, but it may also mean distraction, fatigue, or rapid scrolling. The authors handle this by refusing to infer persona claims from a single implicit negative. They upgrade implicit negatives only when repetition makes the pattern meaningful [PAGE 4]. Formally, this is a Bayesian evidence-accumulation problem with a nonstationary user state: repeated skips under a short temporal window increase the posterior probability of active avoidance, while isolated skips remain ambiguous.

A second derivation concerns the transition from event-level evidence to stable preference claims. The source says that “each explicit corroborating event contributes 1 point, while each implicit corroborating event contributes 0.5 points” [PAGE 5]. This yields an evidence score with thresholded acceptance. The benchmark then separates enduring preferences from short-term intents, requiring lower evidence for short-term intents: “Short-term intents use a lower threshold of 3 because they naturally have less time to accumulate repeated evidence” [PAGE 5]. The gray zone here is temporal: a preference may be real but obsolete. A model that retrieves the correct historical fact can still fail if it cannot determine whether the fact remains valid at query time.

A third derivation is that the benchmark treats recommendation as an LLM reranking problem on top of mature candidate generation. The source says, “we build a 16-candidate pool around a test timestamp. The target is a held-out post that the user will positively engage with shortly after that moment” [PAGE 11]. This is not static preference matching; it is near-future prediction under noisy engagement. The evaluation metric is explicit: “All tasks in this subsection are evaluated with NDCG@5 rather than LLM-as-a-judge” [PAGE 11]. Thus, recommendation quality is formalized as ranked-list utility over five positions, with the target positive item ideally at the top. Hard negatives include posts the user previously or recently negatively engaged with [PAGE 11]. The gray-zone audit is that a model may retrieve topically similar content but fail to distinguish near-future positive engagement from stale positive history or negative evidence.

A fourth derivation concerns the over-personalization tax. The benchmark does not reward maximum personalization; it rewards calibrated restraint. The source defines over-personalization as using true personal information in a way that is invasive, awkward, repetitive, or socially inappropriate [PAGE 9]. It then reports model-specific reversals: “GPT-5.5 Long Context scores 75.4%, but GPT-5.5 Textual Memory drops to 71.0%,” while “Gemini-3.5-Flash Long Context scores only 57.0%, while Gemini-3.5-Flash Textual Memory rises to 69.9%” [PAGE 18]. This is a crucial multi-hop finding: memory compression is not universally safer or riskier. It changes salience, abstraction, and the model’s interpretation of what counts as reusable evidence. The same memory artifact can reduce privacy leakage for one model while increasing over-application for another.

A final derivation concerns agentic proactiveness. The model must decide whether to act or remain silent. The source gives a concrete mistake-prevention example: “the user’s calendar shows a flight from JFK, New York while the user is asking the chatbot about buying a train ticket to Newark, New Jersey instead” [PAGE 12]. This is a cross-layer consistency check involving calendar, geography, and user intent. The benchmark also includes “Idle-moment silence” and “Sensitive-event silence,” where the correct action may be no message at all [PAGE 13]. The gray zone is that silence can be correct for privacy reasons but incorrect when a legitimate proactive alert is expected. Therefore, the evaluation must simultaneously measure recall for useful nudges and precision against unnecessary interruptions.

Overall, the document’s internal logic is: ground personas in real engagement, extract preferences through thresholded cross-validation, distribute the resulting user model across platforms, evaluate both use and restraint, and diagnose failures in retrieval, ranking, temporal validity, privacy, and action timing. The strongest systems solve only a little more than half of the benchmark, with “the best-performing configuration is Claude Opus 4.8 with Claude Code High, at 53.7% overall accuracy” [PAGE 14]. This indicates that the bottleneck is not merely context access but judgment over heterogeneous, temporal, and socially sensitive user evidence.

1. Signal prevalence over engagement events

Let \(E\) be the set of sampled engagement events. Define the explicit-signal probability as

\[
p_{\text{explicit}}=\frac{|E_{\text{explicit}}|}{|E|}
\]

and the implicit-signal probability as

\[
p_{\text{implicit}}=\frac{|E_{\text{implicit}}|}{|E|}.
\]

The source states: “Only about five percent of the signal is explicit; the remaining ninety-five percent is implicit” [PAGE 2]. Therefore,

\[
p_{\text{explicit}}\approx 0.05,
\qquad
p_{\text{implicit}}\approx 0.95.
\]

Both quantities are dimensionless probabilities. For the four signal types, the source also states that “nearly 63.8% of which are implicit negative” [PAGE 3], yielding

\[
p_{\text{implicit negative}}\approx 0.638.
\]

Assumptions: the sampled events are representative of the constructed benchmark population. Breakdown regime: if cohort resampling distorts the event distribution, the probabilities no longer represent the intended real-world engagement distribution.

2. Initial confidence and cross-reference evidence score

For a candidate preference \(q_i\), let \(J_i\) be the set of events supporting \(q_i\). Define the evidence weight

\[
w_j =
\begin{cases}
1, & \text{if event } j \text{ is explicit},\\
0.5, & \text{if event } j \text{ is implicit}.
\end{cases}
\]

The source states: “each explicit corroborating event contributes 1 point, while each implicit corroborating event contributes 0.5 points” [PAGE 5]. The cross-reference score is

\[
S_i=\sum_{j\in J_i} w_j \, \mathbf{1}\{j \text{ supports } q_i\}.
\]

\(S_i\) is measured in dimensionless evidence points. Let \(c_i\in[0,1]\) be the initial confidence score. The source states: “Positive claims require at least 0.75 initial confidence, while negative claims require at least 0.55” [PAGE 5]. Thus,

\[
c_i \ge c_{\min}^{+}=0.75
\quad \text{for positive claims},
\]

\[
c_i \ge c_{\min}^{-}=0.55
\quad \text{for negative claims}.
\]

For long-term preferences, the source states: “the cross-reference threshold is 20 when the evidence is explicit and 50 when the evidence is implicit. Short-term intents use a lower threshold of 3” [PAGE 5]. A formal acceptance gate is

\[
A_i =
\mathbf{1}
\left[
c_i \ge c_{\min}
\;\wedge\;
S_i \ge \theta
\right],
\]

where \(\theta\in\{20,50,3\}\) depending on preference type and evidence regime. \(A_i\) is a dimensionless binary acceptance operator. Breakdown regime: near the threshold, a small change in event classification can switch a preference from accepted to pruned. This is a singular decision boundary, not a smooth interpolation.

3. Long-context token cost and information content

The source reports that “Long-context modes read roughly 410k tokens per query” [PAGE 14] and later “roughly 416k tokens per query” [PAGE 15]. Let \(N_{\text{LC}}\) be tokens per query. Then

\[
N_{\text{LC}}\approx 4.10\times 10^5
\text{ to }
4.16\times 10^5
\quad \text{tokens/query}.
\]

If one assumes a tokenizer vocabulary size \(V\), the corresponding Shannon information upper bound is

\[
I_{\text{LC}} = N_{\text{LC}}\log_2 V
\quad \text{bits/query}.
\]

This equation requires the assumption that each token contributes at most \(\log_2 V\) bits. The source does not report \(V\), so the bit value is conditional. For compact memory modes, the source says Textual Memory and Mem0 “compress the user history to only a few thousand tokens” [PAGE 15], approximately

\[
N_{\text{compact}}\approx 3\times 10^3
\text{ to }
5\times 10^3
\quad \text{tokens/query}.
\]

For agentic modes, token usage includes multi-turn search, but the source notes that reported tokens ignore tool-call result tokens [PAGE 15]. Breakdown regime: token count is not equal to semantic information because tool outputs, redundant evidence, and retrieval artifacts may change effective information without being counted.

4. Feed-ranking objective: NDCG@5

The benchmark uses a 16-candidate pool and evaluates feed tasks with NDCG@5 [PAGE 11]. For a ranked list of five candidates, define relevance scores \(r_k\). The discounted cumulative gain is

\[
\mathrm{DCG}@5
=
\sum_{k=1}^{5}
\frac{2^{r_k}-1}{\log_2(k+1)}.
\]

Let \(\mathrm{IDCG}@5\) be the DCG of the ideal ordering. Then

\[
\mathrm{NDCG}@5
=
\frac{\mathrm{DCG}@5}{\mathrm{IDCG}@5}.
\]

\(\mathrm{NDCG}@5\) is dimensionless and lies in \([0,1]\) under standard nonnegative relevance assumptions. Breakdown regime: if \(\mathrm{IDCG}@5=0\), the metric is undefined. If multiple relevant items exist but the target is defined as a single held-out positive item, the relevance assignment must be specified. The source’s core feed-ranking task targets a held-out post that the user will positively engage with shortly after the test moment [PAGE 11].

The source reports that iterative memory editing “drops or rephrases about 14.4% of its lines at each update” [PAGE 19]. Let \(L_t\) be the set of memory lines at update \(t\), and let \(D_t\) be dropped or rephrased lines. Then

\[
\frac{|D_t|}{|L_t|}
\approx 0.144.
\]

This is a dimensionless fraction per update. The source also reports concept-level survival under different caps:

\[
M_{\text{concept}}(2048)
\approx 63.2\%,
\]

\[
M_{\text{concept}}(4096)
\approx 83.1\%,

\[
M_{\text{concept}}(8192)
\approx 90.8\%.
\]

These are dimensionless survival probabilities or empirical fractions. The source states that “semantic concept survival rises from 63.2% to 83.1% to 90.8% in average, with dip still in the middle of such memory’s self-evolution” [PAGE 19]. Define the middle-position accuracy dip as

\[
\Delta_{\text{mid}}(\text{cap})
=
A_{\text{non-middle}}(\text{cap})
-
A_{\text{middle}}(\text{cap}).
\]

The observed dips are

\[
\Delta_{\text{mid}} \approx 9\%, 7\%, 10\%
\]

for the three caps, measured in percentage points of accuracy [PAGE 19]. Breakdown regime: the dip is confounded because early evidence may have more opportunities to be reinforced by later events, as the authors explicitly acknowledge [PAGE 19].

The paper uses the phrase “over-personalization tax” conceptually [PAGE 2]. A non-toy formalization is to define it as the change in over-personalization restraint accuracy when adding memory:

\tau_{\text{model}}

A_{\text{over-personalization}}

-

\(\tau\) is measured in percentage points. For GPT-5.5:

\[

=

=
57.0\% - 69.9\%
=
-12.9
\text{ percentage points}.
\]

These values follow directly from the reported three-task restraint scores [PAGE 18]. Positive \(\tau\) means memory reduced restraint accuracy; negative \(\tau\) means memory improved restraint accuracy. Breakdown regime: the tax is task-dependent, judge-dependent, and model-dependent. It is not a universal property of memory.

7. Proactive intervention value and veto condition

The benchmark frames proactive action as an agentic decision problem: “the model sees the user’s history up to a test time, but it is not told which trigger is being tested. It must discover whether there is a legitimate reason to act” [PAGE 12]. A formal decision value for proactive message action \(a=\text{speak}\) can be written as

\[
V(\text{speak})
=
p_{\text{useful}}U_{\text{help}}
-
p_{\text{annoyance}}C_{\text{interrupt}}
-
p_{\text{privacy}}C_{\text{privacy}}
-
p_{\text{error}}C_{\text{error}}.
\]

The silence action has baseline value

\[
V(\text{silence})=0.
\]

The proactive veto rule is

\[
a^* =
\begin{cases}
\text{speak}, & V(\text{speak})>0,\\
\text{silence}, & V(\text{speak})\le 0.
\end{cases}
\]

If utilities are normalized, \(V\) is dimensionless. If costs are expressed in equivalent task-loss units, \(V\) has those units. Assumptions: probabilities are calibrated, and the user’s social context is observable enough to estimate annoyance and privacy risk. Breakdown regime: if privacy risk is hard-constrained, the rule becomes a veto rather than a utility tradeoff:

\[
p_{\text{privacy}}>0
\;\Rightarrow\;
a^*=\text{silence}
\]

for sensitive-event scenarios unless the user explicitly introduces the topic. This matches the benchmark’s “Sensitive-event restraint” and “Sensitive-event silence” tasks [PAGE 12][PAGE 13].

PersonaMem-v3 is best understood as the third stage in a lineage that moves from synthetic personalization benchmarks toward real-world-grounded omni-platform personal intelligence. The source explicitly situates the work as “the third generation of the PersonaMem series” [PAGE 26]. PersonaMem-v1 used fully synthetic users and chatbot conversations; PersonaMem-v2 expanded to synthetic users with implicit preferences and agentic memory; PersonaMem-v3 moves to “200 anonymized real-world users with 4,000,000 engagement histories” [PAGE 26]. This progression is retrotemporally important because the meaning of “preference evidence” changes across generations. In v1 and v2, preference updates were fully synthesized, so temporal validity could be controlled but lacked ecological noise. In v3, preference evolution is extracted from real-world engagement, producing “Reinforced, emerging, diminishing, bursting, and varied attention shifts from the real world” [PAGE 26].

The scientific genealogy also includes GIST-Bench, which provides the privacy-preserving engagement substrate. The source says PersonaMem-v3 builds on “Meta’s GIST-Bench, a privacy-preserving dataset derived from real-world social-media engagements” [PAGE 3]. GIST-Bench groups real users into cohorts and resamples from pooled histories to create synthetic users that preserve behavioral distributions without retaining traceable individual trajectories [PAGE 3]. This creates a genealogy of evidence: real engagement behavior is aggregated, anonymized, and then reconstructed into benchmark users. The historical lineage is therefore not merely “more data,” but a chain of transformations: raw behavior → cohort aggregation → synthetic user resampling → persona enrichment → cross-platform event generation → evaluation query.

The psychology and social-linguistics lineage is equally explicit. The source constrains persona generation with named frameworks, including Big Five traits, LIWC anchors, appraisal theory, construction grammar, Bakhtin’s speech-genre theory, Goffman’s presentation of self, Bell’s audience design, Maslow’s hierarchy, self-determination theory, uses and gratifications, social identity theory, parasocial relationship theory, compensatory internet use, health belief model, and life-event stress and coping theories [PAGE 6][PAGE 7]. These frameworks are not decorative. They define what must be generated, what evidence is sufficient, and what constitutes risky inference. For example, hidden personas include “Compensatory need,” “Covert concern,” “Medical-aesthetic concern,” and “Sensitive life event,” each with theoretical anchors and evidence standards [PAGE 7]. The retro-causal effect is that the benchmark’s future evaluation tasks depend on historical theory choices: if a framework requires active management rather than casual curiosity, then only engagements showing management can support that claim.

A major multi-week trap in this lineage is the confusion between short-term intent and enduring preference. The source says PersonaMem-v3 separates enduring preferences from short-term intents, noting that interests tied to a trip, event, purchase, or medical consultation may expire once the situation ends [PAGE 5]. A model trained or prompted to retrieve all historically supported facts will therefore fail when a preference has expired. The benchmark explicitly tests “Tracking preference changes,” asking whether the response follows the user’s current stance instead of relying on an older but tempting preference signal [PAGE 11]. The multi-week trap is that older evidence may be denser, more explicit, or more topically coherent than current evidence, making it artificially salient.

A second multi-week trap is memory staleness. The source reports that Mem0 with RAG is weakest on tracking preference changes, scoring 56.9% with a 51.4% outdated-stance rate, “showing that a topically relevant retrieved fact can remain too sticky after expiry” [PAGE 18]. This is a historical lineage trap: retrieval systems optimized for semantic similarity may retrieve the most related fact, not the currently valid fact. The retro-causal implication is that a memory architecture designed for relevance can become obsolete when temporal validity is the bottleneck.

A third trap is over-personalization caused by memory abstraction. The source observes that GPT-5.5 treats textual memory as “a clean user profile” whose contents become salient and safe-looking evidence to reuse, while Gemini-3.5-Flash may treat compressed memory as background constraint rather than active personalization signal [PAGE 18]. This is a multi-week trap because memory modules are often introduced to improve efficiency, but they can change the model’s attention policy. The lineage therefore runs from raw logs to compressed profiles, but compression can create new failure modes: loss of exact wording, loss of negative evidence, loss of privacy constraints, or increased reuse of stale facts.

A fourth trap is the synthetic-default trap. The authors note that some secondary attributes, such as names or broad education background, may be under-specified by raw data, and an LLM may repeatedly fill gaps with common defaults [PAGE 24]. To mitigate this, PersonaMem-v3 adds reproducible high-level anchors derived from the user identifier [PAGE 25]. Historically, this means the benchmark’s diversity is not purely emergent from engagement; it is partly engineered through generation controls. The multi-week trap is that models may learn benchmark-specific demographic or stylistic priors instead of genuine user understanding.

The final lineage is evaluation history. PersonaMem-v3 cites long-term memory benchmarks such as LongMemEval and LoCoMo, memory-agent benchmarks such as MemoryAgentBench and EvoArena, production memory systems such as Mem0 and MemOS, self-evolving memory work such as Memory-R1, MemAgent, ReasoningBank, Evo-Memory, and EvoMemBench [PAGE 26][PAGE 27]. It also cites recommendation reranking work such as zero-shot LLM rankers, LLM4Rerank, RecRanker, OneRec, OpenOneRec, OneReason, AgenticRec, and MARS [PAGE 27]. PersonaMem-v3’s retro-causal position is that these lines individually measure memory, ranking, or proactivity, but personal intelligence requires their joint evaluation. The benchmark therefore reorganizes historical capabilities into a single temporally grounded environment where memory, recommendation, privacy, social context, and agentic action interact.

<RECURSIVE_THEORY_OF_MIND>
Recursive theory of mind in PersonaMem-v3 refers to the requirement that an agent model not only infer user preferences, but also model the user’s current mental state, the social audience, the likely reaction to personalization, and the temporal validity of the inferred state. The benchmark’s tasks force at least three levels of recursive inference.

Level 1: What does the user seem to want now?  
The model must infer current intent from cross-platform evidence. This includes explicit requests, implicit engagement, skips, repeats, calendar events, and geographic context. The universal rubric asks whether the output “uses the user’s relevant preferences when personalization would help” [PAGE 10]. This is not merely recall; it is contextual relevance.

Level 2: What does the user want me to reveal or withhold?  
The model must infer privacy boundaries and social appropriateness. The rubric includes hard checks such as “Protects private context” and “Avoids creepy framing” [PAGE 10]. The over-personalization tasks include “Sensitive-event restraint,” where the system must “avoid mentioning the sensitive event, the planted evidence row, or related private context” [PAGE 12]. This level requires the model to represent what the user would consider intrusive if surfaced.

Level 3: What will the user think if I act now?  
For proactive tasks, the model must predict whether an intervention will be welcome. The source says proactive personalization requires “knowing when to step in and when to hold back” [PAGE 3]. The agent must decide whether to send a close-friend reminder, surface a trend, warn about a travel mistake, or stay silent [PAGE 13].

Crisis habit regression is a key failure and safety regime. A user navigating a sensitive life event may temporarily rely on familiar habits, avoid new recommendations, or become more private. The benchmark includes sensitive life events such as breakup, surgery, family conflict, job loss, bereavement, illness, abuse recovery, and financial crisis [PAGE 7]. These scenarios create a recursive trap: the model may know a sensitive event from backend evidence, but if it mentions the event, it violates privacy; if it ignores all preferences, it may become unhelpfully generic. The correct behavior is often to use non-sensitive context or remain silent.

The counter-trap is the model’s temptation to over-personalize by making the latent inference explicit. The benchmark lists “Avoids creepy framing” as a hard check, including direct phrasing such as “I know you like X” [PAGE 10]. This is a theory-of-mind trap because the model may have correctly inferred the hidden motivation but incorrectly believe that revealing the inference demonstrates helpfulness. In reality, revealing the inference can make the user feel exposed. The hidden-persona task checks whether the response serves the user’s deeper motivation “without naming the hidden persona or exposing private context” [PAGE 10].

The clock is the temporal validity layer. PersonaMem-v3 treats preferences as time-indexed, not static. The benchmark tracks reinforced, emerging, diminishing, and bursty trajectories [PAGE 17]. It also tests @AI directive persistence after “24 hours, 72 hours, and 7 days” [PAGE 11]. A recursive agent must therefore represent not only the preference but its expiration condition. A formal temporal validity indicator can be written as

\[
I_{\text{valid}}(t; t_0, \tau)
=
\mathbf{1}\{t-t_0 \le \tau\},
\]

where \(t_0\) is the time the short-term intent became active and \(\tau\) is its expected lifetime. The source gives a lower evidence threshold for short-term intents because they have less time to accumulate evidence [PAGE 5]. The clock trap occurs when the model treats a short-term intent as enduring because it is recent, or treats an enduring preference as expired because it is old.

A crisis-habit regression model can be expressed as a shift in the user’s latent state:

\[
z_t = f(z_{t-1}, e_t, c_t),
\]

where \(z_t\) is the current user state, \(e_t\) is new evidence, and \(c_t\) is contextual pressure such as a sensitive life event. Under crisis pressure, the model should increase uncertainty and decrease proactive personalization. A counter-trap policy is

\[
\pi(a \mid z_t)
=
\arg\max_a
\left[
\mathbb{E}[U(a)\mid z_t]
-
\lambda_{\text{privacy}}R_{\text{privacy}}(a)
\right],
\]

where \(R_{\text{privacy}}\) is privacy risk and \(\lambda_{\text{privacy}}\) is a penalty weight. In sensitive-event tasks, the privacy constraint becomes hard: if the action would reveal sensitive context, the action is vetoed unless the user explicitly introduces the topic.

The recursive clock also applies to memory. The source shows that larger memory caps preserve more concepts but do not eliminate the middle dip: “the middle dip remains 9%, 7%, and 10% in accuracy, respectively” [PAGE 19]. This means that even when a memory system knows the user’s history, it may fail to apply the correct temporal slice. The model must not only remember the fact but also remember when the fact was valid, when it was contradicted, and whether later evidence overrides it.

The most delicate recursive scenario is proactive silence. The benchmark includes “Idle-moment silence,” where “The user has recent history, but there is no clear reason to interrupt them” [PAGE 13]. Here, the correct theory-of-mind inference is that the absence of a trigger is itself evidence. A model that treats any recent personal evidence as a reason to speak will fail. Conversely, in “Close-friend DM update,” the model must recognize a meaningful delay and surface the update without exposing private message content [PAGE 13]. The recursive structure is therefore not merely “infer user preference,” but “infer whether the inferred preference or event justifies an action at this moment.”
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
Cross-layer veto adjudication in PersonaMem-v3 concerns whether a proposed personalized output or agentic action should be blocked by constraints from non-textual or quasi-physical layers. The benchmark is primarily digital, but it includes geography, calendar, social context, privacy boundaries, and interruption cost. There is no sports-event physical layer, no biomechanical performance layer, and no weather layer in the released corpus. Therefore, the adjudication must distinguish between vetoes that are present in the benchmark and vetoes that are absent or undefined.

1. Digital-evidence layer

The base layer consists of time-masked backend databases for Instagram, Facebook, Threads, Chatbot, AI Studio, and Calendar [PAGE 9]. For each test query, “the harness cuts the backend at the query’s test time. The system can only access events before that timestamp” [PAGE 9]. A digital veto occurs when the evidence required for a claim is absent after time masking. Formally, let \(H_{<t}\) be the history before test time \(t\). If a claim requires evidence \(e\) such that \(e \notin H_{<t}\), then the claim is unverifiable. This is not a physical veto but an epistemic veto.

2. Geographic and calendar layer

The benchmark includes geographic context and calendar events. The source states that “each user engagement has a geo-location, such as home or travel destinations, and each user has a calendar stream with add, update, and remove events” [PAGE 8]. A concrete cross-layer check is the mistake-prevention example: “the user’s calendar shows a flight from JFK, New York while the user is asking the chatbot about buying a train ticket to Newark, New Jersey instead” [PAGE 12]. This creates a physical-travel veto condition. Let \(C_t\) be the set of calendar locations at time \(t\), and let \(L_t\) be the current inferred location. If a proposed action \(a\) assumes a location inconsistent with \(C_t\) or \(L_t\), the action should be vetoed or corrected. A formal indicator is

\[
V_{\text{geo}}(a)
=
\mathbf{1}
\left[
\text{location}(a)
\notin
\{L_t\}\cup C_t
\right].
\]

If \(V_{\text{geo}}(a)=1\), the action should be blocked unless there is explicit evidence that the location assumption is intentional. The Newark/JFK example is a geo-temporal consistency veto: the user’s calendar suggests air travel from New York, while the chatbot query suggests a train purchase that may be inconsistent with that plan. The correct proactive behavior may be to warn, ask for clarification, or remain silent if the evidence is insufficient.

3. Biomechanical or human interruption layer

The benchmark does not provide biomechanical telemetry, but it does provide a human-interruption layer through mixed-initiative interaction theory. The over-personalization tasks cite “Mixed-Initiative interaction (Horvitz, 1999); notification interruption science” [PAGE 12]. This allows a biomechanical or cognitive-load veto to be formalized as an interruption-cost constraint. Let \(B(a)\) be the expected benefit of proactive action \(a\), \(C_{\text{int}}(a)\) the interruption cost, and \(C_{\text{priv}}(a)\) the privacy cost. A veto rule is

\[
V_{\text{human}}(a)
=
\mathbf{1}
\left[
B(a)
-
C_{\text{int}}(a)
-
C_{\text{priv}}(a)
\le 0
\right].
\]

If \(V_{\text{human}}(a)=1\), the system should remain silent. The benchmark’s “Idle-moment silence” task is a direct test: the user has recent history, but there is no clear reason to interrupt [PAGE 13]. The model must not invent a reason to message the user. This is a human-factor veto even though no explicit biomechanical measurement is provided.

4. Weather layer

The corpus does not contain weather variables. There are no weather fields in the platform databases, no meteorological annotations, and no weather-dependent tasks. Therefore, within the source benchmark, the weather veto operator is undefined or identically inactive. Formally, let \(W\) be the set of weather states. Since \(W=\varnothing\) in the benchmark,

\[
V_{\text{weather}}(a)=0
\]

for all benchmark actions, or more precisely, the veto cannot be evaluated because the required variable is absent. If an external weather layer were added, a weather veto would apply only to actions whose feasibility depends on weather, such as travel or outdoor-event recommendations. 5. Privacy hard veto

The strongest veto in PersonaMem-v3 is privacy. The universal rubric treats “Protects private context” as a hard check: “Does the output avoid revealing sensitive or privacy-flagged information unless clearly needed?” [PAGE 10]. The over-personalization task “Sensitive-event restraint” requires the system to avoid mentioning sensitive evidence [PAGE 12]. This can be written as a hard constraint:

\[
V_{\text{privacy}}(a)
=
\mathbf{1}
\left[
a \text{ reveals sensitive context}
\right].
\]

If \(V_{\text{privacy}}(a)=1\), the action is invalid regardless of personalization benefit, unless the user has explicitly introduced the sensitive context. This is a strict veto because privacy violation is not merely a utility penalty; it is a failure category.

6. Final adjudication order

The benchmark’s implicit veto hierarchy is:

\[
V_{\text{total}}(a)
=
\max
\left(
V_{\text{privacy}}(a),
V_{\text{geo}}(a),
V_{\text{human}}(a),
V_{\text{weather}}(a)
\right).
\]

If \(V_{\text{total}}(a)=1\), the action should be blocked, suppressed, or revised. In the released corpus, \(V_{\text{weather}}(a)=0\) or undefined, while \(V_{\text{privacy}}\) and \(V_{\text{geo}}\) are active, and \(V_{\text{human}}\) is indirectly active through interruption and restraint tasks. Therefore, the physical/biomechanical/weather veto proof is partial: geo-temporal and human-interruption vetoes are evaluable, weather veto is not present, and biomechanical measurement is replaced by cognitive-interruption and social-appropriateness constraints.

<RLVR_COUNTERFACTUAL_VETOES>
Reinforcement Learning with Verifiable Rewards, or RLVR-style counterfactual vetoes, can be derived from PersonaMem-v3 because the benchmark contains explicit hard checks, task-specific metrics, and ground-truth preference evidence. A verifier can assign reward \(R=1\) only if the output satisfies the task objective and all applicable hard constraints. A veto occurs when a counterfactual behavior would pass a naive objective but fail a hard constraint.

General verifiable reward:

\[
R(y,q)
=
\mathbf{1}
\left[
\text{task metric}(y,q) \ge \tau_{\text{task}}
\right]
\cdot
\prod_{h\in H}
\mathbf{1}
\left[
\text{hard check}_h(y,q)=1
\right].
\]

Here \(y\) is the model output, \(q\) is the query, \(H\) is the set of applicable hard checks, and \(\tau_{\text{task}}\) is the task-specific threshold. The hard checks include “Avoids disliked topics,” “Protects private context,” “Avoids outdated memory,” and “Avoids creepy framing” [PAGE 10].

Veto Scenario 1: Stale-preference counterfactual veto

Counterfactual behavior: The agent retrieves a historically supported preference that has expired or been contradicted and uses it as the current stance.

Verification condition: The task is “Tracking preference changes,” where the benchmark asks whether the response follows the user’s current stance instead of relying on an older but tempting preference signal [PAGE 11]. If the output uses an outdated preference, the hard check “Avoids outdated memory” fails [PAGE 10].

Formal veto:

\[
V_{\text{stale}}
=
\mathbf{1}
\left[
\text{output relies on } q_i
\text{ such that }
I_{\text{valid}}(t;t_i,\tau_i)=0
\right].
\]

If \(V_{\text{stale}}=1\), reward is zero.

Empirical prediction: Retrieval-based vector memory should be more vulnerable than compact textual memory because retrieved facts can remain topically relevant after expiry. The source reports Mem0 with RAG scoring 56.9% with a 51.4% outdated-stance rate on tracking preference changes, while GPT-5.5 Textual Memory scores 79.9% with a 25.7% outdated rate [PAGE 18]. Agentic search also does not solve temporal validity by itself: Codex with GPT-5.5, Claude Opus-4.8, and Sonnet-4.6 score 66.0%, 65.7%, and 64.6%, with 37–40% outdated-stance rates [PAGE 18].

Predicted verifier behavior: A reward model should penalize any answer that mentions an expired short-term intent as if active. For example, if the user previously showed a short-term cruise-planning intent but the task occurs after expiry, the verifier should reject cruise-related personalization. The source notes failures often center on expired preferences such as “car shipping, Spanish practice, cruise planning, or resin art” [PAGE 18].

Veto Scenario 2: Sensitive-event privacy counterfactual veto

Counterfactual behavior: The agent detects a sensitive life event from backend evidence and mentions it, even though the user has not explicitly raised it in the current context.

Verification condition: The task is “Sensitive-event restraint” or “Sensitive-event silence.” The system must avoid mentioning the sensitive event, the planted evidence row, or related private context [PAGE 12][PAGE 13]. The hard check is “Protects private context” [PAGE 10].

Formal veto:

\[
V_{\text{sensitive}}
=
\mathbf{1}
\left[
\text{output reveals sensitive event } s
\text{ without explicit user initiation}
\right].
\]

If \(V_{\text{sensitive}}=1\), reward is zero regardless of helpfulness.

Empirical prediction: Long-context models with raw sensitive events should leak more than compressed textual-memory models if the compression reduces raw salience. The source reports that Gemini-3.5-Flash Long Context scores 38.0% on sensitive-event restraint, with privacy-leak violations in 36.6% of rows, while Gemini-3.5-Flash Textual Memory rises to 63.3% and reduces privacy-leak violations to 6.5% [PAGE 18]. However, the effect is model-dependent: GPT-5.5 scores 64.2% on sensitive-event restraint under long context and remains roughly similar at 63.1% with memory [PAGE 18].

Further predictions from ablations: Adding raw sensitive posts alongside memory should reduce restraint more than adding ordinary posts. The source states: “Adding 40 sensitive posts reduces three-task restraint by 2.5 points for GPT-5.5 and 5.5 points for Gemini-3.5-Flash, while adding ordinary posts changes the score by less than one point” [PAGE 19]. Adding frequency counts should not fix the problem, because the count ablation changes the score by less than one point [PAGE 19]. Therefore, an RLVR verifier should veto outputs that mention sensitive evidence even when the model can correctly count or summarize it.

Veto Scenario 3: Proactive timing counterfactual veto

Counterfactual behavior: The agent sends a proactive message when the correct action is silence, or fails to send a message when a grounded proactive alert is required.

Verification condition: Proactive tasks require the agent to decide whether to act or stay silent [PAGE 12]. The benchmark includes “Close-friend DM update,” “Friend-post update,” “Trending-topic surfacing,” “Mistake-prevention alert,” “Idle-moment silence,” and “Sensitive-event silence” [PAGE 13]. A correct proactive action must be grounded in concrete evidence and socially appropriate.

Formal veto for false proactive action:

\[
V_{\text{false proactive}}
=
\mathbf{1}
\left[
a=\text{speak}
\;\wedge\;
B(a)\le 0
\right].
\]

Formal veto for missed proactive action:

\[
V_{\text{missed proactive}}
=
\mathbf{1}
\left[
a=\text{silence}
\;\wedge\;
B(a)>0
\;\wedge\;
V_{\text{privacy}}(a)=0
\right].
\]

Empirical prediction: Models are generally better at restraint than at initiating the correct proactive action. The source says Gemini and Claude models do better on idle-moment silence, while mistake-prevention alerts remain only 8–13% accurate [PAGE 17]. Claude Code often chooses silence when the benchmark expects a grounded proactive message, especially for close-friend updates, trend surfacing, and mistake-prevention alerts [PAGE 22]. Codex under-activation is not the main issue; its failures are dominated by missed evidence or wrong prioritization, followed by proactive timing mistakes [PAGE 22].

Predicted verifier behavior: For idle-moment scenarios, the verifier should reward silence and penalize any invented reason to message the user. For mistake-prevention scenarios, the verifier should reward a warning only if the cross-platform evidence is concrete. The JFK/Newark example is verifiable: if calendar shows a flight from JFK and the user asks about a train to Newark, a warning or clarification may be valid; if no such conflict exists, a warning is a false positive [PAGE 12]. For close-friend DM updates, the verifier should reward surfacing the missed update only if the friend relationship and delay satisfy the trigger, while avoiding exposure of private DM content [PAGE 13].

These three RLVR counterfactual vetoes are verifiable because each maps to an explicit benchmark task and measurable failure mode: stale preference use is measured by outdated-stance rates [PAGE 18], sensitive-event leakage is measured by privacy-leak violations and restraint accuracy [PAGE 18], and proactive timing is measured by proactive task accuracy, idle silence, and mistake-prevention accuracy [PAGE 17][PAGE 22].
