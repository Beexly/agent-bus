Let the detection confidence be a probability-like score p ∈ [0,1]. The paper defines a high-score regime and a low-score regime: detections above 0.6 are high score, detections between 0.6 and 0.1 are low score, and detections below 0.1 are filtered [PAGE 5]. These are dimensionless probability scores, not physical SI units.

The appearance cost is given verbatim as:

\[
\mathrm{Cost}_A = 1 - \text{Cosine Similarity} = 1 - \frac{a \cdot b}{\|a\|\|b\|}
\tag{1}
\]

with citation [PAGE 3]. Here \(a\) and \(b\) are feature vectors, typically ReID embeddings. The cost is dimensionless. If features are nonzero, cosine similarity lies in \([-1,1]\), so \(\mathrm{Cost}_A \in [0,2]\). Assumption: \(a \neq 0\) and \(b \neq 0\). Singularity/breakdown: if either vector has zero norm, the cosine similarity is undefined; implementations must treat zero-norm embeddings as missing or invalid. In sports tracking, severe occlusion can produce degenerate crops, so zero-norm or near-zero-norm features are a realistic failure mode.

The expansion equations are:

\[
h^\star = (2E + 1)h
\tag{2a}
\]

\[
w^\star = (2E + 1)w
\tag{2b}
\]

with citation [PAGE 4]. If \(h\) and \(w\) are measured in pixels, then \(h^\star\) and \(w^\star\) are also in pixels. \(E\) is a dimensionless expansion scale. The expanded coordinates are derived from original top-left \((t,l)\) and bottom-right \((b,r)\) as:

\[
(t - h^\star/2,\; l - w^\star/2)
\]

and

\[
(b + h^\star/2,\; r + w^\star/2)
\]

with citation [PAGE 4]. Under the printed equations, the expanded height is:

\[
H_{\text{exp}} = (b + h^\star/2) - (t - h^\star/2) = h + h^\star = (2E + 2)h
\]

and similarly:

\[
W_{\text{exp}} = w + w^\star = (2E + 2)w
\]

Thus \(E = 0\) produces \(H_{\text{exp}} = 2h\) and \(W_{\text{exp}} = 2w\), not the original box. This is a literal consequence of the source equations. Breakdown regime: if \(E < -0.5\), then \(h^\star\) and \(w^\star\) become negative, which is geometrically invalid for expansion. If \(E\) is very large, expanded boxes may exceed image boundaries, causing clipping, overlap saturation, and ambiguous matching. The paper’s chosen high-score initialization is \(E_{\text{initial}} = 0.7\) with step size \(\lambda = 0.1\) [PAGE 5]. For low-score detections, \(E = 0.7\); for unmatched detections, \(E = 0.5\) [PAGE 6].

Let \(B_i\) be the expanded tracklet box and \(D_j\) the expanded detection box. A formal ExpansionIoU operator can be written as:

\[
\mathrm{EIoU}_{ij} = \frac{\operatorname{area}(B_i \cap D_j)}{\operatorname{area}(B_i \cup D_j)}
\tag{3}
\]

This is dimensionless and, for positive-area boxes, lies in \([0,1]\). The source says the expanded box is used for IoU calculation between tracklets and detections [PAGE 4]. If a cost is required, a standard monotone conversion is:

\[
C_{\mathrm{EIoU}} = 1 - \mathrm{EIoU}
\tag{4}
\]

This cost is also dimensionless. Assumption: both boxes have positive area. Breakdown: if \(\operatorname{area}(B_i \cup D_j) = 0\), EIoU is undefined. In practice, zero-area detections or collapsed boxes must be filtered.

The paper rejects a simple weighted appearance-IoU cost of the form:

\[
C = \lambda C_A + (1-\lambda) C_{\mathrm{IoU}}
\tag{5}
\]

where \(\lambda \in [0,1]\) and both costs are dimensionless [PAGE 4]. Instead, it uses thresholded appearance adjustment:

\[
\widehat{C}_A =
\begin{cases}
1, & \text{if } C_A > \tau_A \text{ or } C_{\mathrm{EIoU}} > \tau_{\mathrm{EIoU}} \\
0.5 C_A, & \text{otherwise}
\end{cases}
\tag{6}
\]

with \(\tau_A = 0.25\) and \(\tau_{\mathrm{EIoU}} = 0.5\) [PAGE 4-5]. The first-stage cost is:

\[
C_{\text{stage1}} = \min(\widehat{C}_A, C_{\mathrm{EIoU}})
\tag{7}
\]

and the second-stage low-score cost is:

\[
C_{\text{stage2}} = C_{\mathrm{EIoU}}
\tag{8}
\]

with citation [PAGE 4]. The minimum operator is dimensionless and assumes the matching solver can compare costs on a common scale. Breakdown: if \(\widehat{C}_A = 1\) and \(C_{\mathrm{EIoU}}\) is also near 1, the pair is effectively non-matchable. If \(C_{\mathrm{EIoU}}\) is below 1 even when appearance fails the threshold, the minimum operator may still permit an association based only on expanded geometry, unless an external hard gate is applied. This is a crucial implementation-dependent singularity.

The iterative scale-up equation is:

\[
E_t = E_{\text{initial}} + \lambda t
\tag{9}
\]

with citation [PAGE 4]. Here \(E_t\) is dimensionless, \(t\) is an integer iteration count, and \(\lambda\) is a dimensionless step size. The source uses \(E_{\text{initial}} = 0.7\), \(\lambda = 0.1\) [PAGE 5], and a small complete iteration count of 2 [PAGE 6]. If \(t\) starts at 0, the nominal high-score sequence is approximately \(E_0 = 0.7\), \(E_1 = 0.8\), and possibly \(E_2 = 0.9\) depending on implementation of the stopping condition. Breakdown: if \(t\) grows without bound, \(E_t\) grows without bound, expanded boxes saturate the image, and EIoU becomes non-discriminative. The paper prevents this by stopping the iterative high-score association and moving to low-score association [PAGE 4-5].

The assignment step is formalizable as:

\[
\pi^\star = \arg\min_{\pi} \sum_i C_{i,\pi(i)}
\tag{10}
\]

where \(C\) is the stage cost matrix and \(\pi\) is a one-to-one matching with allowed unmatched entries. The paper says the Hungarian algorithm is used to obtain the best matching [PAGE 3]. The cost is dimensionless. Breakdown: if all feasible edges are invalid or if missing edges are represented by infinities, the solver must return no match; if missing edges are replaced by large finite values, the tracker may still force spurious matches.

The evaluation metric HOTA is a dimensionless higher-order tracking metric. The paper contrasts it with MOTA: “MOTA mainly focuses on the detection performance instead of association accuracy” [PAGE 6]. The SoccerNet table reports HOTA = 85.443, AssA = 73.567, DetA = 99.236 [PAGE 7]. Numerically, these values satisfy:

\[
\mathrm{HOTA} \approx \sqrt{\mathrm{DetA} \cdot \mathrm{AssA}}
\tag{11}
\]

when metrics are expressed on the same normalized scale. In percentage form, \(\sqrt{99.236 \times 73.567} \approx 85.44\). This identity is not a physical law but a metric consistency check. Breakdown: if DetA = 0 or AssA = 0, HOTA collapses to zero. Thus high HOTA requires both detection quality and association quality; it cannot be repaired by association alone if detections are missing.

The runtime constraint is reported as “The current Deep-EIoU pipeline achieves around 14.6 FPS on a single Nvidia RTX 4080 GPU” [PAGE 7]. FPS has units of frames per second. This is not a tracking accuracy metric but an online feasibility constraint. Breakdown: if input resolution increases, ReID crops increase, or detector latency rises, FPS may fall below operational requirements even if HOTA remains high.

This historical diagnosis explains why sports tracking becomes a boundary case. Sports motion is not merely noisy; it is often discontinuous, tactical, and visually ambiguous.

The first genealogical branch is ByteTrack-style confidence-aware matching. The source says, “Following ByteTrack, we give the high confidence score detections higher weighting during the matching process” [PAGE 4]. This inherits the insight that low-score detections should not be allowed to corrupt high-confidence identity continuity. The second branch is BoT-SORT-style appearance filtering. The source says, “we adopt strategy similar to that of BoT-SORT for appearance-based association” and describes filtering impossible associations with thresholds [PAGE 4]. The third branch is location-only association, including IoU, GIoU, DIoU, and BIoU. The paper cites prior work using expanded bounding boxes and says, “Different from the previous work, we found out that expanding the bounding box even more during association can lead to a significantly better performance in athlete tracking” [PAGE 3-4]. This places Deep-EIoU in a lineage of geometric search-space expansion, but pushes expansion further for sports.

A multi-week trap emerges from copying pedestrian-tracking intuition. Pedestrian trackers often assume moderate motion, limited occlusion, and distinguishable appearance. Sports violates those assumptions. The source lists sports difficulties: “targets’ fast and irregular motions, similar appearance among players in the same team, and more severe occlusion problem” [PAGE 3]. A practitioner who tunes only for pedestrian MOT may choose too small an expansion scale or too short a memory buffer. The paper explicitly increases the buffer to 60 frames for sports because of stronger occlusion [PAGE 6]. Another trap is over-reliance on appearance. ReID is helpful, and the ablation says appearance improves HOTA [PAGE 6], but same-team jerseys can collapse embedding separability. The paper acknowledges “similar appearance between players in the same team due to the same color jersey” [PAGE 2]. A multi-week project that assumes ReID alone will solve sports tracking will likely fail during cluster scrums, pileups, or goal-mouth congestion.

A second historical trap is metric inversion. MOTA can reward detection and punish identity errors heavily, while HOTA balances detection and association. The source says MOTA “mainly focuses on the detection performance instead of association accuracy” [PAGE 6]. A team optimizing only MOTA may improve detector recall but not identity persistence. Deep-EIoU’s reported gains in HOTA, IDF1, and AssA on SportsMOT [PAGE 7] are more relevant to association quality than MOTA alone. A third trap is benchmark leakage through oracle detections. SoccerNet-Tracking uses oracle detections for fair tracker comparison [PAGE 5]. If a team treats the 85.4 HOTA result [PAGE 1] as an end-to-end system score without noting the oracle condition, it will overestimate field performance. The retro-causal lesson is that Deep-EIoU must be read as a conditional operator: strong association under supplied detections, with detector dependence made explicit.

The final genealogical point is that EIoU is described as plug-and-play for Kalman-based trackers. The source reports that replacing IoU with EIoU improves ByteTrack and BoT-SORT in HOTA, AssA, and DetA [PAGE 7]. This means the lineage is not a replacement of all prior machinery but a retrofit: expanded geometry can be inserted into older filters. The multi-week trap is to assume the retrofit preserves the original filter’s probabilistic assumptions. If a Kalman filter predicts a location but the expanded box dominates association, the filter may become a weak prior rather than a true motion model. The paper’s own full method avoids the Kalman filter, but the ablation shows the operator’s portability [PAGE 7].

<RECURSIVE_THEORY_OF_MIND>
The tracker’s recursive problem is to infer which detection belongs to which track while the observed motion violates smooth priors. The designer’s model of the athlete is not a physical simulator but an association policy. The policy must decide when to trust appearance, when to trust expanded geometry, and when to wait. The source’s first stage uses both appearance and ExpansionIoU for high-score detections, while the second stage uses only ExpansionIoU for low-score detections [PAGE 4]. This reflects a belief hierarchy: high-confidence detections are more reliable, so they can support appearance-based reasoning; low-confidence detections are more uncertain, so geometry dominates.

Crisis habit regression occurs when the tracker falls back to familiar pedestrian habits. One habit is to trust small IoU overlap. In sports, small or zero adjacent-frame IoU can be normal because players move quickly. The paper says traditional IoU “often lacks the flexibility to account for object’s large movement, when tracklet and detection bounding boxes share small or no IoU between adjacent frames” [PAGE 4]. The counter-trap is iterative scale-up. Instead of selecting one expansion scale, the tracker begins with a smaller expansion and increases it gradually. The source says the method can “first perform association to those trajectory and detection pairs with higher ExpansionIoU, and gradually search for those pairs with lower overlapping area” [PAGE 4-5]. This is a recursive search policy: first accept easy geometric matches, then expand to harder ones.

A second recursive trap is appearance overconfidence. In same-team scenes, appearance may be weak. If the tracker assumes that cosine similarity below threshold is impossible, it may fail during occlusion. The adjusted appearance cost in equation (6) reduces the appearance cost by half when both appearance and EIoU pass thresholds, but it does not necessarily eliminate geometric association. This creates a recursive ambiguity: the tracker must model the detector’s belief about appearance without allowing appearance to dominate when the detector is uncertain. The paper’s confidence-aware design helps because high-score detections are more likely to have reliable appearance features [PAGE 4]. However, if a player is occluded, the detector may assign low confidence, and the tracker must lean more heavily on geometry.

The clock is explicit. The method is online and cannot use future frames. The paper says the tracking-by-detection paradigm “enables online tracking without using future information” [PAGE 3]. The temporal clock is governed by frame rate, detector latency, ReID latency, and the lost-track buffer. The buffer is 60 frames [PAGE 6]. If occlusion lasts beyond that horizon, the track is removed. Linear interpolation is used after tracking, but it cannot recover identities that were discarded. The runtime clock is also relevant: the pipeline runs at around 14.6 FPS on an RTX 4080 [PAGE 7]. If the clock slows, the system may miss frames or drop detections, increasing association errors.

A counter-trap policy should therefore model three clocks: the motion clock, the evidence clock, and the memory clock. The motion clock asks whether the expanded box covers plausible displacement. The evidence clock asks whether appearance and detection confidence are strong enough to override geometric ambiguity. The memory clock asks whether the track has survived long enough to bridge occlusion. If the memory clock expires before the motion clock reacquires the player, identity loss occurs. The source’s 60-frame buffer is a direct response to this recursive timing problem [PAGE 6]. A deeper counter-trap is to make the expansion scale adaptive to detector confidence and occlusion duration, although the published method uses a fixed iterative schedule rather than a learned adaptive policy. The recursive theory of mind is thus: the tracker must anticipate that its own expansion will create ambiguity, and it must rely on appearance, confidence, and memory to prevent over-expansion from causing identity collapse.

<CROSS_LAYER_VETO_ADJUDICATION>
A physical veto should reject associations that are implausible under court geometry, athlete kinematics, or image formation. The paper does not provide a full physical simulator, but its equations and thresholds allow a formal veto layer. First, define image-space displacement between consecutive track positions:

\[
\Delta p_t = p_{t+1} - p_t
\]

where \(p_t\) is a pixel coordinate. If a homography or court calibration is available, convert to metric displacement:

\[
\Delta x_t = H \Delta p_t
\]

with \(\Delta x_t\) in meters and \(\Delta t\) in seconds. Then velocity is:

\[
v_t = \frac{\|\Delta x_t\|}{\Delta t}
\]

with units meters per second. Without calibration, the veto can only use pixel displacement per frame, which is less physically interpretable. A hard physical veto can be written as:

\[
v_t > v_{\max} \Rightarrow \text{reject association}
\]

where \(v_{\max}\) must be sport-specific and calibrated. For basketball, football, or volleyball, sprint speeds differ, and abrupt direction changes are possible. Therefore \(v_{\max}\) should include a safety margin. If the association requires a displacement beyond plausible human motion, the match should be rejected even if expanded IoU is high.

The second veto is geometric saturation. With the printed expansion formula, large \(E\) can make boxes cover much of the image. If multiple expanded track boxes and expanded detection boxes overlap broadly, EIoU loses discriminative power. A formal ambiguity condition is:

\[
\left| \{j : \mathrm{EIoU}_{ij} > \eta\} \right| > 1
\]

for many detections \(j\), where \(\eta\) is a high-overlap threshold. This condition says the association is ambiguous. If the Hungarian solver must choose among several nearly identical costs, the veto should defer to appearance, detector confidence, or temporal continuity. The source acknowledges that expanding the search space helps recover large movement [PAGE 4], but it does not eliminate ambiguity. The veto therefore requires a maximum expansion regime. Since the high-score iteration uses \(E_{\text{initial}} = 0.7\) and step size 0.1 [PAGE 5], an implementation should cap \(E_t\) before geometric saturation. If no cap exists, the breakdown regime is false merging of nearby players.

The third veto is appearance collapse. Same-team jerseys can make cosine similarity high for wrong identities. The source warns that appearance can be unreliable under “occlusions, similar appearance among tracked objects, appearance variation caused by the object’s rotation, or the lighting condition” [PAGE 3]. A veto can be expressed as:

\[
C_A < \tau_A \quad \text{but} \quad \text{feature entropy is high}
\]

or, more operationally, if multiple candidate detections have appearance costs within a narrow band, appearance should not be decisive. The paper’s threshold \(\tau_A = 0.25\) [PAGE 5] defines a cost gate, but a narrow margin among top candidates is a stronger warning. If the best and second-best appearance costs differ by less than a calibrated margin \(\epsilon_A\), the appearance veto should trigger and the tracker should rely more on geometry or defer assignment.

The fourth veto is occlusion duration versus memory buffer. The source uses a 60-frame buffer for lost tracks [PAGE 6]. If occlusion duration \(T_{\text{occ}}\) exceeds 60 frames, the track should be allowed to expire unless additional evidence exists. A formal condition is:

\[
T_{\text{occ}} > T_{\text{buffer}} = 60 \text{ frames}
\]

Then identity continuity is weak, and re-identification should be treated as a new hypothesis rather than a confident continuation. Linear interpolation cannot fix this because it operates after tracking and cannot reconstruct a track that was removed [PAGE 7]. This veto is especially important in sports where players may leave the camera view or be hidden by a crowd.

The fifth veto is detector confidence collapse. The source filters detections below 0.1 and treats 0.6 as the high-score boundary [PAGE 5]. If a player is heavily occluded, the detector may output low confidence. The tracker then uses low-score association with EIoU only [PAGE 4]. If the detector also produces fragmented boxes, the association may switch identities. A cross-layer veto should therefore consider detector stability: if a track’s detection confidence falls below the low-score boundary for many consecutive frames, the track should be marked uncertain. This is not a physical impossibility, but it is a probabilistic reliability veto.

A weather/lighting layer can be added even though the source mainly mentions lighting as an appearance issue [PAGE 3]. Outdoor sports introduce rain, glare, shadows, and low contrast. These conditions can reduce detector recall and degrade ReID features. A formal weather veto can be expressed as a detector-confidence drop:

\[
p_{\text{det}} \downarrow \quad \text{under low visibility}
\]

If the detector confidence distribution shifts downward, the tracker should widen geometric tolerance but also increase identity uncertainty. The proof is conditional: if weather or lighting degrades the appearance channel, then appearance-based vetoes become less reliable, and the tracker must rely more on motion continuity and buffer constraints. The adjudication is therefore not that Deep-EIoU is physically invalid, but that its geometric expansion must be bounded by kinematic plausibility, appearance ambiguity, memory limits, and detector reliability.

<RLVR_COUNTERFACTUAL_VETOES>
The following are three verifiable counterfactual veto scenarios for a reinforcement-learning-with-verifiable-rewards style audit. The reward signal can be HOTA, AssA, DetA, ID switches, or fragment count, but each scenario must be testable.

1. Appearance-ReID Veto Under Same-Team Occlusion

Counterfactual: If ReID is disabled, or if ReID features are corrupted by occlusion and same-team jerseys, the tracker should lose identity persistence. The source reports that appearance improves SportsMOT performance: “after incorporating ReID model based on appearance association, the HOTA of Deep-EIoU is boosted by 3.8” [PAGE 6]. The ablation table also shows a full configuration reaching 77.220 HOTA with ReID, iterative scale-up, and linear interpolation [PAGE 7].

Verifiable prediction: On SportsMOT, removing ReID should reduce HOTA by approximately several points, with the paper’s text supporting a 3.8-point boost when appearance is included [PAGE 6]. More specifically, if the ReID branch is replaced by random embeddings or by embeddings cropped during severe occlusion, ID switches and Frag should increase, while AssA should fall. If HOTA does not degrade when ReID is removed, the appearance veto is not operative in that environment, and the reward model is over-crediting appearance.

Breakdown regime: If all players wear nearly identical appearance cues and the detector produces low-confidence crops, cosine similarity may not separate identities. The threshold \(\tau_A = 0.25\) [PAGE 5] may pass multiple candidates if their embeddings are close. In that case, the minimum-cost assignment may select the wrong player despite low appearance cost. The veto is verifiable by measuring identity flips during crowded plays.

2. Expansion-Ceiling Veto Under Fast Nonlinear Motion

Counterfactual: If an athlete’s frame-to-frame displacement exceeds the search space generated by the iterative expansion schedule, association should fail. The source uses \(E_{\text{initial}} = 0.7\) and step size \(\lambda = 0.1\) [PAGE 5]. With a small iteration count, the maximum nominal expansion scale is near 0.9, depending on implementation. If the required expansion scale exceeds this ceiling, the expanded boxes may not overlap enough to produce a reliable EIoU.

Verifiable prediction: Inject synthetic fast-motion trajectories or select natural clips with abrupt direction changes. As displacement increases beyond the expansion ceiling, EIoU should fall, assignment cost should rise, and ID switches should increase. If increasing \(t\) or increasing \(\lambda\) improves HOTA only up to a point, then the expansion ceiling is real. If performance improves without bound as expansion grows, the method is not robust; instead it is exploiting geometric saturation.

Breakdown regime: The printed expansion formula can cause large boxes. If \(E\) becomes too large, many expanded boxes overlap, and EIoU becomes non-discriminative. The source’s iterative scale-up is designed to avoid tuning a single expansion scale [PAGE 4], but it still has a practical upper bound. The veto is verifiable by sweeping \(E_{\text{initial}}\), \(\lambda\), and iteration count, then measuring HOTA, AssA, and ID switches. The source already shows robustness to different initial scales from 0.2 to 0.8 [PAGE 6], but robustness does not imply infinite expansion capacity.

3. Oracle-Detection Veto on SoccerNet-Tracking

Counterfactual: If SoccerNet-Tracking is evaluated with oracle detections, the reported HOTA is conditional on near-perfect detection. The source says, “we directly use the oracle detections provided by the dataset for the evaluation of all trackers” [PAGE 5]. The reported SoccerNet result is 85.443 HOTA, with DetA = 99.236 [PAGE 7]. If the same tracker is evaluated with non-oracle detections, especially detections from a general SportsMOT-finetuned detector, DetA should decline and HOTA should decline unless the detector is exceptionally strong.

Verifiable prediction: Rerun SoccerNet-Tracking without oracle detections, using a realistic detector. The DetA should fall from 99.236 toward a lower value, and HOTA should fall accordingly. If HOTA remains near 85.4 without oracle detections, the detector is unusually accurate or the evaluation setup has changed. The source’s own metric relation supports this: HOTA is tied to DetA and AssA [PAGE 6-7]. Since DetA is already near saturation under oracle detections, the main possible degradation under realistic detection is detection recall/precision, not association alone.

Breakdown regime: If the detector misses a player for several frames, the tracker cannot associate a nonexistent detection. The 60-frame buffer [PAGE 6] may preserve identity briefly, but if the detector fails for longer than the buffer or produces fragmented boxes, identity continuity breaks. Linear interpolation can smooth short gaps but cannot restore missing detection evidence [PAGE 7]. The veto is verifiable by comparing oracle-detection HOTA with end-to-end detector HOTA on the same sequences. If the gap is large, the reward model should not treat the oracle score as an unconditional system capability.

Additional audit note: A fourth useful veto, though not required as one of the three, is the long-occlusion memory veto. If occlusion exceeds 60 frames, the tracker should not be credited with stable identity. This is directly testable by extending occlusion durations and measuring whether IDs and Frag rise. The source’s buffer setting makes this a natural RLVR check: reward stable tracking only when the memory clock and motion clock agree.
