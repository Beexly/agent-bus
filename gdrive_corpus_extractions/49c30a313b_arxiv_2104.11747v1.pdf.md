<RECURSIVE_THEORY_OF_MIND>
Crisis habit regression, counter-trap, and clock structure.

Crisis habit regression. Under pressure—occlusion, missed detection, or false positive—the tracker regresses to a set of hard-coded habits: (i) tracks are updated in descending order of age, privileging older tracks as more likely true positives [PAGE 5]; (ii) a track that remains unmatched for three timesteps or 1.5 s is terminated [PAGE 5]; (iii) during gaps, the Kalman predictor extrapolates the track state using the 11-state motion model [PAGE 4]; (iv) new tracks are initialized over two consecutive frames: first a preliminary track from an unmatched active detection, then confirmation if an active detection edge links it to a fresh detection [PAGE 5]. These habits are reactive and local; they do not reason about future frames because none are available [PAGE 1]-[PAGE 3].

Counter-trap. The NMP layer is the counter-trap to local habit regression. By running L rounds of message passing, detection and track nodes mix local features with global relational evidence across the graph, so a classification decision at one edge is conditioned on the connectivity of distant nodes [PAGE 4]-[PAGE 5]. Time-aware messages separate past and future detection edges, letting the network weigh trajectory consistency differently depending on temporal direction [PAGE 4, Eq. (3)]. Skip connections preserve raw edge and node features through the unrolled iterations, preventing information collapse [PAGE 4, Eq. (1)-(2)]. Two-stage training is a second counter-trap: after offline training on ground-truth-matched detections, the tracker runs on the full training set to produce self-generated tracks, and a second training stage fits the network to the online distribution [PAGE 6]-[PAGE 7]. Data augmentation (random detection drops, positional noise, random track removal to simulate termination, and full-track drops to simulate initialization) further hardens the policy against closed-loop drift [PAGE 6].

Clock structure. The system is paced by three clocks. First, the graph window T = 3 timesteps bounds the temporal horizon over which relational evidence can be integrated [PAGE 6]. Second, the nuScenes effective sampling rate is 2 Hz while LIDAR scans at 10 Hz [PAGE 12], so the tracker operates on decimated observations and must extrapolate across unobserved scan intervals. Third, the termination clock (3 timesteps or 1.5 s) imposes a hard deadline: if the association habit fails to renew a track within this window, the track object is retired and any subsequent re-detection is treated as a new identity [PAGE 5]. Runtime completes in 81.3 ms on a Titan Xp, within the 100 ms frame budget at 10 Hz, but graph generation and post-processing consume 57.8 ms of that budget [PAGE 7], [PAGE 12]. Thus the real-time clock is constrained more by Python-side bookkeeping than by the neural message-passing core (23.4 ms).
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
Physical, biomechanical/class, and weather veto proof.

Physical veto. The sensor layer is LIDAR only, with no comprehensive appearance data [PAGE 1]. Association must rely primarily on object dynamics, which is complicated by fast-moving objects such as cars [PAGE 1]. Occlusions cannot be bridged by interpolation; they require extrapolation with a predictive model [PAGE 1]. Graph truncation imposes an implicit maximum-velocity constraint via a distance threshold [PAGE 4]; any object exceeding that bound loses detection edges and risks track fragmentation. Missed or occluded detections are only partially mitigated by data augmentation (random detection drops) during training [PAGE 6]. Because the graph is built only from detections and active tracks, a sensor dropout longer than the termination horizon (three timesteps or 1.5 s) forces track death and potential ID switch upon re-emergence [PAGE 5], [PAGE 13].

Biomechanical/class veto. The object ontology is vehicle-centric (cars, trucks) with orientation encoded as sin/cos relative to a unified coordinate system [PAGE 4]. Failure modes are class-linked: double objects arise when the same physical truck is detected multiple times as different types, creating duplicate or competing tracks [PAGE 13]. Size and orientation features are carried on nodes rather than edges, so their discriminative value scales with detection quality; the ablation shows smaller gains on lower-quality MEGVII detections where such features vary little across objects [PAGE 8].

Weather veto. The paper does not report weather-stratified metrics or sensor degradation models. nuScenes includes diverse conditions, but the algorithm contains no explicit rain/fog/snow compensation; LIDAR range and point density collapse under adverse weather is an external physical veto not addressed by the graph or NMP layers [PAGE 1]-[PAGE 2]. Consistent false positives from physical structures or reflections cannot be recognized by the tracker because it follows the tracking-by-detection paradigm and lacks an appearance model to reject static clutter [PAGE 13].

Adjudication summary. The veto chain is: LIDAR-only physics (no appearance, occlusion-limited) → implicit velocity/truncation bound → fixed termination clock → greedy age-sorted update. If any link fails (long occlusion, static reflector, double detection, weather-induced dropout), the system has no learned fallback outside the NMP classification scores, and failure cases mirror those of existing trackers including CenterPoint [PAGE 13].
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
Three verifiable counterfactual veto scenarios with falsifiable predictions. RLVR here denotes reinforcement-style verifiable rejection conditions applied to the tracking policy.

Scenario A — Occlusion beyond termination horizon. Verifiable condition: inject a synthetic full occlusion of a ground-truth vehicle for duration \(t_{\text{occ}}\) on nuScenes validation sequences, then release the object at the same location. Veto trigger: if \(t_{\text{occ}} > 1.5\) s at the 2 Hz effective rate (i.e., more than three consecutive missed updates), the Kalman-predicted track is terminated per the three-timestep/1.5 s rule [PAGE 5]. Prediction: upon reappearance, the detector initializes a new track, producing an ID switch; ID-switch count increases monotonically with \(t_{\text{occ}}\) beyond 1.5 s, while AMOTA decreases approximately proportional to the lost track duration. The fragmentation rate should rise discontinuously at the termination boundary because the model has no re-identification mechanism.

Scenario B — Persistent static false positive from physical structure. Verifiable condition: insert a stationary, detector-consistent false positive (e.g., a reflector or pole returning a stable LIDAR box) at a fixed map location across many frames. Veto trigger: because the tracker has no appearance model and cannot recognize consistent false positives from static structures [PAGE 13], the detection node may be classified active and promoted to a preliminary track, then confirmed via a self-loop detection edge. Prediction: a spurious track persists until the termination clock expires (if never matched to a true detection, it may persist only if it self-initializes; otherwise it dies after three timesteps/1.5 s). MOTA decreases locally due to false positives; AMOTP is unaffected for true tracks but the false-track occupancy degrades scene-level association purity. The detector-score tie-break in Algorithm 1 means a high-scoring reflector can outcompete a weak true detection for graph resources [PAGE 11].

Scenario C — Class-ambiguous double detection (truck). Verifiable condition: perturb the detection front-end so a single truck emits two boxes with different class labels at overlapping timestamps. Veto trigger: because orientation and size are node features and class is one-hot [PAGE 4], the two detections may occupy separate graph nodes; if each connects to a different track or initializes separate tracks, the same physical object generates two identities. Prediction: ID switches increase between the duplicate class tracks, fragmentation increases because the true trajectory is split across two partial tracks, and AMOTA drops in proportion to the double-detection rate. This is a detector-level veto that the tracker cannot resolve without non-maximum suppression or class-consistency constraints, which are outside the presented graph [PAGE 13].

Verification protocol: run the trained nuScenes validation pipeline under each injection; measure AMOTA, IDS, FRAG, MOTA, and AMOTP before/after. A veto is confirmed if the metric moves outside the paper’s stated ablation variance (e.g., IDS rising above the CenterPoint baseline of 760 on test or 562/462 on validation [PAGE 7]-[PAGE 8]) and if the failure mode matches the documented failure cases [PAGE 13].
