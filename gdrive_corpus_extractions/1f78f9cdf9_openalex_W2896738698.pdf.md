Near shock-like features or constraint-induced kinks, linear interpolation can select a control that is not optimal for the true value function. The formal stability statement is only that there exists “an uniform neighborhood along the reference trajectory” in which a generalized Lyapunov inequality holds [PAGE 5]; it is not a global collision-avoidance theorem for arbitrary unexpected obstacles.

The scientific lineage is a chain of reachability, nonsmooth optimal control, and decentralized MPC. The paper anchors its reach-set idea in Graettinger and Krogh, Varaiya, and Kurzhanski and Varaiya [PAGE 4], and its value-function propagation in Bardi and Capuzzo-Dolcetta, Clarke, Clarke et al., Sethian, Michel et al., Mitchell, and Cross and Mitchell [PAGE 4]. The AUV dynamics lineage is Fossen’s ocean-vehicle guidance/control text and Prestero’s REMUS six-degree-of-freedom model [PAGE 3]. The MPC stability/robustness lineage is Mayne et al., Langson et al., and Mayne et al. [PAGE 3]. The decentralized formation lineage includes Keviczky et al., Franco et al., Fax and Murray, Saber and Murray, and related AUV acoustic-communication work [PAGE 2]. The paper’s novelty is retrocausal in the following sense: it moves most computation into a precomputed past (“pre-compute off-line all the ingredients required for the on-line (feedback synthesis) that remain invariant in the course of the ‘mission execution’” [PAGE 4]) and then makes the online present a search over a stored geometric object. The later field behavior is supposed to be explained by an earlier offline value table. The trap is that a later disturbance can retroactively invalidate the earlier table: if the ocean current or obstacle field changes, the “invariant” ingredients were only invariant for the historical model distribution, not for the actual mission.

Multi-week trap 1: offline table overfitting. Week 1 may show excellent simulation tracking because the value function is computed for the same dynamics used online. Week 2 may add current-like perturbations or parameter drift; the table is then queried outside its validity domain. The paper itself allows only small-variation linear interpolation and large-event mode changes [PAGE 4], so a multi-week field trial without retuning is a trap.

Multi-week trap 2: nonsmooth interpolation drift. Because the value function may be merely continuous and the HJB solution is nonsmooth [PAGE 4], repeated interpolation between table nodes can accumulate bias. In week 3 this appears as limit cycles, chatter, or conservative control that burns energy. The formal warning is in the paper’s own solution-concept language: viscosity, generalized, and proximal normal senses [PAGE 4].

Multi-week trap 3: acoustic-delay creep. The architecture says delays and dropouts “can easily be incorporated” [PAGE 3], but decentralized formation constraints are only as good as the neighbor model. Over multiple weeks, packet-loss statistics and delay distributions can shift; the neighbor model becomes stale, and formation constraints are evaluated against a ghost vehicle. This is a classic retrocausal genealogy failure: the offline/decentralized model encoded last week’s communication regime.

Multi-week trap 4: sensor-cone blindness. The motion supervisor only reacts when the obstacle “falls within the cone of the range sensor” [PAGE 6]. A multi-week deployment with side-entry obstacles, moving obstacles, or occlusion will generate detection latencies that the reach-set table did not anticipate. The later collision would not disprove the reach-set math; it would disprove the unstated assumption that detection occurs before the reach set intersects the obstacle.

Multi-week trap 5: simulation-to-field migration. The paper’s own conclusion places field testing in the future: “the next step the migration for this control structure for the AUV onboard control software for the required field testing” [PAGE 6]. A multi-week trap is to treat simulation success as field validation. The source says “The mathematical details were strongly omitted due to the lack of space” [PAGE 6], so many implementation details needed for field certification are absent.

<RECURSIVE_THEORY_OF_MIND>
The recursive theory-of-mind layer in the paper is shallow but operationally important. Each AUV runs its own MPC and “encompasses the models of its neighboring AUVs” while communicating only with neighbors [PAGE 3]. That is a level-1 model: vehicle \(i\) predicts vehicle \(j\)’s state and constraints. There is no printed level-2 model of “vehicle \(j\)’s model of vehicle \(i\),” nor a formal model of how neighbor \(j\) will behave after \(j\) enters exploration mode. The architecture therefore has a recursive-model gap exactly when an obstacle appears and one vehicle changes behavior.

Crisis habit regression. When an obstacle is detected, the motion supervisor “switches to an exploration mode in order to find the optimal way to circumvent the obstacle by taking into account the original final target” [PAGE 6]. This is a habit regression: the system falls back to a precomputed value function and a search routine rather than re-solving the full constrained MPC. The regression is rational for real-time computation, but it can violate formation or communication constraints because the exploration objective is obstacle circumvention, not necessarily formation preservation. The paper claims the example mitigates “the extent of the distortion of their formation pattern” [PAGE 6], but that is an illustrative simulation result, not a general guarantee.

Counter-trap. The counter-trap is over-trusting the claim that “a priori, the value function in the state space region after circumvention of the obstacle remains exactly as the one pre-computed off-line” [PAGE 6]. If the obstacle is static and the dynamics are unchanged, that may hold. If the obstacle alters local flow, if the vehicle’s actuator state changes, or if the obstacle moves, the value function after circumvention is not exactly the precomputed one. A recursive theory-of-mind failure occurs when the supervisor treats the environment as having the same model before and after the obstacle. The safe stance is to require revalidation of the value function in the post-obstacle region, or at least to bound the model error and use a robust tube.

Clock. The clock layer has three deadlines: the control horizon \(\Delta\), the prediction horizon \(T\), and the exploration/detection latency. The paper’s MPC loop slides time by \(\Delta\), samples \(x\) at \(t+\Delta\), updates the reach set by translation/rotation, and repeats [PAGE 5]. The obstacle supervisor adds a detection-to-exploration delay. A necessary real-time condition is
\[
\tau_{\rm detect}+\tau_{\rm decide}+\tau_{\rm act}\le \Delta_{\rm safe},
\]
where \(\Delta_{\rm safe}\) is the time-to-collision or time-to-constraint-violation margin implied by the current reach set. The paper does not print this inequality, but it is the operational meaning of “real-time constraints” [PAGE 3] and “computational burden in real-time is extremely low” [PAGE 5]. If the clock budget is violated, recursive modeling is irrelevant: the vehicle acts on a state that is already stale. A second clock condition is that exploration must terminate before the reach set intersects the obstacle:
\[
R_f(t+\tau_{\rm explore};t,x(t))\cap O(t+\tau_{\rm explore})=\varnothing.
\]
If this fails, the crisis habit regression has not produced a safe path regardless of how good the offline value table is.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
Physical/actuator layer. No biological biomechanical layer appears in the source; the analogous layer is the AUV’s mechanical/actuator/hydrodynamic layer. The physical veto is actuator feasibility: for every candidate control \(u_i\) used to realize the reach-set endpoint, the required thrust must satisfy \(\boldsymbol{\tau}_i(s)\in U_i\) [PAGE 3]. If the set
\[
\mathcal{U}^{\rm feasible}_i(t)=\{u_i\in U_i:\ \text{there exists a trajectory }x_i(\cdot)\text{ with }\dot x_i=f(x_i,u_i),\ x_i(t+T)\in R_f,\ \text{and all constraints held}\}
\]
is empty, the MPC problem has no admissible control and the physical layer vetoes the plan. This is not a toy ratio; it is a set-feasibility condition directly implied by the control and state constraints [PAGE 3].

Hydrodynamic/weather layer. The paper explicitly warns of “strong perturbations” and distributed-parameter nature [PAGE 2], but it does not print a current/wave disturbance model or a bound. Therefore a weather veto must be expressed against a measured or estimated disturbance \(d(t)\). Let the actual dynamics be \(\dot x=f(t,x,u)+d(t)\). The nominal reach set \(R_f\) is computed for \(d=0\) under the time-invariance assumption [PAGE 4]. Robust containment requires
\[
x(t+\Delta)\in R_f(t+\Delta;t,x(t))\oplus \mathcal{B}_{\delta},
\]
where \(\mathcal{B}_{\delta}\) is the ball of disturbance-induced displacement and \(\oplus\) is Minkowski addition. If the measured or forecast \(\delta\) exceeds the margin between \(R_f\) and the obstacle/communication/formation constraint boundary, the weather layer vetoes the nominal plan. The source does not provide \(\delta\); this is a missing robustness certificate, not a proven safety claim.

Obstacle/sensor layer. The motion supervisor reacts only after the obstacle “falls within the cone of the range sensor” [PAGE 6]. Define the obstacle set \(O(t)\) and the sensor-detection time \(t_{\rm det}\). A safe obstacle veto condition is: either
\[
R_f(t_{\rm det}+\tau_{\rm explore};t_{\rm det},x(t_{\rm det}))\cap O(t_{\rm det}+\tau_{\rm explore})=\varnothing,
\]
or there exists an exploration trajectory \(\gamma:[t_{\rm det},t_{\rm det}+\tau_{\rm explore}]\to \mathcal{C}_{\rm free}\) with \(\gamma(t_{\rm det})=x(t_{\rm det})\) that reaches a state from which the precomputed value function can drive to the original target without violating state/formation constraints. If neither condition holds, veto. The paper’s Figure 4/6 logic illustrates exactly this cone-and-reach-set geometry, but it does not print the inequality [PAGE 6].

Acoustic/communication layer. The decentralized controller uses neighbor models and neighbor communication [PAGE 3]. Let \(\hat x_j\) be the communicated neighbor state and \(x_j\) the true state. If the estimation error \(e_j=\|\hat x_j-x_j\|\) causes the communication constraint \(g^c_{i,j}\in C^c_{i,j}\) or formation constraint \(g^f_{i,j}\in C^f_{i,j}\) to become infeasible for all \(u_i\in U_i\), the communication layer vetoes the formation plan. The paper says delays and dropouts “can easily be incorporated” [PAGE 3], but it gives no maximum allowable \(e_j\); the veto must therefore be based on an externally specified constraint margin.

Energy layer. The cost includes \(\boldsymbol{\tau}_i^\top R_i\boldsymbol{\tau}_i\) to save onboard energy [PAGE 3]. A physical energy veto is
\[
\int_t^{t+T}\boldsymbol{\tau}_i^\top(s)R_i\boldsymbol{\tau}_i(s)\,ds\le E_{i,\rm remaining}.
\]
If the reach-set plan requires more than the remaining energy to reach a safe state or complete the mission, the plan is physically inadmissible even if the value function is finite. The paper does not print an energy budget inequality, but its motivation is explicitly “onboard limited energy, computational power, and communication capabilities” [PAGE 6].

Adjudication order. The correct cross-layer order is: (1) actuator/state feasibility, (2) disturbance containment, (3) obstacle/sensor timing, (4) communication/formation feasibility, (5) energy. Any higher-layer optimization result is overridden by a lower-layer veto. The source’s reach-set/value-function machinery is a planning layer; it cannot create thrust beyond \(U_i\), cannot remove an obstacle, cannot restore a dropped acoustic packet, and cannot make a non-time-invariant value table exact.
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
Scenario 1: occluded obstacle inserted outside the sensor cone. Counterfactual: keep the paper’s Reach Set MPC and motion supervisor unchanged, but place an obstacle on a bearing that is outside the range-sensor cone until the vehicle is already close. Prediction: no exploration-mode switch occurs until the obstacle enters the cone [PAGE 6]; if the switch occurs after the reach set already intersects the obstacle, the exploration routine has insufficient time to find a feasible circumvention path. Verifiable labels: minimum separation \(d_{\min}\), detection time \(t_{\rm det}\), time-to-collision estimate, and feasibility flag from the exploration solver. Veto prediction: veto if \(d_{\min}\) is below the safe radius or if no feasible exploration trajectory exists before the reach set intersects \(O(t)\). This tests the hidden assumption that detection precedes reach-set intersection.

Scenario 2: acoustic dropout burst longer than the control horizon. Counterfactual: keep the decentralized formation MPC but inject a packet-loss/delay burst of duration \(L\) into neighbor state updates, with \(L\) large relative to \(\Delta\). Prediction: each AUV’s neighbor model becomes stale; formation and communication constraints are evaluated against ghost states, so the controller either distorts formation or enters an infeasible/emergency condition. Verifiable labels: packet loss rate, delay \(D\), neighbor-state error \(e_j=\|\hat x_j-x_j\|\), formation-constraint violation, and communication-constraint violation. Veto prediction: veto if \(e_j\) drives the constrained set empty for the current \(U_i\), or if the formation error exceeds the externally specified tolerance. The paper’s claim that delays and dropouts “can easily be incorporated” [PAGE 3] is thus converted into a measurable robustness test rather than an assertion.

Scenario 3: current/wave disturbance step beyond the precomputed reach-set margin. Counterfactual: keep the offline value table and reach-set lookup, but apply a disturbance \(d(t)\) whose integrated displacement exceeds the gap between the nominal reach set and the nearest constraint boundary. Prediction: the actual state exits the nominal \(R_f\), the value lookup is queried outside its precomputed validity domain, and the controller returns a boundary/interpolated control that may saturate thrust or violate formation spacing. Verifiable labels: containment fraction \(c=\Pr[x(t+\Delta)\in R_f\oplus\mathcal{B}_{\delta}]\), tracking RMSE, saturation fraction, and energy consumption. Veto prediction: veto if containment fraction falls below the specified threshold, if RMSE exceeds the mission bound, or if saturation fraction exceeds the actuator limit. This scenario directly tests the source’s time-invariance premise: “Since the dynamics of robotic are time invariant” [PAGE 4]. If the disturbance step invalidates that premise, the reach-set table must be rejected or recomputed, not merely interpolated.
</RLVR_COUNTERFACTUAL_VETOES>
