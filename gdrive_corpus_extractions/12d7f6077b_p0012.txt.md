<RETROCAUSAL_GENEALOGY>
The patent US 8,572,075 B1 sits at the confluence of three historical lineages in information retrieval. First, the vector-space model lineage (Salton, 1970s) represents documents and queries as vectors in a term-weighted space; the patent’s “scoring signals” generalize term frequency, inverse document frequency, anchor text, and URL features into an opaque signal vector $\sigma$ [PAGE 1]. Second, the probabilistic retrieval lineage (Robertson & Spärck Jones; BM25) treats relevance as a probability to be estimated from term statistics; here, the patent deliberately avoids committing to a probabilistic formula, instead externalizing the scoring function to user-supplied code [PAGE 1]. Third, the learning-to-rank lineage (Burges et al., RankNet; pairwise and listwise objectives) anticipates FIG. 5’s “pair-wise comparisons of scoring functions,” but whereas learning-to-rank optimizes a single parametric model from labeled click data, this patent delegates model selection to end users through a graphical interface [PAGE 1].

The multi-week trap emerges from temporal validity of user-supplied scoring parameters. A parameter set such as “title_weight: 10, link_scale: 0.3” [PAGE 1] is tuned for a particular query (“San Francisco Vacation”) and a particular web ecosystem state [PAGE 1]. Over a multi-week horizon, three drift processes invalidate the parameter fixed point: (i) query drift, where the same query string resolves to different intents as news cycles or seasonal travel patterns shift; (ii) anchor-text and link-graph drift, where the link_scale parameter decays in predictive value as referring domains change; and (iii) scoring-function obsolescence, where a user-authored function that performed well under FIG. 1A/B conditions becomes stale as the underlying search engine’s signal distribution shifts. Because the patent discloses no retraining trigger, no parameter half-life, and no automatic re-evaluation of pairwise function rankings over time [PAGE 1], a system deployed on this architecture silently accumulates ranking error over 2–4 week windows. The historical trap is that user-selected scoring functions look optimal at deployment (t=0) but regress toward the mean of the search engine’s default ranking as the web and query distribution evolve, with no rollback mechanism disclosed in the specification.

<CROSS_LAYER_VETO_ADJUDICATION>
A veto is mandatory when any layer cannot satisfy its physical or information-theoretic precondition.

**Physical layer (client device).**  
From FIG. 2, the client device 204 has RAM 206 and processor 208 [PAGE 1]. Let $M_{\text{msg}}$ be the byte size of the encoded scoring signal message and $C_{\text{eval}}$ the CPU cycles required to evaluate $f_{\theta}$. A physical veto is triggered if  
$$ M_{\text{msg}} > R_{206} \quad \text{or} \quad \frac{C_{\text{eval}}}{\text{clock rate}_{208}} > \tau_{\text{session}}, $$  
where $\tau_{\text{session}}$ is the maximum tolerable user-facing latency. This veto is absolute: no score can be returned, and the subset must be presented unranked or via the search engine’s default order.

**Biomechanical layer (human presentation).**  
The GUI presents search results for human consumption (FIGS. 1A–1C) [PAGE 1]. Human reading throughput is bounded by saccadic fixation and working memory (on the order of 200–300 words per minute for dense result snippets). If $|S| \times \bar{w}$ (number of results times average words per result) exceeds the cognitive channel capacity for the session duration, the system must veto additional scoring-function iterations and truncate the subset, because further re-ranking cannot be perceptually resolved by the user.

**Weather/network layer (WAN).**  
The client and search system may be coupled through a LAN or WAN, e.g., the Internet [PAGE 1]. Let $L_{\text{RTT}}$ be the round-trip network latency between client device 204 and search system 214, and let $N_{\text{scoring}}$ be the number of message round-trips required to score the subset (one per result if scoring is outsourced, or one batch if parallelized). A network veto is triggered if  
$$ N_{\text{scoring}} \times L_{\text{RTT}} > \tau_{\text{WAN}}. $$  
Unlike the physical layer, this layer is stochastic; weather-related WAN degradation makes $L_{\text{RTT}}$ a random variable with heavy-tailed outliers, so the veto threshold must be set at a high quantile (e.g., 99th percentile) rather than the mean.

**Veto proof (adjudication).**  
The system is veto-proof only if the conjunction  
$$ \bigl(M_{\text{msg}} \le R_{206}\bigr) \land \bigl(C_{\text{eval}} \le \tau_{\text{session}} \cdot \text{clock rate}_{208}\bigr) \land \bigl(N_{\text{scoring}} \cdot L_{\text{RTT}} \le \tau_{\text{WAN}}\bigr) \land \bigl(|S| \cdot \bar{w} \le C_{\text{human}}\bigr) $$  
holds. Violation of any conjunct forces a graceful degradation: either fall back to the search engine’s native ranking without user-selected scoring functions, or present an error and prompt the user to select a lighter-weight scoring function or fewer parameters. No probabilistic betting line is used to decide the veto; the decision is deterministic given measured layer-state variables.

*Prediction:* the system aborts scoring for that result, marks the function as faulty, and presents the subset using the next available valid scoring function or the search engine default. The user will observe a fallback ranking rather than a hang.

**Veto Scenario 2 — Score degeneracy (zero variance).**  
Scoring parameters are set such that $f_{\theta}$ returns an identical constant score for every search result in the subset (e.g., title_weight = 0 and all other feature weights zeroed, or a threshold parameter that discounts all body terms beyond the first occurrence) [PAGE 1].  
*Verifiable veto condition:* compute sample variance $\operatorname{Var}(\{y_s\}_{s \in S}) = 0$ exactly, in $\mathbb{R}$; this is verifiable by arithmetic on the returned score messages.  
*Prediction:** because ranking by identical scores is undefined (any permutation in $\mathfrak{S}_{|S|}$ is equally valid), the system vetoes the user-selected function and reverts to the search engine’s intrinsic relevance order. The user will see no reordering relative to the unmodified search results.

**Veto Scenario 3 — Information-bottleneck encoding loss.**  
The message encoder $\mathcal{E}$ compresses signals so aggressively that mutual information $I(\sigma; m) < \epsilon$ for a small $\epsilon > 0$ [PAGE 1]. For example, if anchor-text and URL signals are dropped from the message because the user-selected scoring function only accepts title terms, the score $y_s$ cannot discriminate results that differ only in non-title signals.  
*Verifiable veto condition:* estimate $I(\sigma; m)$ from a validation batch of signal-message pairs; if below threshold, the encoding is lossy beyond tolerance. Verifiable because the encoder’s output alphabet and input signal distribution are finite and measurable.  
*Prediction:* the system rejects the scoring function for that session and forces the user to choose a function whose message schema preserves the necessary signals. The user will receive a schema-compatibility error rather than a silently degraded ranking.

Each scenario produces a binary veto decision and an observable fallback behavior, satisfying the RLVR requirement that rewards and constraints be verifiable rather than inferred from opaque user satisfaction. No odds or betting lines enter the reward construction.
