<RECURSIVE_THEORY_OF_MIND>
During an error state, the user undergoes crisis habit regression: under stress, they abandon exploratory behavior and regress to primal escape patterns—hammering the back button, closing the tab, searching for a phone number, or retyping the URL from scratch. The recursive theory of mind here requires modeling three nested agents simultaneously: (1) the distressed user who thinks “Did I break something?” or “Is my data lost?”; (2) the support agent who will inherit the ticket if the error page fails; and (3) the product designer who assumes the user will read carefully and choose rationally.

The counter-trap is over-explanation. Designers often respond to user anxiety by adding more detail: error codes, stack traces, diagnostic steps, and secondary links. This is the recursive trap because each additional element increases the user’s cognitive load precisely when their working memory is most compromised. The theory-of-mind correction is to model the user not as a careful reader but as a distracted scanner who will allocate roughly 10 seconds [PAGE 1] before abandoning. Therefore the copy must sound human—apologetic without groveling, clear without jargon—and must offer exactly one next action so the user’s motor plan requires zero branching decisions.

The clock is the hard constraint. Ten seconds is not a design preference; it is the boundary of the user’s patience during a failure event. If the error page does not establish what the user is seeing, why it matters, how to use it, and what to do next within that window [PAGE 1], the user’s mental model collapses into “this product is broken,” and recovery probability approaches zero. The trust note (“your data is safe,” “we’re fixing this,” or “try again safely”) directly addresses the user’s hidden question: “Am I safe?” Without it, the next action is ignored because the user does not trust the system.

Recursive depth check: Does the support team expect the user to provide a screenshot? If so, the error page must prompt for it or capture it automatically. Does the growth team expect a conversion action? The recursion resolves when all three agents—user, support, product—share the same single next action and the same trust boundary.
