\mathrm{match}(v,\mathrm{eval}(e,\sigma_j)).
\]

Here \(\sigma_j\) is the local state of \(P_j\). The data domain is abstract and dimensionless; \(\mathrm{eval}(e,\sigma_j)\) denotes the value of expression \(e\) in state \(\sigma_j\). If a probabilistic model were externally supplied, the information content of a communicated value \(V\) would be

\[
H(V)=-\sum_{v\in\mathrm{dom}(V)}p(v)\log_2 p(v)\ \mathrm{bits},
\]

but the CSP source itself defines nondeterministic choice, not a probability distribution. Therefore \(p(v)\) is not provided by the paper, and \(H(V)\) is undefined unless an external probabilistic model is added. This is a critical unit assumption.

Synchronization is blocking rendezvous. The source says on [PAGE 2]: “There is no automatic buffeting: In general, an input or output command is delayed until the other process is ready with the corresponding output or input.” It adds: “Such delay is invisible to the delayed process” [PAGE 2]. Thus, in the base language, for a channel between \(X\) and \(Y\),

\[
\mathrm{buffer}(X,Y)=0
\]

unless the program explicitly constructs a buffer process. Time is not part of the language semantics. If an implementation timing model is supplied, a delay \(t_d\) satisfies

\[
t_d \geq 0\ \mathrm{s},
\]

with no upper bound or fairness guarantee derivable from the source. The paper’s discussion of automatic buffering rejects it: “I have deliberately rejected this alternative” [PAGE 10]. Consequently, any model that assumes implicit queues is invalid.

Parallel composition has the termination rule on [PAGE 3]: “They all start simultaneously and the parallel command terminates successfully only if and when they have all successfully terminated.” Formally,

\[
[P_1 \parallel \cdots \parallel P_n]\Downarrow
\iff
\forall i\in\{1,\dots,n\}: P_i\Downarrow.
\]

Guarded alternatives are defined on [PAGE 4]: “An alternative command specifies execution of exactly one of its constituent guarded commands. Consequently, if all guards fail, the alternative command fails.” For guards \(G_1,\dots,G_m\),

\[
[G_1\rightarrow S_1 \,\square\, \cdots \,\square\, G_m\rightarrow S_m]
\]

executes exactly one \(S_k\) whose guard \(G_k\) succeeds. If no guard succeeds, the alternative fails. Repetition is governed by [PAGE 4]: “A repetitive command specifies as many iterations as possible of its constituent alternative command. Consequently, when all guards fail, the repetitive command terminates with no effect.” Thus

\[
*[G_1\rightarrow S_1 \,\square\, \cdots \,\square\, G_m\rightarrow S_m]
\]

terminates when all guards fail. With input guards, the termination condition is stronger: the process may wait until either a corresponding output becomes ready or all sources named by input guards have terminated [PAGE 5]. The deadlock statement is exact: “If neither event ever occurs, the process fails (in deadlock.)” [PAGE 5]. Also, “If X sends a nonmatching message, deadlock will result” [PAGE 5].

The fairness regime is a breakdown regime. The source asks whether a language definition should require fairness and says: “I am fairly sure that the answer is NO” [PAGE 11]. It also states: “it is the programmer's responsibility to prove that his program terminates correctly--without relying on the assumption of fairness in the implementation” [PAGE 11]. Formally, if \(\mathrm{enabled}(a)\) means action \(a\) is executable and \(\Diamond\) means eventual execution, the language does not require

\[
\Box(\mathrm{enabled}(a)\implies\Diamond\mathrm{executed}(a)).
\]

Therefore starvation is possible under an unfair implementation. Additional exact singularity and failure regimes are: an assignment fails if its expression is undefined or if a structured target does not match the value [PAGE 3]; an input fails if its source is terminated [PAGE 4]; an output fails if its destination is terminated or its expression is undefined [PAGE 4]; an alternative fails when all guards fail [PAGE 4]; a repetitive command terminates with no effect when all guards fail [PAGE 4]; a process fails in deadlock when neither a matching communication nor all-source termination occurs [PAGE 5]. The language is static: “there is no recursion and no facility for process-valued variables” [PAGE 2], and “The text of a program determines a fixed upper bound on the number of processes operating concurrently” [PAGE 2]. Any equation or prediction outside these regimes requires an external model and must not be attributed to the source.
</SOURCE_OPERATORS_AND_EQUATIONS>

<RETROCAUSAL_GENEALOGY>
The historical lineage of the paper is unusually explicit. The introduction positions the work against assignment as a primitive, then argues that input and output are also basic primitives [PAGE 1]. It adopts Dijkstra’s guarded commands as the sequential control structure and as “the sole means of introducing and controlling nondeterminism” [PAGE 1]. It builds a parallel command on Dijkstra’s parbegin [PAGE 1]. It names semaphores, events, conditional critical regions, monitors and queues, and path expressions as prior synchronization mechanisms, then proposes a single simple solution to those problems [PAGE 1]. The paper also compares its imperative, machine-oriented approach with Kahn’s functional coroutines: “There, coroutines are strictly deterministic” and output is automatically buffered, whereas the CSP design uses explicit synchronization and nondeterministic input choice [PAGE 11]. The references reinforce the lineage: Dijkstra’s guarded commands [8], parbegin and cooperating sequential processes [6], conditional critical regions [10], Concurrent Pascal monitors [2], SIMULA classes [5], CLU clusters [13], ALPHARD forms [19], actors [1], path expressions [3], COGENT pattern matching [16], UNIX coroutines [17], ALGOL 60 [15], ALGOL 68 [18], and Pascal [20].

The retrocausal lesson is that many later concurrency constructs are presented as special cases or derived patterns rather than primitives. Coroutines appear as a more fundamental structure than subroutines [PAGE 6]. A subroutine can be represented as a process that repeatedly inputs arguments and outputs results [PAGE 6]. Multiple-entry subroutines are represented by alternative input guards with entry names [PAGE 6]. Recursion is simulated by a bounded array of processes [PAGE 6]. Monitors are represented by a single process communicating with several named users [PAGE 8]. Semaphores are implemented by a process with \(V\) and \(P\) operations [PAGE 8]. The dining philosophers, bounded buffer, and prime sieve are all expressed as process networks [PAGE 8 and PAGE 9]. This genealogy matters because it shows which features are primitive and which are derived. The multi-week traps are therefore historical and conceptual: assuming that monitors are primitive rather than derived; assuming automatic buffering because functional coroutines had it; assuming deterministic coroutine choice; assuming unbounded process arrays; assuming fairness; assuming shared global variables; and assuming that a convenient derived facility is semantically free. The paper warns: “The dangers of convenient facilities are notorious” [PAGE 12]. It also warns that automatic termination of repetitive commands with input guards is powerful but subtle and “not primitive,” since it can be replaced by explicit “end()” signals [PAGE 12]. Any later argument that treats these convenient features as axiomatic is retrocausally invalid unless it proves the same behavior from the primitive CSP operators.
</RETROCAUSAL_GENEALOGY>

<RECURSIVE_THEORY_OF_MIND>
In CSP, a process’s “theory of mind” is local and partial. A process knows its own command list, its own local variables, and the names of its sources and destinations. It does not inspect another process’s local state. It learns readiness only through the guard mechanism: an input guard is selected only if the source named in the input command is ready to execute the corresponding output [PAGE 2]. If several input guards have ready destinations, the choice is arbitrary [PAGE 2]. Thus a process cannot assume that its preferred communication will occur, nor can it infer a global schedule from local readiness.

Crisis habit regression appears when a local policy repeatedly picks a ready alternative and starves another. The fairness discussion gives the canonical case: process \(Y\) may always prefer the second alternative, so an output command in \(X\) is passed over infinitely often even though it could have executed [PAGE 11]. That is habit regression at the process level: a local scheduling habit becomes a global nontermination. The counter-trap is an explicit Boolean guard or extra process that prevents the bad local habit from being repeated. The monitor discussion gives the pattern: “two successive inputs from the same process are inhibited” by a Boolean guard that remembers the previous caller [PAGE 8]. The dining philosophers counter-trap is to prevent more than four philosophers from entering the room, breaking the circular hold in which all five pick up their left forks and starve [PAGE 9]. The room count is a global invariant implemented by a separate process, not by a shared variable.

The clock is absent. The paper says “The relative speed with which they are executed is arbitrary” [PAGE 3], and delay is “invisible to the delayed process” [PAGE 2]. There is no global time variable and no timed guard. Therefore a process cannot use a clock to decide that another process is permanently blocked. It can only wait for a matching output or for termination of all input-guard sources. If neither occurs, deadlock results [PAGE 5]. A correct recursive theory of mind must therefore be conservative: model other processes as either ready, terminated, or unknown; never as probabilistically likely; never as fair by default; and never as synchronized to a hidden clock.
</RECURSIVE_THEORY_OF_MIND>

<CROSS_LAYER_VETO_ADJUDICATION>
The source supports formal concurrency vetoes, not physical, biomechanical, or weather vetoes. At the physical layer, the paper explicitly ignores efficient implementation and hardware optimization [PAGE 2]. It allows implementation on a conventional single-store machine or on a fixed network of processors connected by channels [PAGE 2], but it gives no memory timing, cache behavior, processor speed, or hardware failure model. Therefore any claim that depends on a physical timing assumption is vetoed unless that assumption is added as an external model. At the biomechanical layer, there are no bodies, fatigue variables, or motor constraints. The philosophers are abstract processes named PHIL, FORK, and ROOM [PAGE 8 and PAGE 9]. The “starving” language in the dining philosophers note is a deadlock metaphor, not a biomechanical measurement [PAGE 9]. At the weather layer, there is no environmental stochastic model. Nondeterminism is not weather; it is arbitrary choice among successful guards [PAGE 4]. Therefore any weather-based veto or biomechanical inference is unsupported by the source and must be rejected.

The valid cross-layer vetoes are semantic and structural. First, type or pattern mismatch: a structured assignment can fail if the target does not match the value [PAGE 3], and a nonmatching message can cause deadlock [PAGE 5]. Second, source-destination mismatch: input and output must correspond by explicit process names [PAGE 4]. Third, termination mismatch: a parallel command terminates only when all constituent processes terminate [PAGE 3], and a repetitive command with input guards may terminate only when all named sources terminate [PAGE 5]. Fourth, fairness mismatch: the language does not require fairness [PAGE 11], so a termination proof that relies on fairness is vetoed. Fifth, boundedness mismatch: process arrays are bounded in advance [PAGE 2 and PAGE 10]; an unbounded activation claim is outside the described language. These five vetoes are sufficient to adjudicate whether an inference is within the source. Physical, biomechanical, and weather layers have no evidentiary basis in the paper and cannot override these formal constraints.
</CROSS_LAYER_VETO_ADJUDICATION>

<RLVR_COUNTERFACTUAL_VETOES>
1. Bounded buffer invariant. The source gives a buffer process with `in`, `out`, and the comment “0 <_ out <_ in <_ out + 10” [PAGE 8]. A verifier should exhaustively interleave producer and consumer commands and check the invariant \(0 \leq \mathrm{out} \leq \mathrm{in} \leq \mathrm{out}+10\). Prediction: no reachable state violates it. Veto condition: if a reachable state has \(\mathrm{in} > \mathrm{out}+10\) or \(\mathrm{out} > \mathrm{in}\), the model has deleted or weakened a guard. Counterfactual: remove the guard `in < out + 10`; then overflow becomes possible, proving that the guard is necessary.

2. Naive dining philosophers deadlock. The source’s own note says the solution “does not prevent all five philosophers from entering the room, each picking up his left fork, and starving to death because he cannot pick up his right fork” [PAGE 9]. A verifier should search the interleaving space for the circular wait: all five philosophers execute `fork(i)!pickup()` and then wait for the right fork. Prediction: the naive system has a reachable deadlock state. Veto condition: any claim that the naive solution is deadlock-free is rejected. Counterfactual: add a room process that prevents more than four philosophers from entering; the prediction is that the all-five-left-fork circular wait becomes unreachable.

3. Fairness-dependent termination. The source gives the `X::Y!stop()` and `Y::*[continue; X?stop() -> continue := false □ continue -> n := n + 1]` example [PAGE 11]. The paper says an implementation that always prefers the second alternative is unfair, and that termination cannot be proved by relying on fairness [PAGE 11]. Prediction: under an unfair scheduler, there exists an infinite execution in which \(Y\) never inputs `stop()` and \(X\) never terminates. Veto condition: reject any proof of termination that assumes fairness without explicitly adding a fairness axiom or a priority mechanism. Counterfactual: add a scheduling constraint that eventually selects the input guard; then termination becomes provable, but only under the added assumption, not under the source language alone.
</RLVR_COUNTERFACTUAL_VETOES>
