Therefore the recursive equilibrium requires estimating the user's intent entropy H(I|Q) before applying diversity: low entropy (singular intent) should veto or attenuate group quotas; high entropy (plural intent) should activate them. The clock also governs re-clustering frequency: topic partitions must be refreshed faster than the user's intent-drift timescale to avoid serving stale group representatives.

<CROSS_LAYER_VETO_ADJUDICATION>
Three layers must be adjudicated before deploying the diversity ranking, each with a veto condition.

Physical layer: The clustering operator \mathcal{C} over D(Q) has computational complexity dependent on the similarity kernel s. Pairwise similarity over N documents is O(N^2) in the worst case; even approximate nearest-neighbor clustering adds latency. If the p99 latency for computing \mathcal{G} and \rho exceeds the search SLA (e.g., 100 ms end-to-end), the physical layer vetoes diversity and falls back to a static relevance ranking. Datacenter power and GPU/CPU allocation for per-query clustering are finite; during traffic spikes, the physical layer must rate-limit diversity computation.

Biomechanical layer: The user's visual attention span and serial scanning behavior impose a biomechanical constraint. Eye-tracking studies of search result pages show examination probability concentrated in the first two ranks, with rapid drop-off. If the selected representatives \{d_i^*\}_{i=1}^K include low-richness documents forced by the coverage constraint into top positions, the user experiences "rank 1 disappointment." The biomechanical veto triggers when the expected richness of the top-K diversity output falls below the expected richness of a pure relevance top-K by more than a tolerance \delta (bits), i.e., \frac{1}{K}\sum_{i=1}^K \rho(d_i^*) < \frac{1}{K}\sum_{i=1}^K \rho(d_i^{\text{rel}}) - \delta. In that case, diversity is suppressed for that query.

Weather/meta-layer: Treating "weather" as environmental infrastructure (regional network partitions, CDN outages, datacenter failure), a regional outage may increase latency for fetching document features needed to compute \rho(d) or s(d_i,d_j). If feature freshness degrades below a staleness threshold \tau (seconds), the metadata used for richness and topic grouping becomes unreliable. The weather layer vetoes diversity when feature age > \tau, reverting to cached relevance scores only.

Veto proof: The final output rank list is produced by diversity ranking only if (i) physical latency < SLA, (ii) expected richness loss < \delta, and (iii) feature staleness < \tau. Otherwise, a hard veto returns pure relevance ordering. This prevents the system from violating user expectations under resource, attention, or infrastructure stress.
